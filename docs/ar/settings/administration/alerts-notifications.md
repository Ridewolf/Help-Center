# التنبيهات والإشعارات

صفحة التنبيهات والإشعارات (`/settings/alerts-notifications`) هي **وحدة تنبيه المشغل** — كيف يُخبر النظام _الموظفين_ بأن هناك شيئًا يحتاج إلى اهتمام. تغطي القنوات (الإشعارات الفورية / داخل التطبيق / البريد الإلكتروني / الرسائل النصية)، ومزودي الخدمة الخارجيين (SendGrid، Twilio، Telegram، Slack، Discord، الويب هوكس)، والقواعد التي تُشغل التنبيهات، وقوالب الرسائل، وسياسات التصعيد، ومن المشترك ومن سجل التسليم.

هذه الصفحة مخصصة لـ **التنبيهات لفريق تشغيل المنصة**. بالنسبة لنصوص الإشعارات الموجهة للراكب (بدء الرحلة، تطبيق غرامة، إلخ)، راجع تبويب _الإشعارات_ في [عام](general.md).

> _ملاحظة_: هذه الصفحة هي حاليًا **نموذج أولي للواجهة الأمامية فقط** — إعدادات القنوات، القواعد، الاشتراكات وسجل التسليم محفوظة في الحالة المحلية (أو مُحمّلة من `mockData.ts`). _حفظ التغييرات_ يعرض رسالة تأكيد ولكن لا يتصل بأي نقطة نهاية في الخلفية بعد. شكل الصفحة يتطابق مع النموذج الحقيقي وآمن للاستخدام كمواصفة لعمل واجهة برمجة التطبيقات.

الصلاحية المطلوبة: لا توجد `requiredPermissions` محددة على المسار — يمكن لأي مشغل مسجل الدخول فتحها.

## شريط الأدوات العلوي

رأس الصفحة يحتوي على أربعة أزرار:

| الإجراء       | ما يقوم به                                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------------------------------------- |
| التحديث التلقائي | عنصر واجهة `AutoRefresh` المشترك — لا يفعل شيئًا هنا، موجود للتوافق مع الصفحات الأخرى                                          |
| اختبار الكل     | يعرض رسالة _"جارٍ اختبار الكل"_ — عنصر نائب لـ "إرسال اختبار لكل قناة مُمكّنة"                                     |
| كتم الصوت لمدة ساعة      | رسالة _"تم كتم الصوت لمدة ساعة"_ — عنصر نائب لكتم صوت عام لمدة ساعة                                                              |
| الصيانة  | زر أحمر مدمر — يفتح مربع حوار تنبيه يطلب منك التأكيد؛ عند التبديل يعرض رسالة أن الصيانة مُمكّنة |

## التبويبات

سبعة تبويبات في الأعلى. كل منها مكون فرعي مستقل.

| التبويب           | الغرض                                                                            |
| ------------- | ---------------------------------------------------------------------------------- |
| القنوات      | القنوات المدمجة (الإشعارات الفورية / داخل التطبيق / البريد الإلكتروني / الرسائل النصية) + توجيه حسب الشدة + الملخصات       |
| المزودون     | بيانات اعتماد المزودين الخارجيين (البريد الإلكتروني / الرسائل النصية / Telegram / Slack / Discord / الويب هوكس) |
| القواعد         | قواعد التنبيه لكل عائلة حدث                                                       |
| القوالب     | نص الإشعار لكل عائلة حدث × اللغة                                      |
| السياسات      | سلسلة التصعيد، الكتم التلقائي، سلامة الجمهور، إخفاء البيانات الشخصية                        |
| الاشتراكات | من (دور أو مستخدم) يحصل على أي عائلات أحداث على أي قنوات                     |
| السجلات          | سجل التسليم للقراءة فقط (المرسلة / المؤكدة / الفاشلة)                             |

### القنوات

ثلاث بطاقات مكدسة.

**القنوات المدمجة**

- _الإشعارات الفورية_ — إعداد كامل (مفتاح التمكين، حد المعدل، المحاولات، ساعات الهدوء من/إلى، زر الاختبار).
- _داخل التطبيق_ — تمكين، حد المعدل، ثواني الإغلاق التلقائي.
- _البريد الإلكتروني_ — مرتبط بمزود البريد الإلكتروني في تبويب المزودين. تمكين، حد المعدل، المحاولات.
- _الرسائل النصية_ — مرتبط بمزود الرسائل النصية. تمكين، حد المعدل، المحاولات، ساعات الهدوء.

**تعيين الشدة** — ثلاث قوائم منسدلة تربط `info` → `inApp` (افتراضي)، `warning` → `push`، `critical` → `push+email`. هذه هي القنوات المستخدمة عندما يكون للقاعدة تلك الشدة ولكن لا تحدد قنوات معينة.

**الملخص (التقارير)** — التكرار (إيقاف / كل ساعة / يومي / أسبوعي) + وقت الإرسال (محدد HH:00).

### المزودون

ستة كتل مزود، كل منها مع مفتاح تمكين وبيانات اعتماد.

- _البريد الإلكتروني_ — قائمة نوع المزود (SMTP / SendGrid / Mailgun)، مفتاح API أو بيانات اعتماد SMTP (إدخال مخفي)، من النطاق.
- _الرسائل النصية_ — معرف الحساب SID، رمز المصادقة (مخفي)، رقم المرسل — شكل Twilio.
- _Telegram_ — رمز البوت (مخفي) + محدد دردشة (قائمة ثابتة من ثلاث دردشات تجريبية: `@ridewolf_alerts`، `@support_team`، `@management`; زر **اختبار** عنصر نائب).
- _Slack_ — عنوان الويب هوك + القناة.
- _Discord_ — عنوان الويب هوك.
- _Webhook_ — عنوان ويب هوك عام + سر التوقيع.

كل كتلة مزود تعرض شارة _مُمكّن_ بجانب العنوان بمجرد تشغيل المفتاح. أزرار _اختبار_ تعرض رسالة.

### القواعد

جدول قواعد التنبيه. الأعمدة: الاسم / عائلة الحدث / الشدة / القنوات / الحالة / الإجراءات (قائمة ثلاث نقاط: تحرير / تكرار / تمكين-تعطيل / حذف). انقر على **+ إنشاء قاعدة** لفتح مربع حوار القاعدة — اختر اسمًا، النطاق (عام / منطقة / دور)، عائلة حدث واحدة أو أكثر، الشدة (معلومات / تحذير / حرج)، القنوات وعلم التمكين.

القواعد المحمّلة مسبقًا: _فشل المدفوعات_ (حرج، عائلة المدفوعات، push+email+telegram) و _المركبة غير متصلة_ (تحذير، عائلة المركبات، push+email).

### القوالب

اختر عائلة حدث + لغة + قناة، ثم حرر العنوان والمحتوى. المحتوى يدعم العناصر النائبة (مثل `{{ride.id}}`، `{{amount}}`) التي يقوم **معاينة** بتوسيعها مع حدث نموذجي. _إرسال اختبار_ يعرض رسالة بأن اختبارًا يُرسل إلى القناة المختارة.

### السياسات

أربع كتل:

- _تصعيد حرج_ — قائمة سلسلة (مثلاً push → email → telegram → SMS)، مهلة التأكيد بالدقائق، مفتاح طلب إيصال القراءة.
- _الكتم التلقائي_ — كتم التكرارات: إذا حدث نفس الحدث _N_ مرات في _M_ دقائق، كتم الصوت لمدة _K_ دقائق (ثلاثة مدخلات رقمية). جملة ملخصة أدناه تعيد صياغة القاعدة.
- _سلامة الجمهور_ — مفتاح _حظر الرسائل النصية خارج ساعات الهدوء_ (يتجاوز ساعات الهدوء لكل قناة للرسائل النصية تحديدًا).
- _إخفاء البيانات_ — مفتاح _إخفاء البيانات الشخصية في الرسائل الخارجية_؛ تلميح يشرح ما يتم إخفاؤه (الهاتف، البريد الإلكتروني، آخر 4 أرقام من البطاقات، إلخ).

### الاشتراكات

جدول بإدخالات الاشتراك. كل صف يربط هدفًا (دور أو مستخدم محدد) بعائلة أو أكثر من عائلات الأحداث والقنوات — مثل _دور: مسؤول → النظام + المدفوعات → الإشعارات الفورية + البريد الإلكتروني_. زر **+ إنشاء** يفتح حوار الاشتراك؛ قائمة الصف تحتوي على تحرير / حذف.

استخدم الاشتراكات لتوصيل التنبيهات إلى الأشخاص الذين لا يطابقون أي قناة مثبتة في قاعدة — القواعد تحدد _ماذا_ يتم التنبيه عنه، والاشتراكات تحدد _من_ يسمع التنبيه.

### السجلات

جدول للقراءة فقط لمحاولات التوصيل. الأعمدة: الوقت / الحدث / المسار / القناة / المستلم / الحالة (مرسل / مؤكد / فشل) / التأخير. انقر على صف لفتح إشعار تفصيلي (مكان مخصص للوحة تفاصيل كاملة). استخدم هذا لتأكيد أن التنبيه تم إرساله فعليًا، أو لتصحيح مزود فاشل.

## عائلات الأحداث

تعتمد القواعد والقوالب والاشتراكات جميعها على نفس القائمة الثابتة لعائلات الأحداث (المعرفة في `models/channels.ts`):

`authProfile` · `dashboard` · `vehicles` · `rides` · `payments` · `marketing` · `rebalance` · `support` · `maintenance` · `settings` · `system`

هذه تتطابق تقريبًا مع مجالات لوحة التحكم — اختر العائلة التي تناسب نوع الحدث الذي تريد التنبيه عنه.

## سير العمل

- **توصيل تنبيهات البريد الإلكتروني** — تبويب المزودون → تفعيل البريد الإلكتروني → اختيار نوع المزود → لصق مفتاح API → حفظ → العودة إلى القنوات → تفعيل قناة البريد الإلكتروني → تم.
- **استلام تنبيهات عند فشل المدفوعات** — تبويب القواعد → تحرير _فشل المدفوعات_ → تأكد من أن الشدة هي `critical` وأن القنوات تشمل التي تراقبها فعليًا → حفظ.
- **إيقاف الرسائل النصية المزعجة ليلاً** — تبويب السياسات → تفعيل _حظر الرسائل النصية خارج ساعات الهدوء_ → ضبط ساعات الهدوء لكل قناة في تبويب القنوات.
- **إرسال ملخص يومي بدلاً من التنبيهات المتكررة** — تبويب القنوات → بطاقة الملخص → ضبط التكرار إلى _يومي_، والوقت مثلاً 09:00.
- **إضافة دور جديد في الخدمة عند الطلب** — تبويب الاشتراكات → + إنشاء → اختيار الدور → عائلات الأحداث → القنوات → حفظ. سيحصلون على التنبيهات المستقبلية المطابقة.
- **تصحيح تنبيه مفقود** — تبويب السجلات → ابحث عن الحدث حسب المسار أو الوقت → إذا كانت الحالة `failed`، انتقل إلى المزودين للتحقق من بيانات الاعتماد؛ إذا `sent` ولكن لم يره المستخدم، تحقق من الاشتراكات / ساعات الهدوء / حالة الكتم.

## نصائح

- **واجهة أمامية فقط في الوقت الحالي.** الحفظ يعرض إشعارًا لكن API غير موجود بعد — اعتبر هذه الصفحة مواصفة، وليست مصدر الحقيقة.
- **أزرار الاختبار مجرد نماذج.** _اختبار الكل_، _كتم لمدة ساعة_، _اختبار_ لكل قناة وتأكيد _الصيانة_ كلها تعرض إشعارًا فقط — لا ترسل رسائل اختبار فعلية أو تكتم أي شيء.
- **تعيين الشدة هو الحل الاحتياطي.** قائمة _القنوات_ في القاعدة هي الأساس عند تعيينها؛ فقط إذا كانت القائمة غير مضبوطة/فارغة يتم الرجوع إلى تعيين الشدة.
- **الملخص منفصل عن التنبيهات لكل حدث.** تفعيل الملخص لا يكتم التنبيهات الفردية — بل يضيف الملخص الدوري.
- **يمكن أن تستهدف الاشتراكات مستخدمًا**، وليس فقط دورًا. استخدم هذا للتصعيدات الفردية (مثلاً _رئيس نوبة الليل يتلقى كل تنبيهات `rides` على الإشعارات الفورية_) دون إنشاء دور.
- **التصميم على الجوال للقراءة فقط عمدًا.** كل التبويبات على الجوال تقول فقط _استخدم سطح المكتب للتكوين الكامل_ — التنبيه عمل إداري يحتاج سطح المكتب.
- **إخفاء المعلومات الشخصية مهم للرسائل النصية/البريد الإلكتروني.** إذا كان معطلًا، قد تتسرب أجسام التنبيه أرقام الهواتف أو نهايات البطاقات إلى مزودين خارجيين — اتركه مفعّلًا إلا إذا كان لديك سبب محدد.
