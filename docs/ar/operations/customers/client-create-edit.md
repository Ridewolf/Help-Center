# العميل — إنشاء وتحرير

رابطان:

- **إنشاء** — `/clients/create` — تسجيل عميل جديد يدويًا (نادر؛ معظم العملاء يسجلون بأنفسهم)
- **تحرير** — `/clients/:id/edit` — تحديث بيانات العميل الشخصية وحالته الحالية

يمكن الوصول إلى كلا الرابطين من [قائمة العملاء](clients.md) (زر `+ إنشاء` في الأعلى يمين) أو من [صفحة تفاصيل العميل](client-detail.md) (_الإجراءات → تحرير العميل_).

الأذونات:

- **إنشاء** — `العملاء` (`e4f5h6`) + إذن فرعي متعلق بالإنشاء
- **تحرير** — `العملاء` (`e4f5h6`) + الإذن الفرعي `edit`

## متى تستخدم

معظم عملائك **يسجلون بأنفسهم** عبر تطبيق الراكب على الهاتف المحمول — نادرًا ما تقوم بإنشائهم في لوحة التحكم.

الإنشاء اليدوي مخصص لـ:

- **حسابات اختبار** — ضمان الجودة الداخلي، مستخدمو العرض التوضيحي
- **العملاء المهمون / الشركات** — حسابات يجب أن تكون موجودة قبل تحميل الراكب للتطبيق
- **التسجيل بواسطة المشغل** — فعاليات / شراكات حيث يقوم الموظفون بالتسجيل نيابة عن الراكب

لباقي الحالات، دع التطبيق يتولى التسجيل واستخدم **تحرير** عند الحاجة لتصحيح معلومات الاتصال أو تغيير الحالة.

## التخطيط

بطاقة واحدة مع نموذج عمودي، بدون شريط جانبي لدليل الحقول (مختلف عن نموذج المركبة).

## الحقول — إنشاء

سبعة حقول إجمالاً. جميعها مطلوبة.

| الحقل               | التحقق من الصحة                                                                                                         |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **الاسم الأول**      | من 1 إلى 100 حرف                                                                                                       |
| **اسم العائلة**      | من 1 إلى 100 حرف                                                                                                       |
| **البريد الإلكتروني**| صيغة بريد إلكتروني قياسية (`name@domain.tld`)؛ يجب أن يكون فريدًا بين العملاء                                         |
| **الهاتف**           | صيغة دولية تبدأ بـ `+` (مثال: `+373 60 123 456`)؛ أرقام، فراغات، شرطات، وأقواس فقط                                   |
| **كلمة المرور**      | **على الأقل 12 حرفًا**، يجب أن تحتوي على **حرف كبير، حرف صغير، رقم، وحرف خاص**                                       |
| **تأكيد كلمة المرور**| يجب أن تطابق كلمة المرور تمامًا                                                                                        |
| **الحالة**           | الحالة الابتدائية: `نشط` / `غير نشط` / `محظور` / `مجمّد` / `قيد التسجيل` (الافتراضي _نشط_)                        |

يتم التحقق من الصحة عند الحفظ وأثناء الخروج من الحقل. تظهر الأخطاء باللون الأحمر تحت الحقل.

### قواعد كلمة المرور

متطلبات كلمة المرور هي الأكثر صرامة. ترفض لوحة التحكم أي كلمة مرور لا تستوفي جميع الشروط الأربعة:

- 12 حرفًا أو أكثر
- حرف كبير واحد على الأقل (A–Z)
- حرف صغير واحد على الأقل (a–z)
- رقم واحد على الأقل (0–9)
- حرف خاص واحد على الأقل (مثال `!@#$%^&*`)

بعد الحفظ، سيستخدم العميل هذه الكلمة (مع الهاتف أو البريد الإلكتروني) لتسجيل الدخول إلى تطبيق الراكب. أخبر العميل عبر قناة موثوقة — لا تلصق كلمات المرور في محادثات غير مشفرة من طرف إلى طرف.

### الحالة (عند الإنشاء)

| القيمة           | الاستخدام                                                                                 |
| ---------------- | ----------------------------------------------------------------------------------------- |
| **نشط**          | الافتراضي — يمكن للعميل الركوب فورًا                                                     |
| **غير نشط**      | تم الإنشاء لكن لم يُفعّل بعد (ستغيرها إلى نشط لاحقًا)                                   |
| **محظور**        | محظور مسبقًا (نادرًا — عادةً عند إعادة إنشاء حساب بعد حادثة احتيال)                    |
| **مجمّد**        | الحساب موقوف مؤقتًا                                                                       |
| **قيد التسجيل**  | التسجيل لا يزال جاريًا (يستخدم فقط عند التكامل مع تدفق خارجي)                            |

## الحقول — تحرير

في التحرير تُخفي حقول كلمة المرور (يتم إعادة تعيينها في مكان آخر) وتُضاف **العلامات**.

| الحقل           | ملاحظات                                                                       |
| --------------- | ----------------------------------------------------------------------------- |
| **الاسم الأول** | معبأ مسبقًا، نفس التحقق من الصحة كما في الإنشاء                               |
| **اسم العائلة** | معبأ مسبقًا، نفس التحقق من الصحة كما في الإنشاء                               |
| **البريد الإلكتروني** | معبأ مسبقًا؛ تغييره قد يوقف تسجيل دخول العميل حتى يعيد التحقق                 |
| **الهاتف**      | معبأ مسبقًا؛ نفس التحذير كما في البريد الإلكتروني                              |
| **العلامات**    | اختيار متعدد؛ تسميات يضيفها المشغل للتجميع والتصفية                           |
| **الحالة**      | معبأ مسبقًا بالحالة الحالية؛ نفس التعداد                                       |

## حفظ / إلغاء

- **إلغاء** (أو السهم الخلفي) — يتجاهل التغييرات غير المحفوظة ويعود إلى الصفحة السابقة
- **حفظ** — يتحقق من صحة النموذج وينشئ / يحدث العميل. تظهر رسالة تأكيد النجاح؛ وتُبرز الأخطاء الحقلية باللون الأحمر

إذا فشل التحقق (حقل مفقود، قواعد كلمة المرور، بريد إلكتروني مكرر، صيغة الهاتف)، تبقى الصفحة مفتوحة مع تمييز الحقل المخالف.

## الاختلافات بين الإنشاء والتحرير

| الجانب             | إنشاء                                                  | تحرير                                                 |
| ------------------ | ------------------------------------------------------- | ---------------------------------------------------- |
| حقول كلمة المرور    | موجودة وضرورية                                        | مخفية                                               |
| العلامات           | غير موجودة في النموذج (تُحدد لاحقًا عبر التحرير أو القائمة/التفاصيل) | موجودة                                              |
| الحالة             | فارغة → الافتراضي _نشط_                                | مملوءة مسبقًا بالحالة الحالية                       |
| البريد الإلكتروني / الهاتف | فارغ                                                   | مملوء مسبقًا — تغييرها قد يفرض إعادة التحقق          |
| بعد الحفظ          | إعادة التوجيه إلى تفاصيل العميل الجديد                 | إعادة التوجيه إلى تفاصيل العميل                      |
| إدخال سجل النشاط  | "تم إنشاء العميل بواسطة _اسم المشغل_"                 | "تم تحرير العميل بواسطة _اسم المشغل_" مع اختلافات الحقول |

كلا المسارين يكتبان في [سجل النشاط](client-detail.md#لسان-النشاط) الخاص بالعميل.

## سير العمل النموذجي

- **إنشاء عميل مميز** — `+ إنشاء` في القائمة → املأ الاسم، البريد الإلكتروني الحقيقي، الهاتف الحقيقي، كلمة مرور قوية، الحالة _نشط_ → حفظ → إعلام الراكب بالبيانات
- **تصحيح خطأ مطبعي** — صف القائمة → قائمة الصف → _تحرير_ → تصحيح الحقل → حفظ (يظهر التغيير في سجل النشاط مع اختلاف)
- **إضافة دفعة شركات** — برمجة الإنشاء عبر API (هذا النموذج للعمليات الفردية)؛ استخدم التحرير لاحقًا لتطبيق العلامات الخاصة بالشركة
- **تغيير الهاتف بعد تبديل الجهاز** — تحرير → تحديث الهاتف → حفظ → سيحتاج العميل لإعادة التحقق عند تسجيل الدخول التالي (حسب قواعد النظام الخلفي)

## نصائح

- **تنسيق الهاتف مهم** — يجب أن يبدأ بـ `+` ورمز الدولة؛ يتم فرض التنسيق وسيُرفض الإدخال غير الصحيح
- **اختيار كلمة مرور قوية** — لإنشاءات المشغل الفردية، استخدم عبارة طويلة ("rideTheWolf2026!RW") تلبي كل القواعد دفعة واحدة؛ سجّلها في مدير كلمات المرور، وليس في الدردشة
- **تفرد البريد الإلكتروني** — البريد الإلكتروني المكرر هو أكثر أسباب فشل الإنشاء شيوعًا؛ تحقق من القائمة أولًا بالبحث عن البريد
- **لا تغير البريد الإلكتروني / الهاتف بشكل عشوائي على العملاء الحاليين** — تعتمد تدفقات التحقق عليهما؛ نسق مع العميل قبل الحفظ
- **العلامات تخص هذا النموذج، وليس الصف** — يمكنك أيضًا إضافة/إزالة العلامات عبر الإجراء الجماعي في القائمة، لكن نموذج التحرير هو المكان المناسب للتغييرات الدقيقة
- **تغييرات الحالة لها وزن تدقيقي** — الانتقال من _نشط → محظور_ عبر هذا النموذج يُسجل بنفس طريقة _الإجراءات → حظر العميل_ — كلاهما صحيح
