# المدفوعات — السجل

صفحة المدفوعات (`/payments`) هي دفتر حسابات لكل معاملة مالية تمّت على حساب العميل: رسوم الرحلات، تعبئة المحفظة، الاستردادات، الغرامات. استخدمها للتحقيق في رسوم، إصدار استرداد، أو تدقيق تدفق الأموال خلال فترة زمنية.

لأحداث الويب هوكس غير المعالجة من مزودي الدفع، راجع [Pending Webhooks](pending-webhooks.md).

الصلاحية المطلوبة: **المدفوعات** (`m1n2p3`). بعض إجراءات الصفوف تتطلب صلاحيات فرعية إضافية.

## ما يوجد هنا

كل صف يمثل معاملة دفع واحدة:

| النوع       | ما هو                                                                 |
| ---------- | -------------------------------------------------------------------- |
| **تعبئة**  | أموال أُضيفت إلى محفظة العميل (رصيد يدوي من المشغل أو تعبئة بطاقة) |
| **خصم**    | أموال أُخذت من العميل (رسوم رحلة أو غرامة)                          |
| **استرداد**| أموال أُعيدت إلى العميل (عكس خصم سابق)                             |

كل معاملة لها **طريقة/مزود** — القناة التي تمت من خلالها:

- **مزودو البطاقات** (Stripe، إلخ) — أموال حقيقية على بطاقة الدفع
- **الرصيد** — المحفظة الداخلية (ليس مزود دفع؛ مجرد خصم/رصيد على رصيد العميل)
- **بوابات أخرى** حسب تكاملاتك

التفريق بين _مزود البطاقة_ و _الرصيد_ مهم للاستردادات — راجع _إجراءات الصف → استرداد_ أدناه.

## الفلاتر

| فلتر       | النوع    | ملاحظات                                                      |
| ---------- | -------- | ------------------------------------------------------------- |
| بحث        | نص       | يبحث في اسم العميل، معرف الدفع، معرف الرحلة / الغرامة المرتبطة |
| نطاق التاريخ| تقويم   | اختيار من / إلى؛ الافتراضي "كل الوقت"                       |
| النوع      | قائمة منسدلة | `تعبئة` / `خصم` / `استرداد` (أو `الكل`)                    |
| الحالة    | قائمة منسدلة | `قيد الانتظار` / `مكتمل` / `فشل` / `مسترد` (أو `الكل`)      |

تُطبق الفلاتر على الخادم وتُجمع باستخدام AND.

## الأعمدة

| العمود     | قابل للفرز؟ | المحتوى                                                            |
| ---------- | --------- | ------------------------------------------------------------------ |
| **التاريخ**| ✓         | وقت إنشاء المعاملة؛ الفرز الافتراضي = الأحدث أولاً                 |
| **العميل** | —         | اسم العميل وصورته الرمزية؛ رابط لتفاصيل العميل                   |
| **المصدر** | —         | نوع المعاملة (تعبئة / خصم / استرداد)، مع وسم ملون                 |
| **المبلغ** | ✓         | مبلغ المال بعملة الشركة، موقع (+/−) وملون                        |
| **الطريقة**| —         | طريقة الدفع / المزود (بطاقة، رصيد، اسم البوابة)                   |
| **الحالة** | ✓         | حالة المعاملة (راجع المرجع أدناه)                                 |

يمكن الفرز بالنقر على رأس عمود قابل للفرز. الفرز المختار جزء من عنوان URL.

## مرجع الحالة

| الحالة        | المعنى                                                                    |
| ------------- | ------------------------------------------------------------------------- |
| **قيد الانتظار** | تم الإرسال للمزود؛ في انتظار تأكيد الويب هوكس                         |
| **مكتمل**     | أكد المزود النجاح؛ تم تحويل المال                                      |
| **فشل**       | رفض المزود المعاملة (رفض البطاقة، خطأ في الشبكة، فحص الاحتيال)         |
| **مسترد**     | خصم ناجح تم عكسه لاحقًا باسترداد                                        |

## إجراءات الصف

كل صف يحتوي على **قائمة ثلاث نقاط** على اليمين. الإجراءات المتاحة تعتمد على نوع الدفع، الحالة، وصلاحياتك:

| الإجراء         | متى يكون مفعّلًا                     | الصلاحية                                               |
| --------------- | ---------------------------------- | ------------------------------------------------------ |
| **عرض العميل**  | دائمًا (ينتقل إلى ملف العميل)      | —                                                      |
| **استرداد**     | راجع "توجيه الاسترداد" أدناه       | `refund` / `topup-manual` / `fine` (حسب المسار)                           |

### توجيه الاسترداد

لوحة التحكم تخفي تفاصيل المزود عنك، لكن إجراء _الاسترداد_ ذكي بما يكفي لاختيار المسار الصحيح:

- **خصم مزود** (بطاقة، بوابة) → يستدعي نقطة نهاية الاسترداد للمزود → المال يعود إلى البطاقة
- **خصم الرصيد** (المحفظة) → لا يوجد مزود — يفتح حوار **تعبئة الرصيد** لإضافة رصيد للمحفظة (يتطلب `topup-manual`)
- **تعبئة الرصيد** (رصيد يدوي من المشغل) → لا يمكن عكسه عبر مزود — يفتح حوار **إصدار غرامة** لخصم نفس المبلغ (يتطلب `fine`)

الاسترداد **معطل** عندما:

- الصف نفسه استرداد (لا معنى لاسترداد استرداد)
- الحالة ليست _مكتمل_ (لا يمكنك استرداد المعاملات قيد الانتظار / الفاشلة)
- المعاملة قد تم عكسها بالفعل (لوحة التحكم تتعقب هذا وتمنع النقرات المكررة)
- لا تملك الصلاحية الفرعية الصحيحة لمسار التوجيه

## لماذا تظهر المدفوعات هنا (وما الذي ينشئها)

المدفوعات **لا تُنشأ** من هذه الصفحة — بل تنشأ من تدفقات أخرى:

1. **الراكب يأخذ رحلة** → نهاية الرحلة → الخلفية تنشئ معاملة _خصم_ → إذا نجحت، تتحول الحالة إلى _مكتمل_ ويُخصم المال من المحفظة أو البطاقة
2. **الراكب يعبئ المحفظة في التطبيق** → استدعاء المزود → الخلفية تنشئ معاملة _تعبئة_ → تتحول الحالة إلى _مكتمل_ عند تأكيد الويب هوكس
3. **المشغل يضيف رصيدًا للمحفظة** عبر _تعبئة الرصيد_ على عميل → الخلفية تنشئ _تعبئة_ بطريقة _الرصيد_ وتصبح _مكتملة_ فورًا
4. **المشغل يصدر غرامة** → الخلفية تنشئ _خصم_ بطريقة _الرصيد_ وتصبح _مكتملة_ فورًا
5. **استرداد** من هذه القائمة → الخلفية تنشئ معاملة _استرداد_؛ الأصلية تُعلّم كـ _مستردة_

المعاملة الأصلية لا تختفي أبدًا — كل إجراء قابل للتدقيق.

## تدفقات العمل النموذجية

- **التحقيق في عملية خصم** — ابحث بواسطة معرف العميل / الرحلة / الدفع → تحقق من الحالة (مكتمل = تم سحب المال، فشل = لم يتم السحب) والطريقة
- **استرداد رحلة** — ابحث عن صف _خصم_ للرحلة → قائمة الصف → _استرداد_ → تأكيد → يظهر صف _استرداد_ مزدوج، ويتحول الأصلي إلى _تم استرداده_
- **تدقيق اليوم** — حدد نطاق التاريخ = اليوم → فلتر الحالة = مكتمل → راجع الإجماليات
- **العثور على عمليات فاشلة لإعادة المحاولة** — فلتر الحالة = فشل → تواصل مع العملاء لإعادة المحاولة / طريقة بديلة
- **المصالحة مع المزود** — نطاق التاريخ + النوع = تعبئة/خصم + الطريقة = مزود البطاقة → تصدير ومطابقة مع كشف المزود

## نصائح

- **قيد الانتظار ليس فشلًا** — المعاملات قيد الانتظار تنتظر الويب هوك من المزود؛ تحقق من [الويب هوكس المعلقة](pending-webhooks.md) إذا بقي الصف قيد الانتظار لفترة طويلة
- **معاملات الرصيد لا يمكن استردادها عن طريق البطاقة** — النظام يوجهك إلى الحوار الصحيح؛ لا تحاول إنشاء معاملات تعويضية يدويًا
- **الأصلي يبقى بعد الاسترداد** — الاستردادات تضيف صفًا مزدوجًا، ولا تحذف الخصم؛ يبقى كلا الصفين في السجل للتدقيق
- **علامة المبلغ توضح الاتجاه** — `+` (أخضر) تعني مال للعميل؛ `−` (أحمر/داكن) تعني مال من العميل
- **أسماء المزودين مهمة للدعم** — عند التصعيد إلى مزود الدفع، انسخ معرف الدفع واسم المزود من عمود الطريقة
- **الرابط قابل للمشاركة** — انسخ عرضًا مفلترًا (مثلاً _خصومات البطاقة الفاشلة ليوم أمس_) وأرسله إلى المالية أو مكافحة الاحتيال
