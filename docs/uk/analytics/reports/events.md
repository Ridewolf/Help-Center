# Аналітика — Останні події

Сторінка аналітики Подій (`/analytics/events`) — це ваш **дашборд інцидентів**: усі помітні системні, транспортні, користувацькі та зональні події за обраний період із лічильниками KPI, динамікою за часом і пошуковою стрічкою внизу.

На відміну від [панелі Сповіщень](../../features/ux/notifications.md) (в режимі реального часу, подія за подією) — ця сторінка є **агрегованою та історичною**, корисною для виявлення тенденцій і аналізу після інцидентів.

Потрібен дозвіл: **Перегляд останніх подій** (`s1t2u3`).

## Період часу та фільтри

Угорі розташована **панель вибору діапазону дат** — усі метрики та графіки враховують її. Чотири додаткові фільтри звужують перегляд:

| Фільтр          | Варіанти                                                                 |
| --------------- | ----------------------------------------------------------------------- |
| **Серйозність** | `critical` / `warning` / `info` (мультивибір)                           |
| **Тип**         | `error` / `offline` / `battery` / `payment` / `support` / `maintenance` |
| **Тип джерела** | `vehicle` / `user` / `zone` / `system`                                  |
| **Статус**      | `open` / `resolved` / `dismissed`                                       |

Усі фільтри комбінуються через І. URL відображає всі налаштування — поділіться посиланням, і ваш колега побачить точно такий самий зріз.

## Розділи

Сторінка має **п’ять розділів**:

### 1. Підсумок

Чотири картки з метриками підсумовують кількість подій:

| KPI          | Що показує                                                  |
| ------------ | ----------------------------------------------------------- |
| **Всього**   | Загальна кількість подій за період                          |
| **Критичні** | Кількість із `severity = critical` — найважливіше число    |
| **Попередження** | Кількість із `severity = warning`                        |
| **Інформаційні** | Кількість із `severity = info` — зазвичай шум, якщо немає сплеску |

Кожна картка має бейдж порівняння «порівняно з попереднім періодом».

### 2. За типом

Діаграма, що розбиває події за **типом**:

- **Помилка** — збої системи / інтеграції
- **Офлайн** — IoT-пристрої, що перестали відповідати
- **Акумулятор** — тривоги низького заряду / розрядження / аномалії
- **Платіж** — відмови, проблеми з платіжним шлюзом
- **Підтримка** — сплески квитків / чатів
- **Техобслуговування** — події, пов’язані з сервісом

Сплески в одному типі зазвичай є відправною точкою для розслідування.

### 3. Шаблони

Два часові графіки:

- **За днем** — події на день за весь період (візуалізує тижневі цикли)
- **За годиною** — події за годину доби за весь період (візуалізує добові піки)

### 4. Топ джерел

Список **топових джерел** подій — зазвичай окремі транспортні засоби або зони з непропорційно великою кількістю подій.

Кожен запис містить джерело (з посиланням на сторінку деталей), кількість подій і домінуючу серйозність / тип.

Тут ви знайдете **транспортний засіб, що сигналив увесь тиждень**, або **зону з проблемами акумулятора**.

### 5. Стрічка

Прокручувана стрічка окремих подій, що відповідають поточним фільтрам. Кожен рядок показує:

- Іконку серйозності (кольорова)
- Тип події + позначку джерела
- Короткий опис
- Позначку часу
- Статусну мітку

Клік на елемент стрічки веде до пов’язаної сутності (транспортний засіб, клієнт, поїздка, квиток), якщо це можливо.

## Типові робочі процеси

- **Щоденний ранковий огляд** — заздалегідь встановлений _Останні 24 години_ → Серйозність = Критичні → сканування; усе червоне привертає увагу перед відкриттям решти панелі керування
- **Сортування топових джерел** — розділ Топ джерел → клік на транспортний засіб, що постійно з’являється → виправлення або ескалація на джерелі
- **Виявлення шаблонів** — графіки шаблонів; незвичайний день або година показує, що щось змінилося (деплой, погода, відключення)
- **Аналіз після інциденту** — вибір дня → серйозність = критична → порівняння Стрічки з вкладкою Сповіщень [Транспортного засобу](../../operations/fleet/vehicle-detail.md) або розділом Якості [аналітики платежів](payments.md) залежно від типу
- **Прибирання** — Статус = Відкрито → масове закриття застарілих елементів (це робиться на сторінках джерел, не тут, але їх тут можна знайти)

## Поради

- **Спочатку критичні** — починайте з `severity = critical`; попередження та інформаційні часто вирішуються самі по собі
- **Тип — ваш детектив** — коли є сплеск, фільтруйте за домінуючим типом, щоб зменшити шум
- **Топ джерел — золото** — один транспортний засіб у верхівці списку джерел зазвичай пояснює 30-50% усіх подій
- **Агрегації проти сирих даних** — ця сторінка агрегує; для фактичних транзакцій / сповіщень переходьте на сторінку домену джерела
- **Фільтри збережені** — ваші налаштування зберігаються при навігації; очищуйте їх, коли передаєте URL іншій людині
- **Статус `open` ≠ невирішена тривога IoT** — Статус тут — це статус _запису події_; базова тривога могла зникнути на пристрої, а подія все ще відкрита в системі
