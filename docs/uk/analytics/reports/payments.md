# Аналітика — Платежі

Сторінка аналітики Платежів (`/analytics/payments`) — це ваша **фінансова панель керування**: ключові показники та графіки про надходження грошей (поповнення), витрати (повернення), списання коштів (дебети) та стан вашої платіжної системи.

На відміну від [Історії платежів](../../operations/payments/payments.md), яка є журналом по кожній транзакції — ця сторінка **агрегована** за діапазоном дат, щоб ви могли виявляти тренди, втрати та аномалії.

Необхідний дозвіл: **Перегляд аналітики платежів** (`w7x8y9`).

## Період часу

**Панель вибору діапазону дат** розташована у верхній частині сторінки. Всі метрики та графіки враховують цей діапазон:

- Виберіть готовий варіант (Сьогодні, Останні 7 / 30 / 90 днів, Цей / Минулого місяця) або власний діапазон
- Значок порівняння під картками метрик показує "vs попередній період" — якщо ви обрали _Останні 7 днів_, порівняння відбувається з 7 днями до цього
- Діапазон зберігається на сесію: переходьте на інші сторінки і повертайтеся — ваш вибір збережено

## Розділи

Сторінка організована у **шість розділів**, кожен з яких зосереджений на різних аспектах платежів:

### 1. Потік

Загальна картина — надходження грошей проти витрат.

| KPI            | Що вимірює                                                                                                               |
| -------------- | ------------------------------------------------------------------------------------------------------------------------ |
| **Поповнення** | Гроші, зараховані на гаманці у цьому діапазоні (ручні + провайдер)                                                      |
| **Повернення** | Гроші, повернені клієнтам; має бейдж _Рівень повернень_ (повернення / дебети)                                            |
| **Дебети**     | Гроші, списані з клієнтів (поїздки, штрафи). Включає **фільтр за тегом**, щоб ви могли обмежити до певного тегу клієнта (наприклад, _VIP_) |
| **Чистий потік** | Поповнення − Повернення; позитивне значення означає, що ваш грошовий залишок зростає                                      |

### 2. Якість

Стан інтеграції з вашим платіжним провайдером.

| KPI                 | Що вимірює                                                                                                               |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| **Рівень успіху**   | Завершені транзакції / всі спроби — ваш основний показник надійності                                                    |
| **Помилки**         | Кількість невдалих транзакцій у діапазоні                                                                                |
| **Очікується**      | Кількість транзакцій, що ще очікують (перевірте з [Очікуваними вебхуками](../../operations/payments/pending-webhooks.md)) |
| **Повернено**       | Кількість дебетів, які були повернені                                                                                     |
| **Причини помилок** | Графік, що розбиває помилки за причинами (відмова / 3DS / мережа / тощо)                                                |

Сплеск у _Помилки_ + домінування конкретної причини на графіку = збій або проблема інтеграції, яку потрібно підняти.

### 3. Баланс

Стан коштів операторів (гаманці користувачів) на кінець діапазону.

| KPI               | Що показує                                                                                     |
| ----------------- | ---------------------------------------------------------------------------------------------- |
| **Залишок**       | Сума всіх позитивних балансів — гроші, які ви фактично тримаєте для користувачів                 |
| **Заборгованість**| Сума всіх негативних балансів — гроші, які користувачі вам винні                              |
| **Середній баланс**| Середній баланс на активного клієнта                                                          |
| **Користувачі**   | Кількість клієнтів з ненульовим балансом                                                      |
| **Гістограма**    | Гістограма клієнтів за розміром балансу (наприклад, 0–10 / 10–50 / 50–100 / 100+)               |

Використовуйте _Заборгованість_ як сигнал для роботи з боргами — велика заборгованість означає багато штрафів або невдалих списань, які потребують уваги.

### 4. Патерни

Поведінкові патерни поповнень користувачів — корисно для маркетингу та продукту.

- **Гістограма розміру поповнень** — як користувачі розподіляють свої поповнення за сумами. Мода гістограми (найпоширеніший розмір) — це значення, яке має бути за замовчуванням у ваших підказках
- **Поповнення за годинами** — коли протягом дня користувачі поповнюють. Піки зазвичай збігаються з піками поїздок (часи поїздок, вечори вихідних)

### 5. Методи

Табличний розподіл за **методом / провайдером оплати**.

- Колонки: Метод (картка / баланс / гаманець / тощо), Загальна сума, Кількість, Середня транзакція, Рівень успіху
- Корисно для виявлення провайдерів з низькою ефективністю (один метод з низьким рівнем успіху — ваш слабкий ланцюг)

### 6. Користувачі

Перегляд когорти клієнтів — хто вам платить.

| KPI               | Що вимірює                                                                                     |
| ----------------- | ---------------------------------------------------------------------------------------------- |
| **Унікальні платники** | Унікальні клієнти, які здійснили оплату у вибраному діапазоні                                |
| **Нові платники**      | Клієнти, які вперше оплатили у цьому діапазоні                                              |
| **Повторні платники**  | Клієнти, які оплатили більше одного разу у цьому діапазоні                                  |
| **Топ платники**       | Таблиця клієнтів з найбільшими сумами платежів з ім’ям, сумою, кількістю поїздок, посиланням на профіль |

## Типові робочі процеси

- **Щотижневий огляд** — встановіть за замовчуванням _Останні 7 днів_ → перегляньте кожен розділ. Все, що поза стрічкою порівняння (великий ▲ або ▼), потребує детальнішого аналізу
- **Аналіз збоїв** — встановіть діапазон дат на день інциденту → розділ Якість → діаграма причин збоїв → порівняйте з [Історією платежів](../../operations/payments/payments.md) для фактичних транзакцій
- **Глибокий аналіз тегів** — вкладка Дебіти → фільтр за тегом → виберіть тег, наприклад _VIP_ → метрика Дебіти показує лише цю когорту; порівняйте з загальною сумою дебітів для швидкого визначення частки
- **Прискорення стягнень** — розділ Баланс → _Борг_ → якщо він зріс, дослідіть окремих клієнтів через список Клієнтів, відфільтрований за негативним балансом
- **Ціноутворення для маркетингу** — вкладка Шаблони → гістограма розміру поповнень → встановіть рекомендоване в додатку поповнення на найпопулярніший діапазон

## Поради

- **Стрічка порівняння корисніша за абсолютне число** — абсолютна сума доходу залежить від розміру компанії; % зміни показує, чи покращується ситуація
- **Фіксований діапазон дат** — останній вибраний діапазон зберігається при навігації; якщо колега поділиться URL з іншим діапазоном, він буде застосований
- **Фільтр за тегом застосовується лише до Дебітів** — щоб побачити поповнення за тегом, потрібно порівняти з списком Клієнтів
- **Діаграма причин збоїв — це ваш рейтинг провайдера** — раптова поява нової категорії зазвичай означає зміну конфігурації провайдера
- **Позитивний чистий приплив ≠ прибуток** — це кошти у гаманці, а не дохід; не враховує повернення коштів або незавершені баланси
- **Середній баланс × Користувачі ≠ Кошти у гаманці** — кошти у гаманці — це сума позитивних значень; якщо багато користувачів у боргу, середній баланс може бути нижчим за Кошти / Користувачі
