# Сповіщення та повідомлення

Сторінка Сповіщень та повідомлень (`/settings/alerts-notifications`) — це **консоль оповіщення оператора** — як платформа повідомляє _персоналу_, що щось потребує уваги. Вона охоплює канали (push / in-app / email / SMS), зовнішніх провайдерів (SendGrid, Twilio, Telegram, Slack, Discord, вебхуки), правила, які запускають сповіщення, шаблони повідомлень, політики ескалації, хто підписаний і журнал доставки.

Ця сторінка стосується **сповіщень для команди, що керує платформою**. Для текстів повідомлень, орієнтованих на користувачів (Поїздка почалася, Накладено штраф тощо), див. вкладку _Notifications_ у [General](general.md).

> _Примітка_: ця сторінка наразі є **прототипом лише фронтенду** — конфігурації каналів, правила, підписки та журнал доставки зберігаються у локальному стані (або ініціалізовані з `mockData.ts`). _Збереження змін_ показує підтвердження у вигляді тосту, але поки не звертається до бекенду. Структура сторінки відповідає реальній моделі і безпечна для використання як специфікація для роботи з API.

Необхідний дозвіл: на маршруті не встановлено конкретних `requiredPermissions` — будь-який авторизований оператор може відкрити цю сторінку.

## Верхня панель інструментів

У заголовку сторінки є чотири кнопки:

| Дія          | Що робить                                                                                                                 |
| ------------ | -------------------------------------------------------------------------------------------------------------------------- |
| Автооновлення | Загальний віджет `AutoRefresh` — тут неактивний, присутній для узгодженості з іншими сторінками                              |
| Тестувати все | Відображає тост _"Тестування всіх"_ — заповнювач для "надіслати тест на всі увімкнені канали"                            |
| Вимкнути на 1 год | Тост _"Вимкнено на 1 год"_ — заповнювач для глобального вимкнення на 1 годину                                              |
| Техобслуговування | Червона кнопка з підтвердженням у AlertDialog; після підтвердження показує тост, що техобслуговування увімкнено              |

## Вкладки

Сім вкладок у верхній частині. Кожна — окремий підкомпонент.

| Вкладка       | Призначення                                                                         |
| ------------- | ---------------------------------------------------------------------------------- |
| Канали        | Вбудовані канали (push / in-app / email / SMS) + маршрутизація за рівнем важливості + дайджести |
| Провайдери    | Облікові дані зовнішніх провайдерів (Email / SMS / Telegram / Slack / Discord / Webhook) |
| Правила       | Правила сповіщень за сімействами подій                                            |
| Шаблони       | Тексти повідомлень за сімейством подій × мовою                                   |
| Політики      | Ланцюжок ескалації, авто-вимкнення, безпека аудиторії, редагування ПІД            |
| Підписки      | Хто (роль або користувач) отримує які сімейства подій на яких каналах             |
| Журнали       | Журнал доставки лише для читання (надіслані / підтверджені / помилкові записи)    |

### Канали

Три картки, розташовані одна над одною.

**Вбудовані канали**

- _Push_ — повна конфігурація (перемикач увімкнення, обмеження частоти, повторні спроби, тихі години від/до, кнопка тестування).
- _In-app_ — увімкнення, обмеження частоти, час автоматичного закриття в секундах.
- _Email_ — залежить від провайдера Email на вкладці Провайдери. Увімкнення, обмеження частоти, повторні спроби.
- _SMS_ — залежить від провайдера SMS. Увімкнення, обмеження частоти, повторні спроби, тихі години.

**Відображення рівня важливості** — три випадаючі списки, що відображають `info` → `inApp` (за замовчуванням), `warning` → `push`, `critical` → `push+email`. Це канали, які використовуються, коли правило має цей рівень важливості, але не фіксує конкретні канали.

**Дайджест (Підсумки)** — частота (вимкнено / щогодини / щодня / щотижня) + час відправлення (вибір часу HH:00).

### Провайдери

Шість блоків провайдерів, кожен з перемикачем увімкнення та обліковими даними.

- _Email_ — тип провайдера (SMTP / SendGrid / Mailgun), API-ключ або SMTP-дані (маскований ввід), домен відправника.
- _SMS_ — Account SID, Auth token (маскований), номер відправника — формат Twilio.
- _Telegram_ — токен бота (маскований) + вибір chat ID (жорстко заданий список з трьох демонстраційних чатів: `@ridewolf_alerts`, `@support_team`, `@management`; кнопка **Test** — заповнювач).
- _Slack_ — URL вебхука + канал.
- _Discord_ — URL вебхука.
- _Webhook_ — універсальний URL вебхука + секрет підпису.

Кожен блок провайдера показує бейдж _Увімкнено_ поруч із заголовком, коли перемикач увімкнено. Кнопки _Test_ відображають тост.

### Правила

Таблиця правил сповіщень. Колонки: Ім'я / Сімейство подій / Важливість / Канали / Статус / Дії (меню з трьома крапками: Редагувати / Дублювати / Увімкнути-Вимкнути / Видалити). Натисніть **+ Створити правило**, щоб відкрити діалог правила — виберіть ім'я, область застосування (глобально / зона / роль), одне або кілька сімейств подій, важливість (info / warning / critical), канали та прапорець увімкнення.

Попередньо додані правила: _Помилки платежів_ (critical, сімейство платежів, push+email+telegram) та _Транспортний засіб офлайн_ (warning, сімейство транспортних засобів, push+email).

### Шаблони

Виберіть сімейство подій + мову + канал, потім редагуйте заголовок і тіло. Тіло підтримує заповнювачі (наприклад, `{{ride.id}}`, `{{amount}}`), які блок **Попередній перегляд** розгортає з прикладом події. _Надіслати тест_ відображає тост, що тест надсилається на вибраний канал.

### Політики

Чотири блоки:

- _Критична ескалація_ — випадаючий список ланцюжка (наприклад, push → email → telegram → SMS), таймаут підтвердження в хвилинах, перемикач вимоги підтвердження прочитання.
- _Автовимкнення_ — приглушення повторів: якщо одна й та сама подія спрацьовує _N_ разів за _M_ хвилин, вимкнути на _K_ хвилин (три числові поля). Нижче рядок підсумовує правило.
- _Безпека аудиторії_ — перемикач _Блокувати SMS поза тихими годинами_ (перевизначає тихі години для SMS).
- _Редагування даних_ — перемикач _Приховувати ПІД у зовнішніх повідомленнях_; підказка пояснює, що маскується (телефон, email, останні 4 цифри карток тощо).

### Підписки

Таблиця записів підписок. Кожен рядок пов’язує ціль (Роль або конкретного Користувача) з однією або кількома категоріями подій і каналами — наприклад, _Роль: Адмін → система + платежі → push + email_. Кнопка **+ Створити** відкриває діалог підписки; меню рядка містить Редагувати / Видалити.

Використовуйте Підписки для доставки сповіщень людям, які не відповідають жодному закріпленому каналу в Правилі — Правила визначають _про що_ сповіщати, Підписки визначають _хто_ це почує.

### Журнали

Таблиця лише для читання з спробами доставки. Колонки: Час / Подія / Маршрут / Канал / Одержувач / Статус (надіслано / підтверджено / помилка) / Затримка. Клік по рядку відкриває детальний тост (заповнювач для повної панелі деталей). Використовуйте це, щоб підтвердити, що сповіщення дійсно надійшло, або для налагодження проблем з провайдером.

## Категорії подій

Правила, Шаблони та Підписки всі базуються на одному фіксованому списку категорій подій (визначеному в `models/channels.ts`):

`authProfile` · `dashboard` · `vehicles` · `rides` · `payments` · `marketing` · `rebalance` · `support` · `maintenance` · `settings` · `system`

Вони приблизно відповідають доменам Панелі керування — оберіть категорію, що відповідає типу події, про яку хочете сповіщати.

## Робочі процеси

- **Налаштувати email-сповіщення** — вкладка Провайдери → увімкнути Email → обрати тип провайдера → вставити API-ключ → зберегти → повернутися на вкладку Канали → увімкнути канал Email → готово.
- **Отримувати сповіщення про помилки платежів** — вкладка Правила → редагувати _Помилки платежів_ → переконатися, що рівень важливості `critical` і канали включають ті, які ви реально моніторите → зберегти.
- **Зупинити SMS-спам вночі** — вкладка Політики → увімкнути _Блокувати SMS поза тихими годинами_ → встановити тихі години для кожного каналу на вкладці Канали.
- **Надсилати щоденний звіт замість сповіщень** — вкладка Канали → картка Digest → встановити частоту на _щоденно_, час, наприклад, 09:00.
- **Додати нову роль чергового** — вкладка Підписки → + Створити → обрати роль → категорії подій → канали → зберегти. Вони отримуватимуть майбутні сповіщення, що підходять.
- **Відлагодити відсутнє сповіщення** — вкладка Журнали → знайти подію за маршрутом або часом → якщо статус `failed`, перейти до Провайдерів для перевірки облікових даних; якщо `sent`, але людина не бачила, перевірити Підписки / тихі години / стан вимкнення звуку.

## Поради

- **Поки що лише фронтенд.** Збереження показує тост, але API ще не існує — розглядайте цю сторінку як специфікацію, а не джерело істини.
- **Кнопки тестування — заглушки.** _Тестувати все_, _Вимкнути звук на 1 годину_, тестування по каналах і підтвердження _Технічного обслуговування_ лише показують тости — вони не надсилають тестові повідомлення і нічого не вимикають.
- **Відповідність рівня важливості — запасний варіант.** Список _Каналів_ у Правилі має пріоритет; лише якщо він не встановлений або порожній, використовується відповідність рівня важливості.
- **Digest окремо від сповіщень по подіях.** Увімкнення digest не вимикає окремі сповіщення — воно просто додає періодичний звіт.
- **Підписки можуть бути на конкретного користувача**, а не лише на роль. Використовуйте це для одноразових ескалацій (наприклад, _нічний черговий отримує всі сповіщення `rides` через push_) без створення ролі.
- **Мобільний інтерфейс навмисно лише для читання.** Всі вкладки на мобільному кажуть _Використовуйте десктоп для повного налаштування_ — сповіщення це адміністративна робота, що потребує десктопа.
- **Редагування ПІД важливе для SMS/email.** Якщо воно вимкнене, тіла сповіщень можуть розкривати номери телефонів або кінцівки карток зовнішнім провайдерам — залишайте його увімкненим, якщо немає конкретної причини інакше.
