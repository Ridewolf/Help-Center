# Оператори

Сторінка Операторів (`/settings/operators`) — це **довідник співробітників** — кожен працівник, який має доступ до Панелі керування. Кожен оператор має роль (див. [Ролі](roles.md)), необов’язкові метадані відділу / посади, теги для фільтрації та статус (Активний / Неактивний).

На відміну від [Клієнтів](../../operations/customers/clients.md) (ваших замовників) — Оператори є **внутрішньою командою**, яка керує платформою.

Потрібен дозвіл: **Оператори** (`t4u5v6`). Піддозволи контролюють дії редагування.

## Як оператори потрапляють сюди

Операторів створюєте ви (адміністратор) через кнопку **+ Створити** — самостійної реєстрації немає:

1. **+ Створити** відкриває форму оператора — ім’я, електронна пошта, роль, необов’язково відділ / посада / теги
2. Новий оператор отримує електронного листа з інструкціями для входу та тимчасовим паролем
3. Вони входять, заповнюють свій профіль (`/profile`) і можуть починати роботу відповідно до дозволів своєї ролі
4. Неактивні оператори не можуть увійти — змініть статус облікового запису на неактивний, коли співробітник залишає компанію

## Фільтри

| Фільтр | Тип          | Примітки                                                  |
| ------ | ------------ | --------------------------------------------------------- |
| Пошук  | Текст        | Пошук за ім’ям, електронною поштою, посадою, відділом     |
| Статус | Випадаючий   | `Активний` / `Неактивний` (або `Всі`)                     |
| Теги   | Мультивибір  | Фільтрація за тегами, застосованими до операторів (наприклад, «Нічна зміна») |

## Колонки

| Колонка        | Сортується? | Вміст                                                                   |
| -------------- | --------- | ----------------------------------------------------------------------- |
| **Користувач** | ✓         | Аватар + ім’я/прізвище + електронна пошта; посилання на сторінку оператора |
| **Роль**       | —         | Пігулка ролі оператора (посилання на [Ролі](roles.md))                  |
| **Відділ**     | —         | Необов’язкова позначка відділу                                          |
| **Посада**     | —         | Необов’язкова позначка посади                                          |
| **Теги**       | —         | Теги, застосовані до оператора                                          |
| **Статус**     | ✓         | `Активний` (зелений) / `Неактивний` (сірий)                            |

## Дії в рядку

Меню з трьома крапками для кожного рядка. Доступні дії залежать від дозволів:

| Дія              | Дозвіл    | Що робить                                         |
| ---------------- | --------- | ------------------------------------------------- |
| **Переглянути**  | —         | Відкрити сторінку з деталями оператора            |
| **Редагувати**   | `edit`    | Відкрити форму редагування (ім’я, роль, відділ тощо) |

Дії **Видалити немає** — записи операторів зберігаються для аудиту. Щоб заборонити вхід, змініть статус оператора на _Неактивний_ через Редагування.

## Сторінка деталей

Клік по рядку (або _Переглянути_) відкриває сторінку деталей оператора з:

- Особистою інформацією (ім’я, електронна пошта, телефон, фото)
- Роль + знімок дозволів
- Відділ / посада / теги
- Статус
- Журнал активності (події входу, зміни ролі)

Редагуйте звідти або через меню рядка — обидва способи ведуть до однієї форми.

## Форма створення / редагування

**Форма оператора** (`+ Створити` або _Редагувати_) проста:

- **Ім’я / Прізвище** (обов’язково)
- **Електронна пошта** (обов’язково, унікальна серед операторів)
- **Роль** (обов’язково, випадаючий список доступних ролей — див. [Ролі](roles.md))
- **Відділ / Посада** (необов’язково)
- **Теги** (необов’язковий мультивибір)
- **Статус** (Активний / Неактивний)
- Тільки при створенні: поле **початковий пароль** або автоматично згенерований пароль, надісланий оператору електронною поштою

Збереження перевіряє дані і записує в журнал аудиту. Нові оператори автоматично отримують вітального листа.

## Типові робочі процеси

- **Введення нового співробітника** — `+ Створити` → заповнити ім’я/пошту/роль → Зберегти → підтвердити отримання вітального листа → попросити увійти і завершити профіль
- **Зміна ролі після підвищення** — Редагувати → змінити Роль → Зберегти (нові дозволи набирають чинності при наступному запиті оператора, не заднім числом)
- **Відхід зі служби** — Редагувати → встановити Статус = Неактивний → Зберегти (запис зберігається для аудиту; вхід заблоковано)
- **Планування змін за тегами** — застосувати теги, наприклад «Нічна зміна» → відфільтрувати список за тегом, щоб побачити, хто запланований

## Поради

- **Роль — це потужне поле** — будьте уважні при зміні. Зниження з Адміністратора до Підтримки одразу позбавляє прав запису
- **Неактивний ≠ Видалений** — історія оператора зберігається; щоб відновити доступ, змініть статус на Активний
- **Список за замовчуванням відсортований за ім’ям** — якщо операторів багато, шукайте за поштою або відділом замість прокручування
- **Теги тут відрізняються від тегів клієнтів** — вони належать операторам (наприклад, «Нічна зміна», «Тренер») і не мають спільного простору імен
- **Обмеження самостійного редагування** — ви не можете змінити власну роль через меню рядка; для особистих змін використовуйте Профіль
