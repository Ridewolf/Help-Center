# Теги

Сторінка Теги (`/settings/tags`) — це **спільна бібліотека міток** для вашої компанії. Тег — це іменований бейдж, який ви можете прикріпити до транспортних засобів, клієнтів, операторів, поїздок і платежів для фільтрації, групування та звітування. Список тут є єдиним джерелом правди — коли ви додаєте тег, він стає доступним у всіх підтримуваних місцях.

Необхідний дозвіл: **Теги** (`d1e2f3`). Піддозволи контролюють створення, редагування та видалення.

## Де використовуються теги

Теги — це **єдиний глобальний пул** — немає окремої області для кожного типу сутностей. Один і той самий тег можна прикріпити до різних типів записів:

- **[Транспортні засоби](../../operations/fleet/vehicles.md)** — наприклад, «Потрібне прибирання», «Пріоритетне техобслуговування», «Тестовий флот»
- **[Клієнти](../../operations/customers/clients.md)** — наприклад, «VIP», «Корпоративний», «Блоклист»
- **[Оператори](../access/operators.md)** — наприклад, «Нічна зміна», «Тренер», «На виклику»
- **Поїздки** — теговані для перегляду, спору або відстеження кампанії
- **Платежі** — теговані для звірки або подальших дій

Кожен запис може мати кілька тегів; фільтрація за тегом доступна у кожному списку, що їх підтримує.

## Фільтри

| Фільтр  | Тип   | Примітки                                  |
| ------- | ----- | ----------------------------------------- |
| Пошук   | Текст | Пошук за назвою тегу (міткою) та описом  |

Список за замовчуванням показує 50 рядків на сторінку і очищує фільтри за допомогою дії **Очистити**.

## Колонки

| Колонка         | Сортується? | Вміст                                                           |
| --------------- | ---------- | --------------------------------------------------------------- |
| **Назва тегу**  | ТАК        | Іконка тегу + мітка; посилання на сторінку деталей тегу         |
| **Статус**      | ТАК        | `Public` або `Private` (див. нижче)                             |
| **Опис**        | НІ         | Опис у вільному тексті; заповнювач «Немає опису», якщо порожньо |
| **Дати**        | ТАК        | Дата створення зверху, дата оновлення знизу                     |

У заголовку сторінки також доступні **Автооновлення**, **+ Створити**, **Імпорт** (скоро) та **Експорт** (завантаження JSON — поточна сторінка, всі відфільтровані або конкретні сторінки).

## Дії з рядками

Меню з трьома крапками для кожного рядка. Доступні дії залежать від дозволів:

| Дія              | Дозвіл    | Що робить                                                                                      |
| ---------------- | --------- | ---------------------------------------------------------------------------------------------- |
| **Переглянути**  | —         | Відкрити сторінку деталей тегу                                                                 |
| **Редагувати**   | `edit`    | Відкрити форму редагування (мітка, статус, опис)                                               |
| **Видалити**     | `delete`  | Видалити тег з компанії. **Записи, що раніше мали цей тег, втрачають зв’язок** — використовуйте обережно |

Видалення вимагає підтвердження утриманням кнопки протягом 3 секунд, щоб уникнути випадковостей.

## Сторінка деталей

Клік по рядку (або _Переглянути_) відкриває сторінку деталей тегу з:

- **Інформація про тег** — мітка, статус, опис (підтримка Markdown)
- **Метадані** — внутрішній ID, часові позначки створення / оновлення

Редагування та видалення також доступні у діях заголовка на сторінці деталей.

## Форма створення / редагування

**Форма тегу** (`+ Створити` або _Редагувати_) має три поля:

- **Мітка** (обов’язкове) — видима назва тегу; має бути достатньо унікальною для швидкого розпізнавання
- **Статус** (обов’язкове) — `Public` або `Private`
  - **Public** — видимий і доступний для вибору всім операторам компанії
  - **Private** — обмежена видимість; корисно для внутрішніх або адміністративних тегів
- **Опис** (необов’язкове) — вільний текст, що пояснює, коли використовувати тег; показується на сторінці деталей

Живий **попередній перегляд** у бічній панелі показує, як виглядатимуть мітка та опис під час введення. Збереження перевіряє, що мітка не порожня, записує тег у пул компанії та скидає спільний кеш тегів, щоб інші сторінки оновилися при наступному завантаженні.

## Типові робочі процеси

- **Додавання нової мітки** — `+ Створити` → введіть мітку → виберіть Public/Private → за бажанням опишіть, коли використовувати → Зберегти → тег одразу доступний у фільтрах і формах редагування Транспортних засобів / Клієнтів / Операторів
- **Перейменування тегу** — Редагувати → змінити Мітку → Зберегти (всі записи з тегом збережуть зв’язок; нова назва відображається всюди)
- **Виведення тегу з використання** — Видалити через меню рядка або спочатку встановити Статус у Private, щоб приховати від нового тегування, зберігаючи історичні зв’язки (потім можна повторно прикріпити лише через пряме редагування)
- **Прибирання дублікатів** — шукайте у списку схожі дублікати («vip» проти «VIP») → редагуйте один для об’єднання назв, потім видаліть інший (увага: записи під видаленим тегом втратять зв’язок — спочатку повторно тегуйте їх)
- **Масовий експорт** — Експорт → Всі відфільтровані → завантаження JSON для обміну з командою або резервного копіювання таксономії

## Поради

- **Теги глобальні** — немає окремого простору імен для «тегів клієнтів» чи «тегів транспортних засобів». Називайте їх так, щоб тег на кшталт «VIP» був зрозумілим для будь-якої сутності, або використовуйте префікси ("client:vip", "vehicle:maintenance") для впорядкування
- **Public — це за замовчуванням** — залишайте Public, якщо немає конкретної причини обмежувати видимість
- **Видалення є руйнівним** — кожен запис з тегом одразу втрачає зв’язок; немає м’якого видалення. Якщо не впевнені, краще перейменувати або переключити на Private
- **Опис підтримує Markdown** у перегляді деталей — використовуйте для документування, хто і коли має застосовувати тег
- **Спільний кеш скидається при кожному збереженні / видаленні** — інші відкриті вкладки отримають ваші зміни при наступній навігації без повного перезавантаження
- **Назви тегів відображаються у контекстних фільтрах Ridewolf скрізь** — тримайте їх короткими і зручними для нижнього регістру для найкращого UX у щільних таблицях
