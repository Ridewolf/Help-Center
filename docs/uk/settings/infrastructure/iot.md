# IoT-пристрої

Сторінка IoT (`/iot`) — це **апаратний інвентар** — кожен трекер / замок, що належить вашому флоту, незалежно від того, чи він зараз прикріплений до транспортного засобу. Кожен рядок — це один фізичний пристрій, ідентифікований за **IMEI**, з актуальною телеметрією (стан онлайн, GPS, GSM-сигнал, батарея), оновленою за останнім пінгом.

Це дзеркало пристрою з боку [Транспортних засобів](../../operations/fleet/vehicles.md): транспортний засіб без IoT не можна відстежувати або керувати; IoT без транспортного засобу — це просто незв’язане обладнання на полиці.

Потрібен дозвіл: **IoT Devices** (`n8p9q9`). Піддозволи контролюють `edit` / `send-command` / `delete`, а масова дія _Generate vehicle_ використовує дозвіл `operations.vehicles.create`.

## Як пристрої потрапляють сюди

Пристрої не виявляються автоматично — ви реєструєте їх при отриманні поставок:

1. **Закупівля** — ви купуєте IoT-пристрої у постачальника (Omni, Segway, Okai тощо). Кожен пристрій має унікальний **IMEI**, надрукований на коробці або наклейці
2. **+ Створити** тут — введіть Ім'я, IMEI, Постачальника, Статус. Пристрій тепер у інвентарі, але не прив’язаний
3. **Прив’язати до транспортного засобу** — робиться з [Створення / Редагування транспортного засобу](../../operations/fleet/vehicle-create-edit.md) вибором цього IoT у селекторі пристроїв. Один IoT на транспортний засіб, один транспортний засіб на IoT
4. **Починається потік телеметрії** після увімкнення пристрою з SIM-картою та підключення до MQTT-брокера Ridewolf. Список показує найсвіжішу інформацію — оновіть сторінку або дочекайтеся Автооновлення

Альтернативно, використовуйте масову дію **Generate vehicle** нижче, щоб створити новий транспортний засіб для кожного вибраного IoT за один раз (наприклад, після прийому партії нових самокатів).

## Фільтри

| Фільтр  | Тип       | Примітки                                   |
| ------- | --------- | ------------------------------------------ |
| Пошук   | Текст     | Пошук за ім’ям та IMEI                      |
| Статус  | Випадаючий список | `Всі` / `Активний` / `Неактивний` / `Архівований` |

Фільтри синхронізовані з URL (оновлення зберігає ваш вигляд) і скидаються до стандартних через посилання Очистити на панелі фільтрів.

## Колонки

| Колонка         | Сортується? | Вміст                                                                 |
| --------------- | ----------- | --------------------------------------------------------------------- |
| **Ім'я**        | так         | Ім'я пристрою + короткий ID; клік по рядку відкриває сторінку деталей |
| **Замок**       | —           | Стан замка (Заблоковано / Розблоковано) за останньою MQTT-командою    |
| **Онлайн**      | —           | Зелена крапка, якщо останній пінг у межах свіжості; червона, якщо застарілий |
| **GPS**         | —           | Індикатор дійсності GPS-сигналу                                     |
| **GSM**         | —           | Рівень сигналу (шкала 0-32, червоний ≤10, жовтий ≤20, зелений ≤32)   |
| **Батарея**     | так         | Відсоток заряду з кольоровою шкалою                                  |
| **Статус**      | так         | Таблетка `Активний` / `Неактивний` / `Архівований`                   |
| **Останній сигнал** | так      | Час від останнього пакету телеметрії (відносно, напр. "5 хв тому")  |

## Дії з рядком

Меню з трьома крапками для кожного рядка. Доступні дії залежать від дозволів:

| Дія               | Дозвіл    | Що робить                                                                 |
| ----------------- | --------- | ------------------------------------------------------------------------ |
| **Переглянути деталі** | —       | Відкрити сторінку деталей пристрою (вкладки Деталі / Активність / Команди / Історія) |
| **Переглянути місцезнаходження** | — | Відкрити останні відомі GPS-координати в Google Maps (нове вікно)        |
| **Редагувати**    | `edit`      | Відкрити форму редагування (Ім'я / IMEI / Постачальник / Статус)         |
| **Видалити**      | `delete`      | Видалити запис пристрою. Підтвердження з затримкою 3 секунди перед розблокуванням |

## Масові дії

Виберіть кілька рядків (чекбокс у заголовку або в кожному рядку), щоб відкрити панель масових дій. Дії також контролюються дозволами — ті, які ви не можете виконати, приховані, а не сірі:

| Дія                        | Дозвіл          | Що робить                                                                                                         |
| -------------------------- | --------------- | ---------------------------------------------------------------------------------------------------------------- |
| **Generate vehicle**       | `vehicles.create`            | Створити новий транспортний засіб для кожного вибраного IoT, автоматично з ім’ям з префіксом вашої компанії; вибрати модель транспортного засобу + необов’язкові теги |
| **Змінити статус**         | `edit`            | Встановити Активний / Неактивний / Архівований для всіх вибраних                                                    |
| **Перевірити з’єднання (Beep)** | `send-command`      | Надіслати команду `Beep` кожному пристрою — корисно для фізичного пошуку пристроїв на складі                        |
| **Надіслати команду**      | `send-command`            | Вибрати команду від постачальника першого вибраного (попередньо встановлену або складну багатокрокову) і надіслати всім |
| **Видалити**               | `delete`            | Масове видалення з діалогом підтвердження (затримка підтвердження 3 секунди)                                       |

Масові операції виконуються послідовно з індикатором прогресу (`оброблено / всього`) і панеллю невдалих елементів — частковий успіх нормальний, невдалі пристрої залишаються вибраними, щоб ви могли повторити або перевірити.

## Сторінка деталей

Клік по рядку (або _Переглянути деталі_) відкриває сторінку деталей пристрою. Чотири вкладки:

- **Деталі** — IMEI / Постачальник / Статус / координати з вбудованим переглядом Google Maps; повний блок телеметрії (швидкість, дійсність GPS, сире значення GSM, батарея, стан замка)
- **Активність** — загальний журнал активності цього пристрою (`entity-type=iot`)
- **Команди** — відправник команд з урахуванням постачальника. Такий самий механізм використовується на вкладці Команди [Деталей транспортного засобу](../../operations/fleet/vehicle-detail.md) — див. ту статтю для процедури / розширеного потоку
- **Історія** — історія телеметрії / журнал пакетів

У заголовку показано пов’язаний Транспортний засіб (якщо прив’язаний) у вигляді чіпа — натисніть, щоб перейти на сторінку деталей цього транспортного засобу. Випадаюче меню **Дії** в заголовку пропонує Редагувати / Переглянути на Google Maps / Видалити.

## Форма створення / редагування

Форма IoT (`+ Створити` або _Редагувати_) має чотири поля, усі обов’язкові:

- **Ім'я** — коротка мітка, яку ви побачите у списках (наприклад, `SCOOTER-014`). Вільний текст
- **IMEI** — унікальний апаратний ідентифікатор пристрою (використовується для прив’язки транспортного засобу та отримання MQTT-трафіку). Після встановлення вважайте його незмінним — зміна на розгорнутому пристрої порушить телеметрію, доки не оновлять прив’язку транспортного засобу
- **Виробник** — рядок виробника (наприклад, `omni`, `segway`). Визначає набір команд, які розуміє пристрій — будьте точні, пошук виробника чутливий до регістру
- **Статус** — `Активний` (за замовчуванням) / `Неактивний` (прихований у виборі для прив’язки транспортного засобу) / `Архівовано` (зняте з експлуатації обладнання)

Тут немає вбудованої форми для прив’язки до транспортного засобу — це робиться у формі створення / редагування транспортного засобу.

## Типові робочі процеси

- **Зареєструвати партію з 50 трекерів** — Створити кожен (або імпортувати через завантаження CSV, якщо він у вас є) → вибрати всі → _Згенерувати транспортний засіб_ з правильним моделлю → готово; кожен IoT тепер має пару транспортного засобу зі статусом `needs_investigation`, готового до контролю якості
- **Знайти відсутній пристрій на складі** — Відфільтрувати за ім’ям/IMEI → дія рядка _Перевірити з’єднання (Пі-пі)_ або масове Пі-пі → обійти територію, слухаючи
- **Вивести з експлуатації несправний пристрій** — Редагувати → встановити Статус = Архівовано (не Видаляти — журнал дій зберігається). Якщо транспортний засіб був прив’язаний, спочатку відв’яжіть його у формі редагування транспортного засобу
- **Масове розгортання команд для виробника** (наприклад, налаштування прошивки) — Відфільтрувати за шаблоном імені або телеметрією, вибрати всі відповідні → _Надіслати команду_ → вибрати команду виробника і дочекатися виконання зі статусом прогресу
- **Розслідувати "привид" транспортного засобу** (онлайн, але втрачене) — Переглянути місцезнаходження → якщо GPS недійсний, спробувати Пі-пі; якщо все ще без звуку, підозрювати SIM / батарею
- **Перевірити телеметрію з подіями** — відкрити [Звіт подій](../../analytics/reports/events.md), відфільтрований за транспортним засобом цього IoT, щоб зіставити стан обладнання з активністю на платформі

## Поради

- **IMEI — це ключ зв’язку** скрізь — прив’язка транспортного засобу, маршрутизація MQTT, заявки в підтримку. Введіть один раз, копіюйте назавжди
- **Поле Виробник є структурним, а не косметичним** — воно керує каталогом команд на вкладці Команди. Помилка в написанні `omni` як `Omni` може призвести до порожнього списку команд
- **Онлайн ≠ Активний** — Онлайн означає живий сигнал телеметрії; Статус — це адміністративний прапорець. Активний пристрій може бути Офлайн (мертва батарея, немає GSM); Архівований може надсилати пінги, доки не вимкнуть живлення
- **Масова відправка команд використовує виробника з першого рядка** — якщо у виборі змішані виробники, розділіть їх на партії за одним виробником, інакше отримаєте заплутаний список команд
- **Згенерувати транспортний засіб створює `needs_investigation` транспортних засобів навмисно** — потрібне підтвердження людиною, що прив’язка правильна перед запуском. Масове тегування під час генерації полегшує наступний контроль якості
- **Кнопки "примусового повторного спарювання" немає** — якщо телеметрія зупинилася після заміни, перевірте прив’язку IoT у транспортному засобі (редагування транспортного засобу) та SIM / живлення пристрою, а не цю сторінку
- **Архівовані пристрої залишаються доступними для пошуку за IMEI** — зручно, коли старий пристрій повертається з ремонту і його потрібно відновити (переключити назад на Активний)
- **Останній сигнал — найшвидша перевірка стану** — сортуйте за спаданням, щоб спочатку знайти застарілі пристрої; будь-який рядок Активного пристрою з > 24 годинами вартий уваги
