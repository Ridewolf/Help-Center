# Правила транспортних засобів

Сторінка Правил транспортних засобів (`/settings/vehicle-rules`) — це **каталог моделей транспортних засобів**, які Ridewolf вміє обслуговувати — _Xiaomi M365_, _Ninebot Max G30_, _Segway F40_ тощо. Кожен рядок тут — це **шаблон моделі**: багаторазовий набір тарифів, технічних обмежень, правил фото-доказів і тегів, який прив’язується до окремих фізичних [транспортних засобів](../../operations/fleet/vehicles.md) через [форму транспортного засобу](../../operations/fleet/vehicle-create-edit.md).

Потрібен дозвіл: **Правила транспортних засобів** (`e7f8g9`). Піддозволи: `create` / `edit` / `delete`.

## Модель проти екземпляра транспортного засобу

Це найважливіше розрізнення на цій сторінці:

- **Модель транспортного засобу** (ця сторінка) — визначення. _"Кожен Xiaomi M365 у нашому флоті поводиться так"_. Один рядок на марку/конфігурацію.
- **Транспортний засіб** (список [Транспортних засобів](../../operations/fleet/vehicles.md)) — фізичний пристрій зі стікером, наприклад `RW-007`, прив’язаний до одного IoT-пристрою, припаркований десь. Сотні таких вказують на одну модель.

Коли ви змінюєте модель тут, кожен транспортний засіб, що на неї посилається, успадковує нові налаштування — тарифи активуються, оновлюються обмеження швидкості, набирають чинності вимоги до фото-доказів. Розглядайте цю сторінку як **політичний рівень**, що поширюється на багато одиниць одночасно.

## Фільтри

Верхня панель фільтрів має три елементи керування:

| Фільтр       | Тип       | Примітки                                                                                  |
| ------------ | --------- | ----------------------------------------------------------------------------------------- |
| **Пошук**    | Текст     | Пошук за міткою моделі                                                                    |
| **Статус**   | Випадачне | `Всі` / `Активний` / `Неактивний` / `Архівовано`                                         |
| **Тип**     | Випадачне | `Всі` / `Е-самокат` / `Е-велосипед` / `Вантажний е-велосипед` / `Е-мопед` / `Е-авто` / `Е-лодка` |

Зміна будь-якого фільтра скидає пагінацію на сторінку 1 і перезавантажує дані з сервера.

## Колонки

| Колонка         | Сортується? | Вміст                                                                                      |
| --------------- | ----------- | ------------------------------------------------------------------------------------------ |
| **Зображення**  | —           | Мініатюра 64×64; якщо зображення немає, показується загальна іконка автомобіля             |
| **Ім'я**        | ✓           | Мітка моделі (наприклад, _Xiaomi M365 Pro_)                                               |
| **Тип**         | ✓           | Пігулка типу транспортного засобу (е-самокат, е-велосипед тощо)                           |
| **Опис**        | ✓           | Перші 36 символів опису в markdown без форматування                                      |
| **Теги**        | —           | До 2 тегів + `+N` для переповнення — **клік для швидкого редагування** у діалозі          |
| **Статус**      | ✓           | Кольорова пігулка: Активний (зелений) / Неактивний (сірий) / Архівовано (синій) — **клік для швидкого редагування** |
| **Створено**    | ✓           | Дата створення моделі                                                                     |
| **Оновлено**    | ✓           | Дата останньої зміни                                                                       |

Клік для швидкого редагування відкриває невеликий діалог лише з мультивибором тегів або випадачним списком статусу — зручно для масових змін статусу без виходу зі списку.

## Дії на панелі інструментів

Кнопки у верхньому правому куті (видимість залежить від дозволів):

| Кнопка           | Дозвіл     | Що робить                                                                                   |
| ---------------- | ---------- | ------------------------------------------------------------------------------------------- |
| **Автооновлення** | —          | Періодично оновлює список; вмикається/вимикається; іконка крутиться під час завантаження    |
| **Імпорт**       | `create`   | Вибір JSON-файлу (формат експорту). Кожен елемент виконує `create`; теги і тарифи видаляються — потрібно додати вручну |
| **Експорт**      | —          | Відкриває діалог для експорту поточної сторінки / усіх відфільтрованих / конкретних сторінок у `vehicle-models-export.json` |
| **+ Створити**   | `create`   | Переходить на `/settings/vehicle-rules/create`                                             |

## Дії в рядку

Меню з трьома крапками для кожного рядка:

| Дія              | Дозвіл     | Що робить                                                                                   |
| ---------------- | ---------- | ------------------------------------------------------------------------------------------- |
| **Переглянути деталі** | —          | Відкриває деталі моделі за адресою `/settings/vehicle-rules/:id` (вкладки Загальні / Технічні / Історія) |
| **Редагувати**   | `edit`     | Відкриває форму редагування (`/settings/vehicle-rules/:id/edit`) з повним набором полів     |
| **Видалити**     | `delete`   | Діалог підтвердження з 3-секундною затримкою перед активацією кнопки підтвердження. Рядок моделі зникає зі списку |

Клік по рядку (крім швидкого редагування тегів) переходить до **Перегляду деталей**.

## Форма створення / редагування

`+ Створити` (`/settings/vehicle-rules/create`) і _Редагувати_ (`/settings/vehicle-rules/:id/edit`) мають однаковий макет: картка форми зліва, контекстна панель **Посібник по полях** справа з живим попереднім переглядом моделі.

Форма розділена на секції — Створення показує лише основні сім полів; Редагування додає три додаткові підсекції (Технічні характеристики, Автоматичні політики, Вимоги до документів) для розширених налаштувань.

### Основні поля

| Поле             | Обов'язкове | Примітки                                                                                                                               |
| ---------------- | ----------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **Назва**        | ✓           | Людське ім'я, що відображається скрізь (наприклад, _Xiaomi M365 Pro_). Вільний текст                                                  |
| **Опис**         | —           | Редактор Markdown; використовується в деталях моделі та підказках для оператора                                                        |
| **Тип транспортного засобу** | ✓           | Один із: електросамокат / електровелосипед / вантажний електровелосипед / електроскутер / електромобіль / електричний човен. Визначає іконку та логіку категорії |
| **Статус**       | ✓           | Активний / Неактивний / Архівовано. Неактивний видаляє модель з вибору створення транспортного засобу                                  |
| **Зображення**   | —           | Перетягніть або натисніть для завантаження. PNG/JPEG/JPG, макс. 10 МБ. Відображається у мініатюрі списку та в деталях транспортного засобу |
| **Тарифи**       | ✓           | Мультивибір [Тарифів на транспортні засоби](vehicle-tariffs.md). Всі поїздки на цій моделі тарифікуються за цими тарифами             |
| **Теги**         | ✓           | Мультивибір тегів на рівні моделі. Спадкуються кожним транспортним засобом цієї моделі                                                 |

### Технічні характеристики (тільки в режимі редагування)

| Поле                              | Примітки                                                                              |
| -------------------------------- | ------------------------------------------------------------------------------------- |
| **Базове обмеження швидкості (км/год)** | Жорстке обмеження, що застосовується прошивкою IoT під час кожної поїздки               |
| **Резерв батареї (%)**            | Рівень заряду, нижче якого транспортний засіб вважається з низьким зарядом              |
| **Резерв пробігу (км)**           | Оцінений залишковий пробіг, нижче якого пристрій позначається для заміни               |
| **Мін / Макс напруга батареї (В)** | Межі дійсних показників основної батареї — все поза межами позначається як _Потребує розслідування_ |
| **Мін / Макс напруга IoT (В)**   | Те саме для батареї трекера IoT-модуля                                               |

### Автоматичні політики (тільки в режимі редагування)

Перемикач пакету: **Зупинка при низькому заряді**, **Зупинка при низькому балансі**, **Кілька поїздок**, **Автоматичне блокування**, а також **Автоматичне повернення коштів** і **Автоматична знижка** з власними порогами (відстань / час / сума).

### Вимоги до документів (тільки в режимі редагування)

Визначає, які фото / документи повинен надати користувач:

- **Докази початку** — фото транспортного засобу на початку поїздки (перемикач + обов'язково + кількість) та селфі користувача
- **Докази паркування** — фото паркування в кінці поїздки (перемикач + обов'язково + кількість)
- **Додаткові документи** — водійське посвідчення / паспорт / ID-картка / селфі / інші

Ці правила зчитуються додатком Rider App при початку / завершенні поїздки на транспортному засобі, прив'язаному до цієї моделі.

## Взаємозв'язок з іншими сутностями

- **[Тарифи на транспортні засоби](vehicle-tariffs.md)** — рядки тарифів, які ви обираєте у полі **Тарифи**. Модель без тарифів не може тарифікувати поїздку
- **[Транспортні засоби](../../operations/fleet/vehicles.md)** — фізичні одиниці, що посилаються на цю модель через поле _Модель транспортного засобу_ у [формі транспортного засобу](../../operations/fleet/vehicle-create-edit.md). Модель визначає політику; транспортний засіб володіє IoT, назвою та місцезнаходженням
- **Теги** — теги на рівні моделі, які успадковуються кожним транспортним засобом цієї моделі, додатково до тегів на рівні транспортного засобу, застосованих безпосередньо до одиниці. Поїздки успадковують обидва на початку поїздки

## Типові робочі процеси

- **Додати нову модель** — `+ Створити` → заповнити Назву / Тип / Статус / Зображення → вибрати відповідні тарифи → зберегти → відкрити нову модель зі списку та натиснути _Редагувати_ для налаштування технічних характеристик і політик
- **Вивести модель з експлуатації** — відкрити модель → _Редагувати_ → встановити Статус = _Архівовано_ → зберегти. Існуючі транспортні засоби продовжують працювати; модель просто більше не відображається у виборі створення транспортного засобу
- **Зміна тарифів по всьому флоту** — редагувати модель → замінити тарифи → зберегти. Всі транспортні засоби цієї моделі починають тарифікуватися за новими тарифами з наступної поїздки
- **Масовий імпорт після міграції** — експортувати зі стенду → імпортувати JSON-файл тут → вручну повторно прив’язати тарифи та теги до кожної нової моделі (імпорт навмисно видаляє ці посилання)
- **Налаштувати вимоги до фото** — Редагувати → Вимоги до документів → перемкнути Докази початку / паркування → зберегти. Додаток Rider App застосує нові правила при наступному початку поїздки

## Поради

- **Встановіть тарифи перед тим, як активувати** — модель без тарифів відхилятиме запити на тарифікацію поїздок
- **Використовуйте Неактивний, а не Видалити, щоб вивести з експлуатації** — Неактивний приховує модель від створення нових транспортних засобів, але зберігає історію. Видалення незворотне і заблоковане трисекундним підтвердженням з певної причини
- **Зображення має значення** — мініатюра списку та вибір транспортних засобів оператором використовують це зображення. Обрізайте до квадрата з прозорим фоном для найкращого вигляду
- **Теги тут на рівні моделі, а не транспортного засобу** — застосування тегу тут ставить його на кожен транспортний засіб цієї моделі. Для тегів, специфічних для одиниці, редагуйте окремий транспортний засіб
- **Сповіщення про технічні характеристики** — резерв батареї та межі напруги впливають на тригер _Потребує розслідування_; занадто жорсткі налаштування можуть заповнити чергу сповіщень
- **Бічна панель Поля довідника оновлюється при фокусі на полі** — прочитайте її при першому створенні моделі, вона актуальніша за цю статтю
