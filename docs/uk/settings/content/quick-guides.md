# Швидкі посібники

Сторінка Швидких посібників (`/settings/quick-guides`) містить **покрокові інструкції**, які мобільний додаток Ridewolf для користувачів показує для таких речей, як «Як орендувати самокат» або «Перевірка безпеки». Кожен посібник — це впорядкований список пунктів з іконкою, кольором, заголовком і текстом — опублікований для певної аудиторії (додаток для користувача, додаток для клієнта, механік, адміністратор, загальний).

Разом із [FAQ Sets](faq-sets.md) (блоки запитань і відповідей) та [Icon Sets](icon-sets.md) (графіка для карти), Швидкі посібники є третьою опорою контентного шару. Редагуйте посібник тут, додаток користувача отримає зміни при наступному оновленні — випуск додатка не потрібен.

Потрібен дозвіл: **Швидкі посібники** (зверніться до адміністратора).

## Де це відображається користувачу

У мобільному додатку для користувача Швидкі посібники забезпечують навчальні підказки при початку роботи та підказки під час поїздки. Кожен посібник типу **rider-app** зі статусом `active` завантажується; пункти, позначені `visible`, з’являються в `order`, з налаштованими `icon` і `color` зліва, а текст `body` розгортається, якщо `expandByDefault` істинне.

Посібники типів `client-app`, `mechanic`, `admin`, `general` пов’язані з відповідними інтерфейсами.

## Фільтри

| Фільтр  | Тип          | Примітки                                                                |
| ------- | ------------ | ----------------------------------------------------------------------- |
| Пошук   | Текстове поле| Пошук у заголовку / описі / ідентифікаторі                              |
| Теги    | Мультивибір  | Фільтр за тегами (онбординг, основи, технічне, платежі тощо)            |
| Статус  | Випадаючий   | `Активний` / `Чернетка` / `Архівовано` (або `Всі`)                      |
| Тип     | Випадаючий   | `Додаток клієнта` / `Додаток користувача` / `Механік` / `Адмін` / `Загальний` (або `Всі`) |

**Очистити все** скидає всі фільтри.

## Колонки

| Колонка     | Вміст                                                               |
| -----------| ------------------------------------------------------------------ |
| **Набір**  | Іконка книги + заголовок; другорядний рядок показує опис або ідентифікатор |
| **Тип**   | Піктограма аудиторії — Додаток клієнта / Додаток користувача / Механік / Адмін / Загальний |
| **Теги**  | Перші 3 теги, з `+N` для зайвих                                   |
| **Пункти**| Кількість кроків у посібнику                                      |
| **Статус**| `Активний` (зелений) / `Чернетка` (сірий) / `Архівовано` (приглушений) |
| **Оновлено**| Відносна дата; при наведенні повний час + автор                   |

Клацніть рядок, щоб відкрити діалог **Переглянути** (попередній перегляд кожного кроку). Клацніть меню з трьома крапками для дій.

## Дії з рядком

| Дія              | Що робить                                                        |
| ----------------- | ---------------------------------------------------------------- |
| **Переглянути деталі** | Попередній перегляд з відображенням кожного пункту, як бачить користувач |
| **Редагувати**    | Відкрити форму (таку ж, як Створити, з попереднім заповненням)   |
| **Дублювати**    | Клонувати посібник з суфіксом `-copy` в ідентифікаторі та статусом `Чернетка` |
| **Експортувати** | Завантажити у ZIP або JSON                                       |
| **Архівувати**   | Перемістити в `Архівовано` — приховано від додатка користувача, збережено для історії |
| **Видалити**     | Видалити назавжди                                               |

Імпорт (ZIP / JSON) і Експорт (ZIP / JSON) у верхній панелі працюють пакетно.

## Форма створення / редагування

Форма має ті ж основні селектори, що й FAQ Sets, плюс розширений редактор для кожного пункту:

- **Тип** — обов’язковий, визначає, хто бачить посібник
- **Статус** — `Чернетка` / `Активний` / `Архівовано`
- **Теги** — мультивибір
- **Заголовок / Опис** — заголовок обов’язковий, опис необов’язковий
- **Пункти** — список кроків. Кожен пункт має:
  - **Заголовок** — заголовок кроку
  - **Текст** — зміст кроку (довгий, простий текст)
  - **Іконка** — назва іконки Lucide (наприклад, `MapPin`, `QrCode`, `Shield`)
  - **Колір** — колір у форматі hex з брендованими пресетами (Primary `#6366f1`, Success `#22c55e`, Warning `#eab308`, Danger `#ef4444` тощо)
  - **Розгортати за замовчуванням** — якщо увімкнено, пункт відкривається розгорнутим у додатку
  - **Видимий** — перемикач для приховування пункту без видалення
  - **Порядок** — перетягування для зміни порядку

Ідентифікатор (slug) формується з заголовка і використовується в URL API.

## Типові робочі процеси

- **Написати новий посібник з онбордингу** — `+ Створити посібник` → Тип = Додаток користувача, Статус = Чернетка → додати 5–7 впорядкованих пунктів з іконками і кольорами → переглянути через Переглянути деталі → переключити на Активний → він з’явиться в додатку користувача при наступному оновленні
- **Зробити крок необов’язковим / приховати його** — Редагувати → вимкнути `Видимий` для пункту → зберегти (пункт залишається в даних, просто не відображається)
- **A/B-тест нового покрокового посібника** — Дублювати активний посібник → редагувати копію → архівувати старий і активувати новий разом
- **Пакетний імпорт чернетки дизайнера** — у верхньому правому куті _Імпорт_ → ZIP/JSON → підтвердити розбір структури → імпортувати як Чернетку → переглянути і Активувати

## Поради

- **Іконки — це назви Lucide** — обирайте на [lucide.dev](https://lucide.dev), щоб вони відображалися в додатку; помилкові назви іконок замінюються на заглушку
- **Фарбуйте кроки для кращого сприйняття** — користувачі швидко переглядають посібники. Використовуйте Warning для кроків "обережно" і Success для "виконано"
- **`expandByDefault` зазвичай для першого кроку** — відкривати всі пункти за замовчуванням марно, це руйнує сенс акордеону. Залишайте решту згорнутими
- **Текст кроку — це простий текст, не markdown** — тримайте абзаци короткими; мобільний додаток встановлює типографіку
- **Архівуйте замість видалення**, коли посібник більше не потрібен — його завжди можна повторно активувати або дублювати
- **Використовуйте теги послідовно разом із [FAQ Sets](faq-sets.md)** — `onboarding`, `troubleshooting` тощо — спільна термінологія для контентного шару
