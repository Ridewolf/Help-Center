# Rider App — Підтримка, FAQ та Живий чат

Підтримка (`/support`) — це місце, куди звертається користувач за допомогою. Вона має дві вкладки — **FAQ** та **Контакти** — а живий чат відкривається на окремому екрані (`/support/messenger`).

Дві речі, які потрібно знати перед тим, як відповідати на будь-яке питання про підтримку:

- **Кожен канал зв’язку налаштовується вами.** У додатку немає глобальної електронної пошти, номера телефону чи годин роботи служби підтримки Ridewolf — ніколи не цитуйте їх.
- **У додатку є чат, а не форма заявки.** Користувачі не отримують номери заявок. Перегляд тих самих розмов вашою командою — це [Розмови](../../support/tickets-proofs-chat/conversations.md); [Квитки](../../support/tickets-proofs-chat/tickets.md) — це поняття для операторів.

## Вкладка FAQ

Розділи-акордеони, створені з вашого опублікованого контенту запитань і відповідей, а також елементи **Посібника по поїздці**, розділені на групи **Перед початком** та **Перед завершенням**.

Ви керуєте всім цим без випуску оновлення додатку:

- Запитання та відповіді — [Набори FAQ](../../settings/content/faq-sets.md)
- Покрокові інструкції Посібника по поїздці — [Швидкі посібники](../../settings/content/quick-guides.md)

Окремі елементи FAQ мають **глибокі посилання**: посилання на конкретний елемент відкриває Підтримку з уже розгорнутим і прокрученим до нього елементом. Це правильний спосіб направити користувача безпосередньо до однієї відповіді замість «дивіться у FAQ».

## Вкладка Контакти

Кожен канал тут відображається лише тоді, коли ви його ввімкнули в [Моя компанія → Додаток → канали підтримки](../../settings/administration/my-company.md).

| Канал         | Що робить                                                        |
| ------------- | ---------------------------------------------------------------- |
| **Живий чат** | Відкриває месенджер (`/support/messenger`)                       |
| **Електронна пошта** | Відкриває поштовий додаток користувача з вашою адресою       |
| **Вебсайт**   | Відкриває ваш налаштований URL у вбудованому браузері           |
| **Telegram**  | Відкриває ваш контакт у Telegram зовні                           |
| **WhatsApp**  | Відкриває ваш контакт у WhatsApp зовні                           |
| **Телефон**   | Починає дзвінок на ваш налаштований номер                        |

Якщо **жоден** канал не ввімкнено, вкладка показує ілюстрацію без контактів. Користувач, який скаржиться, що «неможливо зв’язатися з підтримкою», майже завжди належить до компанії, у якої всі канали вимкнені — перевірте свою конфігурацію перед тим, як шукати проблему далі.

## Живий чат

Месенджер побудований на основі розмов:

- Користувач бачить свій **список розмов**, кожна з яких має статус, призначеного оператора, останнє повідомлення з часом і кількість непрочитаних.
- **Нова розмова** пропонується **лише якщо у користувача немає відкритої розмови.** Користувач з відкритою темою не бачить можливості почати другу — це задумано. Вони продовжують існуючу розмову.
- Відкриття розмови завантажує історію повідомлень по 50 за раз, підвантажуючи старіші при прокручуванні вгору.

| Статус розмови | Значення                             |
| -------------- | ----------------------------------- |
| **Новий**      | Щойно відкрито, ще не взято в роботу |
| **Очікується** | Очікує відповіді вашої команди       |
| **Активний**   | Обробляється                        |
| **Відкладено** | Відкладено                         |
| **Закрито**    | Закрито оператором                  |

**Типи повідомлень, які відображає додаток:** текст, зображення, файл, місцезнаходження, контакт, поїздка, посилання на додаток і системні повідомлення.

**Іконки статусу повідомлень:** відправлення, надіслано, доставлено, прочитано та помилка.

### Відправлення повідомлення

Користувач може додати:

- До **5 зображень у повідомленні**
- **Мітку місцезнаходження** (широта, довгота та підпис)
- **Файл**

Відправлене повідомлення одразу з’являється як _відправляється_, потім оновлюється до реального статусу після підтвердження сервером. Та ж жива сесія передає оновлення про нові повідомлення, прочитання, закриття розмови, призначення оператора та індикатор "_{name} набирає текст…_".

Після втрати з’єднання додаток перезавантажує список розмов і відкритий чат, уникаючи дублювання повідомлень — тому користувач, який втратив зв’язок, не побачить одне й те саме повідомлення двічі.

Коли оператор **закриває** розмову, введення користувача вимикається, а замість нього з’являється повідомлення "розмова закрита".

## Усунення несправностей

| Користувач каже…                         | Що це означає                                                                                                  |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| «Немає варіантів зв’язку»                | Для вашої компанії не ввімкнено жоден канал — виправте це в [Моя компанія](../../settings/administration/my-company.md) |
| «Немає кнопки Нова розмова»              | У користувача вже є відкрита розмова; він має продовжувати цю тему                                            |
| «Я не можу більше вводити текст»         | Оператор закрив розмову. Нову можна почати, коли не залишиться відкритих тем                                  |
| «Моє повідомлення показує помилку»       | Воно ніколи не покидало пристрій — спробуйте надіслати знову                                                |
| «Мої повідомлення дублювалися після перепідключення» | Вони не дублювалися; перезавантаження уникає дублювання. Запитайте скріншот, якщо наполягають                  |
| «Як швидко ви відповідаєте?»              | У додатку не визначено час відповіді. **Не обіцяйте його** — цитуйте власні опубліковані зобов’язання щодо сервісу |
| «Куди повідомляти про надзвичайну ситуацію?» | Через будь-які ввімкнені канали. Додаток не визначає гарячу лінію для надзвичайних ситуацій і не слід цитувати жодні номери |

## Поради

- **Перевірте вкладку Контакти.** Відкрийте Rider App самі після будь-яких змін у Моя компанія — порожня вкладка Контакти непомітна для вас і дратує користувачів.
- **Використовуйте глибокі посилання на відповіді з FAQ** у відповідях у чаті замість повторного набору тексту. Це навчає користувачів, де шукати відповіді.
- **Правило — одна відкрита розмова одночасно.** Якщо користувач хоче підняти інше питання, спочатку закрийте стару розмову.
- **Підтримуйте актуальність наборів FAQ і швидких посібників** — кожне питання, на яке вони відповідають, це чат, якого вам не доведеться вести.
- **Закриття розмови припиняє можливість користувача відповідати.** Переконайтеся, що відповідь повна, перш ніж закривати.
