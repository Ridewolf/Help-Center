# Вхід — коди, паролі та вхід через месенджер

Все, що проходить користувач перед тим, як потрапити на карту: вибір способу входу, підтвердження одноразового коду, заповнення мінімального профілю, відновлення пароля або перехід із бота Telegram чи Viber.

Використовуйте цю статтю, якщо користувач не може увійти в додаток. Те, що відбувається *після* першого успішного входу, описано в [Onboarding and verification](onboarding-verification.md).

## Які способи входу бачить користувач

Вкладки на екрані входу (`/auth/login`) формуються на основі **Authentication Methods**, які ви активуєте в **Налаштування → Моя компанія → Додаток**. Не кожен користувач бачить усі методи. Можливі методи:

- Одноразовий код по **телефону**
- Одноразовий код по **електронній пошті**
- Одноразовий код через **WhatsApp**
- **Електронна пошта та пароль**
- **Google**
- **Apple**
- **Telegram**
- **Viber**

Якщо користувач каже, що якогось методу немає, значить він не увімкнений для цього оператора. Увімкніть його в [Моя компанія](../../settings/administration/my-company.md) — користувач не може зробити це зі свого боку.

## Поля на кожній вкладці

| Вкладка                  | Поля                                                                                           |
| ------------------------ | ---------------------------------------------------------------------------------------------- |
| **Телефон**              | Номер телефону (не менше 6 символів) плюс вибір способу доставки — надіслати код по **телефону** або через **WhatsApp** |
| **Електронна пошта**     | Адреса електронної пошти                                                                       |
| **Пароль** — вхід        | Електронна пошта та пароль                                                                     |
| **Пароль** — реєстрація  | **Ім'я** (обов’язково, не менше 2 символів), **Прізвище** (необов’язково), електронна пошта, пароль |

Телефон і WhatsApp — це **окремі канали доставки**. Користувач, який чекає SMS, але вибрав доставку через WhatsApp, чекатиме вічно.

Кнопки **Google** та **Apple** з’являються, коли ці методи увімкнені. Якщо користувач відмовляється від вибору провайдера, нічого не відбувається і помилка не показується — це очікувана поведінка, він просто скасував.

## Новий користувач чи той, що повертається

Перед відправленням коду додаток перевіряє, чи належить контакт до існуючого акаунта.

- **Повертається користувач** — код надсилається одразу
- **Новий користувач** — спочатку з’являється короткий діалог реєстрації, який збирає **Ім'я**, **Прізвище** та відсутній контакт: електронну пошту, якщо код надсилається на телефон, або телефон, якщо код надсилається на електронну пошту

## Перевірка безпеки

На екрані входу має завантажитися CAPTCHA перед тим, як можна буде запросити одноразовий код. Якщо вона не завантажується — через заблоковану мережу, дуже старий браузер, блокувальник реклами в браузері додатка — запит коду надіслати неможливо. Попросіть користувача відкрити додаток знову при нормальному з’єднанні.

## Введення одноразового коду — `/auth/otp`

1. Користувач вводить код — рівно **6 цифр**, тільки цифри
2. Кнопка **Надіслати повторно** стає доступною, коли зворотний відлік на екрані доходить до нуля
3. На телефонному каналі підтримувані телефони автоматично заповнюють код і відправляють його

Що відбувається далі:

- **Новий користувач** переходить на екран **Завершення профілю**
- **Повертається користувач** одразу потрапляє в додаток

## Завершення профілю — `/auth/complete-profile`

Показується лише новим користувачам. Запитує:

- **Ім'я** — обов’язково, не менше 2 символів
- **Прізвище** — необов’язково
- Відсутній контакт — електронна пошта, якщо код прийшов на телефон, або телефон, якщо код прийшов на електронну пошту

Вже зібрані значення заповнюються автоматично, і форма відправляється сама, якщо ім'я та контакт вже є. Є кнопка **Пропустити**.

Якщо пізніше виявиться, що номер телефону користувача відсутній, попросіть його перевірити екран **Профіль**, а не припускати, що цей крок зберіг номер — див. [Profile](profile.md).

## Користувачі, які ніколи не вибирали пароль

Користувач, який створив акаунт через onboarding, ніколи не обирав пароль. Якщо він пізніше хоче увійти на вкладці **Пароль**, спочатку потрібно встановити пароль через **Забули пароль**. Не радьте користувачу "просто спробувати свій звичайний пароль".

## Забули пароль — `/auth/forgot-password`

Одне поле: електронна пошта акаунта. Після відправлення екран показує один із трьох результатів, які означають різне:

| Що бачить користувач  | Значення                                      |
| --------------------- | --------------------------------------------- |
| **Зелене повідомлення** | Запит на скидання пароля успішно надіслано    |
| **Жовтий зворотний відлік** | Занадто багато спроб з цього пристрою — дочекайтеся завершення таймера |
| **Червона помилка**    | Запит не вдалося виконати — спробуйте знову    |

Жовтий зворотний відлік зберігається на пристрої користувача, тому не переноситься на інший телефон.

## Скидання пароля — `/auth/reset-password`

Користувач має відкрити цей екран за посиланням із листа для скидання пароля. Відкриття без дійсного посилання повертає його на **Забули пароль** з повідомленням "посилання минуло" — запросіть новий лист.

На екрані користувач вводить новий пароль і підтвердження. Правила пароля показуються в реальному часі під час введення, і обидва поля мають співпадати, щоб форму можна було відправити.

## Вхід через месенджер (Telegram / Viber) — `/auth/messenger-callback`

Коли користувач починає з вашого бота в Telegram або Viber, посилання бота відкриває проміжну сторінку, яка відкриває додаток, який виконує вхід користувача і переносить його в додаток.

Дві помилки мають власні повідомлення:

- **Обліковий запис заблоковано** — користувача перенаправляють на екран **Обліковий запис заблоковано**, див. [Onboarding and verification](onboarding-verification.md)
- **Потрібен доступ користувача** — обліковий запис існує, але не є користувачем цього оператора

Інші випадки показують загальне повідомлення «неправильний вхід»; попросіть користувача почати заново через бота з новим посиланням.

## Обмеження частоти

Обмеження на одноразові коди встановлює сервер, а не додаток. На екрані відображається зворотний відлік, сформований із часу очікування, який повернув сервер. **Оголошуйте користувачу зворотний відлік — ніколи не вказуйте фіксовану кількість хвилин**, оскільки вона не є фіксованою.

## Усунення несправностей

| Симптом                          | Що це означає і що робити                                                                     |
| -------------------------------- | ------------------------------------------------------------------------------------------------ |
| Відсутній метод входу            | Він не увімкнений у ваших **Методах автентифікації**. Увімкніть його в [Моя компанія](../../settings/administration/my-company.md) |
| Код ніколи не надійшов            | Зачекайте на завершення зворотного відліку, потім натисніть **Надіслати повторно**. Перевірте, що вибір доставки на вкладці **Телефон** відповідає очікуванням користувача — телефон і WhatsApp — це окремі канали |
| «Занадто багато спроб»           | Читайте зворотний відлік на екрані; тривалість очікування надана сервером                            |
| Запит коду не відправляється    | CAPTCHA на екрані входу, ймовірно, не завантажилася                                        |
| Користувач не знає свій пароль  | Ймовірно, він ніколи його не встановлював. Надішліть його через **Забули пароль**                          |
| Посилання для скидання пароля минуло | Користувача повертають до **Забули пароль**; запросіть нове посилання                             |
| Екран **Обліковий запис заблоковано** | Див. розділ про заблоковані облікові записи в [Onboarding and verification](onboarding-verification.md)       |
| Увійшли, але нічого не завантажується | Перевірте [Сесії](sessions.md) — якщо обліковий запис очікує на видалення, частини додатка обмежені; див. [Профіль](profile.md) |
