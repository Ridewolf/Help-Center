# Rider App — Підписки та промокоди

**Підписки та промокоди наразі недоступні в додатку.** Користувач не може придбати план, не може активувати промокод і нічого не може скасувати.

Якщо ви хочете надати користувачу знижку, зробіть це на стороні панелі керування — див. [Giving a rider a discount today](#як-сьогодні-надати-користувачу-знижку).

## Що насправді бачить користувач

- Бічне меню на [Карті](../riding/map.md#навігаційна-оболонка) **не містить розділів Промоакції та Підписки**.
- Посилання `/subscriptions` не відкриває екран. Користувач, який вводить його або переходить за ним, потрапляє на екран **Не знайдено** додатку. Це очікувана поведінка, а не помилка облікового запису чи пристрою.
- Старе посилання `/promo` просто перенаправляє на [Гаманець](wallet.md).
- **Немає налаштування в панелі керування**, яке вмикає підписки або промокоди для вашої компанії.

Не обіцяйте користувачу, що код спрацює «коли ми його увімкнемо», і не називайте імена планів чи ціни — жодні з них не діють.

## Як сьогодні надати користувачу знижку

Доступні три механізми, усі на стороні оператора:

| Механізм                  | Де                                                                           | Підходить для                                               |
| ------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------ |
| **Рівні знижок тарифів**  | [Тарифи на транспортні засоби](../../settings/infrastructure/vehicle-tariffs.md) | Робити довші поїздки поступово дешевшими для всіх            |
| **Окремий тариф плюс теги** | [Тарифи на транспортні засоби](../../settings/infrastructure/vehicle-tariffs.md) + [Теги](../../settings/infrastructure/tags.md) | Дешевше для визначеної групи (корпоративні, персонал, VIP)   |
| **Ручове зарахування балансу** | [Деталі клієнта](../../operations/customers/client-detail.md#дії) → **Поповнити баланс** | Одноразова компенсація після скарги або невдалої поїздки     |

Для одноразової компенсації ручове зарахування балансу — найшвидший спосіб, який залишає запис у журналі активності клієнта. Для всього повторюваного вбудовуйте це у тариф.

## Поширені запитання

| Питання                                         | Відповідь                                                                                                     |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| "Як купити підписку?"                          | Наразі недоступно в додатку                                                                                     |
| "Сторінка підписок показує Не знайдено"       | Правильно і очікувано                                                                                           |
| "Чи можемо ми увімкнути підписки для нашої компанії?" | Ні — у панелі керування немає такого налаштування                                                              |
| "Мій промокод не застосовується"               | Промокоди наразі недоступні в додатку                                                                           |
| "Сканування QR промокоду нічого не робить"     | Те саме — наразі недоступно                                                                                      |
| "Як скасувати мій план?"                        | Плану для скасування немає                                                                                       |
| "Яке ціноутворення тоді застосовується?"       | Тариф, прив’язаний до транспортного засобу, яким користуються. Див. [Тарифи на транспортні засоби](../../settings/infrastructure/vehicle-tariffs.md) та [розбивку вартості поїздки](../riding/rides.md#розбивка-вартості) |

## Поради

- **Говоріть «наразі недоступно», а потім пояснюйте, що _можна_ зробити.** Користувач, який питає про промокоди, зазвичай хоче знижку; ручове зарахування балансу відповідає на це питання.
- **Тримайте логіку знижок у тарифах.** Все, що ви там налаштуєте, застосовується послідовно і правильно відображається у розбивці вартості поїздки користувача.
- **Слідкуйте за промокодами третіх сторін.** Якщо користувачі приходять з кодами з кампанії, переконайтеся, що маркетинг знає, що додаток не може їх активувати.
