# Rider App — Історія (Поїздки та Платежі)

Історія (`/history`) — єдине місце в додатку для пасажира з його власними даними. Вона має дві вкладки на одному екрані — **Поїздки** та **Платежі** — і саме сюди ви направляєте пасажира для перегляду інформації про минулі поїздки або платежі.

Кожна вкладка має власну пагінацію та нескінченний скрол, який завантажує наступну сторінку, коли пасажир наближається до низу. Перемикання вкладок скидає позицію скролу та пагінацію, а дані перезавантажуються щоразу при повторному відкритті екрану.

Для еквівалентів на стороні оператора дивіться [Rides — List](../../operations/trips/rides.md) та [Payments — History](../../operations/payments/payments.md).

## Вкладка Поїздки

Кожна картка поїздки показує: тип транспортного засобу, номер транспортного засобу, початкове та кінцеве місцезнаходження, час початку та завершення, відстань у кілометрах, тривалість у хвилинах, вартість та статус. Картки завантажуються по 20 на сторінку. Торкання відкриває [деталі поїздки](#деталі-поїздки).

| Статус       | Колір  | Значення                                    |
| ------------- | ------ | ------------------------------------------- |
| **Завершено** | Зелений | Поїздка завершилася нормально                |
| **Скасовано** | Червоний | Поїздка була скасована                        |
| **Протерміновано** | Жовтий | Поїздка або утримання закінчились без завершення |

## Вкладка Платежі

Кожен запис платежу показує: тип, суму, валюту, статус, провайдера, дату, баланс до та після, а у разі помилки — код помилки.

**Типи:** поповнення, повернення, списання та бонус.

**Кодування кольором суми:**

| Колір  | Застосовується до          |
| ------ | -------------------------- |
| Зелений | Поповнення, повернення, бонуси |
| Помаранчевий | Штрафи                    |
| Червоний | Списання та комісії        |

**Позначки статусу:** _очікується_ — янтарний, _помилка_ — червоний, _повернено_ — приглушений. **Завершений платіж не має позначки взагалі** — відсутність позначки є нормальним, здоровим станом, а не відсутністю даних. Пасажири іноді читають це як "нічого не сталося"; насправді це означає протилежне.

**Код помилки** у разі невдалого платежу — це те, що потрібно читати, коли пасажир запитує, чому платіж не пройшов.

## Деталі поїздки

Торкання картки поїздки відкриває `/history/:id`. Вона показує:

- **Факти поїздки** — статус, ціну, відстань (у км), тривалість (у хвилинах), позначку та тип транспортного засобу, тариф, початкову та кінцеву адресу, часові позначки та рейтинг, який залишив пасажир
- **Розбивка вартості** — п’ять рядків, що складають загальну ціну: плата за розблокування, резервування, активний час, відстань та час паузи. Див. [Розбивка вартості](../riding/rides.md#розбивка-вартості) для відповідності кожного пункту тарифу
- **Хронологія активності** — спочатку період резервування (якщо був), потім блоки поїздки та паузи в хронологічному порядку. Це найзрозуміліший спосіб показати пасажиру, куди саме пішли його гроші під час дорогої поїздки
- **Карта маршруту** — для завершених поїздок: маршрут, намальований лінією, з маркером початку та кінця, масштабований так, щоб охопити всю поїздку

Якщо тариф поїздки не може бути завантажений, екран показує **тільки загальну суму, без розбивки та без повідомлення про помилку**. Загальна сума все одно правильна — саме тому іноді відсутня розбивка.

## Наразі недоступно в додатку

Пасажири регулярно про це питають. Жоден із цих пунктів не існує в Історії, тому скажіть це прямо, а не відправляйте пасажира на пошуки:

- Групування списку за Сьогодні / Вчора / Цього тижня
- Панель фільтрів за датою, типом транспортного засобу або статусом
- Дія **Завантажити квитанцію** (PDF або електронна пошта)
- Повторне оцінювання минулої поїздки (рейтинг дається в кінці поїздки)
- Форма **Повідомити про проблему** щодо поїздки — замість цього використовуйте [Підтримку](../help/support.md)
- Експорт історії поїздок або платежів у CSV або PDF
- Банер із підсумками або загальною сумою витрат у верхній частині списку

Статистика для пасажирів також [наразі недоступна](analytics.md). Якщо пасажиру потрібні підсумки або документ у вигляді квитанції, створіть його з панелі керування: [Rides — List](../../operations/trips/rides.md) та [Payments — History](../../operations/payments/payments.md) обидва підтримують експорт.

## FAQ

| Пасажир питає…                      | Відповідь                                                                                                                       |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| "Що означає ця розбивка?"           | Читайте п’ять рядків по черзі. Велика пауза або рядок резервування пояснює більшість несподіваних сум                            |
| "Чому немає розбивки?"               | Тариф поїздки не вдалося завантажити, тому показано лише загальну суму. Загальна сума правильна                                  |
| "Чому мій платіж очікується?"        | Провайдер не підтвердив його. Для переказу або поповнення через QR пасажир, ймовірно, так і не завершив оплату — див. [Payment Methods](payment-methods.md#поповнення-в-очікуванні) |
| "Де мої підсумки?"                   | У додатку для пасажира немає загальної суми; підсумуйте їх зі списку або отримайте з панелі керування                            |
| "Чи можу я отримати квитанцію?"     | Не з додатку. Експортуйте запис платежу з панелі керування, якщо пасажиру потрібен документ                                     |
| "Чому у мого платежу немає позначки?" | Тому що він завершений. Позначки мають лише платежі зі статусом очікується, помилка та повернено                                |

## Поради

- **Деталі поїздки вирішують спори щодо платежів, а не список.** Відкрийте поїздку, перегляньте розбивку за тарифом, потім поясніть одну домінуючу позицію.
- **Хронологія активності — ваш найкращий візуальний помічник.** Пасажир, який бачить 40-хвилинну паузу, припиняє сперечатися про загальну суму.
- **"Без бейджу" означає завершено.** Навчіть свою команду цьому, щоб вони перестали переслідувати здорові платежі.
- **Коди помилок зафіксовані в записі.** Читайте код, перш ніж робити припущення про банк.
