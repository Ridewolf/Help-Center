# Перебалансування — Поїздки

Сторінка Поїздок перебалансування (`/rebalance/runs`) — це **операційний журнал кожної поїздки з перебалансування**: хто керував яким фургоном, з якого депо виїжджали, скільки самокатів і батарей на борту, чи вчасно вони прибули і де виникли проблеми.

**Поїздка** — це робоча зміна: водій, фургон, депо відправлення, впорядкований список зупинок і запланований інтервал ETA. Сторінка дозволяє диспетчерам контролювати активні поїздки та переглядати завершені.

Ця сторінка — детальний перегляд поїздки, що доповнює оглядовий [Analytics — Rebalance](runs.md) звіт і локаційно орієнтовану дошку [Rebalance — Dead Zones](dead-zones.md).

Потрібен дозвіл: оператор, що увійшов у систему (маршрут лише вимагає _requiresAuth_, без конкретного ID дозволу).

> Примітка — на момент написання `/rebalance/runs` CRUD-ендпоїнти ще не активні. Сторінка відображає блок фільтрів, рядок KPI та макет таблиці з тестовими KPI і порожнім списком. _Створити поїздку_, _Пошук_, _Автооновлення_ та меню дій у рядку (_Відправити_, _Перепризначити_, _Переоптимізувати_, _Друк листа_, _Експорт_, _Редагувати_, _Скасувати_) реалізовані в коді, але закоментовані до появи бекенду. Клік по рядку веде на `/rebalance/runs/:id`, але сторінка деталей не входить у цю збірку.

## Рядок KPI (угорі)

Рядок із п’яти карток KPI підсумовує сьогоднішні поїздки.

| KPI                | Що показує                                                                                   |
| ------------------ | -------------------------------------------------------------------------------------------- |
| **Активні поїздки** | Поїздки в статусах _Відправлено_ / _В процесі_ / _Призупинено_                              |
| **Вчасно %**        | Відсоток поїздок, що вкладаються у запланований інтервал ETA; зелений тренд ≥ 90%, червоний — нижче |
| **Запізнення**      | Кількість поїздок зі статусом _Запізнення_ за SLA — індикатор "що потребує допомоги" для диспетчера |
| **Всього км сьогодні** | Загальна відстань, пройдена всіма фургонами перебалансування сьогодні                         |
| **Заміни батарей**  | Загальна кількість замін батарей, виконаних польовою командою сьогодні                        |

Разом ці п’ять KPI дають швидке уявлення про те, як сьогоднішня польова операція відповідає плану.

## Фільтри

Чотири фільтри розташовані у картці _Фільтри_; усі вони застосовуються одночасно (AND). Кнопка _Очистити все_ праворуч скидає всі фільтри.

| Фільтр            | Тип      | Варіанти                                                                                  |
| ----------------- | -------- | ----------------------------------------------------------------------------------------- |
| **Статус**        | Випадаючий список | _Всі_ / _Заплановано_ / _Відправлено_ / _В процесі_ / _Призупинено_ / _Завершено_ / _Скасовано_ |
| **Ризик SLA**     | Випадаючий список | _Всі_ / _В графіку_ / _Під загрозою_ / _Запізнення_ — позначка запізнення поїздки          |
| **Місто**         | Випадаючий список | _Всі міста_ / _Москва_ / _Санкт-Петербург_                                              |
| **Інциденти**     | Випадаючий список | _Всі_ / _Так_ / _Ні_ — чи зафіксовані інциденти по поїздці                              |

Поле вільного тексту _Пошук_ (за номером поїздки, водієм або фургоном) реалізоване, але наразі приховане разом з _Автооновленням_ і _Створенням поїздки_ до появи ендпоїнта.

## Колонки

Таблиця має дев’ять видимих колонок. Рядки клікабельні — ведуть на `/rebalance/runs/:id` (детальний перегляд не входить у цю збірку).

| Колонка              | Вміст                                                                                                                  |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| **Номер поїздки**     | Зрозумілий ідентифікатор поїздки (наприклад, `RUN-2026-0517-001`)                                                     |
| **Водій / Фургон**    | Аватар водія + ім’я + телефон; під ним модель фургона + номерний знак                                                  |
| **Депо / Місто**      | Назва депо відправлення та місто                                                                                        |
| **Статус**            | Пігулка статусу — сірий _Заплановано_, синій _Відправлено_, зелений _В процесі_, жовтий _Призупинено_, бірюзовий _Завершено_, червоний _Скасовано_ |
| **Зупинки**           | Прогрес у форматі `виконано / всього`, з червоним рядком _Не виконано: N_, якщо є невдалі зупинки                      |
| **Корисне навантаження** | Завантажені самокати (`🛴 в / місткість`) і батареї (`🔋 заряджені + розряджені / місткість`)                          |
| **Плановано**         | Час початку і кінця ETA + запланована відстань (км) і тривалість (хв)                                                  |
| **Ризик SLA**         | Пігулка ризику — зелений _В графіку_, жовтий _Під загрозою_, червоний _Запізнення_                                       |
| **Створено / Оновлено** | Дата створення зверху, дата останнього оновлення знизу                                                                  |

Колонка дій (меню з трьома крапками) реалізована, але закоментована до появи CRUD-ендпоїнтів; див. _Дії в рядку_ нижче для запланованого набору.

## Довідка по статусах

Поїздка має один статус; статус визначає, які дії диспетчера доступні:

| Статус         | Значення                                              |
| --------------- | ---------------------------------------------------- |
| **Плановано**   | Створено та заплановано, але ще не надіслано водієві |
| **Відправлено** | Надіслано водієві / фургону — очікується відправлення |
| **В процесі**   | Фургон рухається і / або робить зупинки              |
| **Призупинено** | Водій призупинив поїздку (перерва, інцидент тощо)    |
| **Завершено**   | Всі зупинки виконано, поїздка закрита                 |
| **Скасовано**   | Перервано до завершення                               |

## Посилання на ризик SLA

Прапорець у реальному часі, що показує, чи поїздка встигне у запланований проміжок часу:

| Ризик        | Значення                                              |
| ------------ | ---------------------------------------------------- |
| **В графіку** | Поточний темп відповідає запланованому ETA           |
| **Під загрозою** | Тенденція до запізнення, але ще в межах відновлення  |
| **Запізнення** | План вже пропущено — потребує уваги диспетчера        |

Використовуйте _ризик SLA = Запізнення_ як перший фільтр диспетчера вранці.

## Дії для рядка (планується)

Кожен рядок матиме меню з трьома крапками праворуч із наведеними нижче діями; наразі стовпець приховано до появи API.

| Дія             | Що вона робить                                            |
| --------------- | ---------------------------------------------------------- |
| **Переглянути** | Відкрити сторінку деталей поїздки за адресою `/rebalance/runs/:id` |
| **Відправити**  | Перевести _Плановану_ поїздку у _Відправлену_, повідомивши водія |
| **Перепризначити** | Змінити водія і / або фургон для поїздки                  |
| **Оптимізувати знову** | Повторно запустити оптимізатор маршруту для залишкових зупинок |
| **Друкувати лист** | Згенерувати друкований лист поїздки (резюме для водія)     |
| **Експортувати** | Експортувати дані поїздки у файл (фільтри / сортування збережено) |
| **Редагувати**  | Відкрити редактор поїздки                                  |
| **Скасувати**  | Скасувати поїздку — відкриває діалог підтвердження         |

## Порожні / завантажувальні стани

- **Завантаження** — індикатор із написом «Завантаження поїздок…» під час запиту до бекенда
- **Помилка** — банер _Тривога_ з кнопкою _Спробувати знову_, якщо запит не вдався
- **Порожньо** — по центру іконка _Вантажівка_ з написом «Поїздок не знайдено»; це **очікуваний стан сьогодні**, оскільки кінцева точка не повертає елементи

## Типові робочі процеси

- **Ранковий перегляд відправлень** — фільтр _Статус = Плановано_, сортування за датою створення, відправлення по черзі
- **Моніторинг у реальному часі** — фільтр _Статус = В процесі_, потім _ризик SLA = Запізнення_ для виявлення водіїв, які потребують допомоги; після увімкнення _Автооновлення_ підтримує актуальність перегляду
- **Підсумок наприкінці дня** — фільтр _Статус = Завершено_, перегляд стовпця _Зупинки_ для поїздок із невдалими зупинками, відкриття кожної для розбору інцидентів
- **Місто за містом** — фільтр за _Містом_ при багатоміських операціях; звірка кількості з [Analytics — Rebalance](runs.md)
- **Сортування інцидентів** — фільтр _Є інциденти = Так_ для виявлення всіх поїздок із проблемами сьогодні
- **Перевірка завантаження** — перегляд стовпця _Корисне навантаження_ у рядках _В процесі_; фургони, близькі до повного завантаження, можуть незабаром повертатися на базу

## Поради

- **Номери поїздок — стабільні ідентифікатори** — діліться ними з польовою командою для чіткої координації ("дивіться RUN-2026-0517-003")
- **Стовпець зупинок одразу показує стан** — `4/7` означає чотири виконано, три залишилось; червоний _Failed: N_ під ним = потребує подальшої уваги
- **Важливість "вичерпання" корисного навантаження** — велика кількість розряджених батарей означає, що фургон заповнений мертвими батареями і має заїхати на зарядку
- **Створено vs Оновлено** — _Оновлено_ відмічається щоразу, коли водій діє по поїздці; старе _Оновлено_ у рядку _В процесі_ = водій давно не відмічався
- **Статус _Призупинено_ — не помилка** — водії призупиняють поїздки для перерв, інцидентів і взаємодії з пасажирами; довго призупинені поїздки варто перевірити телефоном
- **Поки кінцева точка не з’явиться, вважайте цю сторінку попереднім переглядом макета / UX** — структура, фільтри та візуальна мова остаточні; дані за ними — ні
