# Ребалансування — Мертві зони

Сторінка Мертвих зон (`/rebalance/dead-zones`) — це **дошка цілей для польових операцій**: де ваш інвентар простоює, скільки доходу це вам коштує і в які райони слід направити фургон для ребалансування наступним.

На відміну від сторінки [Analytics — Rebalance](runs.md), яка підсумовує активність польової команди з часом, ця сторінка дивиться вперед: вона відповідає на питання _куди йти зараз?_

Необхідний дозвіл: оператор, що увійшов у систему (маршрут вимагає лише _requiresAuth_, без конкретного ID дозволу).

## Що означає «мертва зона»

**Мертва зона** — це міська територія, де транспортні засоби занадто довго стоять припаркованими без оренди. Сторінка їх ідентифікує та ранжує, щоб польовий персонал знав, які кластери розбивати першочергово.

Система підтримує два способи розбиття карти на сегменти:

- **Зони власника** — ваші власні налаштовані полігони з [Налаштування — Зони](../../settings/infrastructure/zones.md)
- **Сітка H3** — шестикутне покриття Uber, використовується для більш детального або незалежного від зон аналізу

Перемикач знаходиться у блоці фільтрів; таблиця відображає ті ж стовпці в обох режимах.

## Рядок KPI (угорі)

Рядок із п’ятьма картками KPI підсумовує ситуацію з мертвими зонами за обраними фільтрами.

| KPI                 | Що показує                                                                                  |
| ------------------- | ------------------------------------------------------------------------------------------ |
| **Мертві зони**     | Кількість зон / клітинок, позначених як мертві                                            |
| **Втрати / день**   | Оцінка втрат доходу на день — сума `lostRevenuePerDay` по відфільтрованих зонах           |
| **Застряглі пристрої** | Загальна кількість простоюючих пристроїв у мертвих зонах — ваша фізична ціль для збору    |
| **Середній час стоянки** | Середній час стоянки (хвилини) у мертвих зонах — скільки часу транспортний засіб стоїть перед рухом |
| **Щотижневий прогрес** | Відсоткова зміна порівняно з минулим тижнем — від’ємне = погіршення ситуації; додатне = покращення |

Кожен KPI оновлюється відповідно до фільтрів; використовуйте їх як одне число для швидкої оцінки перед детальним переглядом списку.

## Режими перегляду — Карта проти Таблиці

Перемикач у верхньому правому куті змінює подання одних і тих же даних:

- **Карта** — географічне відображення мертвих зон на мапі міста (поки що _скоро буде_)
- **Таблиця** — табличний вигляд нижче з усіма стовпцями та контекстом по рядках

Фільтри застосовуються до обох подань. _Таблиця_ — за замовчуванням; _Карта_ підключена, але географічне відображення ще в розробці.

Поруч із перемикачем подання розташований елемент керування _Автооновлення_ — увімкніть його, щоб періодично оновлювати дані (корисно для живих операцій).

## Фільтри

Блок фільтрів має чотири елементи керування; усі вони застосовуються одночасно (логічне І):

| Фільтр        | Тип       | Примітки                                                                            |
| ------------- | --------- | ----------------------------------------------------------------------------------- |
| **Місто**     | Випадаючий список | _Всі міста_ / _Москва_ / _Санкт-Петербург_ — звузити до одного міста операцій       |
| **Серйозність** | Випадаючий список | _Всі_ / _Низький_ / _Середній_ / _Високий_ / _Критичний_ — на основі оцінки серйозності зони |
| **Тип зони**  | Випадаючий список | _Зони власника_ / _Сітка H3_ — який тип покриття використовувати                     |
| **Пошук**     | Текст     | Вільний текст — співпадіння з назвою зони / районом                                |

Кнопка _Очистити все_ праворуч у картці фільтрів скидає всі елементи керування одним кліком.

## Стовпці

У режимі Таблиці дев’ять стовпців. Клік по рядку відкриває панель з інформацією про зону (поки що показує тост із назвою зони як заповнювач).

| Стовпець             | Вміст                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------- |
| **Зона / Клітинка**  | Назва зони плюс місто і район під нею; у режимі H3 це hex ID                                      |
| **Коефіцієнт простою** | Відсоток часу, коли в зоні є простоюючі пристрої, кольори: зелений `< 25%`, жовтий `25–40%`, червоний `≥ 40%` |
| **Час стоянки**      | Медіанний час стоянки в хвилинах, з _p90_ під ним                                                |
| **Середня кількість простоюючих пристроїв** | Середня кількість простоюючих транспортних засобів у зоні, з порівнянням із _Цільовим_ запасом |
| **Початки поїздок**  | Початки поїздок у зоні за _останні 24 години_ / _останні 7 днів_ / _останні 30 днів_             |
| **Конверсія**        | Початки на один простоюючий пристрій за годину — зелений `≥ 0.30`, жовтий `0.15–0.30`, червоний `< 0.15` |
| **Надлишок**         | Пристрої понад ціль — позитивне = забагато, негативне = замало; позитивне підсвічується червоним  |
| **Втрати / день**    | Оцінка втрат доходу лише для цієї зони                                                          |
| **Останній раз бачили простоюючим** | Коли в зоні востаннє були простоюючі пристрої — відформатовано у вашій локалі                   |

Рядки клікабельні; сортування за стовпцями поки що не реалізоване в цій версії.

## Дії з рядком

Кожен рядок має обробник кліку, який наразі показує тост із назвою зони. Повне **меню дій (для кожного рядка)** реалізоване в коді, але наразі вимкнене через відсутність API. Плановані дії наведені нижче для довідки — вони з’являться у меню з трьома крапками праворуч від кожного рядка після активації:

| Запланована дія         | Що вона робитиме                                                        |
| ------------------------ | ---------------------------------------------------------------------- |
| **Створити запуск**      | Відкрити конструктор запуску ребалансування, попередньо заповнений цією зоною |
| **Встановити ліміт часу паркування** | Обмежити максимальний час паркування в зоні                         |
| **Динамічне ціноутворення** | Застосувати цінові важелі для залучення або відштовхування поїздок, що починаються або закінчуються тут |
| **Редагування зони**     | Редагувати межі зони (розділити, об’єднати, змінити форму)             |
| **Позначити як заборону паркування** | Перетворити зону на зону без паркування, щоб виштовхнути транспортні засоби |
| **Зменшити цільову кількість** | Знизити цільову кількість пристроїв, щоб система припинила надсилати сюди транспортні засоби |
| **A/B експеримент**      | Налаштувати контрольований експеримент щодо стратегії усунення проблем  |

Поки кінцева точка не запущена, розглядайте таблицю як **поверхню для читання даних** — поєднуйте її зі списком транспортних засобів для індивідуальних дій з транспортними засобами.

## Порожні / стан завантаження

- **Завантаження** — індикатор завантаження з написом «Завантаження мертвих зон…» під час запиту до бекенда
- **Помилка** — банер _Сповіщення_ з кнопкою _Спробувати знову_, якщо запит не вдався
- **Порожньо** — по центру іконка _AlertTriangle_ з текстом «Немає мертвих зон»; це **очікуваний стан на сьогодні**, оскільки кінцева точка не повертає даних

## Типові робочі процеси

- **Ранкове планування** — сортуйте таблицю за _Втрати / день_ (візуально, сьогодні; незабаром з’являться сортувальні стовпці): виберіть топ-3 зони для призначення на сьогоднішні запуски
- **Сортування за серйозністю** — фільтруйте за _Серйозність = Критична_, щоб побачити лише найгірші випадки, потім відкрийте кожну зону для контексту
- **Операції по містах** — фільтруйте за _Місто_ під час проведення операцій у кількох містах; окремо переглядайте кількість і загальні втрати доходу
- **Перевірка з флотом** — використовуйте число _Застряглих пристроїв_ з рядка KPI, потім переходьте до [списку транспортних засобів](../fleet/vehicles.md), відфільтрованого за зоною, щоб побачити фактичні транспортні засоби
- **Поєднання з аналітикою** — порівнюйте поточну кількість тут із розділами [Аналітика — Ребалансування](runs.md) та [Аналітика транспортних засобів](../../analytics/reports/vehicles.md) «Мертві зони / Бездіяльні пристрої», щоб підтвердити тенденцію

## Поради

- **Конверсія — найоперативніший стовпець** — низька конверсія (червона) при високій надлишковій пропозиції означає, що ребалансування зони _не допоможе_; у вас правильна пропозиція, але попиту немає
- **Співвідношення бездіяльності до середньої кількості бездіяльних пристроїв** — _співвідношення бездіяльності_ зважене за часом (як часто зона бездіяльна), _середня кількість бездіяльних пристроїв_ зважена за кількістю (скільки їх там сидить). Обидва в червоному = найсильніший сигнал мертвої зони
- **_Ціль_ під _Середньою кількістю бездіяльних пристроїв_ береться з конфігурації зони** — якщо вона встановлена неправильно, усі зони виглядатимуть мертвими; перевірте в [Налаштування — Зони](../../settings/infrastructure/zones.md)
- **Сітка H3 корисна для міст без зонування** — коли операторські зони ще не визначені, H3 дає стандартний географічний сегмент
- **Щотижневий прогрес — це індикатор «чи перемагаємо ми» на сторінці** — якщо кількість мертвих зон зростає, але втрачені доходи зменшуються, польова команда працює спочатку з зонами з найвищою вартістю (гарний знак)
- **Обробники дій — це заглушки** — натискання на рядок наразі лише показує інформаційне повідомлення; справжні панелі / діалоги з’являться, коли бекенд буде готовий
