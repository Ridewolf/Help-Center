# Транспортний засіб — Створення та редагування

Два URL використовують однаковий макет форми:

- **Створити** — `/vehicles/create` — реєструє новий фізичний пристрій
- **Редагувати** — `/vehicles/:id/edit` — оновлює метадані існуючого транспортного засобу

Обидва доступні з [Списку транспортних засобів](vehicles.md) (кнопка `+ Створити` у верхньому правому куті) або з [Деталей транспортного засобу](vehicle-detail.md) (`Дії → Редагувати транспортний засіб`).

Дозволи:

- **Створити** — `Транспортні засоби` (`k7m8n9`) + піддозвіл, пов’язаний зі створенням
- **Редагувати** — `Транспортні засоби` (`k7m8n9`) + піддозвіл `edit`

## Макет

Сторінка розділена на дві колонки на десктопі, на мобільних пристроях — стек:

- **Ліва (8/12)** — сама форма, всередині картки _Інформація про транспортний засіб_
- **Права (4/12)** — бічна панель **Посібник по полях** з контекстною допомогою для активного поля, а також живий попередній перегляд введених даних

## Поля

Всього п’ять полів. Обов’язкові поля позначені червоною зірочкою (`*`).

### 1. Позначка (обов’язкове)

Людинозрозумілий код, надрукований на наклейці транспортного засобу (наприклад, _RW-001_).

- Має бути унікальним у межах вашого флоту
- Вільний текст — типовий формат: _ПРЕФІКС-ННН_ (префікс вашої компанії + послідовний номер)
- Натисніть **Згенерувати** (іконка зі спалахом), щоб автозаповнити — система зчитує префікс вашої компанії та існуючі позначки, обчислює наступний номер і записує його у поле. Під час запиту з’являється індикатор завантаження.

### 2. Статус (обов’язкове)

Початковий / поточний статус транспортного засобу. Дванадцять варіантів — той самий список, що й у [фільтрі списку транспортних засобів](vehicles.md#довідка-по-статусах).

Поширені початкові значення при створенні:

- **Не готовий** — створений, але ще не випущений для користувачів (безпечний вибір за замовчуванням)
- **Доступний** — готовий до оренди негайно (використовуйте лише після перевірки IoT та паркування)
- **Зберігання** — для запасу, який ще не введено в експлуатацію

При редагуванні змінюйте статус обережно — це може вивести транспортний засіб з орендного обігу або повернути його назад.

### 3. IoT-пристрій (необов’язкове)

IoT-модуль, прив’язаний до цього транспортного засобу (мобільний пристрій, що керує замком/розблокуванням і передає дані про батарею/GPS).

- Пошуковий випадаючий список — вводьте для фільтрації за IMEI або позначкою
- Необов’язкове — можна створити транспортний засіб без IoT і прив’язати пізніше (у _Редагуванні_)
- Один IoT-пристрій може бути прив’язаний лише до одного транспортного засобу одночасно

При редагуванні заміна IoT-пристрою дозволена, але відчувається як незворотна — новий пристрій починає звітувати за цим транспортним засобом, старий відв’язується. Використовуйте це при фізичній заміні плати.

### 4. Модель транспортного засобу (необов’язкове)

Запис моделі (Налаштування → Налаштування транспортних засобів), що визначає тарифи, налаштування за замовчуванням і категорію одиниці.

- Пошуковий випадаючий список — вводьте для фільтрації за позначкою моделі
- Необов’язкове при створенні, рекомендовано встановити, як тільки відомо модель — тарифи та поведінка залежать від неї
- Зміна моделі пізніше оновлює активні тарифи та правила поведінки — перед зміною на робочому пристрої узгодьте з операціями

### 5. Теги (необов’язкове)

Теги, які оператор застосовує до цього конкретного транспортного засобу.

- Мультивибір — оберіть один або кілька
- Пошуковий
- Це _теги рівня транспортного засобу_, окремі від _тегів рівня моделі_, успадкованих від вибраної моделі транспортного засобу
- Поїздки на цьому транспортному засобі успадковують ці теги рівня транспортного засобу на початку поїздки (див. [Список поїздок](../trips/rides.md) для деталей успадкування тегів)

## Бічна панель Посібника по полях

Права колонка — це **контекстний посібник**, а не дублювання форми:

- **Живий попередній перегляд** введених/вибраних значень (щоб перевірити перед збереженням)
- **Підказка в рядку**, що оновлюється при фокусі на полі — пояснює значення поля, типові помилки, значення за замовчуванням
- Показані **автополі**: поточна позначка, позначка статусу, позначка IoT-пристрою, позначка моделі, кількість тегів

Використовуйте як другу пару очей. На широкому екрані вона залишається видимою під час прокручування форми.

## Зберегти / Назад

- **Назад** (`←`) — відхиляє незбережені зміни і повертає на попередню сторінку (список або деталі у разі редагування)
- **Зберегти** — перевіряє форму і створює / оновлює транспортний засіб. Підтвердження успіху у вигляді тосту; помилки підсвічуються червоним повідомленням під полем

Якщо перевірка не пройшла (відсутня позначка, статус або дубль позначки), сторінка залишається відкритою, а проблемне поле обведене червоним.

## Створення проти редагування — відмінності

| Аспект             | Створення                          | Редагування                                             |
| ------------------ | --------------------------------- | ------------------------------------------------------- |
| Позначка           | Порожнє або _Згенерувати_         | Заповнене поточною позначкою                            |
| Статус             | Порожнє (потрібно обрати)          | Заповнене поточним статусом                             |
| IoT-пристрій       | Порожнє або вибір із нев’язаних    | Заповнене; заміна відв’язує попередній                  |
| Модель транспортного засобу | Порожнє                          | Заповнене                                              |
| Теги               | Порожнє                          | Заповнене поточними тегами рівня транспортного засобу  |
| Після збереження   | Перенаправлення на деталі нового ТЗ | Залишитись на формі / перенаправлення на деталі (залежить від потоку) |
| Запис у журналі дій | "Транспортний засіб створено _ім’я оператора_" | "Транспортний засіб відредаговано _ім’я оператора_" з відмінностями на рівні полів |

Обидва потоки записують у [Журнал дій](vehicle-detail.md#вкладка-активність) транспортного засобу.

## Типові робочі процеси

- **Зареєструйте нову партію** — створіть ярлик → статус _Не готовий_ → прив'яжіть IoT → встановіть Модель → збережіть. Після того, як пристрій буде на місці та протестований, змініть статус на _Доступний_
- **Замініть несправну плату IoT** — редагуйте → відв'яжіть / виберіть новий IoT → збережіть → дочекайтеся першого сигналу (Останній сигнал у деталях)
- **Перекласифікуйте** — змініть Модель при переміщенні пристроїв між флотами/категоріями
- **Додайте тимчасовий тег** — редагуйте → Теги → збережіть (наприклад, "Event 2026-05", "Loaner")

## Поради

- **Використовуйте Генерацію** для ярликів — це допомагає підтримувати нумерацію в порядку та уникати дублікатів
- **Встановлюйте Модель заздалегідь** — тарифи залежать від моделі; якщо модель не встановлена, поїздки на цьому транспортному засобі будуть тарифікуватися за правилами без моделі
- **Не змінюйте Статус на _Доступний_, поки фізично не перевірите IoT** — користувачі зможуть одразу розблокувати транспортний засіб
- **Звертайте увагу на підказки у Полі довідки**, якщо сумніваєтеся щодо поля — вбудована допомога актуальніша за цю статтю
- **Журнал дій — ваша страховка** — кожне збереження фіксується з ім'ям оператора та часовою позначкою у [деталях транспортного засобу](vehicle-detail.md#вкладка-активність)
