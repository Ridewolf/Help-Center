# Деталі клієнта

Сторінка деталей клієнта (`/clients/:id`) — це робоче місце для одного клієнта. Використовуйте її для перегляду особистої інформації, виконання дій з балансом (поповнення, штраф), блокування / розблокування, надсилання повідомлень та аудиту історії поїздок і активності облікового запису клієнта.

Зазвичай ви потрапляєте сюди, натискаючи рядок у [Списку клієнтів](clients.md) або зі сторінки деталей поїздки (посилання на клієнта у заголовку).

Необхідний дозвіл: **Клієнти** (`e4f5h6`). Для окремих дій потрібні піддозволи (зазначені нижче).

## Макет

Зверху вниз:

1. **Заголовок** — назад, ім'я, статус, кнопка _Дії_
2. **Карти огляду** — баланс, поїздки, рейтинг, статус (4 KPI-картки)
3. **Вкладки** — Деталі / Активність / Історія

## Заголовок

Верхня смуга ідентифікує клієнта:

- **Кнопка назад** (`←`) повертає до списку
- **Ім'я** (ім'я + прізвище) та **статусна мітка** (Активний / Заблоковано / Заморожено / Реєстрація)
- Кнопка **Дії** праворуч — відкриває діалог дій

## Дії

Натискання **Дій** відкриває модальне вікно з усіма доступними операторам діями для цього клієнта. Кожна дію захищена дозволом:

| Дія                 | Дозвіл             | Що робить                                                                |
| ------------------- | ------------------ | ----------------------------------------------------------------------- |
| **Поповнити баланс**| `topup-manual`     | Відкриває діалог балансу — зарахування грошей на гаманець клієнта       |
| **Виписати штраф**  | `fine`             | Відкриває діалог штрафу — списання грошей з гаманця (пошкодження, паркування тощо) |
| **Надіслати push**  | —                  | Відкриває діалог для надсилання push-повідомлення в додаток клієнта     |
| **Блокувати / Розблокувати** | `block` / `unblock` | Перемикає статус блокування клієнта з опціональною причиною            |
| **Редагувати клієнта** | `edit`           | Відкриває [форму редагування](client-create-edit.md)                   |
| **Видалити клієнта** | `delete`           | М'яке видалення з підтвердженням (червоний елемент знищення)           |

Дії, на які у вас немає дозволу, приховані.

## Карти огляду

Ряд із чотирьох карток під заголовком дає короткий огляд клієнта:

| Карта        | Що показує                                                                       |
| ------------ | -------------------------------------------------------------------------------- |
| **Баланс**  | Баланс гаманця в валюті компанії (червоний, якщо від’ємний)                      |
| **Поїздки** | Загальна кількість поїздок                                                       |
| **Рейтинг** | Середній рейтинг, який залишали водії для цього клієнта                         |
| **Статус**  | Поточний статус з однорядковим підзаголовком ("Активний / Заблоковано / Заморожено / Реєстрація") |

## Вкладки

Три вкладки:

| Вкладка      | Що всередині                                                                                          |
| ------------ | ---------------------------------------------------------------------------------------------------- |
| **Деталі**  | Особиста інформація (ім'я, електронна пошта, телефон, статус, баланс, теги) та панель **Пристрої** (зареєстровані пристрої) |
| **Активність** | Дії оператора та системні події в обліковому записі клієнта (зміни статусу, редагування балансу тощо) |
| **Історія** | Історія поїздок клієнта — відфільтрований зріз глобального списку Поїздок, обмежений цим клієнтом |

### Вкладка Деталі

Найглибший вигляд стану облікового запису клієнта. Два розділи:

**Особиста інформація (таблиця):**

- Ім'я
- Прізвище
- Електронна пошта (індикатор підтвердження)
- Телефон (індикатор підтвердження)
- Статус (з міткою статусу)
- Баланс (відформатований у валюті компанії)
- Теги (чіпси, застосовані до цього клієнта)

**Панель Пристрої:**

Перелік усіх пристроїв, які увійшли в Rider App під цим обліковим записом, з позначками останнього входу та опціями надіслати push (за наявності дозволу) або вийти з пристрою. Корисно для розслідувань безпеки та випадків підтримки "Не можу увійти".

### Вкладка Активність

Хронологічний **журнал активності** для цього клієнта: кожна дія оператора (поповнення, штраф, зміна статусу, редагування, надсилання SMS/електронної пошти/push) і кожна системна подія (етапи реєстрації, зміни статусу верифікації, коригування балансу через повернення коштів).

Корисно для дотримання вимог, вирішення спорів і підзвітності.

### Вкладка Історія

**Історія поїздок** клієнта у вигляді таблиці — той самий формат рядка, що й у глобальному списку Поїздок, попередньо відфільтрований за цим клієнтом. Натисніть будь-який рядок, щоб відкрити деталі поїздки.

Ця вкладка — ваша відправна точка для випадків "клієнт каже, що поїздка X була неправильною".

## Типові робочі процеси

- **Клієнт каже, що баланс гаманця неправильний** — відкрийте Деталі (поточний баланс), потім Активність (знайдіть останню зміну балансу), потім Історію (перевірте поїздку, що спричинила списання). Якщо щось було неправильно, _Дії → Поповнити баланс_ з причиною
- **Клієнт повідомляє про втрату телефону** — Деталі → Пристрої → вийти з втраченого пристрою (якщо підтримується); за потреби заблокуйте гаманець через _Дії → Заблокувати клієнта_ до відновлення доступу
- **Шахрайство або зловживання** — Активність для хронології, Історія для підозрілих поїздок; потім _Дії → Заблокувати клієнта_ з причиною; причина зберігається в журналі активності
- **Повернення з доброї волі** — _Дії → Поповнити баланс_ з описом на кшталт "Повернення з доброї волі — квиток #12345"; опис видно в Активності для аудиту
- **Привітання / онбординг** — _Дії → Надіслати push_ з вітальним повідомленням; спочатку перевірте Пристрої, щоб переконатися, що є активна сесія

## Поради

- **Слідкуйте за картою Статусу** — навіть якщо все інше виглядає нормально, статус _Заблоковано_ або _Заморожено_ пояснює, чому клієнт не може їхати
- **Панель Пристроїв — ваш старт для налагодження** — більшість випадків "не можу увійти" пов’язані з застарілою сесією пристрою
- **Опис поповнень і штрафів відображається в Активності** — пишіть щось, що оператори зможуть пізніше знайти ("квиток #X", "повернення за поїздку Y"), а не просто число
- **Редагування призначене для метаданих** — ім’я, електронна пошта, телефон — не для балансу. Для операцій з грошима використовуйте спеціальні діалоги балансу (з аудиторським журналом)
- **Рейтинг — це рейтинг _водія_ клієнта** — низький рейтинг у поєднанні з піками доказів паркування / квитків зазвичай вказує на проблемного пасажира
- **URL містить ID клієнта** — вставте його в розмову підтримки, щоб поділитися точним профілем
