# Платежі — Історія

Сторінка Платежі (`/payments`) — це журнал усіх грошових операцій, пов’язаних з рахунком клієнта: оплата поїздок, поповнення гаманця, повернення коштів, штрафи. Використовуйте її для розслідування платежу, оформлення повернення або аудиту руху грошей за певний період.

Для необроблених подій вебхуків від платіжних провайдерів дивіться [Pending Webhooks](pending-webhooks.md).

Необхідний дозвіл: **Платежі** (`m1n2p3`). Деякі дії над рядками потребують додаткових піддозволів.

## Що тут знаходиться

Кожен рядок представляє одну платіжну транзакцію:

| Тип        | Що це таке                                                                 |
| ---------- | -------------------------------------------------------------------------- |
| **Поповнення** | Гроші, додані до гаманця клієнта (ручне зарахування оператором або поповнення карткою) |
| **Списання**  | Гроші, зняті з клієнта (оплата поїздки або штраф)                          |
| **Повернення** | Гроші, повернені клієнту (відміна попереднього списання)                    |

Кожна транзакція має **метод/провайдера** — канал, через який вона пройшла:

- **Провайдери карток** (Stripe тощо) — реальні гроші на платіжній картці
- **Баланс** — внутрішній гаманець (не платіжний провайдер; просто дебет/кредит на балансі клієнта)
- **Інші шлюзи** залежно від ваших інтеграцій

Розподіл між _провайдером картки_ і _балансом_ важливий для повернень — див. _Дії над рядком → Повернення_ нижче.

## Фільтри

| Фільтр     | Тип       | Примітки                                                    |
| ---------- | --------- | ----------------------------------------------------------- |
| Пошук      | Текст     | Пошук за ім’ям клієнта, ID платежу, пов’язаним ID поїздки / штрафу |
| Діапазон дат | Календар  | Вибір від/до; за замовчуванням — «весь час»                 |
| Тип        | Випадаючий список | `Поповнення` / `Списання` / `Повернення` (або `Всі`)       |
| Статус     | Випадаючий список | `Очікується` / `Завершено` / `Помилка` / `Повернено` (або `Всі`) |

Фільтри застосовуються на сервері і комбінуються через AND.

## Колонки

| Колонка    | Сортується? | Зміст                                                              |
| ---------- | ---------- | ------------------------------------------------------------------ |
| **Дата**   | ✓          | Коли створено транзакцію; сортування за замовчуванням — новіші зверху |
| **Клієнт** | —          | Ім’я клієнта та аватар; посилання на деталі клієнта               |
| **Джерело**| —          | Тип транзакції (Поповнення / Списання / Повернення) з кольоровою позначкою |
| **Сума**   | ✓          | Сума в валюті компанії, зі знаком (+/−) та кольоровим кодуванням  |
| **Метод**  | —          | Метод / провайдер платежу (картка, баланс, назва шлюзу)          |
| **Статус** | ✓          | Статус у вигляді позначки (див. довідку нижче)                    |

Сортування за допомогою кліку по заголовку колонки. Обране сортування відображається в URL.

## Довідка по статусах

| Статус        | Значення                                                                    |
| ------------- | ---------------------------------------------------------------------------- |
| **Очікується** | Відправлено провайдеру; очікується підтвердження через вебхук               |
| **Завершено**  | Провайдер підтвердив успіх; гроші списані або зараховані                   |
| **Помилка**   | Провайдер відхилив транзакцію (відмова картки, помилка мережі, перевірка шахрайства) |
| **Повернено** | Успішне списання, яке пізніше було скасоване поверненням                    |

## Дії над рядком

Кожен рядок має **меню з трьома крапками** справа. Доступні дії залежать від типу платежу, статусу та ваших дозволів:

| Дія             | Коли доступна                         | Дозвіл                                                  |
| --------------- | ------------------------------------ | ------------------------------------------------------- |
| **Переглянути клієнта** | Завжди (переходить до профілю клієнта) | —                                                       |
| **Повернення**  | Див. «Маршрутизація повернення» нижче | `refund` / `topup-manual` / `fine` (залежно від маршруту) |

### Маршрутизація повернення

Панель керування приховує деталі провайдера, але дія _Повернення_ достатньо розумна, щоб обрати правильний шлях:

- **Списання через провайдера** (картка, шлюз) → виклик endpoint повернення провайдера → гроші повертаються на картку
- **Списання з балансу** (гаманець) → провайдер не залучений — відкриває діалог **Поповнити баланс** для зарахування коштів назад (потребує `topup-manual`)
- **Поповнення балансу** (ручне зарахування оператором) → не можна скасувати через провайдера — відкриває діалог **Виписати штраф** для списання тієї ж суми (потребує `fine`)

Повернення **відключене**, коли:

- Рядок сам є поверненням (повторне повернення не має сенсу)
- Статус не _Завершено_ (не можна повертати очікувані або помилкові транзакції)
- Транзакція вже була скасована (панель керування відстежує це і блокує дублікати кліків)
- У вас немає потрібного піддозволу для цього маршруту

## Чому платежі з’являються тут (і що їх створює)

Платежі **не створюються** на цій сторінці — вони походять з інших процесів:

1. **Клієнт здійснює поїздку** → кінець поїздки → бекенд створює транзакцію _Списання_ → якщо успішно, статус змінюється на _Завершено_ і гроші списуються з гаманця або картки
2. **Клієнт поповнює гаманець у додатку** → виклик провайдера → бекенд створює транзакцію _Поповнення_ → статус змінюється на _Завершено_ після підтвердження вебхуком
3. **Оператор зараховує гроші в гаманець** через _Поповнити баланс_ у клієнта → бекенд створює _Поповнення_ з методом _баланс_ і одразу зі статусом _Завершено_
4. **Оператор виписує штраф** → бекенд створює _Списання_ з методом _баланс_, одразу зі статусом _Завершено_
5. **Повернення** зі списку → бекенд створює транзакцію _Повернення_; оригінал позначається як _Повернено_

Початкова транзакція ніколи не зникає — кожна дія підлягає аудиту.

## Типові робочі процеси

- **Розслідувати списання** — пошук за ID клієнта / поїздки / платежу → перевірити Статус (Завершено = гроші знято, Помилка = гроші не знято) та Метод
- **Повернути гроші за поїздку** — знайти рядок _Дебет_ для поїздки → меню рядка → _Повернення_ → підтвердити → з’являється парний рядок _Повернення_, початковий змінюється на _Повернено_
- **Перевірити день** — встановити Діапазон дат = сьогодні → фільтр Статус = Завершено → переглянути підсумки
- **Знайти помилки для повторної спроби** — фільтр Статус = Помилка → зв’язатися з клієнтами для повторної спроби / альтернативного методу
- **Звірити з провайдером** — Діапазон дат + Тип = Поповнення/Дебет + Метод = провайдер картки → експортувати та звірити зі звітом провайдера

## Поради

- **Очікується не означає помилка** — очікуючі транзакції чекають на вебхук провайдера; перевірте [Очікувані вебхуки](pending-webhooks.md), якщо рядок довго залишається Очікується
- **Балансові транзакції не можна повернути через картку** — система направить вас у потрібний діалог; не намагайтеся вручну створювати компенсуючі транзакції
- **Початкова транзакція зберігається після повернення** — повернення додають парний рядок, не видаляючи дебет; обидва рядки залишаються в історії для аудиту
- **Знак суми вказує напрямок** — `+` (зелений) означає гроші клієнту; `−` (червоний/темний) означає гроші від клієнта
- **Назви провайдерів важливі для підтримки** — при ескалації до вашого платіжного провайдера скопіюйте ID платежу та назву провайдера з колонки Метод
- **URL можна надсилати** — скопіюйте відфільтрований вигляд (наприклад, _вчорашні помилки списань карткою_) і надішліть у фінанси або відділ боротьби з шахрайством
