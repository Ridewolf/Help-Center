# Автоматичний перегляд квитків

Сторінка Автоматичного перегляду квитків (`/support/tickets/auto-review`) — це **спрощений інтерфейс черги** для послідовної роботи з очікуваними квитками без повернення до списку між рішеннями.

Як і в [Park Proof Auto Review](park-proof-auto-review.md), тут "Авто" означає **автоматичне просування**: після кожної дії сторінка завантажує наступний очікуваний квиток, щоб ви могли продовжувати модерацію без перерв.

Доступно через кнопку **Автоматичний перегляд** у [списку Квитків](tickets.md).

Потрібен дозвіл: **Квитки** (`a8b9c1`).

## Як це працює

1. Сторінка завантажує **поточну чергу очікуваних квитків** при відкритті
2. Ви бачите перший квиток — фото доказу, інформацію про квиток і кнопки дій
3. Обираєте дію (Вирішено / В процесі / Очікування інформації / Відхилено / Дубль) або Пропустити
4. Сторінка **автоматично переходить** до наступного очікуваного квитка
5. Повторюєте, поки черга не спорожніє
6. Коли черга порожня, сторінка переходить у **режим очікування** з відліком часу, що опитує наявність нових квитків

Ваше місце — це сама черга очікування: закриття вкладки і повторне відкриття не втрачає прогрес, ви просто продовжуєте з наступного очікуваного квитка, коли він завантажується.

## Макет

Три колонки на широких екранах, стекаються на вузьких:

| Колонка     | Ширина | Вміст                                                                 |
| ----------- | ------ | -------------------------------------------------------------------- |
| **Зображення** | 5/12   | Масштабоване фото доказу + часовий штамп                            |
| **Дії**     | 4/12   | П’ять кнопок зміни статусу + Пропустити + Коментар                   |
| **Інформація** | 3/12   | Картка інформації про квиток зі статусом, типом скарги, транспортним засобом, повідомником, датами |

Індикатор прогресу зверху показує, наскільки ви просунулися.

## Заголовок

- **Заголовок** "Автоматичний перегляд квитків"
- **Підзаголовок** з прогресом: `Перегляд X з Y · T-12345`
- Кнопка **Пропустити** (угорі справа) — пропускає поточний квиток без прийняття рішення (квиток залишається _Очікується_)
- **Стрілка назад** — повертає до [списку Квитків](tickets.md)

## Кнопки дій

П’ять переходів статусу, плюс Пропустити і необов’язковий Коментар:

| Кнопка          | Новий статус   | Використовуйте, коли                                                        |
| --------------- | -------------- | -------------------------------------------------------------------------- |
| **Вирішено**    | _Вирішено_     | Проблему виправлено (або її не було) — закриває квиток                      |
| **В процесі**   | _В процесі_    | Проблема реальна, ви розпочали виправлення (завдання з техобслуговування, подальші дії) |
| **Очікування інформації** | _Очікування інформації_ | Потрібна додаткова інформація від користувача перед рішенням — користувач отримує запит |
| **Відхилено**   | _Відхилено_    | Не є реальною проблемою (поганий звіт, помилковий об’єкт, спам)            |
| **Дубль**       | _Дубль_        | Існує інший квиток на ту ж проблему / транспортний засіб                   |
| **Пропустити**  | (без змін)     | Не приймати рішення; перейти до наступного квитка                          |
| **Коментар**    | (будь-яка дія) | Необов’язкова примітка, прикріплена до обраної дії                         |

Кожен клік одразу зберігає дію і переходить до наступного квитка. Спочатку введіть **коментар**, якщо хочете його додати.

### Коли використовувати який статус закриття

- **Вирішено** — поломка усунена (або звіт виявився непорозумінням після перевірки транспортного засобу)
- **Відхилено** — звіт був некоректним / фальшивим / не по темі; користувач бачить відхилення у своєму додатку
- **Дубль** — посилання на оригінал; бекенд обробляє ланцюжок, тому закриття одного закриває всі

_Вирішено_, _Відхилено_ і _Дубль_ закривають квиток. _В процесі_ і _Очікування інформації_ залишають його відкритим у іншій категорії.

## Колонка інформації

Картка **Інформація про квиток** праворуч показує структуровані дані за фото:

- **Статус** — поточний статус
- **Тип скарги** — кольорова мітка (механічна поломка, електрика, акумулятор тощо)
- **Транспортний засіб** — мітка і посилання
- **Повідомник** — ім’я (користувач) або мітка (система / оператор)
- **Місцезнаходження** — адреса / координати
- **Створено / оновлено** — часові позначки
- **SLA** — час до завершення (або бейдж "просрочено")

Перед прийняттям рішення ознайомтеся з цією карткою — вона розповідає всю історію без виходу зі сторінки.

## Режим очікування

Коли черга спорожніє, сторінка показує той самий екран очікування, що й для Park Proofs:

- Повідомлення "Усі квитки переглянуті"
- **Таймер зворотного відліку** до наступного автоматичного опитування
- Кнопка **Перевірити зараз** для негайного опитування
- Кнопка **Вийти** для повернення до списку

Якщо під час очікування з’являється новий квиток, сторінка завантажує його автоматично.

## Коли використовувати Автоматичний перегляд, а коли список

| Використовуйте список, коли…                                | Використовуйте Автоматичний перегляд, коли…           |
| ---------------------------------------------------------- | ------------------------------------------------------ |
| Потрібно відфільтрувати за статусом, типом скарги або транспортним засобом | Ви обробляєте нефільтровану чергу очікування           |
| Ви розслідуєте історію конкретного транспортного засобу або користувача | Ви зосереджені на одному квитку за раз, у повноекранному режимі |
| Ви перевіряєте минулі рішення (Вирішено / Відхилено / тощо) | Вам потрібна швидкість: прочитати → вирішити → наступний |
| Потрібно передати справу команді техобслуговування           | Ви працюєте у змінному режимі, обробляючи чергу послідовно |


## Типові робочі процеси

- **Початок зміни** — відкрийте Автоматичний перегляд → опрацюйте кожен очікуваний квиток → завершіть на екрані очікування
- **Швидке сортування** — прочитайте фото + тип скарги + повідомника → якщо очевидно, _Вирішити_ / _Відхилити_ з однорядковим коментарем; якщо ні, _В роботі_ і позначте команду техобслуговування в коментарі
- **Очікування користувача** — коли звіт неясний, _Очікування інформації_ з питанням у коментарі; користувач отримує запит
- **Дубль** — коли пошук виявляє вже відкритий квиток на той самий транспортний засіб, _Дубль_ для зв’язування ланцюжка
- **Невизначений випадок** — _Пропустити_ і відкрити зі списку з повним контекстом (історія транспортного засобу, пов’язані поїздки, IoT-сповіщення)

## Поради

- **Спочатку введіть коментар** — те саме правило, що й для Доказів паркування: дія фіксується раніше, ніж зберігаються пізні коментарі
- **Пропуск ≠ рішення** — пропуск нічого не закриває; квиток залишається в черзі для наступного оператора
- **Вирішити і Відхилити — це різні дії** — _Вирішити_ означає «ми виправили проблему»; _Відхилити_ означає «це не була реальна проблема»; користувач бачить різницю у своєму додатку
- **Обробка дублів** — спочатку шукайте у списку за міткою транспортного засобу; якщо знайдете батьківський квиток, натисніть Дубль, інакше вирішіть найінформативніший і дублюйте решту
- **Таймер SLA продовжує відлік** під час очікування — якщо черга порожня, але у списку є прострочені рядки, вони фільтруються з Автоматичного перегляду (можливо, через права або статус); поверніться до списку, щоб їх побачити
- **Автоматичний перегляд поважає порядок квитків з бекенду** — найновіші очікувані можуть відрізнятися залежно від розгортання; вважайте порядок у черзі авторитетним
