# Квитки — Список

Список квитків (`/support/tickets`) — це черга підтримки для питань, пов’язаних із транспортним засобом — механічні пошкодження, електричні несправності, зламані деталі, питання безпеки тощо. Кожен квиток прив’язаний до конкретного транспортного засобу і містить фото, повідомника, тип скарги, таймер SLA та статус.

Для детального розслідування по квитку (повний ланцюжок, докази, дії з вирішення) дивіться **сторінку деталей квитка** (відкривається кліком по рядку).

Для спрощеного інтерфейсу черги дивіться [Ticket Auto Review](ticket-auto-review.md).

Потрібен дозвіл: **Квитки** (`a8b9c1`).

## Як квитки з’являються тут

Квитки створюються з кількох джерел:

1. **Звіт користувача** — мобільний додаток Rider App має потік «повідомити про проблему»; користувачі вибирають тип скарги, роблять фото, залишають примітку
2. **Ініційовано оператором** — оператор відкриває квиток для транспортного засобу, у якого помітив проблему (рідко; зазвичай віддають перевагу потоку [завдань з технічного обслуговування](../../operations/fleet/vehicle-detail.md))
3. **Автоматично системою** — правила IoT або аналітики можуть автоматично створювати квитки (наприклад, аномалія батареї)

Кожен новий квиток потрапляє до цього списку зі статусом (зазвичай _Очікується_) і запускає таймер SLA.

## Фільтри

| Фільтр         | Тип       | Примітки                                                                                   |
| -------------- | --------- | ------------------------------------------------------------------------------------------ |
| Пошук          | Текст     | Пошук за ID квитка, міткою транспортного засобу, повідомником, місцезнаходженням           |
| Статус         | Випадаючий список | Список з бекенду (`Очікується`, `В процесі`, `Вирішено`, `Відхилено`, `Дубль` тощо)       |
| Тип скарги     | Випадаючий список | 7 типів — див. нижче                                                                       |

Фільтри комбінуються за логікою AND. Фільтри відображаються над таблицею; URL відображає поточний стан.

## Колонки

| Колонка      | Сортується? | Зміст                                                           |
| ------------ | ----------- | --------------------------------------------------------------- |
| **Фото**    | —           | Мініатюра фото доказу від користувача (клік для збільшення)     |
| **Транспортний засіб** | —   | Мітка та модель транспортного засобу; клік для відкриття деталей |
| **SLA**      | —           | Час, що залишився до дедлайну SLA (червоніє при простроченні)   |
| **Місцезнаходження** | —     | Де було повідомлено про проблему — координати та/або адреса     |
| **Повідомник** | —          | Хто повідомив про проблему (ім’я користувача або мітка системи/оператора) |
| **Статус**   | —           | Пігулка статусу з кольором (див. нижче)                         |
| **Дати**    | —            | Дата створення / останнього оновлення                            |

## Типи скарг

Сім типів допомагають швидко сортувати квитки. Кожен має свій колір:

| Тип                   | Колір бейджу     | Що зазвичай означає                                         |
| --------------------- | ---------------- | ----------------------------------------------------------- |
| **Механічне пошкодження** | Руйнувальний (червоний) | Аварія, зламаний каркас, зігнуті деталі                      |
| **Електрична несправність** | Попередження (жовтий) | Проблеми з дроселем, світлом, датчиками                     |
| **Проблема з батареєю** | За замовчуванням (синій) | Не заряджається, розряджається швидше за очікуване           |
| **Зламані деталі**     | Руйнувальний (червоний) | Відсутня підніжка, відсутній відбивач, пошкоджені гальма     |
| **Питання безпеки**   | Руйнувальний (червоний) | Все, що робить транспортний засіб небезпечним для їзди      |
| **Чистота**           | Попередження (жовтий) | Брудний, запах, липкі поверхні — менш терміново              |
| **Інше**              | Контурний         | Не підпадає під вищезазначені категорії — див. опис          |

Червоні категорії зазвичай вимагають негайного виведення транспортного засобу з експлуатації; жовті та сині можуть чекати вікна для сервісу.

## Довідка по статусах

Список статусів отримується з бекенду, тому може трохи відрізнятися залежно від розгортання. Типові статуси:

| Статус          | Варіант           | Значення                                                      |
| --------------- | ----------------- | ------------------------------------------------------------- |
| **Очікується**  | Вторинний (сірий) | Щойно повідомлено, ніхто ще не працював над цим               |
| **В процесі**   | За замовчуванням (синій) | Призначено оператору або створено завдання з техобслуговування |
| **Вирішено**    | Успіх (зелений)   | Проблему виправлено; квиток закрито                           |
| **Відхилено**   | Руйнувальний (червоний) | Оператор визначив, що це не реальна проблема                  |
| **Скасовано**   | Руйнувальний (червоний) | Закрито без вирішення (часто для неякісних звітів)            |
| **Архівовано**  | Контурний         | Старі / історичні                                             |
| **Дубль**       | (закрито)         | Пов’язано з раніше створеним квитком на той самий транспортний засіб |

Статуси, що містять _вирішено_, _відхилено_ або _дубль_, вважаються **закритими** — вони більше не враховуються у відкритій черзі.

## Важливість

Внутрішньо квитки мають рівень важливості (`critical`, `high`, `medium`, `low`), який визначається типом скарги та додатковими даними від оператора чи системи. Сторінка списку відображає важливість через **колір типу скарги** та **колір таймера SLA** — прострочений SLA для критичного квитка є вашим пріоритетом.

## Дії над рядком

Кожен рядок має **меню з трьома крапками** з одним активним пунктом:

| Дія             | Що робить                                                              |
| ---------------- | --------------------------------------------------------------------- |
| **Переглянути деталі** | Відкрити сторінку деталей квитка (повний ланцюжок + докази + дії з вирішення) |

Повний набір дій оператора (Призначити, Заблокувати транспортний засіб, Створити завдання з технічного обслуговування, Надати кредит користувачу, Відповісти, Об’єднати дублікати) знаходиться на **сторінці деталей квитка** і вмикається або вимикається за допомогою feature-flag для кожного розгортання. Завдання списку — бути чергою сортування, а не консоллю для вирішення проблем.

## Дії на сторінці

- **Автоматичний перегляд** — відкриває [чергу автоматичного перегляду квитків](ticket-auto-review.md) — оптимізований перегляд по одному квитку за раз

## Типові робочі процеси

- **Щоденне сортування** — фільтрувати за `Статус = Очікується` → сортувати за SLA (спочатку найстаріші, зверху — найближчий термін) → переглядати, відкривати кожен у деталях, приймати рішення та діяти
- **Сортування лише критичних** — фільтрувати за `Тип скарги = Механічне пошкодження / Питання безпеки` → це квитки, які виводять транспортний засіб з експлуатації
- **Перевірка історії транспортного засобу** — шукати за міткою транспортного засобу → бачити всі квитки, які коли-небудь були створені для цього пристрою → корисно перед повторним випуском після ремонту
- **Тривога SLA** — сортувати за SLA → квитки на початку списку прострочені → негайно ескалувати

## Поради

- **Фото — ваш перший сигнал** — навіть перед відкриттям квитка, мініатюра показує, чи це реальний звіт про пошкодження, чи низькоякісна заявка
- **Червоний колір SLA = діяти негайно** — коли SLA стає червоним, ви вже пропустили контрактний термін; це ваша реактивна черга
- **Перевіряйте разом із транспортним засобом** — натисніть на стовпець транспортного засобу → відкрийте вкладку Сповіщення цього транспортного засобу → проблеми IoT і звіти операторів часто збігаються
- **Остерігайтеся дублікатів** — кілька користувачів часто повідомляють про однаковий зламаний самокат протягом кількох годин; використовуйте Пошук за транспортним засобом, щоб виявити їх до вирішення
- **URL можна надсилати** — скопіюйте відфільтрований вигляд (наприклад, _очікувані квитки з механічними пошкодженнями_) і надішліть команді технічного обслуговування
