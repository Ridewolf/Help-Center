# Докази паркування — Список

Список Доказів паркування (`/support/park-proofs`) — це черга модерації фотографій, які користувачі роблять свого транспортного засобу у ключові моменти поїздки. Ці фотографії підтверджують, що користувач припаркувався правильно (або ні), а завдання вашої команди — **затверджувати хороші фото, попереджати або штрафувати за погані**.

Для перегляду окремої фотографії (екран модерації з великим зображенням) див. [Перегляд доказів паркування](park-proof-review.md). Для правил автоматизації, які обробляють очевидні випадки без вашої участі, див. [Автоматичний перегляд](park-proof-auto-review.md).

Необхідний дозвіл: **Докази паркування** (`d5e6f7`). Для деяких дій у рядку потрібні додаткові піддозволи.

## Як докази потрапляють сюди

Мобільний додаток для користувача пропонує зробити фото у трьох точках:

1. **Початок** — коли розблоковують транспортний засіб (підтверджує, що пристрій був у хорошому стані на початку)
2. **Паркування** — під час паузи в середині поїздки (підтверджує, що користувач припаркувався легально під час зупинки)
3. **Кінець** — коли поїздка завершується (це **головне** — підтверджує, що транспортний засіб залишили припаркованим правильно)

Фото завантажується з GPS-метаданими і потрапляє у цю чергу зі статусом **Очікується**. Автоматичний перегляд може змінити його на _Затверджено_ (хороше фото) без участі оператора; все, у чому Автоматичний перегляд не впевнений, потрапляє сюди для ручної перевірки.

## Фільтри

| Фільтр     | Тип       | Примітки                                                            |
| ---------- | --------- | ------------------------------------------------------------------ |
| Пошук      | Текст     | Пошук за ім'ям клієнта, позначкою транспортного засобу, ID поїздки |
| Діапазон дат | Календар | Вибір від / до; за замовчуванням — "весь час"                     |
| Статус     | Випадаючий список | `Очікується` / `Затверджено` / `Попередження` / `Штраф` / `Заблоковано` (або `Всі`) |
| Тип        | Випадаючий список | `Початок` / `Паркування` / `Кінець` (або `Всі`)                    |

Використовуйте `Статус = Очікується` як щоденний фільтр моніторингу — це черга модерації.

## Колонки

| Колонка     | Сортування? | Вміст                                                      |
| ----------- | ----------- | ---------------------------------------------------------- |
| **Зображення** | —         | Мініатюра фото (клік для відкриття сторінки перегляду)    |
| **Користувач** | —         | Ім'я клієнта та аватар; клік для відкриття профілю клієнта |
| **Транспортний засіб** | — | Позначка та модель транспортного засобу; клік для деталей транспортного засобу |
| **Поїздка**  | —         | ID поїздки; клік для деталей поїздки                       |
| **Тип**      | ✓         | Фаза поїздки (`Початок` / `Паркування` / `Кінець`)         |
| **Статус**   | ✓         | Піктограма статусу (див. довідку нижче)                    |
| **Дата**    | ✓         | Коли зроблено фото; сортування за замовчуванням — новіші спочатку |

## Довідка по статусах

| Статус       | Колір  | Значення                                                                       |
| ------------ | ------ | ----------------------------------------------------------------------------- |
| **Очікується** | Жовтий | Очікує модерації (вашої або Автоматичного перегляду)                         |
| **Затверджено** | Зелений | Фото хороше — користувач припаркувався правильно                            |
| **Попередження** | Помаранчевий | Фото не ідеальне — користувач отримує попередження, але штрафу немає       |
| **Штраф**    | Червоний | Фото погане — користувача оштрафували (або система позначила як кандидат на штраф) |
| **Заблоковано** | Сірий  | Користувача заблоковано через цей доказ (серйозне / повторне порушення)     |

Статуси, встановлені через дії в рядку та на сторінці перегляду, записуються як у запис доказу, так і в [Журнал дій](../../operations/customers/client-detail.md#вкладка-активність) клієнта.

## Дії в рядку

У кожному рядку справа є **меню з трьома крапками**. Доступні дії залежать від дозволів:

| Дія           | Дозвіл       | Що робить                                                                                                  |
| ------------- | ------------ | ---------------------------------------------------------------------------------------------------------- |
| **Переглянути** | `view-detail` | Відкриває [сторінку перегляду](park-proof-review.md) з повним зображенням і контекстом                      |
| **Затвердити** | `review`     | Позначає доказ як _Затверджено_ (без штрафу, без попередження) — типовий варіант для хороших фото          |
| **Попередити** | `review`     | Позначає як _Попередження_ — користувач отримує сповіщення, але не штрафу                                  |
| **Відкрити поїздку** | —         | Переходить до сторінки деталей пов’язаної поїздки (карта маршруту, хронологія тощо)                        |

Дії, на які у вас немає дозволу, приховані.

Повний набір дій (Штраф, Блокування користувача, Створення завдання на техобслуговування, Запит на повторне паркування) доступний на **сторінці перегляду** — туди звертайтеся для дій, що виходять за межі швидкого затвердження/попередження.

## Дії на сторінці (угорі справа)

- **Автоматичний перегляд** — відкриває [сторінку налаштувань Автоматичного перегляду](park-proof-auto-review.md) для конфігурації правил, які автоматично затверджують очевидні хороші фото і автоматично позначають очевидні погані (це розвантажує чергу Очікується, щоб ви перевіряли лише крайні випадки)

## Типові робочі процеси

- **Щоденна черга модерації** — `Статус = Очікується` → сортування за датою від найстаріших → перегляд кожного, _Переглянути_ для контексту, _Затвердити_ / _Попередити_ залежно від ситуації
- **Розслідування скарги** — пошук за ID поїздки або клієнтом → знайти доказ → _Переглянути_ → перевірити фото з претензією користувача
- **Пошук повторних порушників** — пошук за ім'ям клієнта → перегляд кількох доказів для виявлення патерну (журнал дій у профілі користувача розповість ту ж історію)
- **Тільки кінець поїздки** — `Тип = Кінець` → перегляд лише фото наприкінці поїздки (найважливіші; фото паркування в середині поїздки зазвичай без проблем)
- **Аудит Автоматичного перегляду** — фільтр `Статус = Затверджено` за останній день → вибіркова перевірка вибірки, щоб переконатися, що правила працюють правильно

## Поради

- **Мініатюри достатньо для більшості викликів** — чітко всередині зони, пряме кадрування, без перешкод — _Затвердити_ без відкриття. Залиште _Перегляд_ для неоднозначних фото
- **Відкрита поїздка** — ваш швидкий доступ до контексту — якщо пасажир стверджує, що припаркувався легально, карта поїздки покаже, де він фактично завершив
- **Статуси зберігаються** — після встановлення _Затверджено_, пасажир припиняє отримувати нагадування про цей доказ. Не затверджуйте погане фото, щоб «очистити чергу», інакше втратите можливість подальшого контролю
- **Попередження — це ваш "проміжний" статус** — використовуйте, коли фото погане, але не зловмисне (пасажир поспішав, погана погода тощо). Повторні попередження призводять до штрафів через правила Автоматичного перегляду
- **Активно використовуйте Автоматичний перегляд** — черга швидко зростає; чим більше очевидно хороших фото Автоматичний перегляд затверджує самостійно, тим більше часу у вас залишається на справді неоднозначні
- **URL можна ділитися** — скопіюйте відфільтрований перегляд (наприклад, _штрафовані докази за вчора_) і надішліть колезі для вибіркової перевірки
