# Деталі доказу паркування

Сторінка деталей доказу паркування (`/support/park-proofs/:id`) — це місце, де ви детально переглядаєте один доказ паркування і — якщо він ще очікується — модеруєте його. Вона відкривається як велике діалогове вікно поверх [списку доказів паркування](park-proofs.md); URL змінюється, щоб доказ можна було поділитися або відкрити за прямим посиланням.

Зазвичай ви потрапляєте сюди, натискаючи _Переглянути_ у рядку, натискаючи плитку у вигляді галереї або вставляючи пряме посилання.

Необхідний дозвіл: **Докази паркування** (`d5e6f7`). Піддозвіл `review` дає змогу виконувати дії модерації, `delete` — кнопку Видалити.

## Як це пов’язано зі сторінкою перегляду

Існують обидві сторінки `/support/park-proofs/:id` (ця сторінка) та `/support/park-proofs/:id/review` — вони схожі, але виконують різні функції:

| Поверхня                                                                          | Що це таке                                                                                                                                |
| --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| **Деталі доказу паркування (ця сторінка)**                                       | **Діалогове вікно**, відкрите зі списку — повне зображення з масштабуванням, повний контекст, повний набір дій. Перегляд одного запису. URL `/support/park-proofs/:id` |
| [Перегляд доказу паркування](park-proof-review.md)                              | **Повноекранна сторінка** (`/:id/review`) — спеціальна поверхня для перегляду одного доказу                                             |
| [Автоматичний перегляд доказу паркування](park-proof-auto-review.md)             | **Режим оптимізації** — автоматичне послідовне переглядання черги очікуючих доказів по одному                                         |

Щоденно: використовуйте **Автоматичний перегляд** для очищення черги, **діалогове вікно деталей** (ця сторінка) для одиничного перегляду зі списку, а **сторінку перегляду** для спеціалізованого процесу рецензування.

## Макет

Діалог розділений на дві колонки на широких екранах, на вузьких — стосується:

| Колонка          | Ширина | Вміст                                                                                                  |
| ---------------- | ------ | ----------------------------------------------------------------------------------------------------- |
| **Зображення (ліва)** | 3/5    | Фотографія повної роздільної здатності з масштабуванням на чорному фоні                                |
| **Інформація (права)** | 2/5    | Заголовок (назва + статус / тип бейджів), контекст (клієнт / поїздка / транспортний засіб), сітка деталей, дії перегляду |

## Зображення (ліва колонка)

Великий переглядач зображень із фотографією повної роздільної здатності на чорному фоні:

- **Клікніть на зображення**, щоб переключити масштаб (1× → 2× → 3× → 4× → назад до 1×)
- **Колесо прокрутки** для збільшення або зменшення масштабу кроками по 0,5×
- Курсор змінюється між збільшенням і зменшенням залежно від стану
- **Бейдж із відсотком масштабування** з’являється у верхньому лівому куті, коли масштаб більший за 1×

Чотири кнопки з’являються у нижньому правому куті при наведенні (напівпрозорі на чорному фоні):

| Кнопка              | Що робить                                                                    |
| ------------------- | ----------------------------------------------------------------------------- |
| **Збільшити**       | Крок збільшення +0,5× (максимум 4×)                                          |
| **Зменшити**        | Крок зменшення -0,5× (мінімум 1×)                                            |
| **Згорнути**         | Скидає масштаб назад до 1×                                                   |
| **Відкрити в новій вкладці** | Відкриває зображення оригінальної роздільної здатності в новій вкладці браузера для детального перегляду |

Шукайте ті ж сигнали, що й на [сторінці перегляду](park-proof-review.md): весь транспортний засіб у кадрі, законне місце паркування, підніжка опущена, будь-що, що суперечить заяві користувача.

## Заголовок (верх правої колонки)

Стрічка заголовка ідентифікує доказ:

- **Назва** _"Перегляд доказу паркування"_ з коротким описом нижче
- Два **бейджі** вертикально справа:
  - **Бейдж статусу** — кольоровий відповідно до статусу (жовтий Очікується, зелений Затверджено, оранжевий Попередження, червоний Відхилено, темний Заблоковано)
  - **Бейдж типу** — контурна капсула з написом _Початок_ / _Паркування_ / _Кінець_

## Розділ контексту

Три рядки з посиланнями на пов’язані сутності. Кожен — це router-link (натисніть, щоб відкрити відповідну сторінку деталей у тому ж вікні):

| Рядок         | Показує                                                                                                               |
| ------------- | --------------------------------------------------------------------------------------------------------------------- |
| **Клієнт**    | Ім’я клієнта (посилання на [деталі клієнта](../../operations/customers/client-detail.md)), електронна пошта + телефон (натисніть, щоб скопіювати) |
| **Поїздка**   | Назва / ID поїздки з посиланням на [деталі поїздки](../../operations/trips/ride-detail.md)                             |
| **Транспортний засіб** | Позначка транспортного засобу з посиланням на [деталі транспортного засобу](../../operations/fleet/vehicle-detail.md), тип транспортного засобу нижче |

Використовуйте ці перехресні посилання для швидкого формування контексту — чи порушував цей клієнт раніше, чи дійсно він завершив поїздку тут, чи часто цей транспортний засіб позначали.

## Розділ деталей

Двоколонкова сітка ключ/значення під контекстом. Поля, що відображаються, залежать від стану доказу:

| Поле                 | Коли показується           | Що показує                                                                                                                                                                                                                                    |
| -------------------- | -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Створено**         | Завжди                     | Коли додаток райдера завантажив фото                                                                                                                                                                                                          |
| **Переглянуто о**    | Лише після перегляду       | Коли оператор (або Автоматичний перегляд) прийняв рішення                                                                                                                                                                                     |
| **Тривалість перегляду** | Лише після перегляду       | Різниця між часом створення та перегляду (наприклад, «2г 14хв») — корисно для вимірювання SLA щодо доказу                                                                                                                                   |
| **Переглянув**       | Лише після перегляду оператором | Оператор, який переглянув. Посилання на їхній [профіль оператора](../../settings/access/operators.md). Якщо оператора не вдається визначити (404, немає доступу), показується id як клікабельне посилання — сторінка профілю сама обробляє авторизацію |
| **Місцезнаходження** | Коли поїздка має координати | Широта / довгота початку поїздки (для доказів _Початок_) або кінця (для доказів _Паркування_/_Кінець_), з точністю до 6 знаків після коми                                                                                                      |

Якщо доказ було відхилено з накладенням штрафу, під деталями показується червоне сповіщення _Штраф_ із сумою штрафу в валюті компанії.

Якщо є попередній коментар або причина відхилення, вона відображається в розділі _Коментар_ нижче.

## Дії перегляду (лише для статусу Очікується)

Якщо статус доказу **Очікується**, внизу правої колонки з’являється вибір дії. Діалог деталей підтримує **п’ять** дій модерації (на одну більше, ніж на спеціальній сторінці перегляду):

| Дія                      | Вплив на статус | Додаткові поля       | Коли використовувати                                                                |
| ------------------------ | --------------- | -------------------- | ----------------------------------------------------------------------------------- |
| **Затвердити**           | _Затверджено_   | —                    | Фото чітко відповідає вимогам — коментар не потрібен                               |
| **Затвердити з коментарем** | _Затверджено_   | Обов’язковий коментар | Фото хороше, але потрібно залишити примітку (рідкісний випадок, для майбутніх посилань, навчання ML) |
| **Попередити**           | _Попередження_  | Рекомендований коментар | Фото не ідеальне — райдер отримує м’яке сповіщення, штраф не накладається           |
| **Відхилити**            | _Відхилено_     | Коментар + сума штрафу | Погане фото — накладається штраф. Штраф списується з гаманця при підтвердженні      |
| **Заблокувати**          | _Заблоковано_   | Обов’язковий коментар | Серйозне або повторне порушення — блокує райдера від майбутніх поїздок             |

Кожна дія відображається як клікабельна радіокнопка з описом; вибір показує умовні поля (текстове поле для коментаря та/або поле для суми штрафу). Основна кнопка підтвердження набуває кольору дії (зелений / жовтий / червоний / темний).

Після підтвердження діалог закривається, з’являється тост із підтвердженням дії, і список оновлюється.

### Чим відрізняється від сторінки перегляду

Спеціальна [сторінка перегляду](park-proof-review.md) (`/:id/review`) показує **чотири** дії у вигляді кнопок одна під одною. Цей діалог показує **п’ять** дій у вигляді радіокнопок — додаткова дія це _Затвердити з коментарем_, що корисно для фіксації контексту позитивного рішення без підвищення до попередження.

## Закриті докази (вже переглянуті)

Якщо доказ уже переглянуто (Затверджено / Попередження / Відхилено / Заблоковано), розділ дій приховується — діалог стає лише для читання. Ви все одно бачите весь контекст (зображення, клієнт / поїздка / транспортний засіб, деталі, штраф, коментар, хто і коли переглянув), і можете:

- **Видалити** запис (за наявності права `delete`) — лише для спаму / тестових / неправильних завантажень
- **Закрити** діалог

Щоб змінити рішення після факту, зверніться до адміністратора — стандартний процес не дозволяє повторний перегляд через UI.

## Нижній колонтитул

| Кнопка           | Коли відображається                             | Що робить                                                                                                                        |
| ---------------- | ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **Видалити**     | Завжди, якщо у вас є піддозвіл `delete`         | Повністю видаляє запис доказу (з підтвердженням). Використовуйте лише для тестових / спамових / неправильних завантажень — не як модераційний вибір |
| **Скасувати**    | Тільки в стані Очікується                        | Закриває діалог без відправлення                                                                                                |
| **Підтвердити дію** | Тільки в стані Очікується, після вибору дії     | Відправляє вибрану дію (кольорово відповідну дії)                                                                              |
| **Закрити**      | Переглянуті докази                               | Закриває діалог                                                                                                                 |

Закриття діалогу (Скасувати / Закрити / Esc / клік по оверлею) видаляє `/:id` з URL, щоб історія назад / вперед відповідала тому, що ви бачите.

## Типові робочі процеси

- **Розслідувати один доказ зі списку** — знайдіть доказ у списку (фільтр / пошук), натисніть рядок → відкриється діалог деталей → перегляньте контекст → прийміть рішення
- **Глибокий аналіз оштрафованого доказу** — пошук за клієнтом → відкрийте один із їх відхилених доказів → перевірте Reviewed by + коментар, щоб дізнатися, хто і чому прийняв рішення → використовуйте це для вирішення спорів
- **Швидке затвердження за глибоким посиланням** — отримайте URL від колеги → натисніть → відкриється діалог → збільшіть фото → Затвердити / Затвердити з коментарем
- **Перевірка історії транспортного засобу** — відкрийте доказ → натисніть на транспортний засіб → перевірте, чи цей транспортний засіб часто отримує погані фото паркування → це вказує на проблему з розміщенням / знаками, а не на водія
- **Аудит рішень рецензента** — відфільтруйте список за Статусом `Затверджено` → відкрийте докази, щоб побачити Reviewed by + коментар → калібруйте стандарти команди

## Поради

- **Збільшення коліщатком миші швидке** — кнопка не потрібна — просто прокручуйте колесо над зображенням
- **Зображення відкривається у новій вкладці у повній роздільній здатності** — коли збільшення в діалозі недостатнє (наприклад, щоб прочитати знак розміром із номерний знак), відкривайте зовнішньо
- **"Затвердити з коментарем" краще за мовчазне затвердження** для крайніх випадків — залиште однорядкову нотатку, за яку подякує наступний рецензент (або ви через три місяці)
- **Блокування остаточне** — водії можуть бути розблоковані через [деталі клієнта](../../operations/customers/client-detail.md), але для будь-якого доказу _Блокування_ — це найвищий рівень ескалації. Не застосовуйте його за перше порушення
- **Видалити vs Відхилити** — Відхилити залишає запис модерації (і штрафує водія); Видалити повністю стирає доказ. Якщо потрібен паперовий слід, ніколи не видаляйте
- **URL можна поширювати** — `/support/park-proofs/:id` веде безпосередньо сюди, без навігації списком
- **Закриті докази доступні лише для читання** — якщо ви відкрили переглянутий доказ, очікуючи діяти, тому кнопки зникли
