# לקוח — יצירה ועריכה

שני כתובות URL:

- **יצירה** — `/clients/create` — רישום ידני של לקוח חדש (נדיר; רוב הלקוחות נרשמים בעצמם)
- **עריכה** — `/clients/:id/edit` — עדכון פרטים אישיים וסטטוס של לקוח קיים

שניהם נגישים מרשימת [לקוחות](clients.md) (כפתור `+ צור` בפינה הימנית העליונה) או מדף [פרטי הלקוח](client-detail.md) (_פעולות → ערוך לקוח_).

הרשאות:

- **יצירה** — `לקוחות` (`e4f5h6`) + הרשאת משנה הקשורה ליצירה
- **עריכה** — `לקוחות` (`e4f5h6`) + הרשאת המשנה `edit`

## מתי להשתמש

רוב הלקוחות שלך **נרשמים בעצמם** דרך אפליקציית Rider — תיצור אותם בלוח המחוונים רק לעיתים רחוקות.

יצירה ידנית מיועדת ל:

- **חשבונות בדיקה** — בדיקות פנימיות, משתמשי הדגמה
- **לקוחות VIP / עסקיים** — חשבונות שצריכים להתקיים לפני שהרוכב מוריד את האפליקציה
- **קליטת רוכבים על ידי מפעילים** — אירועים / שותפויות שבהם הצוות רושם בשם הרוכב

לכל השאר, תן לאפליקציה לטפל בהרשמה והשתמש ב**עריכה** כשצריך לתקן פרטי קשר או לשנות סטטוס.

## פריסה

כרטיס יחיד עם טופס אנכי, ללא סרגל צד של מדריך שדות (שונה מטופס רכב).

## שדות — יצירה

שבעה שדות בסך הכל. כולם חובה.

| שדה                | אימות                                                                                                                  |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **שם פרטי**         | 1–100 תווים                                                                                                           |
| **שם משפחה**        | 1–100 תווים                                                                                                           |
| **אימייל**           | פורמט אימייל סטנדרטי (`name@domain.tld`); חייב להיות ייחודי בין הלקוחות                                            |
| **טלפון**            | פורמט בינלאומי המתחיל ב-`+` (למשל `+373 60 123 456`); רק ספרות, רווחים, מקפים וסוגריים                              |
| **סיסמה**            | **לפחות 12 תווים**, חייבת להכיל **אות גדולה, אות קטנה, ספרה ותו מיוחד**                                            |
| **אישור סיסמה**      | חייבת להתאים בדיוק לסיסמה                                                                                                |
| **סטטוס**            | סטטוס התחלתי: `פעיל` / `לא פעיל` / `חסום` / `קפוא` / `ברישום` (ברירת מחדל _פעיל_)                                |

האימות מתבצע בעת שמירה ובשורה תוך כדי יציאה מהשדה. שגיאות מופיעות באדום מתחת לשדה.

### כללי סיסמה

דרישת הסיסמה היא המחמירה ביותר. לוח המחוונים דוחה כל סיסמה שאינה עומדת בכל ארבעת הבדיקות:

- ≥ 12 תווים
- ≥ אות גדולה אחת (A–Z)
- ≥ אות קטנה אחת (a–z)
- ≥ ספרה אחת (0–9)
- ≥ תו מיוחד אחד (למשל `!@#$%^&*`)

לאחר השמירה, הלקוח ישתמש בסיסמה זו (בנוסף לטלפון או אימייל) כדי להיכנס לאפליקציית Rider. העבר את הסיסמה בערוץ מאומת — לעולם אל תדביק סיסמאות בשיחות שאינן מוצפנות מקצה לקצה.

### סטטוס (ביצירה)

| ערך             | שימוש                                                                                   |
| --------------- | --------------------------------------------------------------------------------------- |
| **פעיל**        | ברירת מחדל — הלקוח יכול לנסוע מיד                                                    |
| **לא פעיל**     | נוצר אך לא שוחרר עדיין (תעביר ל"פעיל" מאוחר יותר)                                   |
| **חסום**        | חסום מראש (נדיר — בדרך כלל בשימוש כשמשחזרים חשבון לאחר אירוע הונאה)                  |
| **קפוא**        | חשבון מוקפא                                                                           |
| **ברישום**      | ההרשמה עדיין בתהליך (שימוש רק באינטגרציה עם תהליך חיצוני)                            |

## שדות — עריכה

בעריכה שדות הסיסמה מוסתרים (הסיסמאות מאופסות במקום אחר) ומתווסף שדה **תגיות**.

| שדה           | הערות                                                                       |
| -------------- | --------------------------------------------------------------------------- |
| **שם פרטי**   | מלא מראש, אותו אימות כמו ביצירה                                            |
| **שם משפחה**  | מלא מראש, אותו אימות כמו ביצירה                                            |
| **אימייל**    | מלא מראש; שינויו עלול לשבש את כניסת הלקוח עד לאימות מחודש                 |
| **טלפון**     | מלא מראש; אותו אזהרה כמו לאימייל                                           |
| **תגיות**     | בחירה מרובה; תוויות שמפעיל מוסיף לקיבוץ וסינון                             |
| **סטטוס**     | מלא מראש עם הסטטוס הנוכחי; אותו enum                                      |

## שמירה / ביטול

- **בטל** (או חץ חזור) — מבטל שינויים שלא נשמרו וחוזר לדף הקודם
- **שמור** — מאמת את הטופס ויוצר / מעדכן את הלקוח. הודעת הצלחה מופיעה; שגיאות בשדה מודגשות באדום

אם האימות נכשל (שדה חסר, כללי סיסמה, אימייל כפול, פורמט טלפון), הדף נשאר פתוח עם שדה הבעייתי מסומן.

## יצירה מול עריכה — הבדלים

| היבט              | יצירה                                                  | עריכה                                                |
| ------------------ | ------------------------------------------------------- | ---------------------------------------------------- |
| שדות סיסמה        | קיימים ונדרשים                                         | מוסתרים                                              |
| תגיות             | לא בטופס (נקבעות מאוחר יותר דרך עריכה או ברשימה/פרטים) | קיימות                                               |
| סטטוס             | ריק → ברירת מחדל _פעיל_                                | מלא מראש עם הסטטוס הנוכחי                           |
| אימייל / טלפון    | ריק                                                    | מלא מראש — שינוים עשוי לדרוש אימות מחדש            |
| לאחר שמירה        | הפניה לפרטי הלקוח החדש                                | הפניה חזרה לפרטי הלקוח                               |
| רשומת יומן פעילות | "לקוח נוצר על ידי _שם מפעיל_"                         | "לקוח נערך על ידי _שם מפעיל_" עם הבדל בשדות       |

שני התהליכים כותבים ל[יומן הפעילות](client-detail.md#כרטיסיית-פעילות) של הלקוח.

## תהליכים טיפוסיים

- **יצירת VIP** — `+ צור` ברשימה → מלא שם, אימייל אמיתי, טלפון אמיתי, סיסמה חזקה, סטטוס _פעיל_ → שמור → הודע לרוכב עם פרטי ההתחברות
- **תיקון טעות הקלדה** — שורת רשימה → תפריט שורה → _ערוך_ → תקן את השדה → שמור (השינוי מופיע ביומן הפעילות עם הבדל)
- **העלאת אצווה ארגונית** — כתוב סקריפט ליצירה דרך ה-API (טופס זה מיועד ליחידים); השתמש בעריכה מאוחר יותר להוספת תגיות ספציפיות לחברה
- **שינוי טלפון לאחר החלפת מכשיר** — ערוך → עדכן טלפון → שמור → הלקוח יצטרך לאמת מחדש בהתחברות הבאה (תלוי בחוקי השרת)

## טיפים

- **פורמט טלפון חשוב** — חייב להתחיל ב-`+` וקוד המדינה; הפורמט נאכף והמאמת יסרב לקלט שגוי
- **בחירת סיסמה חזקה** — ליצירות חד-פעמיות של מפעילים, השתמש בביטוי ארוך ("rideTheWolf2026!RW") שמקיים את כל הכללים בבת אחת; רשום אותו במנהל הסיסמאות שלך, לא בצ׳אט
- **ייחודיות אימייל** — אימייל כפול הוא הכשל הנפוץ ביותר ביצירה; בדוק קודם ברשימה על ידי חיפוש האימייל
- **אל תשנה אימייל/טלפון בקלות על לקוחות קיימים** — תהליכי האימות תלויים בהם; תאם עם הלקוח לפני השמירה
- **תגיות שייכות כאן, לא בשורה** — ניתן גם להוסיף/להסיר תגיות דרך הפעולה ההמונית ברשימה, אך טופס העריכה הוא המקום הנכון לשינויים מדויקים
- **שינויים בסטטוס נשקלים באודיט** — מעבר מ_פעיל → חסום_ דרך טופס זה מתועד באותה צורה כמו הפעולה הייעודית _פעולות → חסימת לקוח_ — שניהם תקפים
