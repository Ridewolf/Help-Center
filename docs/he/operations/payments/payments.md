# תשלומים — היסטוריה

דף התשלומים (`/payments`) הוא ספר החשבונות של כל עסקה כספית שנגעה בחשבון הלקוח: חיובי נסיעות, טעינות ארנק, החזרים, קנסות. השתמש בו כדי לחקור חיוב, להנפיק החזר או לבדוק את זרימת הכסף בטווח תאריכים.

לאירועי וובהוק לא מעובדים מספקי תשלום ראה [Pending Webhooks](pending-webhooks.md).

הרשאה נדרשת: **תשלומים** (`m1n2p3`). חלק מפעולות השורה דורשות הרשאות משנה נוספות.

## מה נמצא כאן

כל שורה מייצגת עסקת תשלום אחת:

| סוג        | מה זה                                                                 |
| ---------- | -------------------------------------------------------------------- |
| **טעינה**  | כסף שהתווסף לארנק הלקוח (זיכוי ידני של מפעיל או טעינת כרטיס)      |
| **חיוב**   | כסף שנלקח מהלקוח (חיוב נסיעה או קנס)                              |
| **החזר**  | כסף שהוחזר ללקוח (ביטול חיוב קודם)                                |

לכל עסקה יש **שיטה/ספק** — הערוץ דרכו עברה העסקה:

- **ספקי כרטיסים** (Stripe, וכו') — כסף אמיתי בכרטיס תשלום
- **יתרה** — ארנק פנימי (לא ספק תשלום; רק חיוב/זיכוי נגד יתרת הלקוח)
- **שערים אחרים** בהתאם לאינטגרציות שלך

ההפרדה בין _ספק כרטיס_ ל_יתרה_ חשובה להחזרים — ראה _פעולות שורה → החזר_ למטה.

## מסננים

| מסנן       | סוג       | הערות                                                        |
| ---------- | --------- | ------------------------------------------------------------ |
| חיפוש      | טקסט      | מחפש בשם הלקוח, מזהה תשלום, מזהה נסיעה / קנס קשור          |
| טווח תאריכים | לוח שנה | בורר מ/עד; ברירת מחדל "כל הזמנים"                          |
| סוג        | תפריט נפתח | `טעינה` / `חיוב` / `החזר` (או `הכל`)                        |
| סטטוס      | תפריט נפתח | `ממתין` / `הושלם` / `נכשל` / `הוחזר` (או `הכל`)             |

המסננים מופעלים בצד השרת ומשולבים עם AND.

## עמודות

| עמודה      | ניתן למיין? | תוכן                                                              |
| ---------- | ----------- | ---------------------------------------------------------------- |
| **תאריך**  | ✓           | מתי העסקה נוצרה; מיון ברירת מחדל = החדשים ביותר תחילה          |
| **לקוח**   | —           | שם הלקוח ואווטאר; קישור לפרטי הלקוח                             |
| **מקור**   | —           | סוג העסקה (טעינה / חיוב / החזר), עם תג צבעוני                  |
| **סכום**   | ✓           | סכום כסף במטבע החברה, עם סימן (+/−) וקוד צבע                   |
| **שיטה**   | —           | שיטת תשלום / ספק (כרטיס, יתרה, שם שער)                         |
| **סטטוס**  | ✓           | סמן סטטוס (ראה הפניה למטה)                                     |

מיין על ידי לחיצה על כותרת שניתנת למיון. המיון שנבחר הוא חלק מכתובת ה-URL.

## הפניה לסטטוס

| סטטוס       | משמעות                                                                    |
| ------------ | -------------------------------------------------------------------------- |
| **ממתין**   | נשלח לספק; ממתין לאישור וובהוק                                         |
| **הושלם**   | הספק אישר הצלחה; הכסף הועבר                                            |
| **נכשל**    | הספק דחה את העסקה (כרטיס נדחה, שגיאת רשת, בדיקת הונאה)               |
| **הוחזר**   | חיוב מוצלח שבוטל מאוחר יותר על ידי החזר                                |

## פעולות שורה

לכל שורה יש **תפריט שלוש נקודות** מימין. הפעולות הזמינות תלויות בסוג התשלום, הסטטוס וההרשאות שלך:

| פעולה           | מתי מופעלת                          | הרשאה                                                  |
| ---------------- | --------------------------------- | ------------------------------------------------------- |
| **הצג לקוח**    | תמיד (קופץ לפרופיל הלקוח)         | —                                                       |
| **החזר**         | ראה "נתיב החזר" למטה              | `refund` / `topup-manual` / `fine` (תלוי בנתיב)                          |

### נתיב החזר

לוח המחוונים מסתיר ממך את פרטי הספק, אבל פעולת _החזר_ חכמה מספיק כדי לבחור את הנתיב הנכון:

- **חיוב מבוסס ספק** (כרטיס, שער) → קורא לנקודת הקצה של ההחזר של הספק → הכסף חוזר לכרטיס
- **חיוב יתרה** (ארנק) → ללא ספק מעורב — פותח את דו-שיח **טעינת יתרה** לזיכוי הארנק (דורש `topup-manual`)
- **טעינת יתרה** (זיכוי ידני של מפעיל) → לא ניתן לבטל דרך ספק — פותח את דו-שיח **הנפקת קנס** לחיוב אותו סכום (דורש `fine`)

ההחזר **מנוטרל** כאשר:

- השורה היא בעצמה החזר (להחזיר החזר לא הגיוני)
- הסטטוס אינו _הושלם_ (אי אפשר להחזיר עסקאות ממתינות / נכשלות)
- העסקה כבר בוטלה (לוח המחוונים עוקב אחרי זה וחוסם לחיצות כפולות)
- אין לך את הרשאת המשנה הנכונה לנתיב ההחזר

## למה תשלומים מופיעים כאן (ומה יוצר אותם)

תשלומים **אינם** נוצרים מדף זה — הם נובעים מזרימות אחרות:

1. **הרוכב מבצע נסיעה** → סיום נסיעה → השרת יוצר עסקת _חיוב_ → אם מצליח, הסטטוס משתנה ל_הושלם_ והכסף נלקח מהארנק או הכרטיס
2. **הרוכב מטעין את הארנק באפליקציה** → קריאה לספק → השרת יוצר עסקת _טעינה_ → הסטטוס משתנה ל_הושלם_ לאחר אישור וובהוק
3. **מפעיל מזין זיכוי לארנק** דרך _טעינת יתרה_ על לקוח → השרת יוצר _טעינה_ עם שיטה _יתרה_ ומייד _הושלם_
4. **מפעיל מנפיק קנס** → השרת יוצר _חיוב_ עם שיטה _יתרה_, מייד _הושלם_
5. **החזר** מהרשימה הזו → השרת יוצר עסקת _החזר_; המקור מסומן כ_הוחזר_

העסקה המקורית לעולם לא נעלמת — כל פעולה ניתנת לביקורת.

## זרימות עבודה טיפוסיות

- **לחקור חיוב** — חפש לפי מזהה לקוח / נסיעה / תשלום → בדוק סטטוס (הושלם = הכסף נלקח, נכשל = לא נלקח כסף) ושיטה
- **להחזיר נסיעה** — מצא את שורת _חייב_ עבור הנסיעה → תפריט השורה → _החזר_ → אשר → מופיעה שורת _החזר_ זוגית, המקורית משתנה ל_הוחזר_
- **לבצע ביקורת יומית** — הגדר טווח תאריכים = היום → סנן סטטוס = הושלם → בדוק את הסכומים הכוללים
- **למצוא כישלונות לנסות שוב** — סנן סטטוס = נכשל → צור קשר עם הלקוחות לגבי ניסיון חוזר / שיטה חלופית
- **להתאים עם הספק** — טווח תאריכים + סוג = טעינה/חיוב + שיטה = ספק כרטיס → ייצא ובדוק מול דוח הספק

## טיפים

- **ממתין לא שווה נכשל** — עסקאות ממתינות מחכות לוובהוק של הספק; בדוק ב-[וובהוקים ממתינים](pending-webhooks.md) אם שורה נשארת ממתינה זמן רב מדי
- **עסקאות יתרה לא ניתנות להחזר בכרטיס** — המערכת מפנה אותך לדיאלוג הנכון; אל תנסה ליצור עסקאות נגדיות ידנית
- **המקור נשאר לאחר החזר** — החזרים מוסיפים שורה זוגית, הם לא מוחקים את החיוב; שתי השורות נשמרות בהיסטוריה לביקורת
- **סימן הסכום מראה כיוון** — `+` (ירוק) הוא כסף ללקוח; `−` (אדום/כהה) הוא כסף מהלקוח
- **שמות הספקים חשובים לתמיכה** — כשאתה מעלה פנייה לספק התשלומים, העתק את מזהה התשלום ושם הספק מעמודת השיטה
- **הקישור ניתן לשיתוף** — העתק תצוגה מסוננת (למשל _חיובי כרטיס נכשלו של אתמול_) ושלח למחלקת הכספים או למניעת הונאות
