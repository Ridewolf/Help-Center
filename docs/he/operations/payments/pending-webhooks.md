# וובהוקים ממתינים

דף הוובהוקים הממתינים (`/payments/pending-webhooks`) מציג עסקאות תשלום שנתקעו במצב **ממתין** כי אישור הוובהוק מספק התשלום עדיין לא התקבל.

כל שורה היא תשלום ששלחנו לספק אך לא קיבלנו עבורו קריאת חזרה סופית. השתמש בדף זה כ**תור תשלומים תקועים**: סרוק שורות ישנות, זיהה את הספק שמאחר, והעבר לטיפול גבוה יותר.

הרשאה נדרשת: **תשלומים** (`m1n2p3`).

## מה אתה רואה

כאשר לקוח משלם:

1. לוח המחוונים שולח בקשת תשלום ל**ספק** (Stripe, שער תשלום וכו') — נוצר _Payment Intent_
2. הספק מעבד את העסקה באופן אסינכרוני ושולח **וובהוק** עם הסטטוס הסופי (`succeeded`, `failed` וכו')
3. לוח המחוונים מקבל את הוובהוק ומשנה את סטטוס ה[תשלום](payments.md) מ_ממתין_ ל_הושלם_ / _נכשל_

שורות ב**וובהוקים ממתינים** הן שלב 2 תלוי — הספק ניגש אך לא חזר עם תגובה. בדרך כלל הוובהוק מגיע תוך שניות, לפעמים דקות. כל דבר שיותר מ~30 דקות הוא חשוד; מעל שעתיים כנראה תקלה בצד הספק או במקבל הוובהוקים שלנו.

## מסננים

| מסנן           | סוג     | הערות                                                                             |
| -------------- | ------ | --------------------------------------------------------------------------------- |
| **ספק**        | טקסט   | חיפוש לפי שם ספק (למשל `stripe`)                                           |
| **ישן מ-**     | בחירה  | `הכל` / `5` / `15` / `30` / `60` / `120` דקות — הצג רק שורות ישנות יותר מזה |

השתמש ב_ישן מ-30 דקות_ או _60 דקות_ כמסנן ניטור יומי — וובהוקים טריים הם רעש.

## עמודות

| עמודה                | ניתן למיין? | תוכן                                                               |
| --------------------- | --------- | --------------------------------------------------------------------- |
| **נוצר בתאריך**      | ✓         | מתי נוצר ה-Payment Intent                                         |
| **גיל**               | ✓         | דקות מאז יצירה — מקודד בצבע (ראה למטה)                            |
| **ספק**               | —         | ספק התשלום שאליו נשלח ה-Payment Intent                            |
| **מזהה Payment Intent** | —         | מזהה הספק עבור ה-Payment Intent — העתק בעת העברה לטיפול          |
| **סטטוס**             | —         | סטטוס בצד הספק (גולמי) — בדרך כלל `requires_action` / `processing`                      |
| **מזהה הזמנה**        | —         | מזהה הזמנה/תשלום פנימי שלנו                                       |

### קידוד צבע לפי גיל

עמודת **גיל** משנה צבע ככל שהשורה מתיישנת, כדי שתוכל לסרוק ולמיין במהירות:

| גיל             | צבע    | מה לעשות                                     |
| -------------- | ------ | ---------------------------------------------- |
| **< 30 דקות**  | אפור   | רגיל; התעלם                                 |
| **30–120 דקות** | צהוב   | שווה בדיקה; בדוק את לוח המחוונים של הספק |
| **> 120 דקות** | אדום   | כנראה תקלה — העבר לטיפול                     |

## פעולות שורה

תפריט פעולות קטן מימין לכל שורה:

| פעולה           | מה היא עושה                                            |
| --------------- | ------------------------------------------------------- |
| **הצג לקוח**   | פתח את פרופיל הלקוח המשויך ל-Payment Intent זה       |

(פעולת _הצג פרטי תשלום_ קיימת בקוד אך מושבתת זמנית כי דף פרטי התשלום הוסר — יחזור בעתיד.)

## תרחישי עבודה טיפוסיים

- **ניטור יומי** — הגדר _ישן מ- = 30 דקות_ → הדף צריך להיות ריק רוב הזמן → אם לא, סרוק את עמודת הספק
- **תקלה בספק יחיד** — ראה שורות רבות מאותו ספק צובעות צהוב/אדום בו זמנית → בדוק את דף הסטטוס של הספק → פנה לתמיכה עם כמה _מזהי Payment Intent_ מהטבלה
- **בעיה בלקוח יחיד** — שורה או שתיים ישנות → _הצג לקוח_ → בדוק את [פעילות / תשלומים](../customers/client-detail.md) של הלקוח → אמור להם לנסות שוב או להשתמש בשיטה אחרת
- **בעיה במקבל הוובהוקים** — ספקים רבים הופכים לאדומים בו זמנית ללא תקלה בצד הספק → הבעיה היא במקבל הוובהוקים שלנו; העבר לטיפול צוות ההנדסה

## מתי שורה נעלמת

שורה עוזבת דף זה כאשר הוובהוק מגיע — סטטוס התשלום משתנה ל_הושלם_ או _נכשל_ ברשימת [תשלומים](payments.md) הראשית. השורה לא "מתיישנת" מעצמה; רק וובהוק מנקה אותה.

אם יש לך **וובהוקים תקועים ישנים מיום** שלא נעלמים, זו תקלה שיש להעביר לטיפול — ללוח המחוונים אין כפתור "השלמה בכוח" ידני מטעמי בטיחות (השלמה ידנית שגויה יוצרת בלגן חשבונאי קשה לתיקון).

## טיפים

- **העתק את מזהה Payment Intent** כשאתה מעביר לטיפול לספק — זה המזהה היחיד שהם מזהים
- **מיון לפי גיל** (החדש ביותר ראשון → הישן ביותר ראשון) נותן לך תור מיון: בראש הרשימה הממוינת נמצא העבודה הדחופה
- **דף ריק הוא המטרה** — וובהוקים ממתינים צריכים להיות ריקים (או כמעט ריקים) ביום רגיל; כל שורה היא עבודה שיש לעשות
- **חיפוש ספק רופף** — התאמות חלקיות עובדות (`stri` מתאים ל-`stripe`)
- **הדף לא מתעדכן אוטומטית** — השתמש בכפתור רענון או טען מחדש את הדף כשאתה ממיין באופן פעיל
