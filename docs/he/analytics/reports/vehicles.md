# ניתוחים — רכבים

דף ניתוחי הרכבים (`/analytics/vehicles`) הוא **לוח מחוונים לבריאות הצי**: כמה רכבים יש לך, איך הם מתפקדים, מצב הסוללה, בעיות ותקלות לפי סוג ואזור.

שונה מ-[רשימת הרכבים](../../operations/fleet/vehicles.md) — זו התצוגה התפעולית לפי יחידה; כאן מדובר ב**מדדי צי מצטברים** לתקופה נבחרת.

## טווח זמן

**סרגל טווח תאריכים** ממוקם בראש. גרפי מגמה משתמשים בטווח המלא; סיכומי מצב / ספירות משקפים את **המצב הנוכחי** (סוף הטווח).

## חלקים

שבעה חלקים, מלמעלה למטה:

### 1. סקירה כללית

הרכב הצי ברמה העליונה.

| מדד ביצועים (KPI) | מה הוא מציג                                                      |
| ----------------- | ------------------------------------------------------------------ |
| **סה"כ**         | כל הרכבים הרשומים                                               |
| **פעילים**        | זמינים להשכרה לרוכבים כרגע                                      |
| **לא בשימוש**     | עומדים ללא שימוש (יכולים להיות זמינים או בשימוש נמוך)          |
| **מחוץ לשירות**  | בתחזוקה / באחסון / לא מוכנים — לא מייצרים הכנסות               |
| **אבודים / גנובים** | סטטוס = גנוב, או לא מחוברים לרשת זמן ממושך                   |

השתמש בחלק זה ככותרת ראשית לתמונה הכוללת של הצי.

### 2. ביצועים

כמה טוב הצי שלך **מייצר הכנסות** עבורך.

| מדד ביצועים (KPI)     | מה הוא מציג                                              |
| --------------------- | ---------------------------------------------------------- |
| **רכבים מרוויחים**    | רכבים שסיימו לפחות נסיעה אחת בתקופה                      |
| **רכבים לא פעילים**  | רכבים פעילים ללא נסיעות (בזבוז)                          |
| **נסיעות לרכב**       | ממוצע נסיעות לרכב בטווח                                  |
| **שיעור שימוש**       | שעות השכרה / שעות זמינות (מדד תעשייתי: 5-15%)           |

רכבים לא פעילים בזמן שהם פעילים הם הגרועים ביותר — גורמים להוצאות תפעוליות ללא תועלת.

### 3. סוללה

בריאות הסוללה בצי.

| מדד / גרף       | מה הוא מציג                                                                   |
| ---------------- | ------------------------------------------------------------------------------- |
| **רמת ממוצע**   | אחוז סוללה ממוצע בכל הרכבים כרגע                                            |
| **קריטי**       | ספירה מתחת לסף הקריטי (10-20%)                                               |
| **מגמת ממוצע**  | ממוצע סוללה לאורך הטווח — ירידה = החלפות לא עומדות בקצב                   |
| **התפלגות**    | היסטוגרמה של רכבים לפי טווח סוללה (0-20 / 20-40 / 40-60 / 60-80 / 80-100)   |
| **החלפות**     | ספירת פעולות החלפת סוללה בטווח                                               |

אם הממוצע יורד והקריטי עולה, צוות השטח מפגר — יש לתזמן החלפות נוספות.

### 4. בעיות

התראות ועניינים תפעוליים שהועלו נגד הצי.

| מדד             | מה הוא מציג                                                  |
| --------------- | -------------------------------------------------------------- |
| **התראות**     | סך כל ההתראות שהועלו בטווח                                  |
| **סוגי התראות** | פירוט לפי סוג (סוללה / חיבוריות / מכני / וכו')               |
| **קריטיות**    | התראות ברמת חומרה קריטית                                    |
| **תחזוקה**    | רכבים במצב תחזוקה כרגע                                      |
| **מנותקים**   | רכבים ש-IoT שלהם לא דיווח זמן ממושך מהסף                     |

שלב חלק זה עם [ניתוח אירועים אחרונים](events.md) לתצוגה לפי אירוע.

### 5. מגמות

גרף סדרות זמן המציג כיצד מספר ה-**פעילים** השתנה לאורך הטווח. ירידה בדרך כלל מצביעה על שינוי סטטוס המוני (מעבר לתחזוקה, מזג אוויר, קריאה חוזרת).

### 6. לפי סוג

פירוט לפי **סוג רכב** (קורקינט / אופניים / אופניים חשמליים / וכו'). לכל סוג: ספירה, יחס הכנסות, שיעור שימוש, שיעור התראות.

אם סוג אחד שולט בשיעור ההתראות, הבעיה היא ב**דגם** — לא בצוות התפעול.

### 7. לפי אזור

פירוט לפי **אזור**. לכל אזור: ספירת רכבים, שיעור שימוש, שיעור בעיות.

אזורים עם שימוש נמוך ומלאי גבוה = **הזדמנות לאיזון מחדש** (ראה גם [ניתוח איזון מחדש](../../operations/rebalance/runs.md)).

## תרחישי עבודה טיפוסיים

- **סקירת צי שבועית** — תמונת מצב כללית → ביצועים (מגמת שימוש) → סוללה (האם יש עלייה בספירת קריטיות?) → בעיות (קפיצות בהתראות) → מגמות (ירידה לא מוסברת בפעילים?)
- **ניקוי רכבים לא פעילים** — ביצועים → ספירת לא פעילים → אם גדלה, מצא את הרכבים הבעייתיים דרך [רשימת הרכבים](../../operations/fleet/vehicles.md) ובדוק סטטוס / מיקום
- **חירום סוללה** — חלקת סוללה → עלייה בקריטיות + ירידה בממוצע → דחוף את צוות השטח
- **זיהוי דגם בעייתי** — חלק לפי סוג → איזה סוג עם שיעור ההתראות הגרוע ביותר → שקול להוציא מהשימוש / לנהל משא ומתן עם היצרן
- **איזון מחדש** — חלק לפי אזור → אזורים עם שימוש נמוך ומלאי גבוה → תזמן הפצה מחדש
- **תכנון לפני משמרת** — מגמות + דפוסים מ-[אירועים](events.md) → אילו ימים / שעות זקוקים ליותר צוות שטח?

## טיפים

- **פעיל + במצב סרק + מחוץ לשירות + אבוד/גנוב = סך הכל** — כאשר החישוב לא מסתדר, הסטטוסים באמצע מעבר; רענן או בחר תאריך יציב
- **פעיל ≠ מרוויח** — רכב הוא "פעיל" אם ניתן היה לשכור אותו; "מרוויח" אומר שהוא אכן שימש. השווה בין השניים
- **שיעור ניצול מעל 25% הוא לא בריא** — הרוכבים לא מוצאים רכבים כשהם רוצים; שקול להגדיל את המלאי באזור זה
- **שיעור ניצול מתחת ל-5% הוא עומס מת** — עלות שמירת הרכב בשירות עולה על ההכנסות שלו; איזן מחדש או הסר
- **סוללה קריטית + מגמה ממוצעת** — שניהם יחד הם מערכת האזהרה המוקדמת שלך; אחד לבד הוא רעש
- **אבוד / גנוב הוא מצב דביק** — דורש שינוי סטטוס ידני כדי לנקות; השב "גנוב" לפני שאתה חוגג את החזרתו
- **לפי סוג ולפי אזור יחד** — לפעמים סוג נכשל רק באזור אחד (אי התאמת שטח); החיתוך החוצה מגלה זאת
