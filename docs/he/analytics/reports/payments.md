# ניתוחים — תשלומים

דף ניתוחי התשלומים (`/analytics/payments`) הוא **לוח המחוונים הפיננסי** שלך: מדדי ביצועים מרכזיים וגרפים על כסף שנכנס (הפקדות), כסף שיוצא (החזרים), כסף שנגבה (חיובים), ומצב מערכת התשלומים שלך.

שונה מ-[היסטוריית תשלומים](../../operations/payments/payments.md), שהיא יומן עסקאות פרטני — דף זה **מאוגד** על פני טווח תאריכים כדי שתוכל לזהות מגמות, דליפות וחריגות.

הרשאה נדרשת: **הצגת ניתוחי תשלומים** (`w7x8y9`).

## טווח זמן

**סרגל טווח תאריכים** ממוקם בראש הדף. כל מדד וגרף מתחשבים בטווח זה:

- בחר טווח מוגדר מראש (היום, 7 / 30 / 90 הימים האחרונים, החודש / החודש שעבר) או טווח מותאם אישית
- תג השוואה מתחת לכרטיסי המדדים מציג "לעומת התקופה הקודמת" — כשאתה בוחר _7 הימים האחרונים_, ההשוואה היא 7 הימים שלפני כן
- הטווח נשמר לאורך כל המפגש: אם תנווט החוצה וחזור, הטווח שלך יישמר

## חלקים

הדף מאורגן ל-**שישה חלקים**, שכל אחד מתמקד בזווית שונה של התשלומים:

### 1. זרימה

התמונה הגדולה — כסף נכנס לעומת כסף יוצא.

| מדד ביצוע מרכזי | מה הוא מודד                                                                                                              |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **הפקדות**       | כסף שהועבר לארנקים בטווח זה (ידני + ספק)                                                                               |
| **החזרים**       | כסף שהוחזר ללקוחות; מלווה בתג _שיעור החזרות_ (החזרים / חיובים)                                                        |
| **חיובים**       | כסף שנגבה מלקוחות (נסיעות, קנסות). כולל **מסנן תגיות** כדי למקד לתג לקוח ספציפי (למשל _VIP_)                          |
| **זרימה נטו**    | הפקדות − החזרים; חיובי = יתרת הארנק שלך גדלה                                                                            |

### 2. איכות

בריאות האינטגרציה עם ספק התשלומים שלך.

| מדד ביצוע מרכזי     | מה הוא מודד                                                                                                              |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **שיעור הצלחה**    | עסקאות שהושלמו / כל הניסיונות — מספר האמינות הראשי שלך                                                                  |
| **נכשלו**          | ספירת עסקאות שנכשלו בטווח                                                                                               |
| **ממתינים**        | ספירת עסקאות שעדיין ממתינות (השוואה עם [וובהוקים ממתינים](../../operations/payments/pending-webhooks.md))               |
| **הוחזרו**         | ספירת חיובים שהוחזרו                                                                                                    |
| **סיבות לכישלון**  | גרף המפרט את הכישלונות לפי סיבה (דחייה / 3DS / רשת / וכו׳)                                                            |

קפיצה ב-_נכשלו_ + סיבה מסוימת השולטת בגרף = תקלה או בעיית אינטגרציה שיש לטפל בה.

### 3. יתרה

מצב הכספים שבידי המפעיל (ארנקים של הרוכבים) בסוף הטווח.

| מדד ביצוע מרכזי   | מה הוא מציג                                                                |
| ----------------- | -------------------------------------------------------------------------- |
| **יתרה**          | סכום כל היתרות החיוביות — כסף שאתה מחזיק עבור הרוכבים                   |
| **חוב**           | סכום כל היתרות השליליות — כסף שהרוכבים חייבים לך                       |
| **יתרה ממוצעת**   | יתרה ממוצעת לכל לקוח פעיל                                                |
| **משתמשים**       | ספירת לקוחות עם יתרה שאינה אפס                                          |
| **גרף דליים**     | היסטוגרמה של לקוחות לפי גודל היתרה (למשל 0–10 / 10–50 / 50–100 / 100+)  |

השתמש ב-_חוב_ כאינדיקטור לעיכוב גבייה — חוב גדול מצביע על קנסות רבים או חיובים שנכשלו שדורשים מעקב.

### 4. דפוסים

דפוסי התנהגות של הפקדות הרוכבים — שימושי לשיווק / מוצר.

- **היסטוגרמת גודל הפקדות** — איך הרוכבים מחלקים את ההפקדות שלהם לפי סכומים. המצביע של ההיסטוגרמה (הגודל הנפוץ ביותר) הוא ברירת המחדל להנחיות שלך
- **הפקדות לפי שעה** — מתי במהלך היום הרוכבים מפקידים. שיאים בדרך כלל תואמים לשיאי נסיעות (נסיעות לעבודה, ערבי סופ״ש)

### 5. שיטות

פירוט בטבלה לפי **שיטת תשלום / ספק**.

- עמודות: שיטה (כרטיס / יתרה / ארנק / וכו׳), סכום כולל, ספירה, עסקה ממוצעת, שיעור הצלחה
- שימושי לזיהוי ספקים חלשים (שיטה אחת עם שיעור הצלחה נמוך היא הקישור החלש שלך)

### 6. משתמשים

תצוגת קוהורט של לקוחות — מי משלם לך.

| מדד ביצוע מרכזי   | מה הוא מודד                                                                   |
| ----------------- | ------------------------------------------------------------------------------ |
| **משלמים ייחודיים** | לקוחות נפרדים ששילמו בטווח                                                    |
| **משלמים חדשים**    | לקוחות ששילמו לראשונה בטווח זה                                               |
| **משלמים חוזרים**   | לקוחות ששילמו יותר מפעם אחת בטווח זה                                        |
| **משלמים מובילים**  | טבלה של הלקוחות שמשלמים הכי הרבה עם שם, סכום, ספירת נסיעות, קישור לפרופיל |

## זרימות עבודה טיפוסיות

- **סקירה שבועית** — הגדר מראש _7 הימים האחרונים_ → גלול בכל קטע פעם אחת. כל דבר מחוץ לסרט השוואה (▲ או ▼ גדולים) דורש בדיקה מעמיקה יותר
- **בדיקת תקלות לאחר אירוע** — הגדר טווח תאריכים ליום האירוע → קטע איכות → תרשים סיבות כשל → השווה עם [היסטוריית תשלומים](../../operations/payments/payments.md) עבור העסקאות בפועל
- **ניתוח מעמיק של תגיות** — כרטיס חיובים → סינון תגיות → בחר תגית כמו _VIP_ → מדד החיובים מציג רק את הקבוצה הזו; השווה למספר החיובים הכולל לשם שיתוף מהיר
- **דחיפת גבייה** — קטע יתרות → _חוב_ → אם גדל, חקור לקוחות בודדים דרך רשימת הלקוחות המסוננת לפי יתרה שלילית
- **תמחור שיווקי** — דפוסים → היסטוגרמת גודל הטעינה → הגדר את הטעינה המוצעת באפליקציה לדלי הפופולרי ביותר

## טיפים

- **סרט ההשוואה שימושי יותר מהמספר המוחלט** — המספר המוחלט של ההכנסות תלוי בגודל החברה; שינוי באחוזים מראה אם המצב משתפר
- **טווח תאריכים דביק** — טווח התאריכים האחרון שבחרת נשמר בניווט; אם עמית משתף קישור עם טווח שונה, הוא גובר
- **סינון תגיות מוגבל לחיובים בלבד** — כדי לראות טעינות לפי תגית יש להשוות עם רשימת הלקוחות
- **תרשים סיבות הכשל הוא לוח הניקוד של הספק שלך** — הופעת קטגוריית סיבה חדשה פתאומית בדרך כלל מצביעה על שינוי בהגדרות הספק
- **תזרים נטו חיובי ≠ רווח** — זהו סכום הארנק, לא הכנסות; אינו כולל החזרים שתבצע מאוחר יותר או יתרות לא מוסדרות
- **יתרה ממוצעת × משתמשים ≠ סכום הארנק** — סכום הארנק הוא סכום החיוביים; אם רבים מהרוכבים בחוב, הממוצע יכול להיות נמוך מ-סכום הארנק / משתמשים
