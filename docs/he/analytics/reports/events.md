# ניתוחים — אירועים אחרונים

דף ניתוח האירועים (`/analytics/events`) הוא **לוח האירועים** שלך: כל אירוע משמעותי במערכת, ברכב, במשתמש או באזור במשך תקופה נבחרת, עם מונים KPI, דפוסים לאורך זמן, ופיד חיפוש בתחתית.

שונה מ[לוח ההתראות](../../features/ux/notifications.md) (זמן אמת, אירוע-אירוע) — דף זה הוא **מצטבר והיסטורי**, שימושי לזיהוי מגמות ולסקירת אירועים לאחר התרחשותם.

הרשאה נדרשת: **הצג אירועים אחרונים** (`s1t2u3`).

## טווח זמן ומסננים

**סרגל טווח תאריכים** נמצא בראש — כל מדד וגרף מתחשבים בו. ארבעה מסננים נוספים מצמצמים את התצוגה:

| מסנן           | אפשרויות                                                               |
| --------------- | ----------------------------------------------------------------------- |
| **חומרה**      | `critical` / `warning` / `info` (בחירה מרובה)                                       |
| **סוג**         | `error` / `offline` / `battery` / `payment` / `support` / `maintenance`                                   |
| **סוג מקור**    | `vehicle` / `user` / `zone` / `system`                                              |
| **סטטוס**      | `open` / `resolved` / `dismissed`                                                   |

כל המסננים משולבים עם AND. כתובת ה-URL משקפת כל הגדרה — שתף קישור והעמית שלך יראה את אותו החיתוך בדיוק.

## חלקים

לעמוד יש **חמישה חלקים**:

### 1. סיכום

ארבעה כרטיסי מדדים מסכמים ספירות אירועים:

| KPI          | מה הוא מציג                                               |
| ------------ | ----------------------------------------------------------- |
| **סה"כ**    | סך כל האירועים בטווח                                      |
| **קריטי**    | ספירה עם `severity = critical` — המספר שחייב בדיקה       |
| **אזהרה**   | ספירה עם `severity = warning`                             |
| **מידע**    | ספירה עם `severity = info` — בדרך כלל רעש אלא אם יש זינוק |

כל כרטיס נושא תג השוואה "לעומת התקופה הקודמת".

### 2. לפי סוג

גרף המפרק אירועים לפי **סוג**:

- **שגיאה** — כשלי מערכת / אינטגרציה
- **מנותק** — מכשירי IoT שאינם פעילים
- **סוללה** — התראות על סוללה חלשה / ריקה / חריגה
- **תשלום** — דחיות, בעיות שער תשלום
- **תמיכה** — זינוקים בכרטיסים / שיחות
- **תחזוקה** — אירועים הקשורים לשירות

זינוקים בסוג יחיד הם בדרך כלל נקודת ההתחלה שלך לחקירה.

### 3. דפוסים

שני גרפי סדרות זמן:

- **לפי יום** — אירועים ביום לאורך הטווח (מציג מחזורים שבועיים)
- **לפי שעה** — אירועים בשעה ביום לאורך כל הטווח (מציג שיאים יומיים)

### 4. מקורות מובילים

רשימת **מקורות מובילים** היוצרים אירועים — בדרך כלל רכבים או אזורים עם כמות אירועים לא פרופורציונלית.

כל פריט כולל את המקור (קישור לעמוד הפרטים שלו), ספירת האירועים, והחומרה / הסוג הדומיננטיים.

כאן תמצא את ה**הרכב שהתריע כל השבוע** או את ה**אזור עם בעיות סוללה**.

### 5. פיד

פיד גלילה של אירועים בודדים התואמים למסננים הנוכחיים. כל שורה מציגה:

- אייקון חומרה (צבוע)
- סוג האירוע + תווית מקור
- תיאור קצר
- חותמת זמן
- כדור סטטוס

לחץ על פריט בפיד כדי לנווט לישות הקשורה (רכב, לקוח, נסיעה, כרטיס) אם רלוונטי.

## תרחישי עבודה טיפוסיים

- **סקירה יומית בבוקר** — הגדרת מראש _24 השעות האחרונות_ → חומרה = קריטי → סריקה; כל מה שבאדום מקבל תשומת לב לפני פתיחת שאר לוח המחוונים
- **מיון מקורות מובילים** — חלק מקורות מובילים → לחץ על רכב שמופיע שוב ושוב → תקן או הסקלה במקור
- **זיהוי דפוסים** — גרפי דפוסים; יום או שעה חריגים מציגים שינוי (פריסה, מזג אוויר, הפסקה)
- **סקירת אירוע לאחר התרחשות** — בחר יום → חומרה = קריטי → השווה פיד עם לשונית התראות [רכב](../../operations/fleet/vehicle-detail.md) או מדור איכות [ניתוחי תשלומים](payments.md) בהתאם לסוג
- **מעבר ניקוי** — סטטוס = פתוח → פתרון קבוצתי של פריטים מיושנים (אתה עושה זאת מדפי המקור, לא כאן, אבל תמצא אותם כאן)

## טיפים

- **קריטי קודם כל** — התחל עם `severity = critical`; אזהרות ומידע לרוב נפתרים מעצמם
- **הסוג הוא הבלש שלך** — ברגע שיש זינוק, סנן לפי הסוג הדומיננטי כדי לצמצם רעש
- **מקורות מובילים הם זהב** — רכב אחד בראש רשימת המקורות בדרך כלל מסביר 30-50% מכל האירועים
- **הצטברויות מול גולמי** — דף זה מצטבר; לעסקאות / התראות בפועל עבור עמוד תחום המקור
- **מסננים דביקים** — ההגדרות שלך שורדות ניווט; נקה אותן כשאתה מעביר את ה-URL למישהו אחר
- **סטטוס `open` ≠ התראת IoT לא פתורה** — סטטוס כאן הוא סטטוס _רשומת האירוע_; ההתראה הבסיסית ייתכן ונפתרה במכשיר בעוד האירוע עדיין פתוח במערכת
