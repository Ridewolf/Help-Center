# Πελάτης — Δημιουργία & Επεξεργασία

Δύο διευθύνσεις URL:

- **Δημιουργία** — `/clients/create` — εγγραφή νέου πελάτη χειροκίνητα (σπάνια· οι περισσότεροι πελάτες εγγράφονται μόνοι τους)
- **Επεξεργασία** — `/clients/:id/edit` — ενημέρωση προσωπικών στοιχείων και κατάστασης υπάρχοντος πελάτη

Και οι δύο προσπελαύνονται από τη [λίστα Πελατών](clients.md) (κουμπί `+ Δημιουργία` πάνω δεξιά) ή από τη [σελίδα λεπτομερειών πελάτη](client-detail.md) (_Ενέργειες → Επεξεργασία πελάτη_).

Δικαιώματα:

- **Δημιουργία** — `Clients` (`e4f5h6`) + υπο-δικαίωμα σχετικό με τη δημιουργία
- **Επεξεργασία** — `Clients` (`e4f5h6`) + το υπο-δικαίωμα `edit`

## Πότε να χρησιμοποιήσετε

Οι περισσότεροι πελάτες σας **εγγράφονται μόνοι τους** μέσω της εφαρμογής Rider App — σπάνια θα τους δημιουργήσετε εσείς στον Πίνακα ελέγχου.

Η χειροκίνητη δημιουργία προορίζεται για:

- **Δοκιμαστικούς λογαριασμούς** — εσωτερικός έλεγχος ποιότητας, χρήστες επίδειξης
- **VIP / εταιρικούς** — λογαριασμοί που πρέπει να υπάρχουν πριν ο αναβάτης κατεβάσει την εφαρμογή
- **Εγγραφή από χειριστή** — εκδηλώσεις / συνεργασίες όπου το προσωπικό εγγράφει εκ μέρους του αναβάτη

Για οτιδήποτε άλλο, αφήστε την εφαρμογή να χειριστεί την εγγραφή και χρησιμοποιήστε **Επεξεργασία** όταν χρειάζεται διόρθωση στοιχείων επικοινωνίας ή αλλαγή κατάστασης.

## Διάταξη

Μία κάρτα με κάθετη φόρμα, χωρίς πλαϊνή μπάρα Οδηγού Πεδίου (διαφορετικό από τη φόρμα Οχήματος).

## Πεδία — Δημιουργία

Επτά πεδία συνολικά. Όλα υποχρεωτικά.

| Πεδίο               | Επικύρωση                                                                                                              |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **Όνομα**            | 1–100 χαρακτήρες                                                                                                       |
| **Επώνυμο**          | 1–100 χαρακτήρες                                                                                                       |
| **Email**            | Τυπική μορφή email (`name@domain.tld`); πρέπει να είναι μοναδικό ανάμεσα στους πελάτες                                  |
| **Τηλέφωνο**         | Διεθνής μορφή που ξεκινά με `+` (π.χ. `+373 60 123 456`); μόνο ψηφία, κενά, παύλες, παρενθέσεις                        |
| **Κωδικός πρόσβασης**| **Τουλάχιστον 12 χαρακτήρες**, πρέπει να περιέχει **κεφαλαίο γράμμα, πεζό γράμμα, ψηφίο και ειδικό χαρακτήρα**           |
| **Επιβεβαίωση κωδικού** | Πρέπει να ταιριάζει ακριβώς με τον κωδικό πρόσβασης                                                                   |
| **Κατάσταση**        | Αρχική κατάσταση: `Ενεργό` / `Ανενεργό` / `Αποκλεισμένο` / `Παγωμένο` / `Εγγραφή` (προεπιλογή _Ενεργό_)               |

Η επικύρωση εκτελείται κατά την αποθήκευση και ενσωματωμένα όταν φεύγετε από το πεδίο. Τα σφάλματα εμφανίζονται με κόκκινο κάτω από το πεδίο.

### Κανόνες κωδικού πρόσβασης

Η απαίτηση για τον κωδικό είναι η αυστηρότερη. Ο Πίνακας ελέγχου απορρίπτει οποιονδήποτε κωδικό δεν πληροί και τους τέσσερις ελέγχους:

- ≥ 12 χαρακτήρες
- ≥ 1 κεφαλαίο γράμμα (A–Z)
- ≥ 1 πεζό γράμμα (a–z)
- ≥ 1 ψηφίο (0–9)
- ≥ 1 ειδικός χαρακτήρας (π.χ. `!@#$%^&*`)

Μετά την αποθήκευση, ο πελάτης θα χρησιμοποιεί αυτόν τον κωδικό (μαζί με το τηλέφωνο ή το email) για να συνδεθεί στην εφαρμογή Rider App. Ενημερώστε τον πελάτη μέσω επαληθευμένου καναλιού — μην επικολλάτε ποτέ κωδικούς σε συνομιλίες που δεν είναι κρυπτογραφημένες end-to-end.

### Κατάσταση (κατά τη δημιουργία)

| Τιμή            | Χρήση                                                                                  |
| --------------- | ------------------------------------------------------------------------------------ |
| **Ενεργό**      | Προεπιλογή — ο πελάτης μπορεί να χρησιμοποιήσει αμέσως την υπηρεσία                   |
| **Ανενεργό**    | Δημιουργημένο αλλά όχι ακόμη ενεργό (θα αλλάξει σε Ενεργό αργότερα)                  |
| **Αποκλεισμένο**| Προ-αποκλεισμένο (σπάνιο — συνήθως χρησιμοποιείται όταν ξαναδημιουργείται λογαριασμός μετά από απάτη) |
| **Παγωμένο**    | Ο λογαριασμός έχει παγώσει                                                           |
| **Εγγραφή**    | Η εγγραφή βρίσκεται σε εξέλιξη (χρησιμοποιείται μόνο σε ενσωμάτωση με εξωτερική ροή)  |

## Πεδία — Επεξεργασία

Η επεξεργασία αποκρύπτει τα πεδία κωδικού (οι κωδικοί επαναφέρονται αλλού) και προσθέτει **Ετικέτες**.

| Πεδίο          | Σημειώσεις                                                                    |
| -------------- | ----------------------------------------------------------------------------- |
| **Όνομα**      | Προ-συμπληρωμένο, ίδια επικύρωση με τη Δημιουργία                            |
| **Επώνυμο**    | Προ-συμπληρωμένο, ίδια επικύρωση με τη Δημιουργία                            |
| **Email**      | Προ-συμπληρωμένο· αλλαγή μπορεί να διακόψει τη σύνδεση του πελάτη μέχρι να επαληθευτεί ξανά |
| **Τηλέφωνο**   | Προ-συμπληρωμένο· ίδια προειδοποίηση με το Email                            |
| **Ετικέτες**   | Πολλαπλή επιλογή· ετικέτες που εφαρμόζει ο χειριστής για ομαδοποίηση και φιλτράρισμα |
| **Κατάσταση**  | Προ-συμπληρωμένη με την τρέχουσα κατάσταση· ίδια λίστα επιλογών             |

## Αποθήκευση / Ακύρωση

- **Ακύρωση** (ή βέλος πίσω) — απορρίπτει μη αποθηκευμένες αλλαγές και επιστρέφει στην προηγούμενη σελίδα
- **Αποθήκευση** — επικυρώνει τη φόρμα και δημιουργεί / ενημερώνει τον πελάτη. Εμφανίζεται ειδοποίηση επιτυχίας· τα σφάλματα σε επίπεδο πεδίου επισημαίνονται με κόκκινο

Αν η επικύρωση αποτύχει (λείπει πεδίο, κανόνες κωδικού, διπλότυπο email, μορφή τηλεφώνου), η σελίδα παραμένει ανοιχτή με το προβληματικό πεδίο περιγραμμένο.

## Δημιουργία vs Επεξεργασία — διαφορές

| Πτυχή             | Δημιουργία                                             | Επεξεργασία                                          |
| ------------------ | ------------------------------------------------------- | ---------------------------------------------------- |
| Πεδία κωδικού      | Παρόντα και υποχρεωτικά                                | Κρυφά                                               |
| Ετικέτες           | Δεν υπάρχουν στη φόρμα (ορίζονται αργότερα μέσω Επεξεργασίας ή της λίστας/λεπτομέρειας) | Παρόντα                                              |
| Κατάσταση          | Κενό → προεπιλεγμένο _Ενεργό_                          | Προ-συμπληρωμένο με την τρέχουσα κατάσταση         |
| Email / Τηλέφωνο   | Κενό                                                   | Προ-συμπληρωμένο — η αλλαγή τους μπορεί να απαιτήσει επαλήθευση εκ νέου |
| Μετά την αποθήκευση | Ανακατεύθυνση στη λεπτομέρεια του νέου πελάτη          | Ανακατεύθυνση πίσω στη λεπτομέρεια πελάτη            |
| Καταχώρηση στο αρχείο δραστηριότητας | "Πελάτης δημιουργήθηκε από _όνομα χειριστή_"          | "Πελάτης επεξεργάστηκε από _όνομα χειριστή_" με διαφορές πεδίων |


Και οι δύο ροές γράφουν στο [Αρχείο δραστηριότητας](client-detail.md#καρτέλα-δραστηριότητας) του πελάτη.

## Τυπικές ροές εργασίας

- **Δημιουργία VIP** — `+ Δημιουργία` στη λίστα → συμπλήρωση ονόματος, πραγματικού email, πραγματικού τηλεφώνου, ισχυρού κωδικού, κατάσταση _Ενεργό_ → αποθήκευση → ειδοποίηση του rider με τα διαπιστευτήρια
- **Διόρθωση ορθογραφικού λάθους** — γραμμή λίστας → μενού γραμμής → _Επεξεργασία_ → διόρθωση πεδίου → αποθήκευση (η αλλαγή εμφανίζεται στο Αρχείο δραστηριότητας με διαφορές)
- **Ενσωμάτωση εταιρικού παρτίδας** — δημιουργία μέσω API με script (αυτή η φόρμα είναι για μεμονωμένες περιπτώσεις); χρησιμοποιήστε την Επεξεργασία αργότερα για να εφαρμόσετε ετικέτες ειδικές για την εταιρεία
- **Αλλαγή τηλεφώνου μετά από αλλαγή συσκευής** — Επεξεργασία → ενημέρωση Τηλεφώνου → αποθήκευση → ο πελάτης θα χρειαστεί να επαληθευτεί ξανά στην επόμενη σύνδεση (ανάλογα με τους κανόνες backend)

## Συμβουλές

- **Η μορφή του τηλεφώνου έχει σημασία** — πρέπει να ξεκινά με `+` και τον κωδικό χώρας· η μορφή επιβάλλεται και ο έλεγχος εγκυρότητας θα απορρίψει λανθασμένη είσοδο
- **Επιλογή ισχυρού κωδικού** — για μεμονωμένες δημιουργίες χειριστή, χρησιμοποιήστε μια μακροσκελή φράση ("rideTheWolf2026!RW") που ικανοποιεί όλους τους κανόνες ταυτόχρονα· καταγράψτε την στον διαχειριστή κωδικών σας, όχι σε συνομιλία
- **Μοναδικότητα email** — το διπλό email είναι η πιο συνηθισμένη αποτυχία στη Δημιουργία· ελέγξτε πρώτα τη λίστα αναζητώντας το email
- **Μην αλλάζετε Email / Τηλέφωνο επιπόλαια σε υπάρχοντες πελάτες** — οι ροές επαλήθευσης βασίζονται σε αυτά· συντονιστείτε με τον πελάτη πριν αποθηκεύσετε
- **Οι ετικέτες ανήκουν εδώ, όχι στη γραμμή** — μπορείτε επίσης να προσθέσετε/αφαιρέσετε ετικέτες μέσω της μαζικής ενέργειας στη λίστα, αλλά η φόρμα επεξεργασίας είναι το σωστό μέρος για στοχευμένες αλλαγές
- **Οι αλλαγές κατάστασης έχουν βάρος ελέγχου** — η μετάβαση _Ενεργό → Αποκλεισμένο_ μέσω αυτής της φόρμας καταγράφεται με τον ίδιο τρόπο όπως η ειδική ενέργεια _Ενέργειες → Αποκλεισμός πελάτη_ — και οι δύο είναι έγκυρες
