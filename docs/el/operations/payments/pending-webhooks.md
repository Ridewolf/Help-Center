# Εκκρεμείς Webhooks

Η σελίδα Εκκρεμών Webhooks (`/payments/pending-webhooks`) εμφανίζει συναλλαγές πληρωμών που έχουν κολλήσει σε **Σε εκκρεμότητα** επειδή δεν έχει φτάσει ακόμα η επιβεβαίωση webhook από τον πάροχο πληρωμών.

Κάθε γραμμή είναι μια πληρωμή που στείλαμε σε πάροχο αλλά δεν έχουμε λάβει τελικό callback κατάστασης. Χρησιμοποιήστε αυτή τη σελίδα ως την **ουρά κολλημένων πληρωμών**: ελέγξτε για παλιές γραμμές, εντοπίστε τον πάροχο που καθυστερεί και προωθήστε το θέμα.

Απαιτούμενη άδεια: **Πληρωμές** (`m1n2p3`).

## Τι βλέπετε

Όταν ένας πελάτης πληρώνει:

1. Ο πίνακας ελέγχου στέλνει αίτημα πληρωμής σε έναν **πάροχο** (Stripe, gateway, κ.λπ.) — δημιουργείται ένα _Payment Intent_
2. Ο πάροχος επεξεργάζεται τη συναλλαγή ασύγχρονα και στέλνει ένα **webhook** με την τελική κατάσταση (`succeeded`, `failed`, κ.ά.)
3. Ο πίνακας ελέγχου λαμβάνει το webhook και αλλάζει την κατάσταση της [πληρωμής](payments.md) από _Σε εκκρεμότητα_ σε _Ολοκληρωμένο_ / _Απέτυχε_

Οι γραμμές **Εκκρεμών Webhooks** αντιστοιχούν στο βήμα 2 που εκκρεμεί — ο πάροχος κλήθηκε αλλά δεν απάντησε. Τις περισσότερες φορές το webhook φτάνει μέσα σε δευτερόλεπτα, μερικές φορές σε λεπτά. Οτιδήποτε παλαιότερο από ~30 λεπτά είναι ύποπτο· οτιδήποτε παλαιότερο από 2 ώρες είναι σχεδόν σίγουρα σφάλμα από την πλευρά του παρόχου ή στον δέκτη webhook μας.

## Φίλτρα

| Φίλτρο          | Τύπος   | Σημειώσεις                                                                       |
| --------------- | ------- | -------------------------------------------------------------------------------- |
| **Πάροχος**     | Κείμενο | Αναζήτηση με όνομα παρόχου (π.χ. `stripe`)                                      |
| **Παλαιότερο από** | Επιλογή | `Όλα` / `5` / `15` / `30` / `60` / `120` λεπτά — εμφάνιση μόνο γραμμών παλαιότερων από αυτό |

Χρησιμοποιήστε _Παλαιότερο από 30 λεπτά_ ή _60 λεπτά_ ως το καθημερινό φίλτρο παρακολούθησης — οι φρέσκες εκκρεμότητες είναι θόρυβος.

## Στήλες

| Στήλη                 | Ταξινομήσιμη; | Περιεχόμενο                                                        |
| --------------------- | ------------- | ----------------------------------------------------------------- |
| **Δημιουργήθηκε στις** | ✓             | Πότε δημιουργήθηκε το payment intent                               |
| **Ηλικία**             | ✓             | Λεπτά από τη δημιουργία — με χρωματική κωδικοποίηση (βλέπε παρακάτω) |
| **Πάροχος**            | —             | Ο πάροχος πληρωμής στον οποίο στάλθηκε το intent                   |
| **Payment Intent ID**  | —             | Το αναγνωριστικό του παρόχου για αυτό το intent — αντιγράψτε το όταν προωθείτε |
| **Κατάσταση**          | —             | Κατάσταση από την πλευρά του παρόχου (ακατέργαστη) — συνήθως `requires_action` / `processing` |
| **Order ID**           | —             | Το εσωτερικό αναγνωριστικό παραγγελίας/πληρωμής                     |

### Χρωματική κωδικοποίηση ηλικίας

Η στήλη **Ηλικία** αλλάζει χρώμα όσο μεγαλώνει, ώστε να μπορείτε να σαρώσετε και να διαλογήσετε με μια ματιά:

| Ηλικία          | Χρώμα  | Τι να κάνετε                                  |
| --------------- | ------ | --------------------------------------------- |
| **< 30 λεπτά**  | Γκρι   | Κανονικό; αγνοήστε                            |
| **30–120 λεπτά**| Κίτρινο| Αξίζει μια ματιά; ελέγξτε τον πίνακα του παρόχου |
| **> 120 λεπτά** | Κόκκινο| Σχεδόν σίγουρα σφάλμα — προωθήστε το θέμα     |

## Ενέργειες γραμμής

Ένα μικρό μενού ενεργειών στα δεξιά κάθε γραμμής:

| Ενέργεια         | Τι κάνει                                               |
| ---------------- | ----------------------------------------------------- |
| **Προβολή πελάτη** | Ανοίγει το προφίλ πελάτη που συνδέεται με αυτό το payment intent |

(Η ενέργεια _Προβολή λεπτομερειών πληρωμής_ υπάρχει στον κώδικα αλλά είναι προσωρινά απενεργοποιημένη επειδή η σελίδα λεπτομερειών πληρωμής έχει αφαιρεθεί — θα επανέλθει αργότερα.)

## Τυπικά σενάρια εργασίας

- **Καθημερινή παρακολούθηση** — ορίστε _Παλαιότερο από = 30 λεπτά_ → η σελίδα πρέπει να είναι κενή τις περισσότερες φορές → αν όχι, ελέγξτε τη στήλη παρόχου
- **Πρόβλημα με έναν πάροχο** — δείτε πολλές γραμμές με τον ίδιο πάροχο να γίνονται κίτρινες/κόκκινες ταυτόχρονα → ελέγξτε τη σελίδα κατάστασης του παρόχου → επικοινωνήστε με την υποστήριξή τους με μερικά _Payment Intent IDs_ από τον πίνακα
- **Πρόβλημα με έναν πελάτη** — μία ή δύο παλιές γραμμές → _Προβολή πελάτη_ → ελέγξτε τη [Δραστηριότητα / Πληρωμές](../customers/client-detail.md) του πελάτη → πείτε τους να ξαναδοκιμάσουν ή να χρησιμοποιήσουν διαφορετική μέθοδο
- **Πρόβλημα δέκτη webhook** — πολλοί πάροχοι γίνονται κόκκινοι ταυτόχρονα χωρίς πρόβλημα από την πλευρά του παρόχου → το πρόβλημα είναι στον δέκτη webhook μας, όχι στον πάροχο· προωθήστε το στην ομάδα μηχανικών

## Όταν μια γραμμή εξαφανίζεται

Μια γραμμή φεύγει από αυτή τη σελίδα όταν φτάσει το webhook — η κατάσταση πληρωμής αλλάζει σε _Ολοκληρωμένο_ ή _Απέτυχε_ στη βασική [λίστα Πληρωμών](payments.md). Η γραμμή δεν "παλιώνει" από μόνη της· μόνο ένα webhook την καθαρίζει.

Αν έχετε **κολλημένες εκκρεμότητες παλαιότερες της μιας ημέρας** που δεν φεύγουν, αυτό είναι σφάλμα που πρέπει να προωθηθεί — ο πίνακας χειριστή δεν έχει χειροκίνητο κουμπί "αναγκαστικής ολοκλήρωσης" για λόγους ασφάλειας (μια λανθασμένη χειροκίνητη ολοκλήρωση δημιουργεί λογιστικό χάος δύσκολο στην αποκατάσταση).

## Συμβουλές

- **Αντιγράψτε το Payment Intent ID** όταν προωθείτε σε πάροχο — είναι το μοναδικό αναγνωριστικό που αναγνωρίζουν
- **Ταξινόμηση κατά ηλικία** (πρώτα τα πιο πρόσφατα → μετά τα παλαιότερα) σας δίνει ουρά διαλογής: η κορυφή της ταξινομημένης λίστας είναι η επείγουσα εργασία σας
- **Κενή σελίδα είναι ο στόχος** — τα Εκκρεμή Webhooks πρέπει να είναι κενά (ή σχεδόν κενά) κατά τη διάρκεια μιας κανονικής ημέρας· θεωρήστε οποιαδήποτε γραμμή ως εργασία προς διεκπεραίωση
- **Η αναζήτηση παρόχου είναι ευέλικτη** — λειτουργούν μερικές αντιστοιχίες (`stri` ταιριάζει με `stripe`)
- **Η σελίδα δεν ανανεώνεται αυτόματα** — χρησιμοποιήστε το κουμπί ανανέωσης ή φορτώστε ξανά τη σελίδα όταν κάνετε ενεργή διαλογή
