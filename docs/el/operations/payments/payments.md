# Πληρωμές — Ιστορικό

Η σελίδα Πληρωμών (`/payments`) είναι το καθολικό κάθε χρηματικής συναλλαγής που επηρέασε τον λογαριασμό ενός πελάτη: χρεώσεις διαδρομών, αναλήψεις πορτοφολιού, επιστροφές χρημάτων, πρόστιμα. Χρησιμοποιήστε τη για να διερευνήσετε μια χρέωση, να εκδώσετε επιστροφή χρημάτων ή να ελέγξετε τη ροή χρημάτων σε ένα εύρος ημερομηνιών.

Για μη επεξεργασμένα συμβάντα webhook από παρόχους πληρωμών δείτε τα [Εκκρεμή Webhooks](pending-webhooks.md).

Απαιτούμενη άδεια: **Πληρωμές** (`m1n2p3`). Ορισμένες ενέργειες σε γραμμές απαιτούν επιπλέον υπο-άδειες.

## Τι περιλαμβάνεται εδώ

Κάθε γραμμή αντιπροσωπεύει μια μεμονωμένη συναλλαγή πληρωμής:

| Τύπος      | Τι είναι                                                                 |
| ---------- | ------------------------------------------------------------------------ |
| **Ανάληψη**| Χρήματα που προστέθηκαν στο πορτοφόλι του πελάτη (χειροκίνητη πίστωση χειριστή ή φόρτιση κάρτας) |
| **Χρέωση** | Χρήματα που αφαιρέθηκαν από τον πελάτη (χρέωση διαδρομής ή πρόστιμο)      |
| **Επιστροφή** | Χρήματα που επιστράφηκαν στον πελάτη (αντιστροφή προηγούμενης χρέωσης)  |

Κάθε συναλλαγή έχει **μέθοδο/πάροχο** — το κανάλι μέσω του οποίου πραγματοποιήθηκε:

- **Πάροχοι καρτών** (Stripe, κ.ά.) — πραγματικά χρήματα σε κάρτα πληρωμής
- **Υπόλοιπο** — εσωτερικό πορτοφόλι (δεν είναι πάροχος πληρωμών· απλώς χρέωση/πίστωση στο υπόλοιπο του πελάτη)
- **Άλλες πύλες** ανάλογα με τις ενσωματώσεις σας

Ο διαχωρισμός μεταξύ _παρόχου κάρτας_ και _υπολοίπου_ είναι σημαντικός για τις επιστροφές — δείτε _Ενέργειες γραμμής → Επιστροφή_ παρακάτω.

## Φίλτρα

| Φίλτρο    | Τύπος     | Σημειώσεις                                                  |
| ----------| --------- | ----------------------------------------------------------- |
| Αναζήτηση | Κείμενο   | Αναζητά όνομα πελάτη, αναγνωριστικό πληρωμής, σχετική διαδρομή / πρόστιμο |
| Εύρος ημερομηνιών | Ημερολόγιο | Επιλογή από/έως; προεπιλογή "όλο το διάστημα"               |
| Τύπος     | Αναπτυσσόμενο | `Ανάληψη` / `Χρέωση` / `Επιστροφή` (ή `Όλα`)               |
| Κατάσταση | Αναπτυσσόμενο | `Σε εκκρεμότητα` / `Ολοκληρωμένο` / `Απέτυχε` / `Επιστράφηκε` (ή `Όλα`) |

Τα φίλτρα εφαρμόζονται στην πλευρά του διακομιστή και συνδυάζονται με ΛΟΓΙΚΟ ΚΑΙ.

## Στήλες

| Στήλη     | Ταξινομήσιμη; | Περιεχόμενο                                                        |
| ----------| ------------- | ----------------------------------------------------------------- |
| **Ημερομηνία** | ✓         | Πότε δημιουργήθηκε η συναλλαγή; προεπιλεγμένη ταξινόμηση = νεότερα πρώτα |
| **Πελάτης** | —           | Όνομα πελάτη και εικόνα προφίλ; σύνδεσμος στο προφίλ πελάτη       |
| **Πηγή**  | —            | Τύπος συναλλαγής (Ανάληψη / Χρέωση / Επιστροφή), με έγχρωμη ετικέτα |
| **Ποσό**  | ✓            | Ποσό σε νόμισμα εταιρείας, με πρόσημο (+/−) και χρωματική κωδικοποίηση |
| **Μέθοδος** | —           | Μέθοδος / πάροχος πληρωμής (κάρτα, υπόλοιπο, όνομα πύλης)          |
| **Κατάσταση** | ✓          | Ετικέτα κατάστασης (δείτε αναφορά παρακάτω)                        |

Ταξινομήστε κάνοντας κλικ σε μια επικεφαλίδα που υποστηρίζει ταξινόμηση. Η επιλεγμένη ταξινόμηση αποτελεί μέρος του URL.

## Αναφορά καταστάσεων

| Κατάσταση      | Σημασία                                                                    |
| -------------- | -------------------------------------------------------------------------- |
| **Σε εκκρεμότητα** | Υποβλήθηκε στον πάροχο· αναμονή επιβεβαίωσης webhook                      |
| **Ολοκληρωμένο** | Ο πάροχος επιβεβαίωσε επιτυχία· τα χρήματα μεταφέρθηκαν                    |
| **Απέτυχε**    | Ο πάροχος απέρριψε τη συναλλαγή (απόρριψη κάρτας, σφάλμα δικτύου, έλεγχος απάτης) |
| **Επιστράφηκε** | Μια επιτυχημένη χρέωση που αντιστράφηκε με επιστροφή χρημάτων             |

## Ενέργειες γραμμής

Κάθε γραμμή έχει **μενού τριών σημείων** στα δεξιά. Οι διαθέσιμες ενέργειες εξαρτώνται από τον τύπο πληρωμής, την κατάσταση και τις άδειές σας:

| Ενέργεια         | Πότε είναι ενεργή                    | Άδεια                                                    |
| ---------------- | ----------------------------------- | -------------------------------------------------------- |
| **Προβολή πελάτη** | Πάντα (μεταβαίνει στο προφίλ πελάτη) | —                                                        |
| **Επιστροφή**    | Δείτε "Δρομολόγηση επιστροφής" παρακάτω | `refund` / `topup-manual` / `fine` (ανάλογα με τη διαδρομή) |

### Δρομολόγηση επιστροφής

Ο Πίνακας ελέγχου κρύβει τις λεπτομέρειες του παρόχου από εσάς, αλλά η ενέργεια _Επιστροφή_ είναι αρκετά έξυπνη ώστε να επιλέγει τη σωστή διαδρομή:

- **Χρέωση βάσει παρόχου** (κάρτα, πύλη) → καλεί το endpoint επιστροφής του παρόχου → τα χρήματα επιστρέφουν στην κάρτα
- **Χρέωση υπολοίπου** (πορτοφόλι) → δεν εμπλέκεται πάροχος — ανοίγει το διάλογο **Φόρτιση υπολοίπου** για πίστωση του πορτοφολιού (απαιτεί `topup-manual`)
- **Φόρτιση υπολοίπου** (χειροκίνητη πίστωση χειριστή) → δεν μπορεί να αντιστραφεί μέσω παρόχου — ανοίγει το διάλογο **Έκδοση προστίμου** για χρέωση του ίδιου ποσού (απαιτεί `fine`)

Η επιστροφή είναι **απενεργοποιημένη** όταν:

- Η γραμμή είναι ήδη επιστροφή (η επιστροφή μιας επιστροφής δεν έχει νόημα)
- Η κατάσταση δεν είναι _Ολοκληρωμένο_ (δεν μπορείτε να επιστρέψετε εκκρεμείς ή αποτυχημένες συναλλαγές)
- Η συναλλαγή έχει ήδη αντιστραφεί (ο πίνακας ελέγχου το παρακολουθεί και μπλοκάρει διπλές κλικ)
- Δεν έχετε τη σωστή υπο-άδεια για τη διαδρομή επιστροφής

## Γιατί εμφανίζονται οι πληρωμές εδώ (και τι τις δημιουργεί)

Οι πληρωμές **δεν** δημιουργούνται από αυτή τη σελίδα — προέρχονται από άλλες ροές:

1. **Ο αναβάτης πραγματοποιεί διαδρομή** → τέλος διαδρομής → το backend δημιουργεί μια συναλλαγή _Χρέωσης_ → αν πετύχει, η κατάσταση γίνεται _Ολοκληρωμένο_ και αφαιρούνται χρήματα από το πορτοφόλι ή την κάρτα
2. **Ο αναβάτης φορτίζει το πορτοφόλι στην εφαρμογή** → κλήση παρόχου → το backend δημιουργεί μια συναλλαγή _Ανάληψης_ → η κατάσταση γίνεται _Ολοκληρωμένο_ με επιβεβαίωση webhook
3. **Ο χειριστής πιστώνει πορτοφόλι** μέσω _Φόρτιση υπολοίπου_ σε πελάτη → το backend δημιουργεί _Ανάληψη_ με μέθοδο _υπόλοιπο_ και αμέσως _Ολοκληρωμένο_
4. **Ο χειριστής εκδίδει πρόστιμο** → το backend δημιουργεί _Χρέωση_ με μέθοδο _υπόλοιπο_, αμέσως _Ολοκληρωμένο_
5. **Επιστροφή** από αυτή τη λίστα → το backend δημιουργεί μια συναλλαγή _Επιστροφής_; η αρχική σημειώνεται ως _Επιστράφηκε_

Η αρχική συναλλαγή δεν εξαφανίζεται ποτέ — κάθε ενέργεια είναι ελεγχόμενη.

## Τυπικές ροές εργασίας

- **Διερεύνηση χρέωσης** — αναζήτηση με βάση το αναγνωριστικό πελάτη / διαδρομής / πληρωμής → έλεγχος Κατάστασης (Ολοκληρωμένο = χρήματα λήφθηκαν, Απέτυχε = δεν υπήρξαν χρήματα) και Μέθοδος
- **Επιστροφή χρημάτων για διαδρομή** — βρείτε τη γραμμή _Χρέωση_ για τη διαδρομή → μενού γραμμής → _Επιστροφή χρημάτων_ → επιβεβαίωση → εμφανίζεται μια συζευγμένη γραμμή _Επιστροφή χρημάτων_, η αρχική αλλάζει σε _Επιστράφηκε_
- **Έλεγχος της ημέρας** — ορίστε το εύρος Ημερομηνιών = σήμερα → φιλτράρετε Κατάσταση = Ολοκληρωμένο → ελέγξτε τα σύνολα
- **Εύρεση αποτυχιών για επανάληψη** — φιλτράρετε Κατάσταση = Απέτυχε → επικοινωνήστε με τους πελάτες για επανάληψη / εναλλακτική μέθοδο
- **Συμφωνία με τον πάροχο** — εύρος Ημερομηνιών + Τύπος = Φόρτιση/Χρέωση + Μέθοδος = πάροχος κάρτας → εξαγωγή και διασταύρωση με την κατάσταση του παρόχου

## Συμβουλές

- **Σε εκκρεμότητα δεν σημαίνει αποτυχία** — οι εκκρεμείς συναλλαγές περιμένουν το webhook του παρόχου· ελέγξτε τα [Εκκρεμείς Webhooks](pending-webhooks.md) αν μια γραμμή παραμένει σε εκκρεμότητα για πολύ
- **Οι συναλλαγές υπολοίπου δεν μπορούν να επιστραφούν μέσω κάρτας** — το σύστημα σας κατευθύνει στο σωστό διάλογο· μην προσπαθήσετε να δημιουργήσετε χειροκίνητα αντισταθμιστικές συναλλαγές
- **Η αρχική παραμένει μετά από επιστροφή** — οι επιστροφές προσθέτουν μια συζευγμένη γραμμή, δεν διαγράφουν τη χρέωση· και οι δύο γραμμές παραμένουν στο ιστορικό για έλεγχο
- **Το πρόσημο του ποσού δείχνει την κατεύθυνση** — `+` (πράσινο) είναι χρήματα προς τον πελάτη· `−` (κόκκινο/σκούρο) είναι χρήματα από τον πελάτη
- **Τα ονόματα παρόχων είναι σημαντικά για υποστήριξη** — όταν αναβαθμίζετε σε πάροχο πληρωμών, αντιγράψτε το αναγνωριστικό πληρωμής και το όνομα παρόχου από τη στήλη Μέθοδος
- **Το URL είναι κοινοποιήσιμο** — αντιγράψτε μια φιλτραρισμένη προβολή (π.χ. _αποτυχημένες χρεώσεις κάρτας χθες_) και στείλτε την στο τμήμα οικονομικών ή κατά της απάτης
