# Моя компания

Страница «Моя компания» (`/settings/my-company`) — это **профиль юр. лица, обслуживающего ваш флот**: реквизиты, адрес, контакты, валюта, настройка платёжных провайдеров, IoT-брокер и конфигурация райдер-приложения (брендинг, дефолтная карта, signup-flow, способы аутентификации, каналы поддержки, юр. ссылки). Сохранение шлёт `PATCH /companies/my-company` на бэкенд.

Это страница уровня Ridewolf-тенанта — правки одного оператора видны всем. Будьте аккуратны.

Разрешения: страница **гейтится двумя пермишенами одновременно** — `x4y5z6` (GET My Company, baseline) и `a7b8c9` (Edit My Company, sensitive). Маршрутер полностью скрывает страницу от операторов без обоих прав (комментарий в коде уточняет: _без edit это шум только-чтения_). Внутри страницы сама кнопка **Save** дополнительно гейтится capability `edit` страницы `settings.myCompany` в каталоге пермишенов.

## Разделы

Две вкладки. Ментальная модель:

- _Company_ — про сам **юр. субъект**: идентичность, адрес, контакты, валюта, платёжные провайдеры, IoT endpoint, описательный контент. Ничего про внешний вид мобилки.
- _App_ — всё про **конфигурацию мобильного приложения**: брендинг (логотип/цвета), карта по умолчанию, способы аутентификации, шаги регистрации, публичные каналы поддержки, live-чат + Telegram-бот, юр. ссылки в футере приложения.

Закреплённый нижний footer с **Discard** и **Save changes** появляется только при изменениях _и_ при наличии edit-разрешения. Страница загружается через `GET /companies/my-company` и заново вытягивает данные после каждого успешного сохранения для синхронизации.

## Вкладки

### Вкладка Company

Семь карточек.

**1. Identity**

- _Legal name_ (обязательно) — официальное зарегистрированное название.
- _Label_ — короткое отображаемое имя (например, «Ridewolf Romania»).
- _Registration number_ (обязательно).
- _Tax ID_ — необязательно, тултип объясняет, что формат зависит от юрисдикции.

**2. Location**

- _Country_ (обязательно) — заметьте, поле маппится в DTO как `county`, но лейбл — _Country_.
- _City_ (обязательно).
- _Address_ (обязательно).
- _ZIP code_ (обязательно).

**3. Contact**

- _Email_ (обязательно) — основной email.
- _Phone_ — необязательно.
- _Website_ — необязательный URL.

**4. Currency**

- _Currency_ — список валют. При выборе автоматически проставляется _Currency symbol_ (только-чтение).
- Символ показан disabled с подсказкой, что он выводится из кода валюты.

**5. Payment providers**

- _Default provider_ — провайдер по умолчанию для новых платежей (Stripe, PayPal и т.п.).
- _Supported providers_ — мульти-выбор (поисковый список с лейблами). Все отмеченные доступны; default обязан входить в список supported.

**6. IoT connectivity** — почти полностью только-чтение

- _IoT domain_ — хост MQTT-брокера, disabled.
- _Port_ — disabled, приходит с бэкенда per company.
- _Endpoint_ — собранная строка `host:port`, выделяется в один клик.
- Под ней info-Alert с пошаговой инструкцией для настройки ТС — отдельные случаи «вендор хочет два поля (host + port)» и «вендор хочет одну строку endpoint».

**7. Content**

- _Description_ — короткое Markdown-описание компании.
- _About_ — длинный Markdown about.

Оба используют общий `MarkdownEditor` с live-предпросмотром.

### Вкладка App

Объединяет всё визуальное и поведенческое для райдер-приложения. Шесть логических блоков.

**Brand identity + colors** (бывшая Branding-вкладка, заведена сюда)

- _App name_ (полное) и _Short name_ (для home-screen-иконки).
- _Logo_ — загрузка.
- _Theme color_ и _Accent color_ — color-пикеры.

**Default Map View**

- Интерактивный MapLibre-холст с zoom-контролами. Клик по карте задаёт дефолтный центр города для райдер-приложения; сохраняются lat / lng / zoom.
- Под картой строка-индикатор: `lat, lng / Zoom / cityId` после установки, либо _Click to set_ до неё.

**Authentication Methods**

- Список переключаемых способов входа (например, пароль, OTP, Google, Apple). У каждого лейбл + help + switch. Выбранные методы — это то, что райдер видит на экране логина.

**Signup Extra Steps**

- Сортируемый список дополнительных шагов (Step ID + Position + Required + удалить). Полезно для шагов вроде «верификация телефона» или «загрузка ID» после стандартной регистрации.
- _+ Add step_ добавляет пустую строку.

**Support channels** (публичные каналы, видимые райдеру на экране помощи)

- Каждый канал — плитка с включением и полем значения: _Email_, _Phone_, _Website_, _Telegram_ (handle + URL), _WhatsApp_. В приложение попадают только включённые.

**Communications** (live-чат + Telegram-бот — операционная интеграция)

- _Live chat enabled_ — switch + help.
- _Telegram bot_ — токен (masked) + кнопка **Check chats**, которая обращается к боту и перечисляет чаты, в которых он состоит. Выбор из выпадающего списка сохраняет chat ID. Если chat ID уже сохранён, но discovery не запускался, сохранённое значение видно только-чтение.

**Legal & compliance**

- Три URL для футера приложения: _Terms of Service URL_, _Privacy Policy URL_, _Licenses URL_.

## Сценарии

- **Обновить юр. адрес** — Company → Location → отредактировать поля → Save.
- **Сменить основной платёжный провайдер** — Company → Payment providers → задать Default provider → убедиться, что он в Supported providers → Save.
- **Подключить новое ТС к IoT-брокеру** — Company → IoT connectivity → скопировать строку _Endpoint_ в MQTT-конфиг устройства (одним кликом она выделяется).
- **Ребрендинг мобилки** — App → Brand identity → обновить имя + цвета + логотип → Save. Применится в райдер-приложении на следующей синхронизации.
- **Добавить обязательный шаг загрузки ID при регистрации** — App → Signup Extra Steps → + Add step → Step ID `id-upload`, позиция, _Required_ → Save.
- **Указать Telegram-бот поддержки** — App → Communications → вставить токен → _Check chats_ → выбрать чат → Save.
- **Опубликовать новые юр. документы** — App → Legal & compliance → вставить новые публичные URL → Save.

## Советы

- **Два пермишена связаны.** Если у вас есть _view_, но нет _edit_, страница скрыта целиком (маршрут). Если edit пропадёт между загрузкой и Save, footer исчезает — обновите.
- **Country vs County.** Лейбл — _Country_, но DTO-поле называется `county`: это исторический беспорядок в неймингах бэкенда, не баг; смотрите на лейбл.
- **Символ валюты — производная.** Вы не выбираете символ — он подставляется по коду.
- **Default provider должен быть в Supported providers.** Сохранение default-а, которого нет в supported, провалит бэкенд-валидацию.
- **Хост и порт IoT — только-чтение.** Управляются Ridewolf — можно скопировать endpoint, но не редактировать из дашборда.
- **Два Telegram-поля — это разные вещи.** Тот, что на этой странице (App → Communications), — это бот поддержки для общения с райдерами. Тот, что в [Alerts & Notifications](alerts-notifications.md) → Providers — это бот для оповещений персонала. Может быть один бот, но обычно нет.
- **Markdown-редакторы почти WYSIWYG.** Description и About показывают предпросмотр рядом с исходником.
- **После Save страница перезагружается** — то, что вы видите после Save, — это каноническое состояние с бэкенда, а не ваш form-state.
