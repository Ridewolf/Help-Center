# FAQ Sets

Страница FAQ Sets (`/settings/faq-sets`) — это **библиотека вопросов-ответов**, которая показывается внутри приложений Ridewolf, прежде всего в rider mobile app, но также в operator-приложениях. Каждый набор — это пачка Q/A-записей, привязанная к одной аудитории (rider app, client app, mechanic, admin или general).

Вместе с [Quick Guides](quick-guides.md) и [Icon Sets](icon-sets.md) — это контент-слой дашборда: то что оператор меняет здесь, видит райдер на телефоне без релиза мобильного приложения.

Требуется право: **FAQ Sets** (check with admin).

## Где это видно райдеру

В rider mobile app FAQ Sets питают раздел Help / FAQ внутри приложения. Каждый набор с типом **rider-app** и статусом `active` загружается в приложение; записи отмеченные `visible` показываются, в порядке поля `order`. Наборы с типами `client-app`, `mechanic`, `admin`, `general` идут в соответствующие приложения.

Набор `draft` или `archived` не показывается никогда — удобно для подготовки изменений перед публикацией.

## Фильтры

| Фильтр | Тип          | Заметки                                                                   |
| ------ | ------------ | ------------------------------------------------------------------------- |
| Search | Текст        | Поле поиска в шапке — по title / description / slug                       |
| Tags   | Multi-select | Фильтр по тегам набора (onboarding, payments, technical, …)               |
| Status | Дропдаун     | `Active` / `Draft` / `Archived` (или `All`)                               |
| Type   | Дропдаун     | `Client app` / `Rider app` / `Mechanic` / `Admin` / `General` (или `All`) |

**Clear all** сбрасывает все фильтры разом.

## Колонки

| Колонка     | Содержимое                                                             |
| ----------- | ---------------------------------------------------------------------- |
| **Set**     | Иконка + title; вторая строка — description или slug                   |
| **Type**    | Пилюля аудитории — Client app / Rider app / Mechanic / Admin / General |
| **Tags**    | Первые 3 чипа тегов, с `+N` для остатка                                |
| **Items**   | Сколько Q/A-полей в наборе                                             |
| **Status**  | `Active` (зелёная) / `Draft` (серая) / `Archived` (приглушённая)       |
| **Updated** | Относительная дата; на ховере — полный таймстемп + автор               |

Клик по строке открывает диалог **View** (превью). Клик по меню из трёх точек — действия.

## Действия над строкой

| Действие         | Что делает                                                                      |
| ---------------- | ------------------------------------------------------------------------------- |
| **View details** | Read-only превью с рендером каждого Q/A                                         |
| **Edit**         | Открыть форму (та же что Create, заполненная)                                   |
| **Duplicate**    | Клонировать набор: slug получает суффикс `-copy`, статус сбрасывается в `Draft` |
| **Export**       | Скачать набор как ZIP или JSON                                                  |
| **Archive**      | Перевести в `Archived` — скрыт от rider app, но в истории                       |
| **Delete**       | Удалить навсегда (деструктивно — только если точно не нужен)                    |

В верхнем тулбаре также есть массовые **Import** (ZIP / JSON) и **Export** (ZIP / JSON списка).

## Форма Create / Edit

В диалоге три верхнеуровневых селектора и список Q/A:

- **Type** — обязательное, определяет аудиторию (Client app / Rider app / Mechanic / Admin / General)
- **Status** — `Draft` (по умолчанию для новых) / `Active` / `Archived`
- **Tags** — multi-select, для фильтрации и группировки
- **Title** — обязательное, имя набора
- **Description** — опциональное, вторая строка в списке
- **Fields** — Q/A-записи. У каждой:
  - **Label** (вопрос)
  - **Value** (ответ)
  - **Type** — `text` / `markdown` / `link` / `list`
  - **Visible** (скрыть запись без удаления)
  - **Order** (drag для сортировки)

Slug берётся из title и используется в API URL — поменять можно через Edit.

## Типичные сценарии

- **Публикация нового rider FAQ** — `+ Create set` → Type = Rider app, Status = Draft → заполнить title + description → добавить Q/A → save → проверить через View details → Edit, Status = Active → появляется в rider app при следующем fetch
- **Подготовка сезонного контента** — Duplicate существующего набора → редактировать копию как Draft → переключить в один заход: архивировать старый и активировать новый
- **Откат плохого ответа** — открыть набор → Edit → исправить поле (или снять `Visible`) → save; или Archive весь набор и вернуть ранее сделанный дубликат
- **Bulk import из JSON-дампа** — top-right _Import_ → выбрать файл → подтвердить структуру → импорт как Draft, потом ревью и Activate

## Полезные приёмы

- **Type рулит аудиторией** — не кладите rider-копию в `mechanic` набор, до rider app она не дойдёт
- **Draft — ваш друг** — новые наборы по умолчанию Draft, чтобы rider app не показывал недоделки. Активируйте только после ревью
- **Markdown поля рендерят форматирование** — используйте для ответов с буллетами или жирным; `text` — для plain prose
- **Tags общие с фильтром** — держите единый словарь (например `onboarding`, `payments`, `troubleshooting`), чтобы фильтрация дальше оставалась полезной
- **Archive вместо Delete по возможности** — удалённый набор уже не вернуть, архивный можно реактивировать и использовать как историю
