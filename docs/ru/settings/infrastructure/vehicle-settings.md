# Vehicle Settings

Страница Vehicle Settings (`/settings/vehicle-settings`) — это **каталог моделей транспорта**, которые Ridewolf умеет эксплуатировать: _Xiaomi M365_, _Ninebot Max G30_, _Segway F40_ и т.д. Каждая строка здесь — **шаблон модели**: переиспользуемый набор тарифов, технических лимитов, требований к фото-пруфам и тегов, который прикрепляется к конкретным физическим [vehicles](../../operations/fleet/vehicles.md) через [форму машины](../../operations/fleet/vehicle-create-edit.md).

Требуется право: **Vehicle Settings** (`e7f8g9`). Под-права гейтят `create` / `edit` / `delete`.

## Model vs vehicle instance

Самое важное различие на этой странице:

- **Vehicle Model** (эта страница) — определение. _«Все Xiaomi M365 в нашем парке ведут себя вот так»_. По одной строке на марку/конфигурацию.
- **Vehicle** ([список Vehicles](../../operations/fleet/vehicles.md)) — физический юнит с наклейкой типа `RW-007`, привязан к одному IoT-устройству, припаркован где-то. Сотни таких указывают на одну модель.

Когда вы меняете модель здесь, каждая машина, ссылающаяся на неё, наследует новые дефолты — тарифы становятся активными, лимиты скорости обновляются, требования к фото-пруфам вступают в силу. Относитесь к этой странице как к **policy-слою**, который раздаёт настройки множеству юнитов разом.

## Фильтры

Верхняя панель фильтров — три контрола:

| Фильтр     | Тип      | Заметки                                                                          |
| ---------- | -------- | -------------------------------------------------------------------------------- |
| **Search** | Текст    | Ищет по label модели                                                             |
| **Status** | Дропдаун | `All` / `Active` / `Inactive` / `Archived`                                       |
| **Type**   | Дропдаун | `All` / `E-Scooter` / `E-Bike` / `Cargo E-Bike` / `E-Moped` / `E-Car` / `E-Boat` |

Изменение любого фильтра сбрасывает пагинацию на страницу 1 и перезагружает данные с сервера.

## Колонки

| Колонка         | Сортировка? | Содержимое                                                                                             |
| --------------- | ----------- | ------------------------------------------------------------------------------------------------------ |
| **Image**       | —           | Миниатюра 64×64; фоллбек — иконка машины если изображение не загружено                                 |
| **Name**        | ✓           | Label модели (например, _Xiaomi M365 Pro_)                                                             |
| **Type**        | ✓           | Пилюля типа ТС (e-scooter, e-bike, …)                                                                  |
| **Description** | ✓           | Первые 36 символов markdown-описания, без форматирования                                               |
| **Tags**        | —           | До 2 пилюль тегов + чип `+N` — **клик открывает quick-edit** в диалоге                                 |
| **Status**      | ✓           | Цветная пилюля: Active (зелёная) / Inactive (серая) / Archived (синяя) — **клик открывает quick-edit** |
| **Created**     | ✓           | Дата создания модели                                                                                   |
| **Updated**     | ✓           | Дата последнего изменения                                                                              |

Quick-edit-клики открывают маленький диалог с одним полем — мульти-селект тегов или дропдаун статуса — удобно для пакетных смен статуса без ухода со списка.

## Кнопки тулбара

Кнопки в правом верхнем углу (видимость зависит от прав):

| Кнопка           | Право    | Что делает                                                                                                                              |
| ---------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **Auto-refresh** | —        | Опрашивает список с интервалом; вкл/выкл; иконка крутится во время загрузки                                                             |
| **Import**       | `create` | Выбор JSON-файла (формат экспорта). Каждый элемент создаётся через `create`; теги и тарифы сбрасываются — перенавешивайте вручную после |
| **Export**       | —        | Открывает диалог: экспорт текущей страницы / всего отфильтрованного / конкретных страниц в `vehicle-models-export.json`                 |
| **+ Create**     | `create` | Переход на `/settings/vehicle-settings/create`                                                                                          |

## Действия над строкой

Меню из трёх точек на каждой строке:

| Действие         | Право    | Что делает                                                                                                                 |
| ---------------- | -------- | -------------------------------------------------------------------------------------------------------------------------- |
| **View details** | —        | Открывает деталь модели `/settings/vehicle-settings/:id` (вкладки General / Technical / History)                           |
| **Edit**         | `edit`   | Открывает форму редактирования (`/settings/vehicle-settings/:id/edit`) с полным набором полей                              |
| **Delete**       | `delete` | Деструктивный confirm-диалог с задержкой 3 секунды перед активацией кнопки подтверждения. Строка модели исчезает из списка |

Клик по самой строке (вне quick-edit чипов) ведёт на **View details**.

## Форма Create / Edit

`+ Create` (`/settings/vehicle-settings/create`) и _Edit_ (`/settings/vehicle-settings/:id/edit`) делят один лейаут: форма-карточка слева, контекстный сайдбар **Field Guide** справа с live-превью модели.

Форма сгруппирована в секции — Create показывает только 7 основных полей; Edit добавляет 3 доп. под-секции (Tech Specs, Auto Policies, Document Requirements) для продвинутых настроек.

### Основные поля

| Поле             | Required | Заметки                                                                                                                                   |
| ---------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **Label**        | ✓        | Человекочитаемое имя везде (например, _Xiaomi M365 Pro_). Свободный текст                                                                 |
| **Description**  | —        | Markdown-редактор; используется в детали модели и в подсказках оператору                                                                  |
| **Vehicle Type** | ✓        | Один из: e-scooter / e-bike / cargo-e-bike / e-moped / e-car / e-boat. Управляет иконкой и логикой категории                              |
| **Status**       | ✓        | Active / Inactive / Archived. Inactive убирает модель из пикера создания vehicle                                                          |
| **Image**        | —        | Drag-and-drop или клик загрузка. PNG/JPEG/JPG, до 10 MB. Показывается в миниатюре списка и на детали Vehicle                              |
| **Tariffs**      | ✓        | Мульти-селект [Vehicle Tariffs](vehicle-tariffs.md). Все поездки на этой модели тарифицируются по этим тарифам |
| **Tags**         | ✓        | Мульти-селект model-level тегов. Наследуется каждой машиной этой модели                                                                   |

### Tech Specs (только в Edit)

| Поле                                    | Заметки                                                                               |
| --------------------------------------- | ------------------------------------------------------------------------------------- |
| **Базовое ограничение скорости (км/ч)** | Жёсткий потолок, который IoT-прошивка применяет на каждой поездке                     |
| **Резерв батареи (%)**                  | Уровень заряда, ниже которого ТС считается low-battery                                |
| **Резерв запаса хода (км)**             | Оценочный остаток хода, ниже которого юнит флагается на swap                          |
| **Мин/Макс напряжение батареи (V)**     | Границы валидных показаний основной батареи — вне границ — флаг _Needs Investigation_ |
| **Мин/Макс напряжение IoT (V)**         | То же для трекерной батареи IoT-модуля                                                |

### Auto Policies (только в Edit)

Набор тоглов: **Low-battery stop**, **Low-balance stop**, **Multiple rides**, **Auto-lock**, плюс **Auto-refund** и **Auto-discount** со своими порогами (дистанция / время / сумма).

### Document Requirements (только в Edit)

Решает, какие фото / документы райдер обязан загрузить:

- **Start proofs** — фото ТС при старте поездки (toggle + required + count) и селфи райдера
- **Park proofs** — фото парковки при завершении (toggle + required + count)
- **Extra documents** — водительские права / паспорт / ID-карта / селфи / прочее

Эти правила читает приложение райдера при старте / завершении поездки на машине этой модели.

## Связь с другими сущностями

- **[Vehicle Tariffs](vehicle-tariffs.md)** — строки прайсинга, которые вы выбираете в поле **Tariffs**. Модель без тарифов не сможет тарифицировать поездку
- **[Vehicles](../../operations/fleet/vehicles.md)** — физические юниты, которые указывают на эту модель через поле _Vehicle Model_ в [форме vehicle](../../operations/fleet/vehicle-create-edit.md). Модель задаёт policy; vehicle владеет IoT, label и местоположением
- **Tags** — model-level теги наследуются каждой машиной этой модели в дополнение к vehicle-level тегам, навешенным на конкретный юнит. Поездки наследуют оба набора при старте

## Типичные сценарии

- **Завести новую модель** — `+ Create` → заполните Label / Type / Status / Image → выберите подходящие тарифы → save → откройте новую модель из списка и нажмите _Edit_, чтобы настроить Tech Specs и policies
- **Вывести модель из эксплуатации** — откройте модель → _Edit_ → Status = _Archived_ → save. Существующие vehicles продолжают работать; модель просто пропадает из пикера создания vehicle
- **Смена тарифа по всему парку** — отредактируйте модель → замените тарифы → save. Все vehicles этой модели начнут тарифицироваться по новым тарифам со следующей поездки
- **Массовый импорт после миграции** — Export из staging → Import JSON-файла здесь → перенавесьте тарифы и теги вручную на каждую новую модель (импорт намеренно сбрасывает эти ссылки)
- **Подкрутить требования к фото** — Edit → Document Requirements → переключите Start / Park proofs → save. Приложение райдера подхватит новые правила при следующем старте поездки

## Подсказки

- **Назначайте тарифы до того, как ставите Active** — модель без тарифов отвергнет запрос на ценообразование поездки
- **Используйте Inactive, а не Delete для вывода из эксплуатации** — Inactive прячет модель от создания новой vehicle, но сохраняет историю. Delete необратим и заблокирован 3-секундной задержкой не просто так
- **Изображение важно** — миниатюра в списке и пикеры vehicle оператора все используют это изображение. Кропьте в квадрат с прозрачным фоном для самого чистого вида
- **Теги здесь model-level, не vehicle-level** — навешивая тег здесь, вы навешиваете его на каждую машину этой модели. Для тегов конкретного юнита редактируйте отдельную vehicle
- **Tech Specs гейтят алерты** — резерв батареи и границы напряжения питают триггер _Needs Investigation_; слишком тесные границы захлопывают очередь алертов
- **Сайдбар Field Guide обновляется при фокусе поля** — прочитайте его при первом создании модели, он актуальнее этой статьи
