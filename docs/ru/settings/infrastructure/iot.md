# IoT-устройства

Страница IoT (`/iot`) — это **инвентарь железа**: каждый трекер / lock-юнит, которым владеет ваш парк, независимо от того, прикручен ли он сейчас к транспорту. Каждая строка — одно физическое устройство, идентифицируемое по **IMEI**, с живой телеметрией (online, GPS-фикс, GSM-сигнал, батарея) из последнего пинга.

Это зеркало [Транспорта](../../operations/fleet/vehicles.md) со стороны железа: транспорт без IoT нельзя ни трекать, ни контролировать; IoT без транспорта — это просто непривязанная железка на полке.

Требуется право: **IoT Devices** (`n8p9q9`). Под-права гейтят `edit` / `send-command` / `delete`, а bulk-действие _Generate vehicle_ использует `operations.vehicles.create`.

## Откуда сюда попадают устройства

Устройства не обнаруживаются автоматически — вы регистрируете их по мере прихода партий:

1. **Закупка** — вы покупаете IoT-юниты у вендора (Omni, Segway, Okai и т.д.). У каждого свой уникальный **IMEI** на коробке / стикере
2. **+ Создать** здесь — введите Name, IMEI, Vendor, Status. Устройство теперь в инвентаре, но не привязано
3. **Bind к транспорту** — делается из [Vehicle Create / Edit](../../operations/fleet/vehicle-create-edit.md) выбором этого IoT в device-пикере. Один IoT на один транспорт, один транспорт на один IoT
4. **Телеметрия пойдёт** когда устройство включится с SIM и достучится до MQTT-брокера Ridewolf. Список показывает свежайший snapshot — refresh или подождите AutoRefresh

Альтернативно — используйте bulk-действие **Generate vehicle** ниже, чтобы создать по транспорту на каждый выделенный IoT одним проходом (например, при онбординге партии новых самокатов).

## Фильтры

| Фильтр | Тип      | Заметки                                    |
| ------ | -------- | ------------------------------------------ |
| Search | Текст    | Ищет по name и IMEI                        |
| Status | Дропдаун | `All` / `Active` / `Inactive` / `Archived` |

Фильтры синкаются с URL (refresh сохраняет view), сбрасываются ссылкой Clear в баре фильтров.

## Колонки

| Колонка         | Сортировка? | Содержимое                                                              |
| --------------- | ----------- | ----------------------------------------------------------------------- |
| **Name**        | да          | Имя устройства + короткий ID; клик по строке открывает детальную        |
| **Lock**        | —           | Пилюля состояния замка (Locked / Unlocked) из последней MQTT-команды    |
| **Online**      | —           | Зелёный если последний пинг в окне свежести; красный если stale         |
| **GPS**         | —           | Valid / Invalid индикатор фикса                                         |
| **GSM**         | —           | Уровень сигнала (шкала 0-32, красный ≤10, жёлтый ≤20, зелёный ≤32)      |
| **Battery**     | да          | Процент батареи с цветным баром                                         |
| **Status**      | да          | Пилюля `Active` / `Inactive` / `Archived`                               |
| **Last Signal** | да          | Время с последнего пакета телеметрии (относительное, например "5m ago") |

## Действия над строкой

Меню из трёх точек. Доступные действия зависят от прав:

| Действие          | Право    | Что делает                                                                           |
| ----------------- | -------- | ------------------------------------------------------------------------------------ |
| **View details**  | —        | Открыть детальную страницу устройства (табы Details / Activity / Commands / History) |
| **View location** | —        | Открыть последние известные GPS-координаты в Google Maps (новая вкладка)             |
| **Edit**          | `edit`   | Открыть форму редактирования (Name / IMEI / Vendor / Status)                         |
| **Delete**        | `delete` | Удалить запись. Подтверждение с задержкой 3 секунды перед разблокировкой             |

## Bulk-действия

Выделите несколько строк (чекбокс в шапке или per-row), чтобы появился bulk-бар. Действия тоже гейтятся правами — те, что недоступны, скрыты, не задизейблены:

| Действие                   | Право             | Что делает                                                                                                                        |
| -------------------------- | ----------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| **Generate vehicle**       | `vehicles.create` | Создать по новому транспорту на каждый выделенный IoT, с автоименем по префиксу компании; выбор vehicle model + опциональные теги |
| **Change status**          | `edit`            | Поставить Active / Inactive / Archived для всех выделенных                                                                        |
| **Test connection (Beep)** | `send-command`    | Отправить команду `Beep` на каждое устройство — удобно физически локализовать юниты на складе                                     |
| **Send command**           | `send-command`    | Выбрать команду из вендора первой выделенной строки (preset или advanced multi-step procedure) и отправить всем                   |
| **Delete**                 | `delete`          | Bulk-удаление с диалогом подтверждения (задержка 3 секунды)                                                                       |

Bulk-операции идут последовательно с прогрессом (`processed / total`) и панелью failed items — частичный успех это норма, failed-устройства остаются выделенными для повтора или разбора.

## Детальная страница

Клик по строке (или _View details_) открывает детальную. Четыре таба:

- **Details** — IMEI / Vendor / Status / координаты с встроенным Google Maps preview; полный блок телеметрии (speed mode, GPS validity, GSM raw, батарея, locked state)
- **Activity** — generic activity-лог для этого устройства (`entity-type=iot`)
- **Commands** — vendor-aware отправщик команд. Тот же движок используется на табе Commands у [Vehicle Detail](../../operations/fleet/vehicle-detail.md) — см. ту статью про procedure / advanced flow
- **History** — история телеметрии / packet log

В заголовке — привязанный Vehicle (если есть) как chip; клик переходит на детальную транспорта. Дропдаун **Actions** в заголовке предлагает Edit / View on Google Maps / Delete.

## Форма Create / Edit

Форма IoT (`+ Create` или _Edit_) — четыре обязательных поля:

- **Name** — короткий label который вы будете видеть в списках (например `SCOOTER-014`). Свободный текст
- **IMEI** — уникальный hardware-идентификатор устройства (используется для bind транспорта и приёма MQTT-трафика). После установки считайте его immutable — смена IMEI на задеплоенном устройстве сломает телеметрию пока binding не обновят
- **Vendor** — строка производителя (например `omni`, `segway`). Определяет какой набор команд понимает устройство — пишите точно, lookup case-sensitive
- **Status** — `Active` (по умолчанию) / `Inactive` (скрыт из пикера привязки транспорта) / `Archived` (списанное железо)

Inline-формы для bind к транспорту тут нет — это направление управляется через форму Vehicle Create / Edit.

## Типичные сценарии

- **Онбординг партии из 50 трекеров** — создать каждый (или импортнуть из CSV если есть) → выделить все → _Generate vehicle_ с нужной vehicle model → готово; у каждого IoT парный vehicle в статусе `needs_investigation` для QA
- **Найти потерянный юнит на складе** — фильтр по name/IMEI → row-действие _Test connection (Beep)_ или bulk Beep → ходить и слушать
- **Списать сломанное устройство** — Edit → Status = Archived (не Delete — Activity log сохраняется). Если был привязан транспорт, сначала отвяжите из формы Vehicle edit
- **Vendor-wide раскатка команды** (например firmware-настройка) — фильтр по name pattern или телеметрии, выделить всё подходящее → _Send command_ → выбрать вендорную команду, и она пройдёт по списку с прогрессом
- **Разобрать "ghost" транспорт** (online, но потерян) — View location → если GPS Invalid, Beep; если всё ещё тишина — подозревайте SIM / батарею
- **Кросс-чекнуть телеметрию с событиями** — открыть [Events report](../../analytics/reports/events.md) фильтр по транспорту этого IoT, чтобы скоррелировать состояние железа с активностью платформы

## Полезные приёмы

- **IMEI — это join-ключ** везде: bind транспорта, MQTT-роутинг, support-тикеты. Введите раз, копируйте навсегда
- **Поле Vendor структурное, не косметическое** — определяет каталог команд на табе Commands. Опечатка `Omni` вместо `omni` может вернуть пустой список команд
- **Online ≠ Active** — Online это живой сигнал телеметрии; Status это админский флаг. Active устройство может быть Offline (батарея, нет GSM); Archived всё ещё может слать пинги пока не выключили
- **Bulk Send command берёт вендора первой строки** — если у выделения смешанные вендоры, делите на single-vendor batches или получите путаный command-лист
- **Generate vehicle создаёт транспорт в `needs_investigation` намеренно** — нужен человек, чтобы подтвердить корректность binding до go-live. Bulk-теги при генерации упрощают следующий QA-проход
- **Кнопки "force re-pair" нет** — если телеметрия пропала после swap, проверяйте binding Vehicle → IoT (в Vehicle edit) и SIM / питание устройства, не эту страницу
- **Archived-устройства остаются searchable** по IMEI — удобно когда старый юнит вернулся с ремонта и нужно его оживить (флипнуть обратно в Active)
- **Last Signal — самый быстрый health-чек** — сортируйте по убыванию чтобы найти stale-устройства первыми; всё, что больше 24h на Active-строке, стоит проверить
