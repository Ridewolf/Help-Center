# Vehicle Tariffs (Тарифы транспорта)

Библиотека правил ценообразования для вашего флота Ridewolf. **Тариф** — это самодостаточный набор денежных правил (базовая цена, плата за старт поездки, цена за расстояние, цена паузы, платная резервация, плюс discount-уровни и auto-refund предохранитель), которые система использует для расчёта суммы поездки.

Живёт по `/settings/vehicle-tariffs`. Право: **List Tariffs** (`v1w2x3`).

## Что такое Tariff

Тариф **не** привязан к транспорту напрямую — он привязан к **Vehicle Model** в [Vehicle Settings](vehicle-settings.md). Цепочка:

```
Tariff  →  Vehicle Model  →  Vehicle  →  Ride
```

Одна запись тарифа содержит:

- **Идентификация** — `Name`, `Description` (Markdown), `Status` (Active / Inactive / Archived), `Tags`
- **Единица расчёта** — `Type`: один из `per-minute`, `per-hour`, `per-day`, `per-month`. Контролирует гранулярность биллинга (per-minute использует посекундную математику; per-day/per-month — ceil-based billing с авансом за полную единицу)
- **Цены** (все денежные значения в валюте компании):
  - **Base price** — стоимость одной единицы (минута, день и т.д.)
  - **Ride-start price** — фиксированная плата за разблокировку (один раз в начале)
  - **Distance price** — цена за километр
  - **Pause price** — поминутно во время паузы
  - **Paid reservation price** — поминутно после окончания бесплатного окна резервации
  - **Reservation time** — бесплатные минуты резервации перед платной
- **Discount tiers** — три опциональных уровня (First / Second / Third). Каждый — _"после N единиц, скидка X %"_, чтобы длинные поездки становились дешевле
- **Auto-refund** — toggle + два порога (`distance` в метрах, `time` в секундах). Когда включён, если райдер останавливает поездку до достижения обоих порогов — бэкенд отменяет и возвращает деньги. Защита от провалившейся разблокировки

## Где применяется Tariff

1. Оператор создаёт / редактирует **Tariff** здесь
2. Оператор привязывает тариф к **Vehicle Model** в [Vehicle Settings](vehicle-settings.md)
3. Транспорт назначенный этой модели наследует тариф
4. Когда райдер стартует поездку, бэкенд **снапшотит тариф** в ride-запись и использует этот snapshot для всех расчётов

> **Snapshot — самое важное.** Редактирование или удаление тарифа позже **не** меняет ретроактивно завершённые или активные поездки. Breakdown который вы видите в [Ride Detail](../../operations/trips/ride-detail.md) рассчитывается из значений тарифа **на момент старта поездки** — так Ridewolf обеспечивает аудитируемость биллинга.

## Действия в шапке

- **Auto-refresh** — обновляет список (клик или интервал, см. [Auto-refresh](../../features/ux/notifications.md))
- **Export** — открывает диалог экспорта (текущая страница · все отфильтрованные · конкретные страницы). На выходе `vehicle-tariffs-export.json`
- **+ Create** — открывает форму создания. Видна только при наличии под-права **Create Tariff**

## Действия над строкой

Меню `⋯` в каждом ряду:

- **View details** — открывает `/settings/vehicle-tariffs/:id` (всегда доступно)
- **Edit** — открывает `/settings/vehicle-tariffs/:id/edit` (требует под-право `edit`)
- **Delete** — открывает confirm с задержкой 3 секунды; на подтверждение тариф удаляется (требует под-право `delete`)

> **Delete с осторожностью.** Vehicle Models указывающие на удалённый тариф нужно будет переназначить на другой тариф перед стартом новых поездок на этом транспорте. Существующие ride-записи сохраняют свой snapshot.

## Quick edit (Tags / Status)

Клик прямо на **Tags**-чипы или **Status**-бейдж в любом ряду → открывается мини-диалог позволяющий изменить только эти поля без захода в полную форму. Toast подтверждает, таблица обновляется.

## Форма Create / Edit

И `/settings/vehicle-tariffs/create`, и `/settings/vehicle-tariffs/:id/edit` имеют одинаковый layout: слева карточка с инпутами, справа сайдбар **Field Guide** с контекстной подсказкой и **live-превью** введённых значений (имя, тип, базовая цена, start/distance, пауза, резервация, теги, discount-уровни).

### Обязательные поля

| Поле           | Обязательное | Валидация                                  |
| -------------- | ------------ | ------------------------------------------ |
| **Name**       | да           | Не пустое                                  |
| **Type**       | да           | Один из 4 вариантов                        |
| **Status**     | да           | Один из `active` / `inactive` / `archived` |
| **Base price** | да           | `>= 0`                                     |

Все остальные денежные поля дефолтятся в `0` и принимают `0` (фактически "feature отключена").

### Секции

1. **Identity** — Name, Description (Markdown), Type, Status, Tags
2. **Pricing** — Base price, Ride-start price, Distance price, Pause price, Paid reservation price, Reservation time (минуты)
3. **Auto-refund** — Toggle. Когда включён, заполните `Distance` (метры) и `Time` (секунды). Оба порога должны быть преодолены прежде чем поездка считается стартовавшей; иначе авто-отмена с возвратом
4. **Discount tiers** — Три уровня. Каждый: `Discount %` (0-100) и `After units` (сколько единиц должно пройти прежде чем скидка активируется). Оставьте уровень в нулях чтобы пропустить

### Поведение при сохранении

- **Create** → toast "created", редирект на детальную страницу
- **Edit** → toast "updated", редирект на детальную страницу
- **Несохранённые изменения** отслеживаются через snapshot-diff. Уход со страницы (cancel / back) открывает confirm если что-то изменено

> **Маппинг статусов на бэкенд.** Значение формы `archived` отправляется на бэкенд как `deleted` — это внутреннее имя. Операторы видят `archived` везде в UI.

## Детальная страница

`/settings/vehicle-tariffs/:id` показывает шапку с меткой тарифа, status-бейдж, действия **Edit** и **Delete**, три overview stat-карточки (Status / Created / Updated), затем карточку **Details** с:

- Identity-полями (Name, Type, Status, Base price, даты)
- **Description** отрендеренный из Markdown
- **Pricing** — grid-вид всех 5 денежных ставок (`TariffPriceGrid`)
- **Auto-refund** — enabled/disabled бейдж, плюс два порога если активно
- **Discount tiers** — визуальная разбивка трёх уровней (`TariffDiscountTiers`)
- **Tags** — резолвнутые тег-чипы (только если есть)
- **System info** — полный ID, created/updated таймстампы

## Как snapshot управляет Ride breakdown

Когда вы открываете [Ride Detail](../../operations/trips/ride-detail.md), карточка **Breakdown** рассчитывается из:

- `ride.tariff` — snapshot вшитый в поездку на момент старта
- Live телеметрии поездки (длительность, расстояние, время паузы, время резервации)

Математика которую бэкенд зеркалит локально:

- **Base** — `units × Base price`, где `units` = секунды (per-minute) или ceil-ные дни/месяцы для ceil-based типов
- **Unlock fee** — плоский `Ride-start price`, один раз
- **Distance** — `км × Distance price`
- **Pause** — `минуты паузы × Pause price`
- **Reservation** — первые `Reservation time` минут бесплатно, затем `платные минуты × Paid reservation price`
- **Discount tiers** применяются поверх после прохождения порогов

Если вы исправите опечатку в тарифе сегодня, **вчерашние поездки не затронуты** — их breakdowns всё ещё показывают старые цифры, потому что snapshot — источник истины.

## Workflows

- **Запуск новой схемы цен** — создайте тариф (Status `Inactive`) → ревью с финансами → переведите в `Active` → привяжите к соответствующей Vehicle Model в [Vehicle Settings](vehicle-settings.md)
- **Сезонная промо** — продублируйте существующий тариф (вручную: создать новый + скопировать поля), измените `Base price`, дайте имя с датой (например, `Summer 2026 — Scooter`), привяжите к модели на окно промо, верните обратно после
- **Тюнинг auto-refund** — начните с консервативными порогами (малое расстояние + короткое время) чтобы провалившиеся unlock'и не биллились, затем ослабьте если видите false-positive рефанды в [Rides](../../operations/trips/rides.md)
- **Вывод старого тарифа** — установите Status в `Archived` (отправляется как `deleted` на бэкенд) когда ни одна Vehicle Model его не использует. Старые поездки сохраняют snapshot — архивация безопасна
- **Переименование для ясности** — Name это просто метка. Переименования влияют на новые ride-snapshots с этого момента; завершённые поездки сохраняют старое имя в breakdown

## Tips

- **Snapshot, snapshot, snapshot** — когда сомневаетесь в цене исторической поездки, смотрите `ride.tariff.*` в [Ride Detail](../../operations/trips/ride-detail.md), а не текущий тариф в этом списке
- **Не Delete — Archive** — Archived-тарифы остаются в БД (server-side soft-delete) и резолвятся из старых ride-snapshots. Hard `Delete` нормален только для не использовавшихся черновиков
- **Используйте live-превью Field Guide** — правый сайдбар показывает посчитанные тоталы пока вы печатаете, это быстрый способ проверить новый тариф перед сохранением
- **Type важен для математики** — переключение с `per-minute` на `per-hour` не авто-масштабирует `Base price`; нужно пересчитать вручную (1 минута @ €0.20 ≠ 1 час @ €0.20)
- **Discount tiers последовательны** — `After` в тех же единицах что и `Type`. Уровень с `After: 30, Discount: 10 %` на `per-minute` тарифе означает "с минуты 30 заряжаем 90 % от базы". Три уровня стэкаются по порядку — выигрывает максимально применимый
- **Тегируйте тарифы** — теги проходят в Vehicle Model и помогают фильтровать в этом списке. Типичные метки: `Scooter`, `Bike`, `Promo`, `Legacy`
