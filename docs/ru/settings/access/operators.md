# Операторы

Страница Операторы (`/settings/operators`) — это **справочник персонала**: каждый сотрудник с доступом к дашборду. У каждого оператора есть роль (см. [Роли](roles.md)), опциональные метаданные department / position, теги для фильтрации и статус (Active / Inactive).

В отличие от [Клиентов](../../operations/customers/clients.md) (ваши клиенты) — Операторы это **внутренняя команда** управляющая платформой.

Требуется право: **Operators** (`t4u5v6`). Под-права гейтят edit действия.

## Откуда сюда попадают операторы

Операторы создаются вами (админом) через кнопку **+ Создать** — самостоятельной регистрации нет:

1. **+ Создать** открывает форму — имя, email, роль, опциональные department / position / tags
2. Новый оператор получает email с инструкцией для входа и временным паролем
3. Он входит, заполняет профиль (`/profile`), и может начинать работу на основе прав своей роли
4. Inactive-операторы не могут войти — выставляйте Inactive когда сотрудник уходит

## Фильтры

| Фильтр | Тип          | Заметки                                              |
| ------ | ------------ | ---------------------------------------------------- |
| Search | Текст        | Ищет по имени, email, position, department           |
| Status | Дропдаун     | `Active` / `Inactive` (или `All`)                    |
| Tags   | Multi-select | Фильтр по тегам операторов (например, "Night shift") |

## Колонки

| Колонка        | Сортировка? | Содержимое                                                  |
| -------------- | ----------- | ----------------------------------------------------------- |
| **User**       | ✓           | Аватар + имя/фамилия + email; ссылка на деталь оператора    |
| **Role**       | —           | Пилюля роли (ссылка на [Роли](roles.md)) |
| **Department** | —           | Опциональный department                                     |
| **Position**   | —           | Опциональный position                                       |
| **Tags**       | —           | Теги навешенные на оператора                                |
| **Status**     | ✓           | `Active` (зелёная) / `Inactive` (серая)                     |

## Действия над строкой

Меню из трёх точек. Доступные действия зависят от прав:

| Действие         | Право  | Что делает                                                  |
| ---------------- | ------ | ----------------------------------------------------------- |
| **View details** | —      | Открыть детальную страницу оператора                        |
| **Edit**         | `edit` | Открыть форму редактирования (имя, роль, department и т.д.) |

Действия **Delete нет** — записи операторов хранятся для аудита. Чтобы заблокировать вход, поставьте Inactive через Edit.

## Детальная страница

Клик по строке (или _View details_) открывает детальную с:

- Личная инфа (имя, email, телефон, фото)
- Роль + snapshot прав
- Department / position / tags
- Статус
- Activity log (события входа, смены роли)

Edit отсюда или из row-меню — оба ведут к одной форме.

## Форма Create / Edit

**Operator form** (`+ Create` или _Edit_):

- **First name / Last name** (обязательное)
- **Email** (обязательное, уникальное)
- **Role** (обязательное, дропдаун доступных ролей — см. [Роли](roles.md))
- **Department / Position** (опциональные)
- **Tags** (опциональный multi-select)
- **Status** (Active / Inactive)
- Только Create: **начальный пароль** или auto-generated отправляется на email

Save валидирует и пишет в audit-лог. Новые операторы автоматически получают welcome-email.

## Типичные сценарии

- **Онбординг нового сотрудника** — `+ Create` → имя/email/роль → Save → подтвердить welcome-email → попросить войти и заполнить профиль
- **Смена роли после повышения** — Edit → сменить Role → Save (новые права вступают в силу при следующем запросе оператора, не retroactively)
- **Уход сотрудника** — Edit → Status = Inactive → Save (запись остаётся для аудита; вход заблокирован)
- **Tag-based planning смен** — теги типа "Night shift" → фильтр по тегу = кто на смене

## Полезные приёмы

- **Role — мощное поле** — будьте осторожны при смене. Понижение с Admin до Support убирает write-доступ немедленно
- **Inactive ≠ Deleted** — история сохраняется; верните Active чтобы восстановить доступ
- **Список сортирован по имени по умолчанию** — много операторов? Ищите по email или department вместо скролла
- **Теги тут отличаются от тегов клиентов** — operator-scoped (например, "Night shift", "Trainer") и не делят namespace
- **Самоограничения** — нельзя менять свою роль из row-меню; используйте Profile
