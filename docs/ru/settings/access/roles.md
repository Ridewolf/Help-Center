# Роли

Страница Роли (`/settings/roles`) — где вы определяете **что операторы могут делать** в дашборде. Роль — это именованный набор прав; у каждого оператора ровно одна роль; права определяют какие страницы он видит и какие действия может выполнять.

Парно с [Операторы](operators.md) — Операторы назначают роли людям, Роли определяют что каждая роль может.

Требуется право: **Roles** (`d4e5f6`).

## Как работают права

Каждая страница и действие в дашборде стоит за **permission ID** (например, `k7m8n9` для Vehicles, `e4f5h6` для Clients). Роль — это checklist этих permission ID:

- Оператор видит страницу только если у его роли есть это право
- Row action (Edit, Delete и т.д.) скрыт если у роли нет матчинг-под-права
- Права проверяются **на каждый request** — смените роль и оператор увидит изменение при следующей загрузке страницы (или раньше)

**Наследования между ролями нет** — каждая роль независима. Высокий-trust роли просто имеют длиннее список прав.

## Default vs Custom роли

Роли бывают двух типов:

| Тип         | Редактируема? | Назначение                                                                |
| ----------- | ------------- | ------------------------------------------------------------------------- |
| **Default** | Нет           | Поставляется с платформой (Owner, Admin). Гарантирует безопасный baseline |
| **Custom**  | Да            | Создаётся вами — под структуру команды                                    |

**Owner / Admin** default-роли нельзя редактировать или удалить — это safety net. Custom-роли — где вы настраиваете под реальные ответственности.

## Фильтры

| Фильтр | Тип      | Заметки                           |
| ------ | -------- | --------------------------------- |
| Search | Текст    | Ищет по имени роли и описанию     |
| Status | Дропдаун | `Active` / `Inactive` (или `All`) |

## Колонки

| Колонка         | Сортировка? | Содержимое                                                              |
| --------------- | ----------- | ----------------------------------------------------------------------- |
| **Role name**   | ✓           | Метка роли                                                              |
| **Description** | —           | Короткий текст объясняющий для чего роль                                |
| **Type**        | —           | Default / Custom бейдж                                                  |
| **Permissions** | —           | Счёт выданных прав (например, "23 / 84")                                |
| **Trust score** | ✓           | Числовой score показывающий насколько роль мощная (выше = больше может) |
| **Created**     | ✓           | Когда роль создана                                                      |

### Trust score

Trust score — грубый числовой proxy "насколько опасен permission-set этой роли" — используется для сортировки и визуальных подсказок. Роль с delete + bulk-update + permission-management имеет выше trust score чем view-only. Нет фиксированной шкалы; считайте относительной мерой внутри своего списка ролей.

## Действия над строкой

Меню из трёх точек.

| Действие         | Право    | Что делает                                                                    |
| ---------------- | -------- | ----------------------------------------------------------------------------- |
| **View details** | —        | Открыть детальную страницу роли с полной разбивкой прав                       |
| **Edit**         | `edit`   | Открыть форму редактирования (disabled с toast для Default ролей)             |
| **Delete**       | `delete` | Soft-delete роли (с подтверждением; только Custom; только если ни у кого нет) |

Если роль в использовании, система откажется Delete и скажет сколько операторов её ещё имеют — перепривяжите их сначала.

## Форма Create / Edit

Форма роли раскладывает каждое право, сгруппированное по domain (Operations, Support, Analytics, Settings и т.д.) с чекбоксами.

Ключевые поля:

- **Name** (обязательно, уникально)
- **Description** (опционально но рекомендуется)
- **Status** (Active / Inactive)
- **Permission tree** — page-level и sub-permissions, сгруппировано по domain

Когда выключаете top-level page permission, все под-права принудительно выключаются (оператор теряет страницу целиком). Включая page permission даёте view-only по умолчанию — потом opt-in на _create_, _edit_, _delete_ и т.д. под-права индивидуально.

Маленький **Trust score** индикатор обновляется по мере отметок — полезно для сверки с похожими ролями.

## Детальная страница роли

Клик по строке открывает детальную страницу:

- Name, description, type, status
- Trust score
- Полный список прав (read-only, сгруппирован по domain)
- Activity log: когда создана, последний edit, кем
- Список операторов в данный момент назначенных (с ссылками на профили)

## Типичные сценарии

- **Создать новую команду** — `+ Create` → имя (например, "Field-team lead") → отметить нужные права → Save → назначить роль соответствующим [операторам](operators.md)
- **Сузить существующую роль** — найти роль в списке → Edit → снять чекбоксы лишних прав → Save (операторы с ролью теряют доступ при следующем запросе)
- **Повысить тиммейта** — идите в [Операторы](operators.md) → Edit → сменить Role → Save (не отсюда)
- **Аудит кто может удалять транспорт** — открыть список → сорт по Trust score → пройти каждую роль на Edit / Delete sub-permissions на Vehicles
- **Вывести роль из эксплуатации** — убедиться что ни у кого её нет ([Операторы](operators.md) фильтр по роли) → Delete

## Полезные приёмы

- **Меньше — лучше** — начинайте с view-only и добавляйте конкретные действия; не копируйте более высокую роль и не подрезайте
- **Тестируйте impersonation** (где поддерживается) — до деплоя роли войдите как тестовый оператор с ней и попробуйте workflows
- **Default-роли — ваш fallback** — Owner / Admin всегда есть; случайно заблокировались в Custom — Admin восстановит
- **Trust score — намёк, не правило** — две роли с одинаковым score могут делать очень разное; всегда смотрите на actual permission tree
- **Права evaluated server-side** — выключение в роли не убирает текущую сессию оператора, но следующий request попадёт в deny
- **Документируйте Custom-роли** в Description — через полгода "Fleet manager (read + edit, no delete)" — спасение
