# Аналитика — Платежи

Страница аналитики платежей (`/analytics/payments`) — это ваш **финансовый дашборд**: KPI и графики по деньгам входящим (top-ups), исходящим (refunds), списаниям (debits) и здоровью платёжной системы.

В отличие от [истории платежей](../../operations/payments/payments.md) — там per-transaction ledger, а здесь данные **агрегированы** по периоду, чтобы видеть тренды, утечки и аномалии.

Требуется право: **View Payments Analytics** (`w7x8y9`).

## Период

Сверху страницы — **date-range bar**. Все метрики и графики используют его:

- Выбирайте preset (Сегодня, 7 / 30 / 90 дней, Этот / Прошлый месяц) или custom-диапазон
- Comparison-бейдж под карточками читается как "vs предыдущий период" — для _Last 7 days_ сравнение = 7 дней до этого
- Период sticky для сессии: уйдёте и вернётесь — выбор сохранён

## Секции

Страница организована в **шесть секций**, каждая под свой угол платежей:

### 1. Flow

Большая картина — деньги в vs деньги из.

| KPI            | Что измеряет                                                                                                |
| -------------- | ----------------------------------------------------------------------------------------------------------- |
| **Top-ups**    | Деньги зачисленные на кошельки за период (manual + provider)                                                |
| **Refunds**    | Деньги вернувшиеся клиентам; бейдж _Refund rate_ (refunds / debits)                                         |
| **Debits**     | Деньги списанные с клиентов (поездки, штрафы). Включает **tag filter** для конкретного tag (например _VIP_) |
| **Net inflow** | Top-ups − Refunds; положительный = float растёт                                                             |

### 2. Quality

Здоровье интеграции с платёжным провайдером.

| KPI                 | Что измеряет                                                                                    |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| **Success rate**    | Completed / все попытки — основное число надёжности                                             |
| **Failed**          | Счёт failed-транзакций за период                                                                |
| **Pending**         | Счёт всё ещё pending (сверьте с [Pending Webhooks](../../operations/payments/pending-webhooks.md)) |
| **Refunded**        | Счёт debits завершившихся возвратом                                                             |
| **Failure reasons** | График разбивки failures по причинам (decline / 3DS / network и т.д.)                           |

Всплеск _Failed_ + доминирующая причина в графике = outage или integration-проблема для эскалации.

### 3. Balance

Состояние operator-held средств (кошельки райдеров) на конец периода.

| KPI               | Что показывает                                                            |
| ----------------- | ------------------------------------------------------------------------- |
| **Float**         | Сумма всех положительных балансов — деньги которые вы держите за райдеров |
| **Debt**          | Сумма всех отрицательных — долги райдеров                                 |
| **Avg balance**   | Средний баланс на активного клиента                                       |
| **Users**         | Счёт клиентов с ненулевым балансом                                        |
| **Buckets chart** | Histogram клиентов по размеру баланса (0–10 / 10–50 / 50–100 / 100+)      |

Используйте _Debt_ как сигнал collections-бэклога — большой долг = много штрафов или failed debits для follow-up.

### 4. Patterns

Поведенческие паттерны top-ups — полезно для маркетинга / продукта.

- **Top-up size histogram** — как райдеры распределяют top-ups по суммам. Мода (самый частый размер) = дефолт для предложений в приложении
- **Top-ups by hour** — когда в течение дня райдеры пополняют. Пики обычно совпадают с пиками поездок (commute, weekend evenings)

### 5. Methods

Таблица разбивки по **методу / провайдеру оплаты**.

- Колонки: Method (card / balance / wallet и т.д.), Total amount, Count, Average transaction, Success rate
- Полезно для поиска отстающих провайдеров (метод с низким success rate = ваше слабое звено)

### 6. Users

Cohort-вид клиентов — кто вам платит.

| KPI               | Что измеряет                                                               |
| ----------------- | -------------------------------------------------------------------------- |
| **Unique payers** | Уникальные клиенты заплатившие за период                                   |
| **New payers**    | Клиенты заплатившие впервые в этом периоде                                 |
| **Repeat payers** | Клиенты заплатившие больше одного раза                                     |
| **Top payers**    | Таблица самых платящих клиентов: имя, сумма, ride count, ссылка на профиль |

## Типичные сценарии

- **Еженедельный обзор** — preset _Last 7 days_ → пройтись по каждой секции. Всё что выпадает за comparison-ribbon (большой ▲ или ▼) — углубляйтесь
- **Post-mortem инцидента** — date range на день инцидента → Quality → Failure reasons → сверка с [Payments history](../../operations/payments/payments.md) на конкретные транзакции
- **Tag deep-dive** — карточка Debits → tag-фильтр → выбрать _VIP_ → метрика показывает только этот cohort; сравнить с общим debits для быстрой доли
- **Collections push** — Balance → _Debt_ → если выросло, копайте отдельных клиентов через Clients-список с negative balance
- **Marketing pricing** — Patterns → Top-up size histogram → ставьте suggested top-up на самый частый bucket

## Полезные приёмы

- **Comparison ribbon важнее абсолютного числа** — абсолют зависит от размера компании; % изменения говорит улучшается ли ситуация
- **Sticky date range** — последний выбранный диапазон сохраняется при навигации; если коллега шарит URL с другим диапазоном — тот побеждает
- **Tag-фильтр только на Debits** — top-ups по тегу смотрите через Clients-список
- **Failure reasons — scorecard провайдера** — новая категория причины = смена конфига провайдера
- **Net inflow positive ≠ прибыль** — это wallet float, не выручка; не учитывает будущие refunds или unsettled balances
- **Average balance × Users ≠ Float** — Float = сумма положительных; если много в долгах, Avg ниже чем Float / Users
