# Аналитика — Транспорт

Страница аналитики транспорта (`/analytics/vehicles`) — это **дашборд здоровья флота**: сколько у вас транспорта, как они работают, состояние батарей, проблемы и разбивки по типу и зоне.

В отличие от [списка транспорта](../../operations/fleet/vehicles.md) — там per-unit оперативный вид; здесь **агрегированные метрики флота** за период.

## Период

Сверху **date-range bar**. Trend-графики используют весь период; overview / status counts отражают **текущее состояние** (конец периода).

## Секции

Семь секций, сверху вниз:

### 1. Overview

Top-level состав флота.

| KPI               | Что показывает                                                 |
| ----------------- | -------------------------------------------------------------- |
| **Total**         | Все зарегистрированные                                         |
| **Active**        | Доступны для аренды прямо сейчас                               |
| **Idle**          | Стоят, не используются (могут быть Available, low-utilization) |
| **Off-service**   | В Maintenance / Storage / Not ready — не зарабатывают          |
| **Lost / Stolen** | Status = Stolen или off-grid дольше порога                     |

Используйте как headline-снимок флота.

### 2. Performance

Как хорошо флот **зарабатывает** для вас.

| KPI                   | Что показывает                                               |
| --------------------- | ------------------------------------------------------------ |
| **Earning vehicles**  | Транспорт сделавший хотя бы одну поездку за период           |
| **Dormant vehicles**  | Active-транспорт с нулём поездок (waste)                     |
| **Rides per vehicle** | Среднее поездок на транспорт за период                       |
| **Utilization**       | Часов в аренде / часов доступности (бенчмарк отрасли: 5-15%) |

Dormant на Active — худший вид: тратите операционные расходы без выручки.

### 3. Battery

Здоровье батарей по флоту.

| KPI / График     | Что показывает                                               |
| ---------------- | ------------------------------------------------------------ |
| **Avg level**    | Средний % батареи по всем транспортам сейчас                 |
| **Critical**     | Счёт ниже критического порога (10-20%)                       |
| **Avg trend**    | Средняя за период — падает = swaps не успевают               |
| **Distribution** | Histogram по бакетам (0-20 / 20-40 / 40-60 / 60-80 / 80-100) |
| **Swaps**        | Счёт операций swap за период                                 |

Если Avg падает а Critical растёт — полевая команда не успевает; добавьте swaps.

### 4. Problems

Alerts и операционные проблемы по флоту.

| KPI             | Что показывает                                                |
| --------------- | ------------------------------------------------------------- |
| **Alerts**      | Всего alerts за период                                        |
| **Alert types** | Разбивка по типу (battery / connectivity / mechanical и т.д.) |
| **Critical**    | Critical-severity alerts                                      |
| **Maintenance** | Транспорт в статусе Maintenance                               |
| **Offline**     | Транспорт, IoT которого не отчитывался дольше порога          |

Парно с [Recent Events](events.md) для per-event-вида.

### 5. Trends

Time-series графики — как **Active**-счёт двигался за период. Падение = массовая смена статуса (move-to-maintenance, погода, recall).

### 6. By Type

Разбивка по **типу транспорта** (самокат / велосипед / e-bike и т.д.). Для каждого: счёт, earning ratio, utilization, alert rate.

Если один тип доминирует в alerts — **модель** имеет проблему, не операционная команда.

### 7. By Zone

Разбивка по **зонам**. Для каждой: счёт, utilization, problem rate.

Зоны с низким utilization и большим inventory = **возможность ребаланса** (см. также [Rebalance analytics](../../operations/rebalance/runs.md)).

## Типичные сценарии

- **Еженедельный обзор флота** — Overview snapshot → Performance (тренд utilization) → Battery (растёт ли critical?) → Problems (всплески alerts) → Trends (необъяснимый dip Active?)
- **Cleanup dormant** — Performance → счёт Dormant → если растёт, ищите конкретный транспорт через [список](../../operations/fleet/vehicles.md) и проверьте статус / локацию
- **Battery emergency** — секция Battery → Critical растёт + Avg падает → надо подкручивать полевую
- **Detect bad model** — By Type → какой тип имеет худший alert rate → рассмотреть phase out / переговоры с производителем
- **Ребалансировка** — By Zone → low-utilization + high-inventory зоны → планируйте redistribution
- **Pre-shift планирование** — Trends + Patterns из [Events](events.md) → какие дни / часы требуют больше field staff?

## Полезные приёмы

- **Active + Idle + Off-service + Lost/Stolen = Total** — если математика не сходится, статусы в переходе; рефреш или стабильная дата
- **Active ≠ earning** — Active = "может быть арендован"; Earning = "был арендован". Сравнивайте оба
- **Utilization выше 25% — нездорово** — райдеры не могут найти транспорт; добавьте inventory в зону
- **Utilization ниже 5% — мёртвый груз** — стоимость содержания превышает выручку; rebalance или pull
- **Critical battery + Avg trend** — оба вместе = ранняя сигнализация; одно — шум
- **Lost / Stolen залипает** — требует ручной смены статуса; восстановили украденный — обновите
- **By Type и By Zone вместе** — иногда тип ломается только в одной зоне (terrain mismatch); cross-cut раскрывает
