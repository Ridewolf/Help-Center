# Rebalance — Dead Zones

Страница Dead Zones (`/rebalance/dead-zones`) — это **таргетинг-борд полевых операций**: где inventory стоит idle, сколько денег это стоит, и в какие районы отправлять rebalance-фургон следующим.

В отличие от страницы [Аналитика — Rebalance](runs.md), которая суммирует активность полевой команды во времени, эта страница смотрит вперёд: отвечает на вопрос _куда едем сейчас?_

Право доступа: авторизованный оператор (роут требует только _requiresAuth_, без специфического permission ID).

> Заметка — на момент написания backend-endpoint `/rebalance/dead-zones` ещё не подключён. Страница рендерится с моковыми KPI (нет зон в таблице), а per-row действия (_Create run_, _Set park time limit_, _Dynamic pricing_, _Zone surgery_, _Mark no-parking_, _Reduce supply target_, _A/B experiment_) сейчас выключены. Фильтры, KPI и раскладка таблицы работают — ждут только бэкенда.

## Что значит "dead zone"

**Dead zone** — это городская область где транспорт слишком долго стоит припаркованным без аренды. Страница идентифицирует такие зоны и ранжирует их так чтобы полевая команда знала, какие кластеры разбивать в первую очередь.

Система поддерживает два способа бакетизации карты:

- **Owner zones** — ваши собственные настроенные полигоны из [Настройки — Зоны](../../settings/infrastructure/zones.md)
- **H3 grid** — гекс-сетка Uber, используется для более мелкого разрешения или zone-agnostic анализа

Переключатель — в блоке фильтров; таблица показывает одни и те же колонки в обоих режимах.

## KPI-ряд (сверху)

Ряд из пяти KPI-карточек суммирует ситуацию с dead zones по тому что вы отфильтровали.

| KPI                 | Что показывает                                                                           |
| ------------------- | ---------------------------------------------------------------------------------------- |
| **Dead zones**      | Количество зон / cells сейчас помеченных как dead                                        |
| **Lost / day**      | Расчётная потерянная выручка в день — сумма `lostRevenuePerDay` по отфильтрованным зонам |
| **Devices trapped** | Всего idle-устройств застрявших в dead zones — ваша физическая цель для pickup           |
| **Avg dwell**       | Среднее dwell time (минуты) по dead zones — сколько транспорт стоит до перемещения       |
| **Weekly progress** | Изменение в % vs прошлая неделя — минус = хуже; плюс = лучше                             |

Каждый KPI обновляется по фильтрам; используйте их как single-number gut-check до того как drill into list.

## Режимы — Map vs Table

Переключатель в правом верхнем углу меняет вид одних и тех же данных:

- **Map** — географический вид dead zones поверх карты города (сейчас плейсхолдер _coming soon_)
- **Table** — таблица ниже со всеми колонками и per-row контекстом

Фильтры применяются к обоим видам. _Table_ — по умолчанию; _Map_ заведён но географический рендер ещё в работе.

Рядом с переключателем — контрол _Auto-refresh_: включите чтобы пере-poll-ить данные на интервале (полезно для live-ops).

## Фильтры

В блоке четыре контрола; все AND-ятся:

| Фильтр        | Тип      | Опции                                                                          |
| ------------- | -------- | ------------------------------------------------------------------------------ |
| **City**      | Dropdown | _All cities_ / _Moscow_ / _Saint Petersburg_ — выбрать одну operating city     |
| **Severity**  | Dropdown | _All_ / _Low_ / _Medium_ / _High_ / _Critical_ — на основе zone severity score |
| **Zone type** | Dropdown | _Owner zones_ / _H3 grid_ — какая бакетизация                                  |
| **Search**    | Текст    | Свободный текст — матчит имя зоны / district                                   |

Кнопка _Clear all_ справа от карточки фильтров сбрасывает всё в один клик.

## Колонки

В Table-виде девять колонок. Клик по строке открывает insight drawer (сейчас показывает toast с именем зоны как плейсхолдер).

| Колонка              | Содержимое                                                                                      |
| -------------------- | ----------------------------------------------------------------------------------------------- |
| **Zone / Cell**      | Имя зоны плюс city и district снизу; для H3-режима — hex ID                                     |
| **Idle ratio**       | % времени когда в зоне idle-устройства, цвет: зелёный `< 25%`, жёлтый `25–40%`, красный `≥ 40%` |
| **Dwell**            | Median dwell time в минутах, с _p90_ снизу                                                      |
| **Avg idle devices** | Среднее количество idle-устройств в зоне, с _Target_ supply для сравнения                       |
| **Starts**           | Старты поездок в зоне за _last 24h_ / _last 7d_ / _last 30d_                                    |
| **Conversion**       | Starts per idle device per hour — зелёный `≥ 0.30`, жёлтый `0.15–0.30`, красный `< 0.15`        |
| **Oversupply**       | Устройства сверх target — плюс = слишком много, минус = недостаточно; плюс красным              |
| **Lost / day**       | Расчётная потерянная выручка для этой зоны в день                                               |
| **Last seen idle**   | Когда зона последний раз имела idle-устройства — формат по локали                               |

Строки кликабельны; сортировка по колонкам пока не подключена в этой итерации.

## Per-row действия

У каждой строки есть click handler который сейчас показывает toast с именем зоны. Полное **меню действий (per row)** реализовано в коде, но выключено пока нет API. Запланированные действия для справки — они появятся в three-dot меню справа когда включат:

| Запланированное действие | Что будет делать                                                       |
| ------------------------ | ---------------------------------------------------------------------- |
| **Create run**           | Открыть rebalance run builder pre-populated этой зоной                 |
| **Set park time limit**  | Сократить максимальное время парковки внутри зоны                      |
| **Dynamic pricing**      | Применить ценовые рычаги чтобы привлечь / отвлечь старты или окончания |
| **Zone surgery**         | Редактировать границы зоны (split, merge, reshape)                     |
| **Mark no-parking**      | Конвертировать зону в no-parking чтобы вытолкнуть транспорт            |
| **Reduce supply target** | Понизить device target чтобы система перестала слать сюда транспорт    |
| **A/B experiment**       | Поставить контролируемый эксперимент стратегии исправления             |

Пока endpoint не подключён, рассматривайте таблицу как **read-only insight surface** — комбинируйте с Vehicles-листом чтобы action транспорт индивидуально.

## Empty / loading состояния

- **Loading** — спиннер с "Loading dead zones…" пока бэк отвечает
- **Error** — _Alert_-баннер с кнопкой _Try again_ если запрос упал
- **Empty** — центрированная _AlertTriangle_-иконка с "No dead zones"; это **ожидаемое состояние сегодня** так как endpoint не отдаёт данных

## Типичные workflows

- **Утреннее планирование** — Сортировать таблицу по _Lost / day_ (визуально сегодня; sortable-колонки придут): отобрать топ-3 зон на сегодняшние runs
- **Severity triage** — Фильтр _Severity = Critical_ чтобы увидеть только худшие, открыть каждую зону для контекста
- **City-by-city ops** — Фильтр _City_ при multi-city операциях; считать количество и total lost revenue отдельно
- **Cross-reference с флотом** — Использовать _Devices trapped_ из KPI-ряда, потом прыгнуть в [Список транспорта](../fleet/vehicles.md) с фильтром по зоне чтобы увидеть конкретные транспорты
- **Сравнение с аналитикой** — Сопоставить live-цифры здесь с секциями Dead Zones / Idle Devices на [Аналитика — Rebalance](runs.md) и [Аналитика транспорта](../../analytics/reports/vehicles.md) чтобы подтвердить тренд

## Tips

- **Conversion — самая операционная колонка** — низкая conversion (красный) с большим oversupply значит ребаланс зоны _не поможет_; supply у вас правильный, но demand нет
- **Idle ratio vs avg idle devices** — _idle ratio_ time-weighted (как часто зона idle), _avg idle devices_ count-weighted (сколько штук стоит). Оба красные = сильнейший dead-zone сигнал
- **_Target_ под _Avg idle devices_ берётся из конфига зоны** — если он выставлен неправильно, каждая зона будет выглядеть как dead; перепроверить в [Настройки — Зоны](../../settings/infrastructure/zones.md)
- **H3 grid полезен для unzoned cities** — если ещё не определили operator zones, H3 даёт дефолтную географическую бакетизацию
- **Weekly progress — это "выигрываем ли мы" индикатор страницы** — если dead zone count растёт, но revenue lost падает, полевая команда отрабатывает самые highest-value зоны первыми (хороший сигнал)
- **Action-хендлеры — стабы** — клик по строке сейчас только бросает info-toast; настоящий drawer / диалоги придут когда бэк готов
