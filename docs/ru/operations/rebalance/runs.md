# Rebalance — Runs

Страница Rebalance Runs (`/rebalance/runs`) — это **операционный лог каждого rebalance-trip**: кто водил какой van, из какого depot выехал, сколько scooters и батарей на борту, в графике ли он, и где что пошло не так.

**Run** — это одна смена полевой работы — водитель, van, depot, упорядоченный список stops, плановое ETA-окно. Страница позволяет диспетчерам мониторить active runs и ревьюить завершённые.

Эта страница — per-trip деталь, дополняющая верхнеуровневое summary [Аналитика — Rebalance](runs.md) и таргетинг-борд [Rebalance — Dead Zones](dead-zones.md).

Право доступа: авторизованный оператор (роут требует только _requiresAuth_, без специфического permission ID).

> Заметка — на момент написания CRUD-endpoints `/rebalance/runs` ещё не подключены. Страница рендерит блок фильтров, KPI-ряд и таблицу с моковыми KPI и пустым списком. _Create run_, _Search_, _Auto-refresh_ и per-row меню действий (_Dispatch_, _Reassign_, _Reoptimize_, _Print sheet_, _Export_, _Edit_, _Cancel_) в коде есть но закомментированы пока нет бэка. Клик по строке навигирует на `/rebalance/runs/:id`, но детальная страница не в этом билде.

## KPI-ряд (сверху)

Ряд из пяти KPI-карточек суммирует runs сегодня.

| KPI                | Что показывает                                                                       |
| ------------------ | ------------------------------------------------------------------------------------ |
| **Active runs**    | Runs сейчас в _Dispatched_ / _In progress_ / _Paused_                                |
| **On-time %**      | % runs попадающих в плановое ETA-окно; зелёный up ≥ 90%, красный down ниже           |
| **Late runs**      | Количество runs с флагом _Late_ по SLA — диспетчерский индикатор "кому нужна помощь" |
| **Total km today** | Кумулятивный пробег всех rebalance-vans сегодня                                      |
| **Battery swaps**  | Всего battery swaps полевой командой сегодня                                         |

Пять вместе дают one-glance картину как сегодняшняя полевая операция идёт vs план.

## Фильтры

В карточке _Filters_ четыре фильтра; все AND-ятся. Кнопка _Clear all_ справа сбрасывает блок.

| Фильтр            | Тип      | Опции                                                                                  |
| ----------------- | -------- | -------------------------------------------------------------------------------------- |
| **Status**        | Dropdown | _All_ / _Planned_ / _Dispatched_ / _In progress_ / _Paused_ / _Completed_ / _Canceled_ |
| **SLA risk**      | Dropdown | _All_ / _On track_ / _At risk_ / _Late_ — флаг опоздания run                           |
| **City**          | Dropdown | _All cities_ / _Moscow_ / _Saint Petersburg_                                           |
| **Has incidents** | Dropdown | _All_ / _Yes_ / _No_ — есть ли incidents на run                                        |

Свободный текстовый _Search_ (по номеру run, водителю или van) реализован, но скрыт вместе с _Auto-refresh_ и _Create run_ пока endpoint не подключён.

## Колонки

В таблице девять видимых колонок. Строки кликабельны — навигируют на `/rebalance/runs/:id` (детальный вид не в этом билде).

| Колонка               | Содержимое                                                                                                                      |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **Run #**             | Человеко-читаемый идентификатор (например `RUN-2026-0517-001`)                                                                  |
| **Driver / Van**      | Аватар водителя + имя + телефон; модель van + plate number снизу                                                                |
| **Depot / City**      | Имя depot и city                                                                                                                |
| **Status**            | Status-pill — серый _Planned_, синий _Dispatched_, зелёный _In progress_, жёлтый _Paused_, teal _Completed_, красный _Canceled_ |
| **Stops**             | Прогресс как `done / total`, с _Failed: N_ снизу красным когда есть failed                                                      |
| **Payload**           | Scooters загружены (`🛴 in / capacity`) и батареи загружены (`🔋 charged + depleted / capacity`)                                |
| **Planned**           | ETA start–end время + плановая дистанция (km) и duration (min)                                                                  |
| **SLA risk**          | Risk-pill — зелёный _On track_, жёлтый _At risk_, красный _Late_                                                                |
| **Created / Updated** | Created date сверху, last-updated снизу                                                                                         |

Колонка действий (three-dot) в коде есть, но закомментирована пока нет CRUD-endpoints; см. _Per-row действия_ ниже для запланированного набора.

## Status справочник

Run в одном статусе; статус определяет какие dispatch-действия доступны:

| Статус          | Значение                                             |
| --------------- | ---------------------------------------------------- |
| **Planned**     | Создан и запланирован, но ещё не отправлен водителю  |
| **Dispatched**  | Отправлен водителю / van — ждёт отправления          |
| **In progress** | Van движется и / или делает stops                    |
| **Paused**      | Водитель приостановил run (перерыв, инцидент и т.д.) |
| **Completed**   | Все stops отработаны, run закрыт                     |
| **Canceled**    | Прерван до завершения                                |

## SLA risk справочник

Real-time флаг попадания в плановое окно:

| Risk         | Значение                                           |
| ------------ | -------------------------------------------------- |
| **On track** | Текущий темп совпадает с плановым ETA              |
| **At risk**  | Тренд к опозданию, но в пределах исправимого       |
| **Late**     | План уже пропущен — нужно вмешательство диспетчера |

Используйте _SLA risk = Late_ как первый фильтр диспетчера утром.

## Per-row действия (запланированные)

Каждая строка получит three-dot меню справа со следующими действиями; сегодня колонка скрыта пока нет API.

| Действие        | Что будет делать                                                 |
| --------------- | ---------------------------------------------------------------- |
| **View**        | Открыть деталь run на `/rebalance/runs/:id`                      |
| **Dispatch**    | Перевести _Planned_ run в _Dispatched_, уведомив водителя        |
| **Reassign**    | Сменить водителя и / или van на run                              |
| **Reoptimize**  | Перезапустить route optimiser по оставшимся stops                |
| **Print sheet** | Сгенерить printable run sheet (driver-facing summary)            |
| **Export**      | Экспортнуть run-данные файлом (фильтры / сортировка учитываются) |
| **Edit**        | Открыть редактор run                                             |
| **Cancel**      | Отменить run — открывает confirmation-диалог                     |

## Empty / loading состояния

- **Loading** — спиннер с "Loading runs…" пока бэк отвечает
- **Error** — _Alert_-баннер с кнопкой _Try again_ если запрос упал
- **Empty** — центрированная _Truck_-иконка с "No runs found"; это **ожидаемое состояние сегодня** так как endpoint не отдаёт items

## Типичные workflows

- **Утренний dispatch sweep** — Фильтр _Status = Planned_, сортировка по дате создания, диспатчить каждый по порядку
- **Live мониторинг** — Фильтр _Status = In progress_, потом _SLA risk = Late_ чтобы поднять водителей которым нужна помощь; когда включат, _Auto-refresh_ держит вид свежим
- **End-of-day review** — Фильтр _Status = Completed_, сканировать колонку _Stops_ на runs с failed stops, клик в каждый для разбора инцидентов
- **City-by-city** — Фильтр _City_ при multi-city операциях; cross-check числа против [Аналитика — Rebalance](runs.md)
- **Incident triage** — Фильтр _Has incidents = Yes_ поднимает каждый run с проблемами сегодня
- **Capacity check** — Глянуть колонку _Payload_ на _In progress_ строках; van-ы близкие к capacity скоро вернутся в depot

## Tips

- **Run numbers — стабильные идентификаторы** — шейрите их с полевой командой для чёткой координации ("посмотри RUN-2026-0517-003")
- **Колонка Stops говорит правду одним взглядом** — `4/7` значит четыре сделано, три осталось; красное _Failed: N_ снизу = нужен follow-up
- **Payload "depleted" важен** — высокий depleted-battery count = van полон мёртвых батарей и должен заехать на зарядку
- **Created vs Updated** — _Updated_ тикает каждый раз когда водитель что-то делает с run; старый _Updated_ на _In progress_ строке = водитель давно не check-in-ил
- **Статус _Paused_ — не ошибка** — водители паузят на перерывы, инциденты, общение с райдерами; долго-paused runs стоит позвонить
- **Пока endpoint не подключён, рассматривайте страницу как layout / UX превью** — структура, фильтры и визуальный язык финальные; данных за ними ещё нет
