# Клиенты — Список

Список клиентов (`/clients`) — это ваша база клиентов: каждый человек, зарегистрировавший аккаунт в сервисе, с балансом, тегами, сводкой по поездкам и каналами связи.

Для работы с одним клиентом (полная история, действия с балансом, устройства, комментарии) откройте [страницу детали клиента](client-detail.md).

Требуется право: **Clients** (`e4f5h6`). Доп. под-права гейтят конкретные row и bulk действия.

## Как сюда попадают клиенты

Обычно клиентов не создаёте вы — они регистрируются через мобильное приложение:

1. Человек ставит **приложение Ridewolf rider** и регистрируется (телефон или email)
2. Бэкенд создаёт запись клиента; строка появляется здесь со статусом **Registering** пока идёт верификация (SMS, ID, способ оплаты)
3. После верификации статус меняется на **Active** — клиент может ездить
4. Операторы могут вручную создать клиента (например, для VIP или тестовых аккаунтов) через `+ Создать` — описано в статье _Create_

Список обновляется при перезагрузке или смене фильтров.

## Фильтры

| Фильтр     | Тип          | Заметки                                                     |
| ---------- | ------------ | ----------------------------------------------------------- |
| Search     | Текст        | Ищет по имени, телефону, email, ID клиента                  |
| Date range | Календарь    | Фильтр по **дате регистрации**; от / до                     |
| Status     | Дропдаун     | `Active` / `Blocked` / `Frozen` / `Registering` (или `All`) |
| Tags       | Multi-select | Фильтр по тегам навешенным на клиента                       |

Все фильтры И-комбинируются. Чипы появляются над таблицей; URL отражает состояние.

## Колонки

| Колонка       | Сортировка? | Содержимое                                                    |
| ------------- | ----------- | ------------------------------------------------------------- |
| **Client**    | ✓           | Аватар + имя/фамилия + телефон или email; ссылка на деталь    |
| **Channels**  | —           | Иконки верифицированных каналов связи (phone, email, social)  |
| **Balance**   | ✓           | Баланс кошелька в валюте компании, красный если отрицательный |
| **Tags**      | —           | Теги навешенные на клиента                                    |
| **Status**    | ✓           | Пилюля статуса (справка ниже)                                 |
| **Rating**    | ✓           | Средний рейтинг от райдеров (рейтинг водителя)                |
| **Rides**     | ✓           | Общее количество поездок за всё время                         |
| **Last ride** | ✓           | Когда клиент последний раз ездил                              |
| **Payment**   | —           | Иконка дефолтного способа оплаты (карта, кошелёк и т.д.)      |

Сортировка кликом по заголовку. Сорт попадает в URL.

## Справка по статусам

| Статус          | Значение                                                                         |
| --------------- | -------------------------------------------------------------------------------- |
| **Active**      | Полностью верифицирован, может ездить, можно списывать                           |
| **Blocked**     | Не может ездить; оператор-блокировка (фрод, abuse, долг) или системная           |
| **Frozen**      | Аккаунт на паузе (например, во время расследования спора или по запросу клиента) |
| **Registering** | Регистрация в процессе — телефон / email / ID / способ оплаты не верифицирован   |

## Действия над строкой

У каждой строки справа — **меню из трёх точек**. Доступные действия зависят от прав:

| Действие            | Право               | Что делает                                                                    |
| ------------------- | ------------------- | ----------------------------------------------------------------------------- |
| **View profile**    | —                   | Открыть [детальную страницу](client-detail.md)        |
| **Ride history**    | —                   | Открыть поездки клиента (срез глобального списка)                             |
| **Send SMS**        | —                   | Диалог отправки SMS на верифицированный телефон                               |
| **Send email**      | —                   | Диалог отправки email на верифицированный адрес                               |
| **Send push**       | —                   | Диалог отправки push-уведомления в приложение                                 |
| **Top up balance**  | `topup-manual`      | Диалог баланса — пополнить кошелёк клиента                                    |
| **Issue fine**      | `fine`              | Диалог штрафа — списать сумму из кошелька (за повреждение, парковку и т.п.)   |
| **Block / Unblock** | `block` / `unblock` | Диалог блокировки — переключить статус blocked с опциональной причиной        |
| **Edit**            | `edit`              | Открыть [форму редактирования](client-create-edit.md) |
| **Delete**          | `delete`            | Soft-удаление (с подтверждением; красный destructive)                         |

Действия без прав скрыты из меню.

## Bulk-действия

Выделите одного или больше клиентов чекбоксами слева. Сверху появится **bulk-бар** со счётчиком и действиями:

| Bulk-действие     | Право               | Что делает                                                                      |
| ----------------- | ------------------- | ------------------------------------------------------------------------------- |
| **Add balance**   | `topup-manual`      | Зачислить одинаковую сумму на каждый выделенный кошелёк (с подтверждением)      |
| **Charge amount** | `fine`              | Списать одинаковую сумму с каждого выделенного кошелька (например, event-штраф) |
| **Change status** | `block` / `unblock` | Поставить всем выделенным один статус (Active / Blocked / Frozen)               |
| **Send push**     | —                   | Отправить push всем выделенным клиентам сразу                                   |

Bulk-диалоги проведут вас через сумму / сообщение / статус, и применят ко всем выделенным одной операцией с финальным подтверждением.

## Действия страницы (сверху-справа)

- **+ Создать** — открывает [форму создания клиента](client-create-edit.md) (отдельная статья)

## Типичные сценарии

- **Расследовать жалобу на платёж** — поиск по телефону или email → открыть деталь → проверить баланс и историю поездок
- **Пополнить кошелёк по запросу клиента** — найти клиента, _Top up balance_ в меню строки, ввести сумму, подтвердить
- **Заблокировать мошенника** — найти клиента → _Block / Unblock_ → поставить Blocked с причиной; статус меняется, поездки невозможны
- **Отправить outage-SMS** — фильтр по зоне-тегу → _Выделить все_ → _Send push_ (или Marketing → SMS для не-срочного broadcast)
- **Аудит держателей тега** — фильтр по тегу, просмотр баланса и количества поездок на предмет outliers

## Полезные приёмы

- **Статус — тихий гейтер** — клиенты в _Registering_ / _Frozen_ / _Blocked_ не могут ездить; не ждите их в списке поездок
- **Иконки channels говорят что верифицировано** — отсутствие email-иконки = SMS единственный канал для клиента
- **Rating — это рейтинг клиента от райдеров** (не поездки) — низкий рейтинг часто = проблемы с парковкой или грубое поведение; сверяйте с park proofs и тикетами
- **Красный баланс** = отрицательный кошелёк. Клиент не может стартовать поездку пока не пополнит или не получит возврат
- **Права слоистые** — можно иметь право _Send SMS_ но не _Top up_ для того же клиента; меню показывает что можно
- **URL шарится** — копируйте отфильтрованный вид (например, _Blocked clients with rides > 0_) и отправляйте коллеге
