# Клиент — Создание и редактирование

Два URL:

- **Создание** — `/clients/create` — вручную зарегистрировать нового клиента (редко; большинство клиентов регистрируются сами)
- **Редактирование** — `/clients/:id/edit` — обновить личные данные и статус существующего клиента

К обоим попадают из [списка клиентов](clients.md) (кнопка `+ Создать` сверху-справа) или из [детали клиента](client-detail.md) (_Actions → Edit client_).

Права:

- **Создание** — `Clients` (`e4f5h6`) + create-связанное под-право
- **Редактирование** — `Clients` (`e4f5h6`) + под-право `edit`

## Когда использовать

Большинство клиентов **регистрируются сами** через мобильное приложение — в дашборде вы редко их создаёте.

Ручное создание для:

- **Тестовых аккаунтов** — внутренний QA, demo-юзеры
- **VIP / корпоративных** — аккаунты которые должны существовать до того, как клиент скачает приложение
- **Оператор-онбординг** — мероприятия / партнёрства, где персонал регистрирует от имени клиента

Для всего остального пусть приложение делает регистрацию, а **Edit** используйте для корректировки контактов или смены статуса.

## Структура

Одна карточка с вертикальной формой, без Field Guide sidebar (отличается от формы транспорта).

## Поля — Создание

Всего семь полей. Все обязательные.

| Поле                 | Валидация                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------ |
| **First name**       | 1–100 символов                                                                                         |
| **Last name**        | 1–100 символов                                                                                         |
| **Email**            | Стандартный формат email (`name@domain.tld`); должен быть уникальным среди клиентов                    |
| **Phone**            | Международный формат с `+` (например, `+373 60 123 456`); только цифры, пробелы, дефисы, скобки        |
| **Password**         | **Минимум 12 символов**, должен содержать **заглавную, строчную букву, цифру и спецсимвол**            |
| **Confirm password** | Должен точно совпадать с password                                                                      |
| **Status**           | Начальный статус: `Active` / `Inactive` / `Blocked` / `Frozen` / `Registering` (по умолчанию _Active_) |

Валидация работает при сохранении и inline когда покидаете поле. Ошибки появляются красным под полем.

### Правила пароля

Требование пароля — самое строгое. Дашборд отклонит любой пароль не прошедший все 4 проверки:

- ≥ 12 символов
- ≥ 1 заглавная буква (A–Z)
- ≥ 1 строчная буква (a–z)
- ≥ 1 цифра (0–9)
- ≥ 1 спецсимвол (например, `!@#$%^&*`)

После сохранения клиент будет использовать этот пароль (плюс телефон или email) для входа в мобильное приложение. Передавайте клиенту по верифицированному каналу — никогда не вставляйте пароли в чаты без end-to-end шифрования.

### Статус (при создании)

| Значение        | Использование                                                                  |
| --------------- | ------------------------------------------------------------------------------ |
| **Active**      | По умолчанию — клиент может ездить сразу                                       |
| **Inactive**    | Создан, но ещё не выпущен (позже переключите на Active)                        |
| **Blocked**     | Пре-блокирован (редко — обычно при пересоздании аккаунта после фрод-инцидента) |
| **Frozen**      | Аккаунт на паузе                                                               |
| **Registering** | Регистрация в процессе (только при интеграции с внешним flow)                  |

## Поля — Редактирование

Edit прячет поля пароля (пароли сбрасываются в другом месте) и добавляет **Tags**.

| Поле           | Заметки                                                              |
| -------------- | -------------------------------------------------------------------- |
| **First name** | Заполнено, валидация та же                                           |
| **Last name**  | Заполнено, валидация та же                                           |
| **Email**      | Заполнено; смена может сломать вход клиента до повторной верификации |
| **Phone**      | Заполнено; та же оговорка что и Email                                |
| **Tags**       | Multi-select; оператор-применённые метки для группировки/фильтрации  |
| **Status**     | Заполнено текущим статусом; то же перечисление                       |

## Save / Cancel

- **Cancel** (или стрелка назад) — отбрасывает несохранённое и возвращает на предыдущую страницу
- **Save** — валидирует и создаёт/обновляет клиента. Toast подтверждает; ошибки полей подсвечиваются красным

Если валидация падает (нет поля, правила пароля, дубликат email, формат телефона), страница остаётся открытой с обведённым красным полем.

## Create vs Edit — различия

| Аспект                | Create                                                   | Edit                                                      |
| --------------------- | -------------------------------------------------------- | --------------------------------------------------------- |
| Поля пароля           | Есть и обязательны                                       | Скрыты                                                    |
| Tags                  | Не в форме (ставятся позже через Edit или список/деталь) | Есть                                                      |
| Status                | Пусто → дефолт _Active_                                  | Заполнено текущим                                         |
| Email / Phone         | Пусто                                                    | Заполнено — смена может потребовать повторной верификации |
| После save            | Редирект на деталь нового клиента                        | Редирект обратно на деталь клиента                        |
| Запись в Activity-лог | "Client created by _operator name_"                      | "Client edited by _operator name_" с диффом               |

Оба flow пишут в [Activity-лог](client-detail.md#таб-activity) клиента.

## Типичные сценарии

- **Создать VIP** — `+ Создать` на списке → ввести имя, реальный email, реальный телефон, сильный пароль, статус _Active_ → сохранить → передать клиенту учётные данные
- **Поправить опечатку** — строка списка → меню → _Edit_ → исправить поле → сохранить (изменение видно в Activity с диффом)
- **Завести корпоративную партию** — скриптуйте создание через API (эта форма для разовых); потом Edit для применения company-tags
- **Сменить телефон после замены устройства** — Edit → обновить Phone → сохранить → клиенту нужно будет повторно верифицировать при следующем входе (зависит от правил бека)

## Полезные приёмы

- **Формат телефона важен** — должен начинаться с `+` и кода страны; формат enforced, неверный ввод отклоняется
- **Сильный пароль** — для разовых operator-create используйте длинную фразу ("rideTheWolf2026!RW") удовлетворяющую все правила; пишите в password manager, не в чат
- **Уникальность email** — дубликат email — самая частая причина падения Create; сначала ищите в списке по email
- **Не меняйте Email / Phone у существующих клиентов без надобности** — на них завязаны верификационные flow; согласуйте с клиентом до сохранения
- **Tags здесь, не в строке** — теги можно добавить/убрать через bulk на списке, но edit-форма для точечных изменений
- **Смена статуса имеет аудит-вес** — _Active → Blocked_ через эту форму записывается так же как через специальное _Actions → Block client_ — оба валидны
