# Деталь клиента

Страница детали клиента (`/clients/:id`) — это рабочее место для одного клиента. Используйте чтобы просматривать персональные данные, выполнять действия с балансом (top up, штраф), блокировать/разблокировать, отправлять сообщения и аудитировать историю поездок и активности аккаунта.

Обычно сюда попадают кликом по строке в [списке клиентов](clients.md) или из детальной страницы поездки (ссылка на клиента в шапке).

Требуется право: **Clients** (`e4f5h6`). Конкретные действия требуют под-прав (отмечено ниже).

## Структура

Сверху вниз:

1. **Шапка** — назад, имя, статус, кнопка _Actions_
2. **Overview-карточки** — баланс, поездки, рейтинг, статус (4 KPI плитки)
3. **Табы** — Details / Activity / History

## Шапка

Верхняя полоса идентифицирует клиента:

- **Кнопка назад** (`←`) возвращает в список
- **Имя** (имя + фамилия) и **пилюля статуса** (Active / Blocked / Frozen / Registering)
- **Кнопка Actions** справа — открывает диалог действий

## Действия

Клик по **Actions** открывает модальный диалог со всеми операторскими действиями. Каждое гейтится правом:

| Действие            | Право               | Что делает                                                                    |
| ------------------- | ------------------- | ----------------------------------------------------------------------------- |
| **Top up balance**  | `topup-manual`      | Диалог баланса — пополнить кошелёк клиента                                    |
| **Issue fine**      | `fine`              | Диалог штрафа — списать сумму из кошелька (повреждение, парковка)             |
| **Send push**       | —                   | Диалог отправки push-уведомления в приложение                                 |
| **Block / Unblock** | `block` / `unblock` | Переключить статус заблокированного с опциональной причиной                   |
| **Edit client**     | `edit`              | Открыть [форму редактирования](client-create-edit.md) |
| **Delete client**   | `delete`            | Soft-удаление с диалогом подтверждения (красный destructive)                  |

Действия без прав скрыты.

## Overview-карточки

Ряд из четырёх карточек под шапкой суммирует клиента одним взглядом:

| Карточка    | Что показывает                                                             |
| ----------- | -------------------------------------------------------------------------- |
| **Balance** | Баланс кошелька в валюте компании (красный если отрицательный)             |
| **Rides**   | Общее число поездок за всё время                                           |
| **Rating**  | Средний рейтинг от райдеров                                                |
| **Status**  | Текущий статус с подзаголовком ("Active / Blocked / Frozen / Registering") |

## Табы

Три таба:

| Таб          | Что внутри                                                                                                     |
| ------------ | -------------------------------------------------------------------------------------------------------------- |
| **Details**  | Личные данные (имя, email, телефон, статус, баланс, теги) и панель **Devices** (устройства с активной сессией) |
| **Activity** | Операторские и системные действия по этому аккаунту (смены статуса, правки баланса и т.д.)                     |
| **History**  | История поездок клиента — срез глобального списка поездок отфильтрованный на клиента                           |

### Таб Details

Самое глубокое представление состояния аккаунта. Две области:

**Личные данные (сетка):**

- Имя
- Фамилия
- Email (индикатор верификации)
- Телефон (индикатор верификации)
- Статус (с пилюлей)
- Баланс (в валюте компании)
- Теги (чипы навешенные на клиента)

**Панель Devices:**

Перечисляет каждое устройство, заходившее в приложение под этим аккаунтом, с last-seen timestamp и опцией отправить push (если разрешено) или sign-out устройство. Полезно для security-расследований и "не могу залогиниться" support-кейсов.

### Таб Activity

Хронологический **activity-лог** клиента: каждое операторское действие (top-up, штраф, смена статуса, edit, send SMS/email/push) и каждое системное событие (вехи регистрации, смены верификации, balance-правки от возвратов).

Полезно для compliance, разбора споров и ответственности.

### Таб History

**История поездок** клиента в виде таблицы — тот же формат строки как в глобальном списке поездок, отфильтрован на клиента. Клик по строке открывает деталь поездки.

Этот таб — отправная точка для кейсов "клиент говорит что поездка X была неправильной".

## Типичные сценарии

- **Клиент говорит что баланс неверный** — откройте Details (текущий баланс), потом Activity (последнее изменение баланса), потом History (проверьте поездку, вызвавшую списание). Если что-то не так — _Actions → Top up balance_ с причиной
- **Клиент сообщил о потере телефона** — Details → Devices → sign out потерянное устройство (где поддерживается); опционально заблокируйте кошелёк через _Actions → Block client_ пока не восстановит доступ
- **Фрод или abuse** — Activity для таймлайна, History для подозрительных поездок; потом _Actions → Block client_ с причиной; причина сохраняется в activity-лог
- **Goodwill refund** — _Actions → Top up balance_ с описанием типа "Goodwill refund — ticket #12345"; описание видно в Activity для audit
- **Welcome / onboarding outreach** — _Actions → Send push_ с welcome-сообщением; сначала проверьте Devices что у них активная сессия

## Полезные приёмы

- **Смотрите на карточку Status** — даже если всё остальное выглядит ОК, _Blocked_ или _Frozen_ объясняет почему клиент не может ездить
- **Панель Devices — стартер для дебага** — большинство "не могу залогиниться" сводится к старой сессии устройства
- **Описания top-up и штрафов попадают в Activity** — пишите то что оператор сможет найти потом ("ticket #X", "refund for ride Y"), а не просто число
- **Edit — для метаданных** — имя, email, телефон — не для баланса. Используйте отдельные balance-диалоги (с audit trail) для денежных операций
- **Rating — это _водительский_ рейтинг клиента** — низкий рейтинг + всплеск park-proof / тикетов = проблемный райдер
- **URL содержит ID клиента** — вставьте в support-разговор чтобы поделиться точным профилем
