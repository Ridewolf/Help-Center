# Деталь транспорта

Страница детали транспорта (`/vehicles/:id`) — это рабочее место для одной единицы. Используйте чтобы видеть живые IoT-данные, отправлять команды, смотреть историю поездок, расследовать алерты и выполнять операторские действия (редактировать, сменить локацию, отправить в обслуживание, сгенерировать QR, удалить).

Обычно сюда попадают кликом по строке в [списке транспорта](vehicles.md).

Требуется право: **Vehicles** (`k7m8n9`). Некоторые табы и действия требуют дополнительных прав (отмечено ниже).

## Структура

Сверху вниз:

1. **Шапка** — назад, метка, статус, кнопка _Actions_
2. **Overview-карточки** — батарея, последний сигнал, IoT-здоровье, модель и т.д.
3. **Карта локации** — маленькая карта с текущим GPS-пином
4. **Табы** — Details / Rides / Activity / Alerts / Commands

## Шапка

Верхняя полоса идентифицирует транспорт:

- **Кнопка назад** (`←`) возвращает в список
- **Метка транспорта** (например, _RW-001_) и **пилюля статуса** (Available, In Use и т.д.)
- **Кнопка Actions** справа — открывает диалог действий

## Действия

Клик по **Actions** открывает модальный диалог со всеми операторскими действиями. Часть гейтится правами:

| Действие                 | Право    | Что делает                                                                                 |
| ------------------------ | -------- | ------------------------------------------------------------------------------------------ |
| **Edit vehicle**         | `edit`   | Открывает [форму редактирования](vehicle-create-edit.md)               |
| **View route history**   | —        | Диалог координат с недавним GPS-треком                                                     |
| **Mark for maintenance** | —        | Быстрая смена статуса на _Maintenance_                                                     |
| **Change location**      | —        | Диалог-карта для ручного обновления GPS (когда IoT молчит, а оператор знает где транспорт) |
| **Generate QR code**     | —        | QR-генератор для одной единицы (печатный стикер)                                           |
| **Delete vehicle**       | `delete` | Soft-удаление с диалогом подтверждения                                                     |

Действия без прав скрыты из диалога.

## Overview-карточки

Сетка маленьких карточек под шапкой суммирует транспорт одним взглядом:

- **Battery** — заряд самоката (и батарея IoT-платы, если отдельно отчитывается)
- **Last signal** — когда IoT последний раз отчитывался, с пилюлей (Online / Offline / Stale)
- **Lock** — locked / unlocked
- **Model** — название модели, статус, картинка
- **GSM / GPS** — статусы сотовой связи и валидности GPS
- **Speed mode** — текущий режим скорости (eco, normal, sport, если поддерживается моделью)
- **Voltage** — напряжение IoT-платы (инженерное поле)

## Карта локации

Маленькая карта показывает транспорт одним пином на последней известной GPS-координате с авто-зумом по пину. Используйте для быстрого "где он сейчас?" без открытия истории маршрута.

## Табы

Деталь переключается между пятью табами (часть гейтится правами):

| Таб          | Право         | Что внутри                                                                     |
| ------------ | ------------- | ------------------------------------------------------------------------------ |
| **Details**  | —             | Полные данные — IoT-поля, модель + тарифы, теги, зоны, GSM/GPS, режим скорости |
| **Rides**    | view-rides    | Недавние поездки на этом транспорте (срез глобального списка поездок)          |
| **Activity** | —             | Activity-лог по этому транспорту (операторские и системные действия)           |
| **Alerts**   | —             | Сгруппированные IoT-ошибки и алармы с пагинацией (история "что пошло не так")  |
| **Commands** | `iot-command` | Прямые IoT-команды устройству (lock, unlock, alarm, reboot и т.д.)             |

### Таб Details

Дефолтный таб и самое глубокое представление состояния:

- **IoT панель** — батарея, voltage, замок, GSM-сигнал, валидность GPS, последний сигнал, режим скорости
- **Model панель** — название модели и картинка, статус, теги унаследованные от модели
- **Tariffs панель** — тарифы привязанные к модели транспорта (управляют ценообразованием поездок)
- **Tags панель** — теги навешенные на конкретный транспорт (редактируются через _Edit_)
- **Zones панель** — зоны, в которых транспорт сейчас

Если IoT-данные не загрузились, в табе появится баннер ошибки; остальная страница работает.

### Таб Rides

Список недавних поездок на этом транспорте — тот же формат строки как в глобальном списке поездок, отфильтрованный на этот транспорт. Клик по строке открывает деталь поездки.

Таб скрыт без права `view-rides` на этом транспорте.

### Таб Activity

Хронологический **activity-лог** для транспорта: каждое операторское действие (отредактировано, статус сменён, удалено, теги обновлены) и каждое системное событие (переход статуса по IoT-триггеру, запуск автоматизации).

Полезно для compliance, ответственности и дебага неожиданных смен состояния.

### Таб Alerts

Сгруппированные **IoT-алерты и ошибки** от устройства, с пагинацией. Каждая запись содержит:

- Код и человекочитаемый заголовок
- Timestamps первого / последнего наблюдения
- Частоту (сколько раз код был поднят)
- Статус (active / resolved)

Кнопка _Clear_ (где поддерживается) позволяет пометить группу как resolved. Пагинация — пройти по истории алертов.

### Таб Commands

Прямые **IoT-команды** устройству, сгруппированы по категории (например, _Lock & unlock_, _Alarm_, _Lights_, _System_). Гейтится правом `iot-command`.

- Выберите команду и нажмите _Send_
- Команда отправляется в IoT-устройство; время ответа зависит от сотового сигнала
- Недавняя история команд показана ниже со статусом (sent / delivered / failed)

Используйте когда нужно что-то что не покрывает bulk _Send command_ — диагностика, разовый reboot, ручной unlock для support-кейса.

## Типичные сценарии

- **Расследовать жалобу** — откройте Activity чтобы увидеть кто что трогал сегодня; потом Alerts для IoT-ошибок; потом Rides для конкретной поездки
- **Принудительно lock/unlock** — таб Commands → _Send Lock_ или _Send Unlock_ (требуется `iot-command`)
- **Снять с линии для обслуживания** — _Actions → Mark for maintenance_ (ставит статус); отправляйте полевую команду
- **Вручную исправить GPS** — _Actions → Change location_ (когда IoT молчит, а вы знаете где транспорт)
- **Распечатать свежий стикер** — _Actions → Generate QR code_

## Полезные приёмы

- **Следите за табом Alerts** — частые коды это ранние предупреждения о железных проблемах; решайте до того как станет инцидентом
- **Activity — это audit trail** — каждое операторское изменение залогано с именем и timestamp
- **Команды — fire-and-forget по сотовой** — если ответа нет за минуту, устройство возможно offline; проверьте Last signal в overview перед повтором
- **Теги и тарифы — из двух мест** — теги уровня транспорта (Tags panel, редактируется в Edit) переопределяют / дополняют теги уровня модели (read-only здесь, ставятся в Vehicle Settings)
- **Карта локации — это последний пин** — для трека используйте _Actions → View route history_
