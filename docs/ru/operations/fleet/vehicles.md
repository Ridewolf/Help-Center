# Транспорт — Список

Список транспорта (`/vehicles`) — это инвентарь всего вашего флота: каждый самокат, велосипед или другая единица с текущим состоянием, местоположением, зарядом, IoT-подключением, тегами и зоной. Это самая используемая страница дашборда: с неё начинается почти любая операция с флотом.

Для работы с одним транспортом (полный статус, история, IoT-команды, реплей маршрута) откройте [страницу детали](vehicle-detail.md).

Требуется право: **Vehicles** (`k7m8n9`).

## Как сюда попадает транспорт

Транспорт не появляется сам — его создаёте и поддерживаете вы:

1. Оператор **создаёт транспорт** через кнопку _Create_ (метка, модель, IoT-устройство, начальное состояние)
2. Транспорт регистрируется на IoT-устройстве; устройство начинает непрерывно отчитываться: **заряд, состояние замка, последний сигнал, GPS-координаты**
3. Как только IoT-устройство шлёт первый heartbeat, строка списка наполняется живыми данными — процент заряда, время сигнала, индикатор замка
4. Операторы (и bulk-действия) **меняют статус, теги, зону, настройки** в течение жизни транспорта
5. Когда транспорт выводится из эксплуатации, ставится статус _Storage_ / _Maintenance_ / и т.д., или удаляется

Список обновляется при перезагрузке или смене фильтров; live IoT-обновления с бека могут также обновлять строки на месте.

## Режимы — Table vs Map

У страницы два режима, переключаются контролом сверху:

- **Table** — полная дата-таблица со всеми фильтрами, сортом и bulk-выделением
- **Map** — тот же флот спроектированный на карту зоны работы; транспорт — это пины окрашенные по статусу с бейджами заряда

Фильтры применяются к обоим режимам. Map хорош для замечания кластеров, пустот и возможностей для ребалансинга; Table — для работы с данными.

## Фильтры

| Фильтр   | Тип             | Заметки                                                                          |
| -------- | --------------- | -------------------------------------------------------------------------------- |
| Search   | Текст на ширину | Ищет по метке, ID, IoT-серийнику — текст **debounced ~300мс**                    |
| Odometer | Дропдаун        | Диапазоны общего километража: `<1k`, `1k–10k`, `10k–50k`, `50k–100k`, `>100k` км |
| Status   | Дропдаун        | Фильтр по статусу транспорта (справка по статусам ниже)                          |
| Tags     | Multi-select    | Фильтр по тегам навешенным на транспорт                                          |

Все фильтры И-комбинируются. Чипы фильтров появляются над таблицей; URL обновляется.

## Колонки

| Колонка         | Сортировка? | Содержимое                                                                                      |
| --------------- | ----------- | ----------------------------------------------------------------------------------------------- |
| **Health**      | —           | Компактные индикаторы здоровья IoT (periphery) — маленькие иконки суммирующие статус подсистем  |
| **Code**        | ✓           | Метка транспорта (читаемый код на стикере), ссылка на детальную страницу                        |
| **Status**      | ✓           | Пилюля статуса (Available, In Use, Charging и т.д. — справка ниже)                              |
| **Model**       | —           | Название модели и миниатюра (например, Xiaomi M365)                                             |
| **Lock**        | —           | Иконка замка — закрытый (locked) / открытый (unlocked) по последнему IoT-отчёту                 |
| **Battery**     | ✓           | Процент заряда с цветной полоской (зелёный ≥ 60%, янтарный 30–60%, красный < 30%)               |
| **Tags**        | —           | Теги навешенные на транспорт (операторы могут редактировать)                                    |
| **Zone**        | —           | Зона, в которой сейчас находится транспорт, или "Вне зоны"                                      |
| **Last ride**   | ✓           | Дата / время последней поездки                                                                  |
| **Last signal** | ✓           | Когда IoT-устройство последний раз отчиталось (старый сигнал = устройство скорее всего offline) |

Сортируемые колонки помечены ✓ — клик по заголовку. Сортировка попадает в URL.

## Справка по статусам

Каждый транспорт в одном статусе. Статус влияет на поведение (могут ли райдеры арендовать, срабатывают ли IoT-алерты и т.д.):

| Статус                  | Значение                                                  |
| ----------------------- | --------------------------------------------------------- |
| **Available**           | Свободен, можно арендовать, припаркован правильно         |
| **In Use**              | Сейчас на поездке                                         |
| **Charging**            | На зарядной станции                                       |
| **Discharged**          | Заряд слишком низкий для аренды                           |
| **Needs Investigation** | Помечен системой или оператором — требует ручной проверки |
| **Maintenance**         | В мастерской / выведен из флота для ремонта               |
| **Not Ready**           | Создан, но ещё не выпущен к райдерам                      |
| **Reserved**            | Зарезервирован за конкретным райдером/бронированием       |
| **Transportation**      | В процессе перемещения (ребаланс, забор с поля)           |
| **Storage**             | В долгосрочном хранении, вне эксплуатации                 |
| **Stolen**              | Заявлен как украденный / не учитывается                   |
| **Alert**               | Критический алерт от IoT или системы                      |

## Действия над строкой

У каждой строки справа — **меню из трёх точек**. Доступные действия зависят от прав:

| Действие                | Право                 | Что делает                                                              |
| ----------------------- | --------------------- | ----------------------------------------------------------------------- |
| **View details**        | —                     | Открывает [страницу детали](vehicle-detail.md)      |
| **View route history**  | `coordinates-history` | Открывает карту с реплеем недавнего GPS-трека                           |
| **Open in Google Maps** | —                     | Открывает последние координаты транспорта в Google Maps (новая вкладка) |
| **Edit**                | `edit`                | Открывает форму редактирования                                          |
| **Change status**       | `edit`                | Маленький диалог сменить статус без ухода со списка                     |
| **Delete**              | `delete`              | Soft-удаление транспорта (с диалогом подтверждения)                     |

Действия без прав скрыты.

## Bulk-действия

Выделите одну или больше строк чекбоксами слева. Сверху появляется **bulk-бар** со счётчиком и действиями:

| Bulk-действие       | Право         | Что делает                                                        |
| ------------------- | ------------- | ----------------------------------------------------------------- |
| **Change status**   | `bulk-update` | Диалог + применить один статус ко всем выделенным                 |
| **Change tags**     | `bulk-update` | Добавить или убрать теги по выделению                             |
| **Change settings** | `bulk-update` | Применить настройки транспорта (например, макс. скорость, алармы) |
| **Send command**    | `iot-command` | Отправить IoT-команду (lock, unlock, alarm on/off, reboot) на все |
| **Batch QR**        | —             | Сгенерировать печатный QR-лист для выделенного                    |
| **Delete selected** | `delete`      | Soft-удалить каждый выделенный (с диалогом подтверждения)         |

## Действия страницы (сверху-справа)

- **+ Создать** — открывает [форму создания](vehicle-create-edit.md) (отдельная статья)
- **Export** — скачать текущий отфильтрованный список файлом (фильтры и сорт учтены)
- **Batch QR** (также есть в bulk) — мастер пакетной генерации QR

## Map-режим

Когда переключаетесь на Map:

- Транспорт — это **пины** окрашенные по статусу (зелёный = Available, синий = In Use и т.д.)
- Рядом с каждым пином — маленький **бейдж заряда**
- Клик по пину открывает popover с меткой, статусом, зарядом и ссылкой _View details_
- **Фильтры всё ещё применяются** — сужайте по статусу, тегам и т.д., карта обновляется
- Pan / zoom мышью или двумя пальцами

Карта питается теми же данными что и таблица — это другая линза, не другой датасет.

## Типичные сценарии

- **Bulk ребаланс** — фильтр `Status = Discharged` + зона, выделить все, _Send command → Lock_ (или _Change status → Transportation_) перед забором
- **Найти зависший транспорт** — сортировка по _Last signal_ по возрастанию: самые старые сигналы сверху
- **Заметить низкие батареи до проблемы** — сорт по _Battery_ по возрастанию; дно списка — ваша ближайшая очередь обслуживания
- **Аудит тега** — фильтр по тегу и просмотр строк
- **Подготовка для полевых** — фильтр под цели дня, _Batch QR_ для печати наклеек на новые единицы

## Полезные приёмы

- **Поиск debounced** — пауза в наборе чтобы сервер дёрнулся один раз
- **URL = вид** — копируйте и шарите отфильтрованные ссылки коллегам
- **Колонка Health одним взглядом** — маленькие иконки суммируют IoT-подсистемы; наведите курсор на любую чтобы узнать что она показывает (например, сотовая связь, замок, датчик)
- **Цвет батареи — шорткат** — красная полоска в списке = нужна зарядка или забор скоро
- **Индикатор замка — последний IoT-отчёт** — может быть устаревшим на пару секунд; используйте _Send command → Lock_ если нужно гарантировать состояние на устройстве
