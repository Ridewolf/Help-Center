# Задачи обслуживания

Страница «Задачи обслуживания» (`/maintenance/tasks`) — дом **нарядов на работы по флоту**: ремонты, инспекции, плановое обслуживание. Она делит **Insight-панель обслуживания** с [Инвентарём и запчастями](inventory.md) и [Автоматизацией обслуживания](automation.md), давая живую 30-дневную картину нагрузки на ТО.

В сайдбаре: **Обслуживание → Задачи**.

> **Важно: создание задач — coming soon.** Кнопка **Create task** сейчас отключена с тултипом «coming soon» — записи задач пока нельзя создавать и редактировать. Числа Insight-панели при этом живые. Не стройте рабочий процесс вокруг создания задач здесь, пока фича не выйдет.

## Insight-панель обслуживания

Панель вверху страницы полностью рабочая и только для чтения. Она покрывает **скользящее окно в 30 дней** (фиксированное — выбора дат нет) и показывает:

| Блок           | Метрики                                                        |
| -------------- | -------------------------------------------------------------- |
| **Tasks**      | всего, pending, in progress, completed, overdue                |
| **Service**    | запланировано, завершено, средняя длительность, на этой неделе |
| **Inventory**  | всего позиций, low stock, out of stock, общая стоимость        |
| **Automation** | активные правила, срабатываний сегодня, success rate           |

- Плитка становится **warning**, когда есть открытые задачи, и **danger**, когда что-то out of stock.
- Ниже плиток: бар-чарт распределения задач по статусам и прогресс-метр success rate автоматизации.
- Та же панель (и те же данные) на всех трёх страницах Maintenance, поэтому переключение между ними мгновенное.

## Модель задачи

Хотя создание пока недоступно, форма задачи уже определена — полезно при планировании, как команда будет этим пользоваться:

- **Label** и **description**
- **Статус** — `unassigned`, `assigned`, `in-progress`, `on-hold`, `completed`, `cancelled`, `active`, `inactive`, `archived`
- **Priority** и **severity** — каждый `low` / `medium` / `high` / `critical`
- **Impact** — `cosmetic`, `minor-issue`, `degraded`, `out-of-service`
- **Source** — `user`, `iot`, `inspection`, `schedule` (откуда задача возникла)
- **Категория / подкатегория**, привязанный **транспорт**, **исполнитель**, **теги**
- **Стоимость** — запчасти, работа, итого
- **SLA** — дедлайн и статус SLA

Отдельного поля «тип задачи» нет — то, что вы бы назвали _routine_, _repair_ или _inspection_, раскладывается на **source**, **category**, **severity** и **impact**.

## Планируемый флоу создания

Когда создание выйдет, это будет визард из трёх шагов:

1. **Info** — название и описание
2. **Status** — стартовый статус
3. **Review** — сводка, из которой можно вернуться и поправить любое поле, затем сабмит

## Частые вопросы

- **«Create task» не открывается — это права?** Нет. Кнопка отключена для всех, пока фичу доделывают. Ожидаемое поведение.
- **Insight-панель игнорирует фильтры по датам.** Их и нет — окно в 30 дней фиксированное.
- **Метрики замены батарей показывают скелетоны.** Эта агрегация пока недоступна.
- **Где история обслуживания по конкретному транспорту?** В текущей сборке недоступна. Ближайшая замена — activity-лог на [детальной странице транспорта](../fleet/vehicle-detail.md).

## Советы

- **Срочные ремонты пока ведите через [Тикеты](../../support/tickets-proofs-chat/tickets.md)** — до выхода создания задач очередь тикетов (с severity и SLA) остаётся рабочей альтернативой для actionable-фоллоуапов.
- **Используйте Insight-панель как дашборд здоровья** — просроченные задачи и out-of-stock запчасти — два числа, красящих плитки в красный; проверяйте их в начале смены.
