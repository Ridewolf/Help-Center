# Деталь поездки

Страница детали поездки (`/rides/:id`) — это рабочее место для одной поездки. Используйте чтобы разобрать жалобу, аудитировать списания, выполнить операторские действия (пауза, возврат, архив) и просмотреть полный лог событий.

Обычно сюда попадают кликом по строке в [списке поездок](rides.md) или из профиля клиента.

Требуется право: **Rides** (`i1j2k3`).

## Структура

Сверху вниз:

1. **Шапка** — ключевые факты + кнопка _Actions_
2. **Overview-карточки** — длительность, дистанция, стоимость, статус
3. **Info-карточки** — ride info, breakdown, снимок тарифа
4. **Табы** — Details (карта + таймлайн) и Activity (полный лог событий)

## Шапка

Верхняя полоса идентифицирует поездку:

- **Кнопка назад** (`←`) возвращает в список
- **ID поездки** с иконкой _Copy_
- **Пилюля статуса** (Active, Completed, Cancelled и т.д.)
- **Клиент** и **транспорт** ссылками
- **Время старта → финиша** и **итоговая стоимость**
- **Кнопка Actions** справа — открывает диалог действий (описан ниже)

## Действия

Клик по **Actions** в шапке открывает диалог со всеми операторскими действиями для поездки. Действия автоматически отключаются по статусу и правам, с tooltip объясняющим почему:

| Действие              | Когда активно                    | Гейт прав       |
| --------------------- | -------------------------------- | --------------- |
| **Pause / Resume**    | Поездка должна быть активной     | `pause-unpause` |
| **End ride**          | Поездка должна быть активной     | `end-ride`      |
| **View route on map** | Всегда (переход на таб карты)    | —               |
| **Refund ride**       | Поездка должна быть завершённой  | refund-related  |
| **Send notification** | Всегда (отправляет push рейдеру) | notification    |
| **Archive ride**      | Всегда                           | archive         |

Наведите на отключённое действие чтобы увидеть причину (например, "Ride must be completed to refund").

Диалог _Actions_ в шапке — это **полный набор** действий; меню в строке списка содержит только три самых частых (Pause / Resume / End). Для возврата, просмотра маршрута, push-уведомления и архива — приходите сюда.

## Overview-карточки

Ряд из четырёх маленьких карточек под шапкой даёт быстрые факты:

- **Duration** — общее время поездки
- **Distance** — общая дистанция
- **Cost** — итоговая стоимость
- **Status** — текущий статус (повторяет пилюлю в шапке, крупнее и заметнее)

## Info-карточки

Сетка из трёх карточек под overview показывает основные данные поездки:

- **Ride info** — транспорт, клиент, тариф, ID, временные метки
- **Breakdown** — поминутный состав стоимости (стартовая плата, время, дистанция, модификаторы, скидки)
- **Tariff details** — снимок тарифа использованного для этой поездки (вы видите по чему именно клиент был тарифицирован, даже если тариф позже изменили)

## Табы

Под карточками детали переключаются между двумя табами:

| Таб          | Что внутри                                                                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Details**  | Карта маршрута, таймлайн значимых событий, полные info-карточки                                                                                              |
| **Activity** | Хронологический лог событий — каждая смена состояния, сигнал, системное действие связанное с поездкой — шире чем таймлайн в Details (полезно для IoT-дебага) |

### Карта маршрута

Внутри таба Details карта маршрута показывает GPS-трек поездки:

- **Старт / финиш маркеры** с адресами
- **Polyline** окрашен по скорости (медленные vs быстрые сегменты)
- **Зоны** наложены если поездка зашла в ограниченные области
- **Легенда** объясняет цветовую шкалу
- **Zoom / pan** мышью или двумя пальцами

### Таймлайн

Под картой вертикальный таймлайн перечисляет каждое значимое событие поездки:

- **Старт поездки** (с разблокировкой транспорта)
- **Паузы / возобновления** (если есть)
- **Входы / выходы из зон**
- **Предупреждения о скорости**
- **Финиш поездки** (с блокировкой / парковочным proof, если есть)
- **События платежа**

Используйте таймлайн чтобы разобрать споры ("райдер говорит что с него списали после окончания поездки") — у каждого события точная отметка времени.

### Таб Activity

Таб Activity показывает полный лог событий, включая системные действия — шире чем таймлайн в Details. Используйте когда простого таймлайна не хватает (например, при техническом дебаге IoT-проблемы).

## Типичные сценарии

- **Разобрать жалобу клиента** — прочитайте breakdown, потом карту маршрута и таймлайн; таймлайн редко врёт
- **Аудит возврата** — откройте карточку breakdown; строки точно показывают за что клиент платил, затем _Actions → Refund ride_
- **Поставить на паузу и позвонить клиенту** — _Actions → Pause_ замораживает поездку; _Actions → Send notification_ пингует клиента; _Resume_ когда вернётся
- **Закрыть зависшую поездку** — для поездок которые не закрываются (потеряна связь, клиент бросил транспорт включённым) используйте _Actions → End ride_ для принудительного закрытия — система возьмёт последнее известное местоположение для park-proof

## Полезные приёмы

- **Читайте tooltip отключённого действия** — серые кнопки не сломаны; tooltip говорит в каком состоянии должна быть поездка
- **Копируйте ID поездки** из шапки чтобы вставить в support-разговор или backend-запрос
- **Tariff details показывают тариф _как он был_** — даже если тариф позже изменили, снимок сохраняется для аудита
- **Диалог Actions — это полное меню** — не ищите refund/archive в списке; они живут здесь
