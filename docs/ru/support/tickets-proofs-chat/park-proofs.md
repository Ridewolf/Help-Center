# Park Proofs — Список

Список Park Proofs (`/support/park-proofs`) — это очередь модерации фото, которые райдеры делают своим транспортом в ключевые моменты поездки. Эти фото доказывают, что райдер припарковался правильно (или нет), и задача вашей команды здесь — **одобрять хорошие фото, предупреждать или штрафовать за плохие**.

Для пошагового разбора (большой экран модерации одного фото) см. [Park Proof Review](park-proof-review.md). Для правил автоматизации, обрабатывающих очевидные случаи без вас, см. [Auto Review](park-proof-auto-review.md).

Требуется право: **Park Proofs** (`d5e6f7`). Некоторые row actions требуют доп. под-прав.

## Как сюда попадают proofs

Мобильное приложение райдера просит сделать фото в трёх точках:

1. **Start** — при разблокировке транспорта (доказывает что юнит был в порядке когда брали)
2. **Park** — во время паузы посреди поездки (доказывает законную парковку при остановке)
3. **End** — при завершении поездки (**главное** — доказывает что транспорт оставлен правильно)

Фото загружается с GPS-метаданными и попадает в очередь со статусом **Pending**. Auto Review может переключить его в _Approved_ (хорошее фото) без оператора; всё, в чём Auto Review не уверен, попадает сюда на ручную модерацию.

## Фильтры

| Фильтр     | Тип       | Заметки                                                              |
| ---------- | --------- | -------------------------------------------------------------------- |
| Search     | Текст     | Поиск по имени клиента, метке транспорта, ID поездки                 |
| Date range | Календарь | От / до; по умолчанию "за всё время"                                 |
| Status     | Дропдаун  | `Pending` / `Approved` / `Warning` / `Fined` / `Blocked` (или `All`) |
| Type       | Дропдаун  | `Start` / `Park` / `End` (или `All`)                                 |

Используйте `Status = Pending` как ежедневный фильтр мониторинга — это очередь модерации.

## Колонки

| Колонка     | Сортировка? | Содержимое                                           |
| ----------- | ----------- | ---------------------------------------------------- |
| **Image**   | —           | Миниатюра фото (клик открывает страницу review)      |
| **User**    | —           | Имя и аватар клиента; клик открывает профиль         |
| **Vehicle** | —           | Метка и модель транспорта; клик открывает деталь     |
| **Ride**    | —           | ID поездки; клик открывает деталь поездки            |
| **Type**    | ✓           | Фаза поездки (`Start` / `Park` / `End`)              |
| **Status**  | ✓           | Пилюля статуса (справка ниже)                        |
| **Date**    | ✓           | Когда сделано фото; сорт по умолчанию = новые сверху |

## Справка по статусам

| Статус       | Цвет      | Значение                                                                     |
| ------------ | --------- | ---------------------------------------------------------------------------- |
| **Pending**  | Жёлтый    | Ждёт модерации (вашей или Auto Review)                                       |
| **Approved** | Зелёный   | Фото хорошее — райдер припарковался правильно                                |
| **Warning**  | Оранжевый | Фото не очень — райдер получает предупреждение, штрафа пока нет              |
| **Fined**    | Красный   | Фото плохое — райдер оштрафован (или система пометила как кандидат на штраф) |
| **Blocked**  | Серый     | Райдер заблокирован из-за этого proof (серьёзное / повторное нарушение)      |

Статусы выставленные через row actions и на review page логируются и в запись proof и в [Activity-лог](../../operations/customers/client-detail.md#таб-activity) клиента.

## Действия над строкой

У каждой строки справа — **меню из трёх точек**. Доступные действия зависят от прав:

| Действие      | Право         | Что делает                                                                                                 |
| ------------- | ------------- | ---------------------------------------------------------------------------------------------------------- |
| **View**      | `view-detail` | Открыть [страницу review](park-proof-review.md) с большим фото и контекстом |
| **Approve**   | `review`      | Пометить proof как _Approved_ (без штрафа и предупреждения) — для хороших фото                             |
| **Warn**      | `review`      | Пометить как _Warning_ — райдер получит уведомление, но без штрафа                                         |
| **Open ride** | —             | Перейти на деталь связанной поездки (карта маршрута, таймлайн и т.д.)                                      |

Действия без прав скрыты.

Полный набор (Fine, Block user, Create maintenance task, Ask to repark) живёт на **странице review** — заходите туда для всего что больше быстрого approve/warn.

## Действия страницы (сверху-справа)

- **Auto Review** — открывает [страницу Auto Review](park-proof-auto-review.md) для настройки правил, авто-одобряющих очевидно хорошие фото и авто-флагающих очевидно плохие (это разгружает очередь Pending, оставляя вам только пограничные случаи)

## Типичные сценарии

- **Дневная очередь модерации** — `Status = Pending` → сорт по дате старые сверху → пройти каждый, _View_ для контекста, _Approve_ / _Warn_ по ситуации
- **Расследовать жалобу** — поиск по ride ID или клиенту → найти proof → _View_ → сверить фото с заявлением райдера
- **Найти повторных нарушителей** — поиск по имени клиента → посмотреть несколько proofs на паттерн (activity-лог профиля юзера расскажет ту же историю)
- **Только end-of-ride** — `Type = End` → модерировать только финальные фото (важнейшие; mid-ride park photos обычно ок)
- **Аудит Auto Review** — `Status = Approved` за день → выборочная проверка чтобы убедиться что правила работают

## Полезные приёмы

- **Миниатюры достаточно для большинства решений** — явно в зоне, фото прямое, ничего не мешает — _Approve_ без открытия. _View_ — для двусмысленных
- **Open ride** — ваш быстрый путь к контексту — если райдер утверждает что припарковался законно, карта поездки покажет где он на самом деле остановился
- **Статусы залипают** — поставили _Approved_, и райдер не получит больше напоминаний по этому proof. Не одобряйте плохие фото чтобы "очистить очередь" — потеряете возможность вернуться
- **Warning — промежуточный** — для плохих, но не злонамеренных фото (райдер торопился, плохая погода и т.д.). Повторные warnings эскалируются в штрафы через правила Auto Review
- **Используйте Auto Review агрессивно** — очередь растёт быстро; чем больше очевидно-хороших фото авто-одобряются, тем больше энергии остаётся на пограничные случаи
- **URL шарится** — копируйте отфильтрованный вид (например, _вчерашние fined_) и отправляйте коллеге для spot-check
