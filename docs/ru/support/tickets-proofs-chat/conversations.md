# Чаты

Страница Чаты (`/support/conversations`) — это **operator messenger**, real-time чат-интерфейс между вашей support-командой и райдерами. Каждый чат принадлежит одному клиенту и содержит полную историю сообщений, действий команды и смен статуса.

Требуется право: **Conversations** (`x2y3z4`).

## Как сюда попадают чаты

Чаты приходят из нескольких flow:

1. **Райдер открывает чат** в мобильном приложении — создаётся _New_, попадает в очередь _Waiting_
2. **Оператор инициирует** — _+ New_ в сайдбаре позволяет начать чат с конкретным клиентом (например, follow-up по штрафу или fraud-проверка)
3. **Reopened** — закрытые чаты можно вернуть (райдером или оператором), возвращаются наверх списка

Список **live** — новые чаты и входящие сообщения приходят по WebSocket без перезагрузки.

## Структура

Страница содержит две основные области. Layout адаптируется под размер экрана:

- **Desktop** — split view, сайдбар слева (30%) и контент справа (70%) с перетаскиваемым хэндлом
- **Mobile** — одна область за раз: список или открытый чат (стрелка назад возвращает в список)

## Сайдбар (слева)

Очередь чатов и фильтры:

- **+ New** — диалог поиска клиента и создание нового чата (статус _Waiting_)
- **Search** — текстовый поиск по имени, ID, последнему сообщению
- **Status-фильтры** — пилюли со счётчиками: `All` / `New` / `Waiting` / `Active` / `Delayed` / `Closed`
- **Карточки чатов** — аватар, имя клиента, превью последнего сообщения, status pill, timestamp, бейдж непрочитанных. Клик открывает
- **Load more** — пагинация по скроллу

Дефолтный сорт ставит unanswered (Waiting / Active с непрочитанным) сверху — самые срочные чаты всегда на глазах.

### Справка по статусам

| Статус      | Значение                                               |
| ----------- | ------------------------------------------------------ |
| **New**     | Только открыт, никто ещё не прочитал                   |
| **Waiting** | Не назначен, в очереди для любого оператора            |
| **Active**  | Назначен оператору, в работе                           |
| **Delayed** | Оператор поставил на hold (ждём инфу, follow-up позже) |
| **Closed**  | Решён и закрыт                                         |

## Контент чата (справа)

Когда выбираете чат, правая колонка показывает:

### Шапка чата

- **Стрелка назад** (только mobile) — возврат в список
- **Заголовок** — имя клиента с пилюлей статуса
- **Open info** — открывает [User Info sidebar](#info-панели) с полным контекстом клиента
- **Delay / Transfer / Close** — кнопки в зависимости от статуса

### Окно чата

- **Message bubbles** — сообщения оператора справа (accent), сообщения райдера слева; с timestamps и индикаторами прочтения
- **Typing-индикатор** — показывается когда райдер печатает
- **Load older** наверху — догрузка ранних сообщений
- **To new messages** — shortcut "вниз" когда отскроллили вверх
- **Действия над сообщением** при наведении — Edit / Delete на своих сообщениях

### Canned responses

Ряд над input-ом показывает шаблоны быстрых ответов по категориям. Клик кладёт текст в input — можно отредактировать перед отправкой.

### Footer чата

Что появляется в footer-е зависит от **статуса** и назначения:

- **Active + назначен на вас** → **Message input** с attachment-меню (текст + image / file)
- **Иначе** → **Conversation Actions** бар с релевантными кнопками

## Действия (по статусу)

Footer показывает нужные кнопки для текущего статуса. Типичные:

| Действие      | Доступно когда…              | Что делает                             |
| ------------- | ---------------------------- | -------------------------------------- |
| **Accept**    | Waiting / New (не ваш)       | Назначает на вас, переводит в _Active_ |
| **Take over** | Active (принадлежит другому) | Переназначает на вас                   |
| **Return**    | Active (назначен на вас)     | Возвращает в _Waiting_                 |
| **Delay**     | Active                       | Ставит на hold → _Delayed_             |
| **Reopen**    | Closed                       | Возвращает в _Active_                  |
| **Close**     | Active                       | Помечает как решённый → _Closed_       |
| **Delete**    | Permission-gated             | Soft-удаление (admin)                  |
| **New**       | Всегда                       | Начать новый чат с тем же клиентом     |

Вы защищены от действий с чужим чатом — увидите _Take over_ вместо message input если чат не ваш.

## Info-панели

Две выезжающие панели открываются из chat-window:

- **User Info Sidebar** — быстрый контекст для назначенного оператора (вас) и недавняя активность райдера в чате
- **Client Info Sheet** — полный snapshot профиля клиента (баланс, статус, теги, недавние поездки) не уходя из чата — для быстрых решений

## Пустое состояние (desktop)

Когда чат не выбран на десктопе, правая панель показывает empty-state с подсказкой выбрать чат. На мобильном правой панели нет пока не выберете чат — сайдбар занимает весь экран.

## Типичные сценарии

- **Взять waiting-чат** — `Status = Waiting` → клик по верхней карточке → _Accept_ → начать переписку
- **Перехватить чат коллеги** — открыть чат (видно что он чужой) → _Take over_ (используйте осторожно; разрывает continuity для райдера)
- **Охладить медленный чат** — когда райдер перестал отвечать, _Delay_ убирает из активной очереди; вернётся в inbox когда ответит
- **Закрыть** — проблема решена → _Close_ с canned-ответом ("Всё ок, удачной поездки!")
- **Быстро получить контекст** — _Open info_ в шапке → видите баланс / поездки / теги до ответа на billing-вопрос
- **Используйте canned responses** — для повторяющихся ответов (refund policy, lost item) выберите template и персонализируйте

## Полезные приёмы

- **Live по умолчанию** — новые сообщения приходят без refresh; счётчик обновляется автоматически
- **Unanswered сверху** — сорт держит срочные чаты вверху; доверяйте порядку
- **Canned responses — шаблоны, не скрипты** — всегда персонализируйте приветствие и закрытие; райдеры чувствуют boilerplate
- **Take over аккуратно** — райдер не видит operator-level state. Переключение посреди разговора может казаться неприятным; берите только когда текущий оператор явно завис (offline, off-shift)
- **Delay > Close в неуверенных случаях** — если думаете что проблема может вернуться, _Delay_ сохраняет thread; _Close_ заставит райдера открыть новый чат для продолжения
- **Edit только свои сообщения** — и только короткие опечатки; переписывание старого сообщения после прочтения райдером подрывает доверие
- **URL содержит ID чата** — вставьте в тикет или escalation-заметку чтобы следующий оператор сразу попал в чат
