# Park Proof — Детали

Страница деталей park proof (`/support/park-proofs/:id`) — где вы инспектируете один park-proof в глубину и — если он pending — модерируете его. Открывается как большой диалог поверх [списка park proofs](park-proofs.md); URL меняется так что proof можно расшарить / открыть по deep-link.

Обычно сюда приходят кликом по _View_ в строке, кликом по плитке в gallery view или вставкой прямого URL.

Требуется право: **Park Proofs** (`d5e6f7`). Суб-право `review` включает модерационные действия, `delete` — кнопку Delete.

## Как соотносится со страницей review

И `/support/park-proofs/:id` (эта страница), и `/support/park-proofs/:id/review` существуют — выглядят похоже, но решают разные задачи:

| Поверхность                                                                        | Что это                                                                                                                                        |
| ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **Park Proof Detail (эта страница)**                                               | **Диалог** открываемый из списка — полное фото с зумом, полный контекст, полный action-set. Single-record view. URL `/support/park-proofs/:id` |
| [Park Proof Review](park-proof-review.md)           | **Полноэкранная страница** (`/:id/review`) — выделенная reviewer-поверхность для одного proof                                                  |
| [Park Proof Auto Review](park-proof-auto-review.md) | **Streamline-режим** — автопрогружающаяся очередь pending proofs, по одному за раз                                                             |

День-к-дню: используйте **Auto Review** для разгребания очереди, **детали-диалог** (эту страницу) для one-off инспекции из списка, и страницу **review** для выделенного reviewer-flow.

## Layout

Диалог делится на две колонки на широких экранах, стекуется на узких:

| Колонка           | Ширина | Содержимое                                                                                            |
| ----------------- | ------ | ----------------------------------------------------------------------------------------------------- |
| **Image (слева)** | 3/5    | Полноразмерное фото с зумом на чёрном фоне                                                            |
| **Info (справа)** | 2/5    | Header (заголовок + status / type бейджи), контекст (client / ride / vehicle), details-грид, действия |

## Image (левая колонка)

Большой image viewer с полноразмерным фото на чёрном фоне:

- **Клик по фото** — циклит зум (1× → 2× → 3× → 4× → обратно 1×)
- **Колесо мыши** — зум in/out шагом 0.5×
- Курсор переключается между zoom-in / zoom-out в зависимости от состояния
- **Бейдж % зума** появляется в левом верхнем при зуме >1×

Четыре кнопки появляются в правом нижнем при hover (полупрозрачные на чёрном фоне):

| Кнопка              | Что делает                                                                 |
| ------------------- | -------------------------------------------------------------------------- |
| **Zoom in**         | +0.5× шаг (макс 4×)                                                        |
| **Zoom out**        | -0.5× шаг (мин 1×)                                                         |
| **Minimize**        | Сбрасывает зум на 1×                                                       |
| **Open in new tab** | Открывает оригинальное разрешение в новой вкладке для детального просмотра |

Ищите те же сигналы что и на странице [review](park-proof-review.md): транспорт целиком в кадре, легальное место парковки, подножка опущена, всё что противоречит словам райдера.

## Header (верх правой колонки)

Header идентифицирует proof:

- **Заголовок** _"Review Park Proof"_ с коротким description под ним
- Два **бейджа** стопкой справа:
  - **Status-бейдж** — цвет под статус (жёлтый Pending, зелёный Approved, оранжевый Warning, красный Rejected, тёмный Blocked)
  - **Type-бейдж** — outline-пилюля _Start_ / _Park_ / _End_

## Context-секция

Три строки-линки на связанные сущности. Каждая — router-link (клик открывает страницу сущности в том же окне):

| Строка      | Что показывает                                                                                                         |
| ----------- | ---------------------------------------------------------------------------------------------------------------------- |
| **Client**  | Имя клиента (линк на [детали клиента](../../operations/customers/client-detail.md)), email + phone (клик для копирования) |
| **Ride**    | Имя / id поездки с линком на [детали поездки](../../operations/trips/ride-detail.md)                                      |
| **Vehicle** | Label транспорта с линком на [детали транспорта](../../operations/fleet/vehicle-detail.md), тип транспорта ниже           |

Используйте эти cross-references для быстрого контекста — нарушал ли этот клиент раньше, действительно ли он закончил поездку здесь, часто ли этот транспорт флагируется.

## Details-секция

Двух-колоночный key/value грид ниже контекста. Поля появляются в зависимости от состояния proof'а:

| Поле                | Когда                          | Что показывает                                                                                                                                                                                                     |
| ------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Created**         | Всегда                         | Когда приложение райдера загрузило фото                                                                                                                                                                            |
| **Reviewed at**     | Только после review            | Когда оператор (или Auto Review) принял решение                                                                                                                                                                    |
| **Review duration** | Только после review            | Created → Reviewed delta (например "2h 14m") — полезно для замера SLA по proof'у                                                                                                                                   |
| **Reviewed by**     | Только после operator-review   | Оператор который проверил. Линк на [профиль оператора](../../settings/access/operators.md). Если оператор не резолвится (404, нет прав) — id показывается как кликабельный линк, страница профиля сама проверяет auth |
| **Location**        | Если у поездки есть координаты | Lat / lng старта поездки (для _Start_ proofs) или конца (для _Park_/_End_), 6 знаков                                                                                                                               |

Если proof отклонён со штрафом — ниже details красный alert _Fine_ с суммой штрафа в валюте компании.

Если есть предыдущий комментарий или причина отказа — появляется секция _Comment_ ниже.

## Review actions (только pending)

Если статус proof'а — **Pending** — action chooser появляется в низу правой колонки. Диалог поддерживает **пять** модерационных действий (на одно больше чем выделенная review-страница):

| Action                   | Эффект на статус | Доп. поля             | Когда использовать                                                                   |
| ------------------------ | ---------------- | --------------------- | ------------------------------------------------------------------------------------ |
| **Approve**              | _Approved_       | —                     | Фото явно хорошее — комментарий не нужен                                             |
| **Approve with comment** | _Approved_       | Comment required      | Фото хорошее, но хочется оставить заметку (edge case, future reference, ML training) |
| **Warn**                 | _Warning_        | Comment recommended   | Фото не идеальное — райдер получит soft-уведомление, без штрафа                      |
| **Reject**               | _Rejected_       | Comment + Fine amount | Плохое фото — применяется штраф. Списывается с кошелька при submit                   |
| **Block**                | _Blocked_        | Comment required      | Серьёзное / повторное нарушение — блокирует райдера от будущих поездок               |

Каждая action — кликабельная radio-карточка с описанием; выбор раскрывает условные поля (textarea комментария и/или input штрафа). Primary submit-кнопка подхватывает цвет action'а (зелёный / жёлтый / красный / тёмный).

После submit диалог закрывается, тост подтверждает действие, список обновляется.

### Чем отличается от страницы review

Выделенная [страница review](park-proof-review.md) (`/:id/review`) показывает **четыре** action'а как стопку кнопок. Этот диалог показывает **пять** action'ов как radio-карточки — дополнительная это _Approve with comment_, которая полезна для логирования контекста на позитивное решение без эскалации до warning.

## Закрытые proofs (уже проверенные)

Если proof уже проверен (Approved / Warning / Rejected / Blocked) — секция action скрыта, диалог становится read-only. Виден весь контекст (фото, client / ride / vehicle, details, штраф, комментарий, кто и когда), и доступны:

- **Delete** (с правом `delete`) — для spam / test / wrong-ride uploads, не для модерационного решения
- **Close** — закрыть диалог

Изменить решение постфактум — обращайтесь к админу, стандартный flow не разрешает re-review через UI.

## Footer

| Кнопка            | Когда видна                           | Что делает                                                                                                      |
| ----------------- | ------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| **Delete**        | Всегда при наличии суб-права `delete` | Удаляет запись proof'а целиком (с confirmation). Только для test / spam / wrong-ride uploads — не для модерации |
| **Cancel**        | Только pending                        | Закрывает диалог без submit                                                                                     |
| **Action submit** | Только pending, после выбора action   | Submit'ит выбранный action (цвет под action)                                                                    |
| **Close**         | Уже проверенный proof                 | Закрывает диалог                                                                                                |

Закрытие диалога (Cancel / Close / Esc / клик за пределы) дропает `/:id` из URL так что back / forward-история совпадает с тем что видно.

## Типовые workflow

- **Расследовать один proof из списка** — найти в списке (фильтр / поиск), кликнуть row → откроется детали-диалог → проскроллить контекст → принять решение
- **Глубокий разбор оштрафованного proof'а** — поиск по клиенту → открыть один из его rejected proofs → проверить Reviewed by + комментарий чтобы увидеть кто и почему принял решение → для разбора диспута
- **Быстрое одобрение по deep-link** — получить URL от коллеги → клик → диалог → zoom на фото → Approve / Approve with comment
- **Cross-check истории транспорта** — открыть proof → клик по транспорту → если тот же транспорт постоянно получает bad park photos → проблема placement'а / разметки, а не райдера
- **Аудит решений reviewer'а** — фильтр списка по Status `Approved` → клик в proofs смотреть Reviewed by + комментарии → калибровать стандарты команды

## Tips

- **Колесо мыши — быстрый зум** — кнопка не нужна — просто крутите над фото
- **Фото открывается в новой вкладке на оригинальном разрешении** — когда зум в диалоге недостаточен (например прочитать табличку с парковки), открывайте externally
- **"Approve with comment" лучше тихого approve** для edge cases — оставьте one-line заметку которую следующий reviewer (или вы через три месяца) поблагодарит
- **Block — это финал** — клиента можно разблокировать через [детали клиента](../../operations/customers/client-detail.md), но для одного proof'а _Block_ — высшая эскалация. Не хватайтесь за неё на первом нарушении
- **Delete vs Reject** — Reject оставляет moderation-record (и штрафует райдера); Delete стирает proof целиком. Если нужен paper trail — никогда не удаляйте
- **URL шарится** — `/support/park-proofs/:id` ведёт прямо сюда, без навигации по списку
- **Закрытые proofs — read-only** — если открыли проверенный proof в ожидании действовать на нём — поэтому кнопки и пропали
