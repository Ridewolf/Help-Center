# Park Proof Review

Страница review (`/support/park-proofs/:id/review`) — это место где вы детально модерируете одно фото park-proof. Полное изображение, весь связанный контекст (клиент / поездка / транспорт) и полное меню действий живут здесь.

Обычно сюда попадают кликом по миниатюре (или _View_ в меню строки) на странице [Park Proofs](park-proofs.md).

Требуется право: **Park Proofs** (`d5e6f7`) + под-право `review` для модерации.

## Структура

На широких экранах страница разделена на три колонки, на узких складывается:

| Колонка           | Ширина | Содержимое                                               |
| ----------------- | ------ | -------------------------------------------------------- |
| **Image**         | 5/12   | Фото в полном размере с зумом и панорамированием         |
| **Actions**       | 4/12   | Кнопки модерации, опциональный комментарий, admin Delete |
| **Info-карточки** | 3/12   | Клиент, Поездка, Транспорт, детали Proof                 |

## Image (левая колонка)

**Зумируемый просмотрщик** с фото в полном разрешении:

- **Клик + перетаскивание** — пан при увеличении
- **Колесо мыши** (или щипок на мобильном) — зум
- **Двойной клик** — сброс зума

Ищите:

- Весь транспорт в кадре (не только колесо)
- Законное место парковки (не блокирует пешеходов, не в зоне запрета)
- Подножка опущена, транспорт вертикально
- Что-то что противоречит истории райдера при споре

## Actions (средняя колонка)

Четыре кнопки модерации сложены вертикально, по нарастанию строгости:

| Кнопка               | Статус     | Когда использовать                                                     |
| -------------------- | ---------- | ---------------------------------------------------------------------- |
| **Approve**          | _Approved_ | Фото хорошее — райдер припарковался правильно                          |
| **Warn**             | _Warning_  | Фото не очень, но не настолько плохо чтобы штрафовать — уведомление    |
| **Reject with fine** | _Fined_    | Фото плохое — применяется штраф на сумму, введённую ниже кнопки        |
| **Block**            | _Blocked_  | Серьёзное / повторное нарушение — блокирует райдера от будущих поездок |

Каждое действие требует под-право `review`. Действия без прав скрыты или отключены.

### Сумма штрафа

У кнопки **Reject with fine** прямо под ней — числовое поле для **суммы штрафа** в валюте компании. Штраф списывается с кошелька клиента (или дефолтного способа оплаты, в зависимости от конфигурации). Сумма обязательна при клике _Reject with fine_ — иначе кнопка отключена.

### Комментарий

**Comment**-textarea под кнопками. То что вы пишете, прикрепляется к действию и сохраняется в:

- Запись proof (для будущего аудита)
- [Activity-лог клиента](../../operations/customers/client-detail.md#таб-activity) (любой кто расследует клиента позже увидит вашу заметку)
- In-app уведомление райдера (в зависимости от действия — он видит почему получил предупреждение / штраф)

Пишите комментарий **до** клика по действию — он отправляется вместе с действием, не после. Будьте конкретны: "самокат блокирует тротуар, фото сделано в 22:14" лучше чем "плохая парковка".

### Delete (admin)

Кнопка **Delete** внизу (видна только с admin-правом) полностью удаляет запись proof. Используйте для:

- Тестовых / спам-фото
- Дубликатов (одна поездка, несколько идентичных фото)
- Фото загруженных не к той поездке (data error)

Не используйте Delete вместо Approve / Reject — Delete для _удаления записи из системы_, не для модерационного решения.

## Info-карточки (правая колонка)

Три "связанных" карточки + детали стоят вертикально:

- **Client** — имя, телефон, email, статус, ссылки на [детальную клиента](../../operations/customers/client-detail.md)
- **Ride** — ID поездки, время старта/финиша, дистанция, цена; ссылка на [детальную поездки](../../operations/trips/ride-detail.md)
- **Vehicle** — метка, модель, статус; ссылка на [детальную транспорта](../../operations/fleet/vehicle-detail.md)
- **Park Proof Details** — тип (start/park/end), время создания, GPS-координаты, auto-review вердикт если был

Используйте карточки чтобы **быстро собрать контекст**:

- Первый раз нарушитель или повторный? — Client → Activity
- Закончил ли поездку именно в этой точке? — Ride → карта маршрута
- Часто ли этот транспорт паркуют плохо? — Vehicle → недавние proofs

## Типичные сценарии

- **Быстрое одобрение** — фото явно хорошее → оставить comment пустым → _Approve_ → назад в очередь
- **Warn с контекстом** — фото плохое но мягкое → коротко пишем заметку → _Warn_ → райдер получает мягкий пинок
- **Штраф с обдумыванием** — фото явно плохое → проверить Client карточку на повторы → написать заметку с обоснованием → ввести сумму → _Reject with fine_
- **Эскалация в блок** — третий strike → проверить Client → Activity на предыдущие warnings → написать заметку → _Block_
- **Аудит предыдущего решения** — открыть proof → прочитать Comment в activity-логе чтобы увидеть что писал предыдущий оператор

## Полезные приёмы

- **Увеличьте перед решением** — подножки, парковочные знаки, пешеходные тропы легко не заметить на миниатюре
- **Сначала комментарий** — клик по действию = отправка; если пишете комментарий после, вы уже модерировали без контекста
- **Approve > Warn > Fine > Block** — одностороннее повышение — не прыгайте сразу в Block на первое нарушение
- **Комментарий публичен** (для команды и райдера) — пишите фактически; без внутреннего жаргона, без оценок клиента
- **Delete необратим** — после удаления proof восстановить нельзя; используйте _Reject_ если хотите оставить запись о плохом фото
- **Фото — это правда** — когда райдер оспаривает штраф, оригинальное фото + ваш комментарий + таймлайн = досье дела
