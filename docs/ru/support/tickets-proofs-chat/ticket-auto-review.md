# Ticket Auto Review

Страница Ticket Auto Review (`/support/tickets/auto-review`) — **streamlined-интерфейс очереди** для прохождения pending-тикетов один за другим, без возврата к списку между решениями.

Так же как в [Park Proof Auto Review](park-proof-auto-review.md), "Auto" значит **auto-advance**: после каждого действия страница загружает следующий pending-тикет, чтобы не разрывать flow.

Открывается из кнопки **Auto Review** на [странице Tickets](tickets.md).

Требуется право: **Tickets** (`a8b9c1`).

## Как это работает

1. Страница загружает **текущую очередь pending-тикетов** при открытии
2. Вы видите первый тикет — evidence-фото, info-карточку и кнопки действий
3. Выбираете действие (Resolve / In Work / Waiting Info / Dismiss / Duplicate) или Skip
4. Страница **автопереходит** на следующий pending-тикет
5. Повторяете пока очередь не закончится
6. Когда пусто — переход в **режим ожидания** с countdown, который опрашивает новые тикеты

Своё место не теряете: закрытие и открытие вкладки = подхватите со следующего pending-тикета когда он загрузится.

## Структура

Три колонки на широких экранах, складываются на узких:

| Колонка     | Ширина | Содержимое                                                               |
| ----------- | ------ | ------------------------------------------------------------------------ |
| **Image**   | 5/12   | Зумируемое evidence-фото + timestamp                                     |
| **Actions** | 4/12   | Пять кнопок смены статуса + Skip + Comment                               |
| **Info**    | 3/12   | Карточка ticket info со статусом, типом, транспортом, репортёром, датами |

Прогресс-бар сверху показывает как далеко вы в очереди.

## Шапка

- **Заголовок** "Ticket Auto Review"
- **Подзаголовок** с прогрессом: `Reviewing X of Y · T-12345`
- **Кнопка Skip** (вверху-справа) — пропустить текущий тикет без решения (тикет остаётся _Pending_)
- **Стрелка назад** — возврат к [списку тикетов](tickets.md)

## Кнопки действий

Пять переходов статуса плюс Skip и опциональный Comment:

| Кнопка           | Новый статус     | Когда использовать                                             |
| ---------------- | ---------------- | -------------------------------------------------------------- |
| **Resolve**      | _Resolved_       | Проблема решена (или была не реальной) — закрывает тикет       |
| **In Work**      | _In progress_    | Проблема реальная, запустили fix (maintenance task, follow-up) |
| **Waiting Info** | _Waiting info_   | Нужна доп. инфа от райдера до решения — он получит prompt      |
| **Dismiss**      | _Dismissed_      | Не реальная проблема (low-quality report, wrong target, спам)  |
| **Duplicate**    | _Duplicate_      | Другой тикет уже существует на тот же транспорт / проблему     |
| **Skip**         | (без изменений)  | Не решать; перейти к следующему                                |
| **Comment**      | (любое действие) | Опциональная заметка прикреплённая к клику                     |

Каждый клик commit-ит немедленно и переходит к следующему. **Сначала пишите комментарий** если хотите его прикрепить.

### Какой закрывающий статус выбрать

- **Resolve** — сломанное починили (или репорт был недоразумением проверенным на транспорте)
- **Dismiss** — репорт плохой / фейк / не туда; райдер видит dismiss в приложении
- **Duplicate** — link к оригиналу; бэк обрабатывает цепочку, resolution одного закрывает всех

_Resolve_, _Dismiss_ и _Duplicate_ — все закрывают тикет. _In Work_ и _Waiting Info_ оставляют его открытым в другой корзине.

## Info-колонка

Карточка **Ticket Info** справа показывает структурированные данные за фото:

- **Status** — пилюля текущего статуса
- **Complaint type** — окрашенная пилюля (mechanical damage, electrical, battery и т.д.)
- **Vehicle** — метка и ссылка
- **Reporter** — имя (рейдер) или label (system / оператор)
- **Location** — адрес / координаты
- **Created / updated** — timestamps
- **SLA** — оставшееся время (или "overdue" бейдж)

Читайте эту карточку до решения — она даёт полную картину не уходя со страницы.

## Режим ожидания

Когда очередь пустеет, страница показывает тот же waiting screen что и для Park Proofs:

- Сообщение "All tickets reviewed"
- **Countdown** до следующего автоопроса
- Кнопка **Check now** — опросить сразу
- Кнопка **Exit** — вернуться к списку

Если новый тикет приходит во время ожидания, страница автозагрузит его.

## Когда использовать Auto Review vs Список

| Используйте список когда…                              | Используйте Auto Review когда…                    |
| ------------------------------------------------------ | ------------------------------------------------- |
| Нужен фильтр по статусу, типу или транспорту           | Разгребаете неотфильтрованную pending-очередь     |
| Расследуете историю конкретного транспорта или райдера | Сосредоточены на одном тикете за раз, full-screen |
| Аудит прошлых решений (Resolved / Dismissed и т.д.)    | Нужна скорость: прочитать → решить → следующий    |
| Нужно эскалировать на maintenance-команду              | В режиме смены, работаете очередь end-to-end      |

## Типичные сценарии

- **Старт смены** — открыть Auto Review → пройти каждый pending → закончить на экране ожидания
- **Быстрый триаж** — прочитать фото + тип + репортёра → если очевидно, _Resolve_ / _Dismiss_ с однострочным комментарием; если нет, _In Work_ и тегнуть maintenance в комментарии
- **Ждать райдера** — когда репорт неясен, _Waiting Info_ с вопросом в комментарии; райдер получит prompt
- **Дедуп** — когда поиск показывает уже открытый тикет на тот же транспорт, _Duplicate_ для связи
- **Двусмысленный случай** — _Skip_ и открыть из списка с полным контекстом (история транспорта, related rides, IoT alerts)

## Полезные приёмы

- **Сначала комментарий** — то же правило что и Park Proofs: action commit-ит до того как поздний комментарий сохранится
- **Skip ≠ решение** — Skip ничего не закрывает; тикет остаётся в очереди для следующего оператора
- **Resolve vs Dismiss — не одно и то же** — _Resolve_ = "мы починили"; _Dismiss_ = "это не было реальной проблемой"; райдер видит разницу в приложении
- **Обработка дубликатов** — сначала поиск по метке транспорта; если есть parent — Duplicate, иначе resolve самый информативный и Duplicate остальные
- **SLA-таймер всё ещё тикает** во время ожидания — если очередь пустая но в списке есть overdue, эти строки отфильтрованы из Auto Review (возможно permissions, возможно статус); зайдите на список
- **Auto Review уважает порядок с бека** — порядок новых pending может варьироваться по deployment; считайте порядок очереди авторитетным
