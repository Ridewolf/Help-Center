# Welcome to Ridewolf Dashboard

The Ridewolf Dashboard is the control center for managing a shared-mobility fleet. Whether you operate scooters, bikes, or any other vehicle type, this is where you monitor real-time activity, manage customers, handle support, and analyze performance.

## Who this dashboard is for

The dashboard is built for **operators** — staff who work day-to-day with the fleet:

- **Fleet managers** — vehicles, zones, tariffs
- **Support agents** — tickets, conversations, park proofs
- **Analysts** — metrics, reports, performance
- **Administrators** — operators, roles, system settings

What each operator sees depends on their **role and permissions**. Your view may be narrower than the screenshots in this guide if some modules are restricted for your role.

## Core concepts

The dashboard is organized around a few concepts you will meet everywhere:

| Concept        | What it means                                                                 |
| -------------- | ----------------------------------------------------------------------------- |
| **Vehicle**    | A physical unit in the fleet (scooter, bike, etc.) — has GPS, battery, status |
| **Ride**       | A trip taken by a customer on a vehicle — has start/end time, route, cost     |
| **Client**     | A registered customer who can rent vehicles                                   |
| **Payment**    | Money transactions tied to rides, top-ups, or refunds                         |
| **Zone**       | A geographic area where vehicles operate (or are restricted from)             |
| **Tariff**     | Pricing rules that govern how much rides cost                                 |
| **Tag**        | A label attached to clients or vehicles for grouping and filtering            |
| **Ticket**     | A customer support request                                                    |
| **Park Proof** | A photo a customer submits to confirm correct parking                         |

## Basic navigation

### Sidebar (left)

The sidebar is the primary navigation. Groups expand to reveal sub-pages — for example, **Support** expands into Tickets, Park Proofs, and Conversations.

### Top bar

The top bar appears on every page and contains:

- **Breadcrumb** — the path back through the hierarchy (e.g. Home → Vehicles → RW-001)
- **AI Chat** (sparkle icon) — an assistant that can answer questions about the dashboard
- **Help** (question-mark icon) — opens this knowledge base, contextual to the current page
- **Notifications** (bell icon) — recent system events and alerts
- **Profile** (avatar) — settings, password change, sign out, theme controls

### Tables

Most list pages (vehicles, rides, clients, etc.) follow the same layout:

1. **Search bar** on top for full-text search
2. **Filter pills** below for narrowing by status, type, etc.
3. **Sortable columns** — click a column header to sort
4. **Pagination** at the bottom
5. **Row actions** — a three-dot menu on each row for quick actions

## What to do first

If this is your first time in the dashboard, we recommend:

1. **Update your profile** — avatar → Profile, fill in name, photo, contact details
2. **Browse the fleet** — open **Vehicles** to see what is currently active
3. **Check today's rides** — open **Rides** filtered to today to watch real-time activity
4. **Open the home dashboard** — the main `/dashboard` page summarizes daily KPIs
5. **Read this knowledge base** — open the relevant section before doing your first action in each module

## Getting help

There are three ways to get help from inside the dashboard:

- **Help icon (?)** in the top bar — opens a side drawer with documentation relevant to the page you are on
- **Help** in the sidebar (book icon) — the full, searchable knowledge base
- **Feedback / Suggestion forms** on the Help home page — write to the team directly
